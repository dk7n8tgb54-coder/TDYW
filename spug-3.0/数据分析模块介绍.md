# 数据分析模块介绍

## 概述

数据分析模块是一个**只读聚合统计**模块，跨 `fault`（故障）、`interference`（干扰）、`device`（设备）、`upgrade`（升级）四个业务域，为管理人员提供全局可视化的数据看板。

该模块不新增任何业务表或数据库迁移，所有数据均从现有业务表实时聚合而来，辅以 60 秒 Redis 缓存提升响应速度。

## 功能页面

模块包含 5 个分析页面，以 Tab 形式组织，用户可根据权限访问对应页面：

### 1. 总览分析

跨模块汇总指标，一屏掌握全局状况。

| 指标 | 说明 |
|---|---|
| 故障记录数 | 所选日期范围内的故障记录总数 |
| 干扰记录数 | 所选日期范围内的干扰记录总数 |
| 设备总数 | 当前设备快照（不受日期范围影响） |
| 设备故障数 | 当前处于故障状态的设备数 |
| 升级记录数 | 所选日期范围内的升级记录总数 |
| 升级完成数 | 所选日期范围内已完成的升级记录数 |
| 升级完成率 | 已完成数 / 升级记录总数 |
| 设备正常数 | 当前处于正常状态的设备数 |

同时展示 3 条月度趋势折线图：故障记录趋势、干扰记录趋势、升级记录趋势。

### 2. 故障分析

聚焦故障记录与故障件的统计。

- **汇总指标**：故障记录数、故障件总数、已归档数、未归档数、归档率
- **趋势图**：故障记录月度趋势、故障件月度趋势
- **分布图**：按故障级别、按所属系统、按故障件状态、按故障件系统

### 3. 干扰分析

聚焦无线电干扰记录的统计。

- **汇总指标**：干扰记录数、已上报数、未上报数、上报率
- **趋势图**：干扰记录月度趋势
- **分布图**：按干扰类型、按频率、按状态、按上报部门

### 4. 设备分析

聚焦设备台账的当前快照与新增趋势。

- **汇总指标**：设备总数、正常、故障、维修中、停用、报废、区间新增
- **趋势图**：设备新增月度趋势
- **分布图**：按设备状态、按设备型号、按厂商、按使用单位

### 5. 升级分析

聚焦系统升级记录的统计。

- **汇总指标**：升级记录数、处理中、已完成、已回退、完成率
- **趋势图**：升级记录月度趋势
- **分布图**：按升级状态、按升级类型、按系统

## 使用方式

### 日期筛选

页面右上角提供日期范围选择器，默认展示**最近 365 天**的数据。用户可自定义日期范围，最大跨度为 366 天。切换日期后当前 Tab 会自动重新加载数据。

### 刷新

点击"刷新"按钮可手动重新获取当前 Tab 的数据（受 60 秒缓存 TTL 约束）。

### 权限控制

模块采用独立的 5 个权限码，管理员可为角色按需分配：

| 权限码 | 说明 |
|---|---|
| `data_analysis.overview.view` | 查看总览分析 |
| `data_analysis.fault.view` | 查看故障分析 |
| `data_analysis.interference.view` | 查看干扰分析 |
| `data_analysis.device.view` | 查看设备分析 |
| `data_analysis.upgrade.view` | 查看升级分析 |

- 菜单显示条件：拥有以上任意一个权限
- Tab 显示：仅显示有权限的 Tab，默认打开第一个有权限的页面
- 超级管理员和全局管理员可查看全租户数据，普通用户仅可查看本租户数据

## 技术架构

### 后端

```
spug_api/apps/data_analysis/
├── apps.py                  # AppConfig
├── urls.py                  # 5 条路由
├── views.py                 # 视图工厂（权限 + 日期解析 + 缓存 + 服务调用）
├── services/
│   ├── common.py            # 日期校验、范围过滤、分布构建、月度趋势
│   ├── cache.py             # 可见范围感知的缓存键与容错
│   ├── overview.py          # 总览分析
│   ├── fault.py             # 故障分析
│   ├── interference.py      # 干扰分析
│   ├── device.py            # 设备分析
│   └── upgrade.py           # 升级分析
└── tests.py                 # 单元测试（39 个断言）
```

**关键设计**：

- **纯只读**：不创建 model、不写 migration，仅跨 app 查询现有业务表
- **日期半开区间**：使用 `__gte=start 00:00:00` + `__lt=end+1day 00:00:00`，避免 `23:59:59` 写法
- **月度趋势补零**：`TruncMonth` 一次聚合后，在 Python 中对缺失月份填 `count: 0`
- **分布 Top10**：高基数字段只返回前 10 项，其余合并为"其他"
- **缓存隔离**：缓存键含 `scope`（`all` 或 `tenant:{id}`），防止跨租户串数
- **Redis 容错**：缓存读取失败时回退到实时查询，不影响页面可用性
- **软删除过滤**：所有查询显式排除 `is_deleted=True`
- **租户隔离**：统一调用 `apply_tenant_filter(qs, user)`

### 前端

```
spug_web/src/pages/dataAnalysis/
├── index.js                         # 主容器（Tab 导航 + 权限过滤 + 日期选择）
├── store.js                         # MobX store（5 Tab 独立状态）
├── Overview.js                      # 总览分析页
├── FaultAnalysis.js                 # 故障分析页
├── InterferenceAnalysis.js          # 干扰分析页
├── DeviceAnalysis.js                # 设备分析页
├── UpgradeAnalysis.js               # 升级分析页
└── components/
    ├── StatCard.js                  # 统计卡片
    ├── TrendChart.js                # 月度趋势折线图
    └── DistributionChart.js         # 分布图表（饼图/柱图切换）
```

**关键设计**：

- **MobX 状态管理**：每个 Tab 维护独立的 `loading`/`data`/`error` 状态，互不干扰
- **observer 包裹**：所有读取 store 的组件均用 `observer` 包裹，确保 UI 响应 store 变更
- **按需加载**：切换 Tab 时首次加载，已加载的 Tab 切回不重复请求
- **BizCharts 图表**：折线图展示月度趋势，饼图/柱图展示分布（可切换）
- **响应式布局**：使用 antd Row/Col 栅格，桌面端和移动端均可正常查看
- **加载/错误状态**：Skeleton 骨架屏 + Alert 错误提示 + 重试按钮

## API 接口

| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/data-analysis/overview/` | GET | 总览分析 |
| `/api/data-analysis/fault/` | GET | 故障分析 |
| `/api/data-analysis/interference/` | GET | 干扰分析 |
| `/api/data-analysis/device/` | GET | 设备分析 |
| `/api/data-analysis/upgrade/` | GET | 升级分析 |

**请求参数**：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `start_date` | string | 否 | 开始日期，格式 `YYYY-MM-DD`，默认今天往前 364 天 |
| `end_date` | string | 否 | 结束日期，格式 `YYYY-MM-DD`，默认今天 |

**响应结构**：

```json
{
  "data": {
    "meta": {
      "start_date": "2025-08-05",
      "end_date": "2026-08-04",
      "timezone": "Asia/Shanghai",
      "generated_at": "2026-08-04 10:30:00"
    },
    "summary": { ... },
    "trends": { ... },
    "distributions": { ... }
  }
}
```

## 配置说明

### 后端注册

- `spug_api/spug/settings.py` 的 `INSTALLED_APPS` 已添加 `'apps.data_analysis'`
- `spug_api/spug/urls.py` 已添加 `path('data-analysis/', include('apps.data_analysis.urls'))`

### 前端注册

- `spug_web/src/routes.js` 中 `/data-analysis` 路由已添加 `auth` 权限表达式
- `spug_web/src/pages/system/role/codes.js` 已添加 `data_analysis` 权限组（5 个页面各 1 个 `view` 权限）

### 授权方式

1. 以管理员身份登录系统
2. 进入 **系统管理 -> 角色管理**
3. 编辑目标角色，在权限树中勾选"数据分析"下所需的页面权限
4. 保存后该角色用户即可在左侧菜单看到"数据分析"入口

## 数据口径说明

| 项目 | 口径 |
|---|---|
| 日期范围 | 默认最近 365 天，最大跨度 366 天 |
| 日期边界 | 半开区间 `[start 00:00:00, end+1day 00:00:00)` |
| 月度趋势 | 按自然月聚合，缺失月份补零 |
| 比例 | 保留 1 位小数，分母为 0 时返回 `0.0%` |
| 空值字段 | 统一显示"未填写" |
| 高基数字段 | 返回前 10 项，其余合并为"其他" |
| 设备状态快照 | 不受日期范围影响，始终为当前状态 |
| 故障件归档 | `status == '正常归档'` 为已归档 |
| 干扰上报 | `is_reported == '是'` 为已上报 |
| 升级完成率 | `已完成 / 本期升级记录总数 * 100` |
| 软删除 | 所有查询显式排除 `is_deleted=True` |
| 租户隔离 | 超级/全局管理员可见全租户，普通用户仅本租户 |
