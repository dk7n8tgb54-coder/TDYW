## 五、性能问题检查

### 5.1 N+1查询问题

#### 5.1.1 回收站列表查询
**文件**: `views/recycle_bin/list.py` 第279-285行

```python
# 问题代码
for folder_id in folder_ids:
    files = FileModel.all_objects.filter(folder_id=folder_id, is_deleted=True)
    total_files += files.count()
    total_size += sum(f.file_size for f in files)  # N+1查询
```

**优化建议**:
```python
# 使用聚合查询
from django.db.models import Sum, Count
stats = FileModel.all_objects.filter(
    folder_id__in=folder_ids, 
    is_deleted=True
).aggregate(
    total_files=Count('id'),
    total_size=Sum('file_size')
)
```

#### 5.1.2 文件夹删除统计
**文件**: `views/recycle_bin/folder_delete.py` 第142-148行

同样存在N+1查询问题，建议使用批量查询优化。

### 5.2 递归性能问题

#### 5.2.1 深度递归风险
**文件**: `folder_delete.py`, `folder_restore.py`, `cleanup.py`

**问题**: 使用递归处理文件夹树，层级过深时可能导致:
- Python 递归深度限制（默认1000）
- 栈溢出
- 内存占用过高

**优化建议**: 使用迭代+队列替代递归
```python
# 优化前（递归）
def _get_folder_descendants(folder):
    result = [folder.id]
    for child in folder.children.all():
        result.extend(_get_folder_descendants(child))
    return result

# 优化后（迭代）
def _get_folder_descendants_iter(folder):
    result = []
    queue = [folder]
    while queue:
        current = queue.pop(0)
        result.append(current.id)
        queue.extend(current.children.all())
    return result
```

### 5.3 前端性能问题

#### 5.3.1 分片上传阻塞
**文件**: `chunkUpload.js` 第128-181行

```javascript
// 问题：顺序上传分片，没有并发
for (let i = 0; i < chunks.length; i++) {
    await uploadChunk(chunks[i]);  // 阻塞等待
}
```

**优化建议**: 使用并发池控制并发数
```javascript
// 使用Promise.all + 并发控制
const CONCURRENT_UPLOADS = 3;
for (let i = 0; i < chunks.length; i += CONCURRENT_UPLOADS) {
    const batch = chunks.slice(i, i + CONCURRENT_UPLOADS);
    await Promise.all(batch.map(uploadChunk));
}
```

#### 5.3.2 进度更新过于频繁
**文件**: `chunkUpload.js` 第343-354行

```javascript
// 问题：每上传一个分片就更新UI
onProgress: (progress) => {
    updateProgress(progress);  // 触发React重新渲染
}
```

**优化建议**: 使用节流函数
```javascript
import { throttle } from 'lodash';

const throttledUpdate = throttle(updateProgress, 200);
onProgress: (progress) => {
    throttledUpdate(progress);
}
```

#### 5.3.3 MD5计算阻塞

**优化建议**:

- 对于大文件，使用抽样MD5而非全量计算

## 六、异常处理与日志检查

### 6.1 后端异常处理

#### 6.1.1 事务一致性缺失
**问题**: 文件夹批量删除/恢复操作缺少数据库事务保护

**位置**:
- `folder_delete.py`: `async_batch_folder_permanent_delete`
- `folder_restore.py`: `_restore_folder_recursive`

**风险**: 操作中途失败可能导致数据不一致（部分文件删除，部分未删除）

**优化建议**:
```python
from django.db import transaction

@transaction.atomic
def delete_folders_atomic(folder_ids):
    """原子性删除文件夹"""
    for folder_id in folder_ids:
        # 删除操作...
        pass
```

#### 6.1.2 异常捕获不完善
**位置**: `cleanup.py` 多处

**问题**: 部分代码块使用裸 `except:` 捕获所有异常，可能隐藏真正的问题

**建议**: 使用具体异常类型
```python
# 不推荐
except:
    logger.error('操作失败')

# 推荐
except (DocumentFolder.DoesNotExist, PermissionDenied) as e:
    logger.error(f'操作失败: {e}')
except Exception as e:
    logger.exception(f'未预期的错误: {e}')
    raise
```

### 6.2 前端异常处理

#### 6.2.1 组件卸载时未取消请求
**位置**: `chunkUpload.js`, `fileUpload.js`

**问题**: 组件卸载时，未完成的上传请求未取消，可能导致内存泄漏和状态更新错误

**优化建议**:
```javascript
// 使用AbortController
const abortController = new AbortController();

// 组件卸载时取消
useEffect(() => {
    return () => {
        abortController.abort('组件卸载');
    };
}, []);
```
