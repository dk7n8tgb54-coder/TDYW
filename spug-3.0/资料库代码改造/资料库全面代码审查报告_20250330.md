## 二、新发现的问题

### 2.1 低风险问题（P2）

#### 🟡 P2-3: folder/views.py N+1查询问题

**位置**: `views/folder/views.py` 第117行、173行

**问题代码**:
```python
# 第117行
total_folders = folders_query.count()  # 第1次count
# ... 若干行 ...
total_files = files_query.count()      # 第2次count

# 第173行重复同样的问题
total_folders = folders_query.count()
total_files = files_query.count()
```

**影响**: 分页接口产生额外的COUNT查询，数据量大时性能下降

**建议**: 使用 `len()` 替代 `count()`（如果已查询）或缓存结果

---

#### 🟡 P2-4: chunk_checker.py 异常信息可能泄露

**位置**: `views/upload/chunk_checker.py` 第246行

**问题代码**:
```python
except Exception as e:
    logger.error(...)
    return False, {
        'exists': False,
        'uploaded_chunks': [],
        'error': f'验证传输记录失败: {str(e)}'  # 可能泄露敏感信息
    }
```

**影响**: 异常信息可能包含数据库结构等敏感信息

**建议**: 返回通用错误消息

---

#### 🟡 P2-5: batch.py 复杂Q对象查询

**位置**: `views/transfer/batch.py` 第45-48行、107-110行

**问题代码**:
```python
permitted_transfers = all_transfers.filter(
    Q(user=request.user) | Q(user__isnull=True) if is_supper else Q(user=request.user),
    Q(tenant_id=request_tenant_id) | Q(tenant_id='') | Q(tenant_id__isnull=True) if is_supper else Q(tenant_id=request_tenant_id)
).distinct()
```

**问题**:
1. 条件表达式嵌套复杂，可读性差
2. 超级管理员查询范围过大，可能性能问题

**建议**: 拆分条件逻辑，简化查询
