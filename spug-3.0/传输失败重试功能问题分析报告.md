# 传输失败重试功能问题分析报告

## 问题描述

用户点击传输失败任务的重试按钮后没有任何反应，任务状态没有变化，也没有错误提示。

## 根本原因

**文件对象在上传失败时被清理，导致重试时无法继续上传。**

### 问题流程

```
1. 上传过程中发生错误
   ↓
2. 状态机进入 error 状态
   ↓
3. onErrorEntry 钩子调用 cleanupAllResources()
   ↓
4. cleanupAllResources 将 item.file 设为 null  ← 【问题点】
   ↓
5. 用户点击"重试"按钮
   ↓
6. 状态机从 error → waiting 状态转换成功
   ↓
7. 从 waiting → calculating 时检查 file 对象
   ↓
8. 发现 file 为 null，再次进入 error 状态
   ↓
9. 提示"请重新选择文件"（但用户看不到）
```

## 代码定位

### 1. 问题代码位置

**文件**: `spug_web/src/pages/document/stores/upload/core/UploadStateMachine.js`

**代码片段1** - error状态的entry钩子清理资源:
```javascript
onErrorEntry() {
  this.updateItem({
    status: 'error',
    canAbort: false
  });
  
  // 清理资源
  this.cleanupAllResources();  // ← 这里清理了file对象
}
```

**代码片段2** - cleanupAllResources方法:
```javascript
cleanupAllResources() {
  const scheduleCleanup = typeof queueMicrotask !== 'undefined'
    ? queueMicrotask
    : (fn) => Promise.resolve().then(fn);
  scheduleCleanup(() => {
    this.updateItem({
      abortController: null,
      abortToken: null,
      file: null  // ← file被设为null，导致重试失败
    });
  });
}
```

**代码片段3** - calculating状态的entry钩子检查file:
```javascript
onCalculatingEntry() {
  const item = this.getItem();
  if (!item?.file) {
    this.updateItem({
      status: 'error',
      error: '请重新选择文件',  // ← 用户看不到这个提示
      canAbort: false
    });
    // ...
    return;
  }
  // ...
}
```

## 解决方案

### 方案1：错误状态不清理file对象（推荐）

修改 `onErrorEntry`，在错误状态时不清理 file 对象，只清理其他资源：

```javascript
onErrorEntry() {
  this.updateItem({
    status: 'error',
    canAbort: false
  });
  
  // 【修复】错误状态不清理file，保留用于重试
  // 只清理中止控制器和令牌
  const scheduleCleanup = typeof queueMicrotask !== 'undefined'
    ? queueMicrotask
    : (fn) => Promise.resolve().then(fn);
  scheduleCleanup(() => {
    this.updateItem({
      abortController: null,
      abortToken: null
      // 注意：不清理 file，保留用于重试
    });
  });
}
```

### 方案2：completed状态才清理file

修改 `cleanupAllResources`，只在 completed 和 cancelled 状态清理 file：

```javascript
cleanupAllResources(shouldCleanupFile = true) {
  const scheduleCleanup = typeof queueMicrotask !== 'undefined'
    ? queueMicrotask
    : (fn) => Promise.resolve().then(fn);
  scheduleCleanup(() => {
    const updates = {
      abortController: null,
      abortToken: null
    };
    if (shouldCleanupFile) {
      updates.file = null;
    }
    this.updateItem(updates);
  });
}
```

然后在 `onErrorEntry` 中：
```javascript
onErrorEntry() {
  this.updateItem({
    status: 'error',
    canAbort: false
  });
  
  // 【修复】错误状态保留file
  this.cleanupAllResources(false);
}
```

### 方案3：重试时触发文件重新选择

如果file确实需要清理（内存考虑），则重试时应该触发文件选择对话框：

```javascript
onCalculatingEntry() {
  const item = this.getItem();
  if (!item?.file) {
    // 【修复】触发文件重新选择，而不是直接报错
    if (this.context.triggerFileReSelection) {
      this.context.triggerFileReSelection(this.uploadId);
    }
    this.updateItem({
      status: 'waiting',
      error: '请重新选择文件以继续上传',
      canAbort: false
    });
    return;
  }
  // ...
}
```

## 建议实施方案

**推荐方案1**，理由：
1. 实现最简单，改动最小
2. 用户体验最好，重试无需重新选择文件
3. 只有 completed 和 cancelled 状态才真正需要释放 file 内存
4. error 状态的任务很快会被用户重试或删除，不会长期占用内存

## 修复代码

```javascript
// UploadStateMachine.js

onErrorEntry() {
  this.updateItem({
    status: 'error',
    canAbort: false
  });
  
  // 【修复】错误状态不清理file，保留用于重试
  // 只清理中止控制器和令牌，避免内存泄漏
  const scheduleCleanup = typeof queueMicrotask !== 'undefined'
    ? queueMicrotask
    : (fn) => Promise.resolve().then(fn);
  scheduleCleanup(() => {
    this.updateItem({
      abortController: null,
      abortToken: null
    });
  });
}
```

## 验证测试

修复后应验证以下场景：

1. **网络错误重试**: 断开网络导致上传失败，恢复网络后点击重试
2. **服务器错误重试**: 服务器返回500错误，点击重试
3. **分片上传失败重试**: 大文件分片上传中某分片失败，点击重试
4. **MD5计算失败重试**: MD5计算过程中出错，点击重试
5. **内存占用**: 确认error状态不清理file不会导致内存问题
