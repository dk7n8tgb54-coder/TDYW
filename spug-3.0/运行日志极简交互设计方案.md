# 运行日志极简交互设计方案

## 核心简化：反向创建 + 智能匹配

**原流程（3步）：**
```
1. 创建运行日志事件（容器）
2. 去模块录入
3. 选择关联事件
```

**新流程（1步）：**
```
直接在模块录入，一键"记到运行日志"
```

## 更激进的简化：全自动关联

### 智能匹配规则

系统根据以下条件自动建议/创建关联：

```python
规则1: 同设备 + 时间差<2小时 → 自动归入同一事件
规则2: 故障创建时 → 自动创建同名运行日志事件
规则3: 故障状态变更（修复/关闭）→ 自动添加动态
规则4: 升级记录 → 自动创建运行日志事件
```

### 效果

**值班人员操作：**
```
1. 去设备履历正常录入故障
   ↓
2. 系统自动：
   • 创建运行日志事件"支付服务超时故障处置"
   • 添加动态"14:30 故障发生"
   
3. 故障修复后更新状态
   ↓
4. 系统自动：
   • 添加动态"16:00 故障修复"
   
5. 打开运行日志 → 看到完整事件时间线
   （全程无需手动操作）
```

**需要手动的情况：**
```
• 写纯文本的补充说明 → 点击"添加动态"
• 把两个无关的事件合并 → 手动选择关联
• 创建无模块关联的事件 → 点击"手动创建"
```

## 三种模式对比

| 模式 | 操作步骤 | 适用场景 | 实现复杂度 |
|------|----------|----------|------------|
| **原方案** | 3步：创建事件→模块录入→选择关联 | 精确控制 | 中 |
| **简化方案** | 1步：模块录入时一键关联 | 推荐✅ | 低 |
| **全自动** | 0步：系统自动关联 | 标准化流程 | 中 |

---

## 推荐：简化方案（一键关联）

**理由：**
1. 不改变现有模块录入习惯
2. 一键操作，心智负担最低
3. 既自动又可控（可取消关联）
4. 实现简单

**界面改造点：**
1. 各模块表单底部增加 `[记到运行日志]` 按钮
2. 弹出层：创建新事件 / 关联现有事件
3. 运行日志页被动展示，无需主动创建
