# 平台顶部多标签页导航方案

## 1. 文档目的

本文定义平台顶部多标签页导航的产品行为、技术设计、实施范围、测试要求和上线策略，作为后续开发与评审依据。

本方案中的“标签页”是**导航型标签页**：记录用户当前会话中打开过的页面，帮助用户在多个业务模块之间快速切换。标签切换仍然通过 React Router 路由完成，不在后台同时挂载多个页面组件。

## 2. 背景与现状

当前平台的主框架由以下部分组成：

- `spug_web/src/layout/index.js`：主布局和页面路由出口。
- `spug_web/src/layout/Header.js`：顶部栏，承载侧栏开关、告警和账户入口。
- `spug_web/src/layout/Sider.js`：左侧主菜单，通过 `history.push()` 切换路由。
- `spug_web/src/routes.js`：菜单、路由组件和前端权限的统一配置。
- `spug_web/src/libs/history.js`：全局 Browser History 实例。

当前左侧菜单用于发现和进入系统功能，但无法展示用户已经打开的工作页面。用户在执照、合同、日志、设备等页面之间反复切换时，需要多次展开菜单并重新定位入口。

## 3. 建设目标

### 3.1 目标

1. 在顶部栏和内容区之间增加一行标签栏。
2. 用户进入一个可展示的路由时，自动创建或激活对应标签。
3. 用户可以通过标签快速切换、关闭当前页面，并批量关闭其他标签。
4. 标签状态与浏览器前进、后退、左侧菜单和页面内跳转保持同步。
5. 页面刷新后可以恢复当前账号本次浏览器会话中的标签列表。
6. 恢复标签时重新执行路由和权限校验，不能恢复无权访问的页面。
7. 不改变现有后端接口、权限编码和租户隔离逻辑。

### 3.2 非目标

第一阶段不实现以下能力：

- 不缓存已经切走的 React 页面实例。
- 不承诺保留未提交表单、已打开弹窗、滚动位置或组件内部临时状态。
- 不在服务端或不同浏览器之间同步标签。
- 不允许一个标签绕过 `routes.js` 中的 `auth` 权限。
- 不用标签页替代左侧主菜单。

## 4. 导航职责划分

| 导航区域 | 职责 | 数据来源 |
|---|---|---|
| 左侧主菜单 | 展示平台完整功能结构，帮助用户寻找功能 | `routes.js` |
| 顶部标签栏 | 展示当前会话已打开页面，帮助用户快速切换 | 当前路由 + 会话标签状态 |
| 浏览器前进/后退 | 按历史记录移动 | Browser History |
| 页面内链接 | 进入详情、个人中心、公告查询等页面 | 页面业务逻辑 |

左侧菜单和顶部标签最终都调用同一个 `history` 实例，因此当前路由、左侧高亮和标签激活状态必须始终一致。

## 5. 交互设计

### 5.1 布局位置

标签栏放在 `Header` 下方、`Layout.Content` 上方：

```text
+----------------------------------------------------+
| Header：折叠菜单                  告警  用户        |
+----------------------------------------------------+
| [工作台] [无线电台执照 x] [合同协议 x]             |
+----------------------------------------------------+
|                                                    |
| 当前路由对应的页面内容                             |
|                                                    |
+----------------------------------------------------+
| Footer                                             |
+----------------------------------------------------+
```

标签栏高度固定，不随标题长度或标签数量改变。标签过多时横向滚动，不挤压右侧内容，不改变主内容区宽度。

### 5.2 打开标签

以下行为都应触发相同的标签同步逻辑：

- 点击左侧菜单。
- 点击页面内的 `<Link>`。
- 业务代码调用 `history.push()` 或 `history.replace()`。
- 使用浏览器前进或后退。
- 直接输入平台内部 URL。
- 刷新页面后恢复路由。

路由已存在标签时只激活该标签，不重复创建。

### 5.3 标签唯一性

标签唯一键默认使用 `pathname`：

- `/radio-license?page=1` 与 `/radio-license?page=2` 使用同一个标签。
- 查询参数变化时更新该标签保存的完整 URL，切回来时进入最近一次查询状态。
- `/upgrade/workbench/12` 与 `/upgrade/workbench/18` 的 `pathname` 不同，因此是两个标签。

标签保存的跳转地址应包含 `pathname + search + hash`，但不得保存 token、Cookie 或页面数据。

### 5.4 切换标签

点击非当前标签时执行 `history.push(tab.url)`。禁止直接修改标签激活状态而不更新路由。

切换后：

- 左侧菜单同步高亮匹配的菜单项。
- 当前标签进入激活样式。
- `<Switch>` 渲染对应路由组件。
- 页面按照现有生命周期重新加载，不承诺保留组件内部状态。

### 5.5 关闭标签

关闭非当前标签时，只移除标签，不改变当前路由。

关闭当前标签时按以下顺序选择下一个页面：

1. 优先激活右侧相邻标签。
2. 没有右侧标签时激活左侧相邻标签。
3. 没有相邻标签时进入当前用户有权限访问的第一个默认路由。

如果“工作台”对当前用户可见，可将其配置为固定标签且不可关闭。不能假定所有账号都拥有工作台权限；无权限账号不得创建工作台标签。

### 5.6 标签菜单

标签右键菜单提供：

- 关闭当前。
- 关闭其他。
- 关闭右侧。
- 关闭全部可关闭标签。

菜单操作必须保留固定标签，并在当前标签被移除时按关闭回退规则导航。

第一阶段不增加“刷新当前页”按钮。浏览器刷新和重新进入路由已经能够完成刷新，额外的组件强制重挂载会增加页面副作用风险。

### 5.7 标题显示

标题优先级如下：

1. 路由显式配置的动态标签标题。
2. 路由显式配置的静态标签标题。
3. 路由现有的 `title`。
4. 未配置标题时不创建标签，并在开发环境输出警告。

标签标题单行显示，超出最大宽度时省略，鼠标悬停通过 Tooltip 展示完整标题。标题中不得展示敏感业务数据。

### 5.8 移动端

- 标签栏保持单行横向滚动。
- 单个标签设置稳定的最小和最大宽度。
- 当前标签自动滚动到可见区域。
- 标签关闭按钮保持固定尺寸，不能被标题挤出。
- 不使用随视口宽度缩放的字体。

## 6. 技术方案

### 6.1 总体数据流

```text
routes.js
   |
   v
路由元数据扁平化 + 权限过滤
   |
   v
PageTabs 监听 location 变化 <---- 左侧菜单 / 页面 Link / 浏览器历史
   |
   +---- 新增或更新标签
   +---- 设置当前 activeKey
   +---- 写入 sessionStorage
   |
   v
点击或关闭标签 ----> history.push/replace ----> Layout 中的 Switch
```

路由是事实来源。标签状态不得成为第二套路由系统。

### 6.2 建议文件结构

```text
spug_web/src/layout/
├── PageTabs.js                    # 标签栏组件和交互
├── routeTabs.js                   # 路由扁平化、匹配、恢复与权限过滤
├── layout.module.less             # 标签栏样式
├── index.js                       # 在 Header 和 Content 之间挂载 PageTabs
└── __tests__/
    └── PageTabs.test.js           # 真实渲染和路由行为测试
```

除非后续出现多个独立消费者，否则第一阶段不新增全局 MobX Store。标签状态由 `PageTabs` 管理，并通过 `sessionStorage` 做会话恢复。

### 6.3 路由元数据

保留现有 `title` 作为菜单标题，并为特殊路由增加可选的 `tab` 配置：

```jsx
{
  title: '无线电台执照',
  auth: 'radio_license.license.view',
  path: '/radio-license',
  component: RadioLicenseIndex,
  tab: {
    title: '无线电台执照',
    affix: false,
  },
}
```

动态详情路由使用标题函数：

```jsx
{
  path: '/upgrade/workbench/:id',
  component: UpgradeWorkbench,
  tab: {
    title: match => `升级工作台 #${match.params.id}`,
  },
}
```

明确不需要标签的路由使用：

```jsx
tab: false
```

兼容规则：已有带 `title` 的业务路由无需批量修改；只有隐藏路由、动态路由或需要固定的路由才补充 `tab`。

### 6.4 路由匹配

`routeTabs.js` 递归扁平化 `routes.js`，只保留包含 `path` 和 `component` 的叶子路由，并使用 React Router 5 的 `matchPath()` 匹配当前 `pathname`。

匹配要求：

- 使用 `exact: true`，避免父路径误匹配子路径。
- 动态路由必须保留 `match.params`，用于生成标题。
- 匹配前后均执行 `auth` 权限校验。
- 菜单分组节点只有 `child`、没有 `component`，不得创建标签。
- 404 页面不创建可持久化标签。

### 6.5 标签数据结构

```js
{
  key: '/upgrade/workbench/12',
  url: '/upgrade/workbench/12?mode=view',
  pathname: '/upgrade/workbench/12',
  routePath: '/upgrade/workbench/:id',
  title: '升级工作台 #12',
  closable: true,
}
```

约束：

- `key` 在标签数组中唯一。
- `url` 只允许平台内部相对路径。
- 不序列化 React 组件、图标、权限结果或函数。
- `closable` 根据经过权限校验的路由配置重新计算，不信任缓存值。

### 6.6 会话持久化

使用按用户隔离的 `sessionStorage` 键：

```text
spug:page-tabs:v1:<userId>
```

值只保存标签顺序、URL 和当前标签键。恢复流程如下：

1. 读取当前登录用户 ID。
2. 解析缓存；解析失败时丢弃缓存，不能阻断页面加载。
3. 使用当前 `routes.js` 重新匹配每个 URL。
4. 使用当前 `hasPermission()` 重新过滤。
5. 重新生成标题、关闭属性和路由信息。
6. 移除重复项、404、外部 URL 和已删除路由。
7. 把当前地址对应标签加入列表并设为激活项。

退出登录时清理当前用户的标签缓存。即使未清理，缓存也不能包含业务数据或认证信息，重新登录后仍必须按用户 ID 和权限重新过滤。

### 6.7 Layout 接入

目标结构：

```jsx
<Layout style={{height: '100vh'}}>
  <Sider />
  <Layout className={styles.mainLayout}>
    <Header />
    <PageTabs routes={routes} />
    <Layout.Content className={styles.content} id="spug-container">
      <Switch>
        {Routes}
        <Route component={NotFound}/>
      </Switch>
    </Layout.Content>
    <Footer />
  </Layout>
</Layout>
```

`PageTabs` 必须在卸载时注销 history 监听器。不得新增固定周期定时器。

### 6.8 antd 组件约束

项目使用 antd 4.21.5，标签栏采用兼容该版本的 API：

```jsx
<Tabs
  type="editable-card"
  hideAdd
  activeKey={activeKey}
  onChange={handleChange}
  onEdit={handleEdit}
>
  {tabs.map(tab => (
    <Tabs.TabPane
      key={tab.key}
      tab={tab.title}
      closable={tab.closable}
    />
  ))}
</Tabs>
```

不要使用仅在更高版本 antd 中提供的 API。右键菜单继续使用项目当前 antd 4 的 `Dropdown overlay={menu}` 写法。

## 7. 页面状态策略

### 7.1 第一阶段行为

标签切换会改变路由，`<Switch>` 只渲染当前页面。离开的页面通常会卸载，再次进入时重新挂载并按现有逻辑请求数据。

可以稳定恢复的状态应逐步放入 URL，例如：

```text
/radio-license?page=3&status=expiring&keyword=ABC
```

这样标签保存完整 URL 后，可以恢复分页和筛选条件，同时保持浏览器前进、后退行为正确。

### 7.2 暂不采用全局 KeepAlive 的原因

平台中的页面并非纯展示组件，长期后台挂载可能带来以下问题：

- 资料库存在分片上传、目录导航和 `system_folder` 上下文。
- 提醒、告警和菜单徽标包含监听器或刷新逻辑。
- 页面级 MobX Store 可能继续持有旧查询条件和租户相关状态。
- 编辑表单可能保留过期数据，重新激活时覆盖服务端最新状态。
- 多个隐藏页面可能继续发请求、占用内存或响应全局事件。

如果后续确实需要页面现场保留，应按模块显式声明可缓存能力，逐个验证卸载、激活、租户切换和异步请求行为，不能默认缓存所有路由。

## 8. 权限与安全约束

1. 标签只能由当前用户有权访问的路由创建。
2. 从 `sessionStorage` 恢复时必须重新调用 `hasPermission()`。
3. 标签隐藏不等于权限控制，后端接口继续独立鉴权。
4. 权限变化导致当前标签失效时，应关闭该标签并导航到首个可访问路由。
5. 标签 URL 只接受以 `/` 开头的平台内部路径，禁止 `javascript:`、协议相对 URL 和外部 URL。
6. 标签存储不得包含 token、Cookie、表单内容、业务响应或用户输入标题。
7. 动态标题只使用经过约束的路由参数；不得直接展示 URL 查询参数中的任意文本。

## 9. 高风险模块处理

### 9.1 资料库与党建工作

- 标签切换不缓存 `DocumentIndex` 和 `PartyBuildingDocumentsIndex` 实例。
- 党建 `system_folder` 上下文继续由现有路由逻辑控制。
- 两个页面必须使用不同 `pathname` 和标签键，禁止合并。
- 上传任务是否允许跨路由继续执行维持现有行为，本方案不得擅自改变。

### 9.2 系统升级工作台

- `/upgrade/workbench/:id` 按实际 `pathname` 创建独立标签。
- 标题可以包含记录 ID，但第一阶段不额外请求接口获取业务名称。
- 同一 ID 的查询参数变化更新原标签 URL，不重复创建。

### 9.3 权限与租户切换

- 标签缓存按用户 ID 隔离。
- 登录、退出或权限刷新后重新过滤标签。
- 不缓存页面组件，避免旧租户页面实例继续持有数据。

### 9.4 告警、提醒和菜单徽标

- 标签栏不得调用或重启 badge store。
- `layout/index.js` 中现有 Store 生命周期保持唯一。
- 标签切换不得增加 `setInterval` 或循环 `setTimeout`。

## 10. 样式规范

建议视觉参数：

| 项目 | 建议值 |
|---|---|
| 标签栏高度 | 40px |
| 背景 | `#f5f7fa` 或现有 Layout 背景色 |
| 标签最小宽度 | 96px |
| 标签最大宽度 | 200px |
| 关闭按钮区域 | 固定 24px |
| 圆角 | 不大于 4px |
| 标题 | 单行省略，字距为 0 |

标签栏应与 Header、Content 形成清晰层级，不使用营销式卡片、渐变和装饰性背景。内容区现有 padding 保持不变。

## 11. 测试方案

测试必须真实渲染组件并执行路由行为，禁止读取源码字符串做正则断言。

### 11.1 组件行为测试

`spug_web/src/layout/__tests__/PageTabs.test.js` 至少覆盖：

1. 首次进入业务路由创建并激活标签。
2. 进入第二个路由后保留第一个标签。
3. 重复进入相同 `pathname` 不重复创建标签。
4. 查询参数变化更新标签 URL，不创建新标签。
5. 不同动态参数创建不同标签。
6. 点击标签调用路由跳转并同步激活状态。
7. 关闭非当前标签不改变当前路由。
8. 关闭当前标签后正确选择相邻标签。
9. 固定标签不可关闭。
10. 关闭其他、关闭右侧和关闭全部遵守固定标签规则。
11. 浏览器前进、后退后标签激活状态同步。
12. 无权限路由不创建标签。
13. 会话恢复时过滤无权限、重复、未知和非法 URL。
14. 缓存 JSON 损坏时正常进入当前页面。
15. 组件卸载后 history 监听器被清理。

### 11.2 现有布局回归

- 左侧菜单选中状态继续跟随当前路由。
- 侧栏折叠、展开不影响标签宽度计算。
- 告警弹层、账户菜单和退出登录正常。
- Footer 与内容区不重叠。
- 375px、768px、1440px 宽度下无文字或控件重叠。
- 标签栏出现后内容区仍只有一个主滚动容器。

### 11.3 重点业务冒烟

- 执照、批复、合同三个到期红点生命周期不变。
- 资料库与党建路由切换时上下文不串页。
- 升级工作台不同记录可生成独立标签。
- 个人中心、公告查询和隐藏管理路由能获得明确标题或被显式排除。

## 12. 实施步骤

### 阶段一：路由元数据与纯函数

1. 实现路由树扁平化和 `matchPath()` 匹配。
2. 实现标题解析、权限过滤和 URL 校验。
3. 为隐藏路由、动态路由补充最少量 `tab` 配置。
4. 为纯函数补充测试。

### 阶段二：标签交互

1. 实现 `PageTabs`。
2. 接入 history/location 同步。
3. 实现新增、激活、关闭和批量关闭。
4. 接入按用户隔离的 `sessionStorage`。
5. 在 Layout 中挂载标签栏并完成响应式样式。

### 阶段三：回归与上线

1. 运行标签组件和现有 Layout 测试。
2. 执行生产构建。
3. 在专用测试环境完成桌面和移动端浏览器回归。
4. 检查资料库、升级工作台、权限账号和退出重登流程。
5. 首次上线只发布导航型标签，不同时引入页面缓存。

## 13. 验收标准

满足以下条件才视为完成：

- 左侧菜单、页面链接、浏览器历史与标签激活状态一致。
- 相同普通页面不会产生重复标签。
- 动态详情路由能按记录区分标签。
- 关闭当前标签不会进入空白页或无权限页面。
- 刷新后只恢复当前账号仍有权限访问的合法标签。
- 退出登录后不会向其他账号展示前一账号的标签。
- 标签栏在手机和桌面宽度下无溢出、遮挡或布局跳动。
- 不改变后端接口、数据库结构、租户隔离和现有权限编码。
- 不增加固定周期轮询，不让隐藏页面在后台持续运行。
- 相关组件测试、布局回归测试、生产构建和 `git diff --check` 通过。

## 14. 后续演进

导航型标签稳定后，可以独立评估以下增强项：

- 允许用户固定常用标签。
- 为少数只读列表页恢复 URL 中的分页和筛选条件。
- 为经过专项验证的页面增加显式缓存白名单。
- 增加标签排序，但不得影响浏览器历史语义。
- 根据真实使用数据决定是否限制最大标签数量。

这些增强项不应与第一阶段捆绑上线。
