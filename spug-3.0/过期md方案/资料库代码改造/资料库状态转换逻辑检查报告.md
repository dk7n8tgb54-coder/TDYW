## 三、发现的问题

### 🔴 P0: TransferFailView 缺少状态转换验证

**位置**: `views/transfer/status.py` 第64-105行

**问题代码**:
```python
class TransferFailView(View):
    def post(self, request, transfer_id):
        # ... 权限检查 ...
        
        # 幂等性校验
        if transfer.status == TransferStatus.FAILED.value:
            return json_response(data={'status': TransferStatus.FAILED.value.lower()})

        # 【问题】直接更新状态，没有验证状态转换是否合法！
        transfer.status = TransferStatus.FAILED.value  # 第95行
        transfer.error_message = form.error_message or '上传失败'
        transfer.save()
```

**风险分析**:
1. 从终态（COMPLETED/CANCELED）可以直接标记为FAILED，违反状态机规则
2. 可能导致已完成/已取消的任务被错误标记为失败
3. 与批量操作中的状态检查逻辑不一致

**修复建议**:
```python
# 添加状态转换验证
current_status_enum = next((s for s in TransferStatus if s.value == transfer.status), None)
target_status_enum = TransferStatus.FAILED

# 【P0修复】只允许从特定状态转换到FAILED
ALLOWED_TO_FAIL = [TransferStatus.PENDING, TransferStatus.UPLOADING, 
                   TransferStatus.PAUSED, TransferStatus.MERGING]
if current_status_enum not in ALLOWED_TO_FAIL:
    return json_response(error=f'不能从 {transfer.status} 状态标记为失败')
```

### 🟠 P1: 批量取消任务缺少状态转换验证

**位置**: `tasks/batch.py` 第84-153行

**问题代码**:
```python
def batch_cancel_transfers(transfer_ids, request_user_id, request_tenant_id):
    for transfer_id in transfer_ids:
        with transaction.atomic():
            transfer = DocumentTransfer.objects.select_for_update().get(id=transfer_id)
            
            # 只能取消未完成的传输
            if transfer.status in ['COMPLETED', 'FAILED', 'CANCELED']:
                skipped_count += 1
                continue
            
            # 【问题】直接设置为CANCELED，没有使用is_valid_status_transition验证
            transfer.status = 'CANCELED'  # 第132行
```

**风险分析**:
1. MERGING状态被取消可能导致文件损坏（虽然业务层有保护）
2. 与ALLOWED_STATUS_TRANSITIONS定义不一致

**修复建议**:
```python
from ...constants import is_valid_status_transition, TransferStatus

# 使用状态机验证
current_enum = TransferStatus(transfer.status)
if not is_valid_status_transition(current_enum, TransferStatus.CANCELED):
    skipped_count += 1
    continue
```

### 🟠 P1: 前端状态机 merging 状态缺少 CANCEL 转换

**位置**: `UploadStateMachine.js` 第112-119行

**问题代码**:
```javascript
merging: {
  entry: this.onMergingEntry.bind(this),
  exit: this.onMergingExit.bind(this),
  transitions: {
    MERGE_SUCCESS: { target: 'completed' },
    ERROR: { target: 'error' },
    // 【问题】缺少 CANCEL 转换！
  }
}
```

**风险分析**:
1. 虽然StateMachineManager.batchCancel()排除了merging状态
2. 但单个任务在merging状态时无法通过前端状态机取消
3. 与后端 ALLOWED_STATUS_TRANSITIONS 定义不一致（后端允许 MERGING -> CANCELED）

**修复建议**:
```javascript
merging: {
  transitions: {
    MERGE_SUCCESS: { target: 'completed' },
    ERROR: { target: 'error' },
    CANCEL: { target: 'cancelled', action: this.actions.onCancel }  // 【P1修复】添加
  }
}
```

**问题代码**:
```javascript
export function shouldResumeWaiting({ item, history }) {
  const wasWaiting = history.some(h => h.from === 'waiting' || h.to === 'waiting');
  const hasFileHash = !!item?.fileHash;
  const isMerging = item?.isMerging || (item?.currentChunk >= item?.chunkCount);

  return wasWaiting && !hasFileHash && !isMerging;
}
```

**风险分析**:

| 维度 | 评分 | 说明 |

1. **TransferFailView 可修改终态任务** - 可能导致已完成任务被错误标记为失败
2. **前后端 merging 取消不一致** - 后端允许取消合并中任务，前端状态机不支持
3. **部分代码使用字符串比较状态** - 容易因拼写错误导致bug

1. **立即修复**: TransferFailView 添加状态转换验证（P0）
2. **本周修复**: 批量取消添加状态验证、前端状态机添加CANCEL转换（P1）
