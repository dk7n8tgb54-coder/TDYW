## 漏洞 #21：Redis连接无密码保护

### 风险描述
所有Redis连接（缓存、Channel Layer、Celery Broker/Backend）均使用无密码的本地连接。如果Redis端口被意外暴露或容器网络配置不当，攻击者可直接访问Redis。

### 涉及文件

**文件：`spug_api/spug/settings.py`**
```python
CACHES = {
    "default": {
        "BACKEND": "django_redis.cache.RedisCache",
        "LOCATION": "redis://127.0.0.1:6379/1",  # ← 无密码
        ...
    }
}

CHANNEL_LAYERS = {
    "default": {
        "CONFIG": {
            "hosts": [("127.0.0.1", 6379)],  # ← 无密码
        },
    },
}

CELERY_BROKER_URL = 'redis://127.0.0.1:6379/2'  # ← 无密码
CELERY_RESULT_BACKEND = 'redis://127.0.0.1:6379/3'  # ← 无密码
```

### 风险分析
- 在Docker单机部署中，Redis运行在同一容器内，风险较低
- 但如果未来拆分为多容器部署，Redis将通过网络暴露
- Redis无密码时，攻击者可：
  - 读取所有缓存数据（包括用户Token）
  - 修改缓存数据（绕过限流、伪造权限）
  - 通过Redis写入文件实现RCE

## 其他安全建议

### 1. 操作日志完整性保护

**当前状态：** 系统有审计日志模块（`apps.logs`），但日志存储在同一数据库中，管理员可以修改或删除日志。

**建议：**
- 日志写入后设置为只读（数据库层面）
- 关键操作日志同步到外部日志服务
- 添加日志完整性校验（如HMAC签名）

### 2. 密码策略

**当前状态：** 有密码复杂度验证（`verify_password`函数要求8位+大小写+数字+特殊字符）

**建议：**
- 添加密码历史记录，防止重复使用旧密码
- 添加密码过期策略（如90天强制更换）
- 检查密码是否在常见泄露密码列表中

### 3. API响应信息泄露

**当前状态：** 部分API返回过多信息

**示例：** 登录失败时返回"账户已被系统禁用"，攻击者可据此确认用户名存在。

**建议：** 统一返回"用户名或密码错误"，不区分具体原因。

### 4. 文件上传安全

**当前状态：** Nginx配置 `client_max_body_size 0`（无限制）

**建议：**
- 设置合理的上传大小限制
- 在应用层验证文件类型（不仅检查扩展名，还检查文件头）
- 上传文件存储路径不应在Web可直接访问的目录中

### 5. Nginx以root用户运行

**当前状态：** `docker/config/nginx.conf` 第7行
```nginx
user root;
```

**风险：** 如果Nginx存在漏洞被利用，攻击者直接获得root权限。

**建议：** 改为 `user nginx;` 或 `user www-data;`
