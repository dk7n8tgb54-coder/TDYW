## 漏洞 #14：SSH连接自动接受未知主机密钥（MITM风险）

### 风险描述
SSH客户端使用 `AutoAddPolicy` 策略，自动接受任何未知的主机密钥而不进行验证。这使得系统容易受到中间人攻击（MITM）。

### 涉及文件

**文件：`spug_api/libs/ssh.py` 第83-89行**
```python
def get_client(self):
    if self.client is not None:
        return self.client
    self.client = SSHClient()
    self.client.set_missing_host_key_policy(AutoAddPolicy)  # ← 自动接受任何密钥
    self.client.connect(**self.arguments)
    return self.client
```

### 攻击场景
1. 攻击者在网络中进行ARP欺骗或DNS劫持
2. 将SSH连接重定向到攻击者控制的服务器
3. 由于AutoAddPolicy，客户端自动接受伪造的主机密钥
4. 攻击者获取SSH凭据（密码或私钥）
5. 攻击者可以：
   - 窃取传输的命令和数据
   - 在目标服务器上执行恶意命令
   - 获取服务器完全控制权

### paramiko策略对比

| 策略 | 行为 | 安全性 | 适用场景 |
|------|------|--------|----------|
| `RejectPolicy` | 拒绝未知密钥 | 最高 | 严格安全环境 |
| `WarningPolicy` | 警告但接受 | 中等 | 运维工具（推荐） |
| `AutoAddPolicy` | 静默接受 | 最低 | 仅开发测试 |

### 影响范围
- 系统通过SSH执行远程命令（批量执行、文件分发等）
- 如果SSH连接被劫持，攻击者可在所有管理的服务器上执行任意命令
- 影响范围取决于SSH管理的服务器数量
