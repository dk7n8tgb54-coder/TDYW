# 🔴 01-密钥与敏感信息泄露

> 风险等级：P0-严重
> 涉及漏洞编号：#1、#2、#4

---

## 漏洞 #1：SECRET_KEY 硬编码在源码中

### 风险描述
Django的SECRET_KEY用于加密签名（session、CSRF token、密码重置链接等）。当前SECRET_KEY直接硬编码在源码中，任何能访问代码仓库的人都可以获取，导致：
- 伪造session实现任意用户登录
- 伪造CSRF token绕过防护
- 解密已加密的敏感数据

### 涉及文件

**文件1：`spug_api/spug/settings.py` 第28行**
```python
SECRET_KEY = 'vk0do47)egwzz!uk49%(y3s(fpx4+ha@ugt-hcv&%&d@hwr&p7'
```

**文件2：`spug_api/spug/overrides.py` 第4行**
```python
SECRET_KEY = 'Dc1Wpu2QCmt1R4vW!5Rmj7w%dcZxeiod#ReGNWSn1jjhyfrCr!'
```

### 攻击场景
1. 攻击者获取源码（内部人员、代码泄露、Git仓库暴露）
2. 使用SECRET_KEY伪造Django签名
3. 构造合法的session cookie，冒充管理员登录

### 影响范围
- 所有使用该密钥签名的数据均可被伪造
- 系统完全可被接管

## 漏洞 #2：数据库密码明文存储且被Git追踪

### 风险描述
`db_config.ini` 文件包含数据库明文密码，且该文件被Git追踪（不在.gitignore中），任何克隆仓库的人都能获取数据库凭据。

### 涉及文件

**文件：`db_config.ini`**
```ini
[database]
host = localhost
user = root
password = spug.cc
name = spug

[index]
size_threshold = 10000

[log]
level = INFO
```

### 当前.gitignore状态
检查 `.gitignore` 文件，**未发现** `db_config.ini` 被排除：
```
# 环境配置
.env
.env.local
.env.*.local
```
仅排除了 `.env` 文件，但 `db_config.ini` 未被排除。

### 攻击场景
1. 攻击者获取代码仓库访问权限
2. 直接读取 `db_config.ini` 获得数据库root密码
3. 连接数据库获取所有用户数据、修改数据

### 影响范围
- 数据库完全暴露
- 所有业务数据面临泄露风险

## 漏洞 #4：默认管理员密码硬编码在entrypoint.sh

### 风险描述
Docker启动脚本中硬编码了默认管理员账号密码，且该密码为弱密码模式（`Admin888..`），容易被猜测。

### 涉及文件

**文件：`docker/config/entrypoint.sh` 第35-44行**
```python
if not User.objects.filter(username='admin').exists():
    user = User.objects.create(
        username='admin',
        nickname='管理员',
        password_hash=User.make_password('Admin888..'),
        is_supper=True,
        is_active=True
    )
    print('管理员账号已创建: admin / Admin888..')
```

### 攻击场景
1. 攻击者知道系统使用spug框架
2. 尝试默认账号 `admin / Admin888..` 登录
3. 获得超级管理员权限，完全控制系统

### 影响范围
- 如果部署后未修改默认密码，系统可被直接接管
- 密码格式可预测（常见的Admin+数字+特殊字符模式）
