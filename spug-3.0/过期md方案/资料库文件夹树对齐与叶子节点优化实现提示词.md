# 资料库文件夹树对齐与叶子节点优化实现提示词

> 使用方式：将以下完整内容交给编码 Agent。  
> 本任务只优化资料库“文档管理”和“党建文档”共用的左侧文件夹树，不修改上传、搜索、附件管理或党建数据隔离架构。

---

## 角色与任务

你是一名资深 React/Django 全栈工程师，需要直接在当前仓库中修复资料库左侧文件夹树的两个用户体验问题：

1. 展开三角、文件夹图标、文件夹名称以及可能出现的创建人信息没有稳定对齐；
2. 没有子文件夹的叶子目录仍显示展开三角，点击后才发现没有内容。

“文档管理”和“党建文档”共用同一个 `FolderTree`，本次修改必须同时对两个模块生效，并保持现有按需加载、导航、权限和系统根目录锁定行为不变。

请直接完成代码修改、测试和浏览器视觉验证，不要只输出代码片段或设计建议。

## 一、工作约束

### 1.1 保护现有修改

- 当前仓库可能有其他 Agent 和用户尚未提交的修改，开始前执行 `git status --short`。
- 不回退、不覆盖、不格式化与本任务无关的修改。

- 不执行全仓库格式化、依赖升级或无关组件重构。
- 不创建提交，除非用户明确要求。

### 1.2 技术栈

- React `16.13.1`；
- Ant Design `4.21.5`；
- JavaScript，不迁移 TypeScript；
- Less/CSS Modules；
- Django 后端；
- Docker 运行在 WSL 中，后端测试优先在现有容器内执行。

### 1.3 设计原则

- 叶子目录不显示三角，但必须保留与三角槽位相同宽度的空白占位，使同层文件夹图标和名称对齐；
- 是否为叶子目录必须由真实数据决定，不能根据名称、当前展开状态或前端猜测；
- 页面首次渲染时就应尽可能知道叶子状态，不能要求用户先点一次三角才消失；
- 不为了判断叶子目录给每个节点分别发送一次请求，避免 N+1；
- 保留现有 `Tree.loadData` 按需加载，不改成一次性加载整个目录树；
- 根节点通过颜色和字重突出，不使用更大的图标或不同的水平间距破坏对齐；
- 视觉修改应安静、紧凑，符合后台资料管理工具，不增加卡片、说明文字或装饰元素。

## 三、目标交互与视觉规范

### 3.1 展开三角

- 只有存在至少一个当前用户可见、未删除的直接子文件夹时才显示三角；
- `has_children=true`：显示 Ant Tree 原有展开/收起三角；
- `has_children=false`：设置 `isLeaf: true`，不显示三角图形；
- 叶子节点仍保留 Ant Tree switcher/noop 槽位宽度，使同层图标对齐；
- 展开和收起不能导致文件夹图标或名称水平跳动；
- 点击叶子目录仍应正常进入该目录，只是不触发子目录加载；
- 目录中只有文件、没有子文件夹时，也属于叶子目录，不显示三角。

### 3.2 行布局

建议以以下稳定尺寸为基准，若现有设计系统要求略有调整可以微调，但必须全树一致：

```text
节点行高：30px
switcher 槽位：20px 或 24px，固定宽度，水平/垂直居中
文件夹图标：16px，固定宽高
图标与名称间距：8px
普通名称字号：13px
根节点字号：13px 或 14px，但图标和水平间距与普通节点一致
```

要求：

- `.ant-tree-treenode`、`.ant-tree-switcher`、`.ant-tree-node-content-wrapper` 和自定义 title 内容使用一致的垂直居中规则；
- title 内容使用 `display:flex; align-items:center; min-width:0;`；
- 文件夹名称使用 `flex:1; min-width:0; overflow:hidden; text-overflow:ellipsis; white-space:nowrap;`；
- 创建人使用独立的右侧区域，`flex-shrink:0`，必要时限制最大宽度并省略；
- 不使用负 margin 或针对某个层级写像素补丁；
- 不隐藏 Ant Tree 的缩进槽位；不同深度仍应保持稳定的 16px 左右层级缩进；
- 选中、hover、展开和加载状态不能改变行高或节点宽度；
- 根节点使用颜色、字重区分，文件夹图标统一为 16px；
- 所有文字保持 `letter-spacing: 0`。

### 3.3 文档管理和党建一致性

- 公共共享库根节点、我的文件根节点和党建文档根节点使用同一套节点骨架；
- 三种根节点的 switcher、图标和标题起始位置一致；
- 党建单根模式不能因为 `system-root` 的特殊 key 使用另一套间距；
- 自动展开党建目录树时，叶子节点依然正确隐藏三角；
- 文档管理在公共/私人空间切换后，叶子状态重新按对应空间数据计算。

## 四、后端实现要求

### 4.1 为目录响应增加 `has_children`

为目录列表中的每一个文件夹增加向后兼容字段：

```json
{
  "id": 123,
  "name": "示例目录",
  "parent_id": 10,
  "has_children": true
}
```

现有字段和响应外层结构不得改变。

### 4.2 查询实现

优先使用 Django ORM 的 `Exists` + `OuterRef` 对当前目录查询做一次相关子查询标注，或者使用等价的单次批量查询方案。禁止在序列化列表时逐个执行 `.exists()`。

示意结构：

```python
visible_children = FolderModel.objects.filter(
    parent_id=OuterRef('pk'),
    is_deleted=False,
)
folders_query = folders_query.annotate(
    has_children=Exists(visible_children)
)
```

不能直接照抄示意而忽略作用域。子目录存在性必须和目录接口的可见范围一致：

- 私有资料库：只计算当前租户可见的未删除子目录；
- 普通公共资料库：不能把党建或其他系统目录算作可见子目录；
- 党建文档：只计算党建根目录子树内的子目录；
- 软删除子目录不计入；
- 文件不计入，只有直接子文件夹决定 `has_children`；
- 如果目录数据存在异常跨作用域关系，按 fail closed 的可见范围计算。

建议抽取一个小型 helper，为 `_get_all_folders()`、`_get_root_contents()` 和 `_get_folder_contents()` 复用，避免三个响应分支漏字段或产生不同语义。不要为这个小功能重写整个 FolderView。

### 4.3 根节点

公共共享库和我的文件是前端虚拟根节点，党建根节点是真实绑定目录：

- 虚拟根节点的 `hasChildren` 可在已加载一级目录后根据 `folders.length > 0` 设置；
- 党建真实根节点可在加载一级目录后更新叶子状态；
- 初始化加载过程中可以暂时保留根节点加载能力，但数据返回后必须准确显示或隐藏三角；
- 不允许因为根节点暂时未知而永久显示空三角。

## 五、前端实现要求

### 5.1 映射叶子状态

修改 `_buildFolderChildren()`：

```text
has_children === true
  -> isLeaf: false
  -> children: undefined，保留 loadData

has_children === false
  -> isLeaf: true
  -> children: []
```

兼容策略：

- 新后端明确返回布尔值时，以该值为准；
- 如果旧环境暂时没有 `has_children`，保守视为“未知且可能有子目录”，继续允许展开，避免升级期间目录无法访问；
- 节点成功加载后，如果返回空数组，立即更新为 `children: []`、`isLeaf: true`；
- 节点成功加载到子目录时，更新为 `children: [...]`、`isLeaf: false`；
- `_setRootChildren()`、`_setNodeChildren()`、自动展开党建树等所有更新路径必须保持 `children` 与 `isLeaf` 一致；
- 刷新、空间切换和党建根目录变化后不能残留旧的叶子状态。

### 5.2 统一节点 DOM

减少根节点与普通节点重复的布局 JSX。可以抽取一个小型 `FolderTreeNodeTitle` 组件或统一 title helper，但不要过度重构整个 class component。

统一结构建议：

```jsx
<div className={cx(styles.nodeContent, root && styles.rootNode)}>
  <span className={styles.folderIcon}>...</span>
  <span className={styles.nodeLabel}>...</span>
  {creator && <span className={styles.nodeMeta}>...</span>}
</div>
```

要求：

- 所有根节点和普通节点共用 `.nodeContent`、`.folderIcon`、`.nodeLabel`；
- 根节点只追加颜色/字重修饰类；
- 不新增依赖；如果项目没有 `classnames`，不要为了一个组件引入它；
- 保留 `FolderIcon`，不要手绘 SVG；
- 图标的 open/closed 外观可以保留现状，但尺寸必须一致。

### 5.3 Ant Tree 样式

在 `FolderTree.module.less` 中集中处理：

- switcher 固定尺寸并使用 flex 居中；
- switcher 内 SVG 垂直居中；
- content wrapper 固定最小高度/行高并使用 flex；
- 自定义节点内容填满可用宽度；
- title、图标、文本不使用相互冲突的 line-height；
- 选中背景和 hover 背景覆盖整行但不改变布局；
- 叶子节点的 noop switcher 不显示图形，但保留固定宽度；
- 长名称和创建人不会产生横向溢出或覆盖。

注意 CSS Modules 与 `:global` 的作用域，不能写成影响全站所有 Ant Tree 的全局样式。
