# 文件夹上传功能问题分析与优化方案

## 一、当前代码分析

### 1.1 文件位置

## 二、存在的问题

### P0级（必须修复）

#### 1. 回滚时可能误删用户已有文件夹（数据安全风险）
**问题描述**：
- 当前代码没有区分「本次创建的文件夹」和「已存在的文件夹」
- 如果创建失败触发回滚，会删除所有涉及的文件夹，包括用户已有的历史文件夹

**代码位置**：`createFolderStructure()` 方法（131-179行）

**当前代码**：
```javascript
// 问题：没有区分本次创建 vs 历史复用
if (existingId) {
  currentParentId = existingId;  // 历史文件夹也使用
  continue;
}
// 创建后统一缓存，没有标记哪些是本次创建的
this.rootStore.pendingFolderFiles.folderMap.set(currentPath, currentParentId);
```

**风险场景**：
1. 用户上传 `/A/B/C/file.txt`
2. 文件夹 `/A` 已存在（用户之前创建的）
3. 创建 `/A/B` 时失败
4. 回滚时误删了用户原有的 `/A` 文件夹及其内容

---

#### 2. 文件夹串行创建性能差
**问题描述**：
- 当前是逐个文件串行创建文件夹结构
- 100个同级文件夹需要串行请求100次，耗时严重

**代码位置**：`handleFolderSelect()` 方法（91-118行）

**当前代码**：
```javascript
// 问题：循环内串行创建
for (let i = 0; i < files.length; i++) {
  if (folderPath && !folderMap.has(folderPath)) {
    const createdFolderId = await this.createFolderStructure(folderPath, targetFolderId);
    // 每次await阻塞，无法并发
  }
}
```

---

#### 3. 文件夹创建失败无回滚机制
**问题描述**：
- 创建失败仅提示错误，已创建的文件夹不清理
- 可能留下半成品文件夹结构

**代码位置**：`handleFolderSelect()` 方法（110-116行）

**当前代码**：
```javascript
try {
  const createdFolderId = await this.createFolderStructure(folderPath, targetFolderId);
} catch (e) {
  message.error(`文件夹 "${folderPath}" 创建失败...`);
  hasFolderError = true;
  break;  // 直接退出，没有回滚
}
// 已创建的文件夹残留
```

---

### P1级（建议优化）

#### 4. 唯一键无过期机制
**问题描述**：
- `folderUniqueKey` 仅在完成时清理
- 页面刷新/崩溃后，key残留，用户无法重新上传同一文件夹

**代码位置**：`handleFolderSelect()` 方法（61-68行）

---

#### 5. 外部依赖强耦合
**问题描述**：
- 强依赖 `validateFileName` 外部函数
- 若 `upload-utils` 路径变更或函数不存在，上传功能崩溃

**代码位置**：第8行、25-31行

---

#### 6. 无路径安全校验
**问题描述**：
- 未校验文件路径中的 `../` 等危险字符
- 存在路径遍历风险

## 三、优化方案

### 3.1 P0级修复

#### 修复1：区分本次创建和历史复用（数据安全）

```javascript
export class FolderUploadStore {
  constructor(queueStore, fileUploadStore, rootStore) {
    // ... 原有代码 ...
    
    // 新增：区分本次创建 vs 历史复用
    this.createdByThisInstance = new Set();  // 仅回滚这些
    this.reusedFolderIds = new Set();        // 不回滚这些
  }

  /**
   * 创建文件夹结构（修复版）
   */
  async createFolderStructure(folderPath, parentFolderId) {
    const { http } = await import('libs');
    const isPublic = this.rootStore.pendingFolderFiles?.isPublic ?? this.rootStore.rootStore?.navigationStore?.isPublic;
    const paths = folderPath.split('/');
    let currentParentId = parentFolderId;
    let currentPath = '';

    for (const folderName of paths) {
      currentPath = currentPath ? `${currentPath}/${folderName}` : folderName;
      
      // 检查本地缓存
      let existingId = null;
      for (const [path, id] of this.rootStore.pendingFolderFiles?.folderMap || []) {
        if (path === currentPath) {
          existingId = id;
          break;
        }
      }
      
      if (existingId) {
        currentParentId = existingId;
        this.reusedFolderIds.add(existingId);  // 标记为复用
        continue;
      }

      // 【新增】服务端幂等检查 - 查询是否已存在
      try {
        const checkResult = await http.get('/api/document/folder/', {
          params: { parent_id: currentParentId, name: folderName, is_public: isPublic }
        });
        if (checkResult.results?.length > 0) {
          currentParentId = checkResult.results[0].id;
          this.reusedFolderIds.add(currentParentId);  // 标记为复用
          this.rootStore.pendingFolderFiles?.folderMap.set(currentPath, currentParentId);
          continue;
        }
      } catch (e) {
        // 查询失败继续创建
      }

      // 创建新文件夹
      const params = {
        name: folderName,
        parent_id: currentParentId,
        is_public: isPublic,
      };
      
      const tenantId = isPublic ? null : localStorage.getItem('tenant_id');
      if (tenantId != null && tenantId !== '') {
        params.tenant_id = tenantId;
      }

      const result = await http.post('/api/document/folder/', params);
      currentParentId = result.id;
      
      // 【关键】标记为本次创建
      this.createdByThisInstance.add(currentParentId);
      
      if (this.rootStore.pendingFolderFiles?.folderMap) {
        this.rootStore.pendingFolderFiles.folderMap.set(currentPath, currentParentId);
      }
    }

    return currentParentId;
  }

  /**
   * 【新增】失败回滚 - 仅删除本次创建的文件夹
   */
  async rollbackCreatedFolders() {
    const { http } = await import('libs');
    console.warn('[FolderUpload] 回滚本次创建的文件夹:', this.createdByThisInstance.size);
    
    for (const folderId of [...this.createdByThisInstance].reverse()) {
      try {
        await http.delete(`/api/document/folder/${folderId}/`);
      } catch (e) {
        console.error(`回滚文件夹 ${folderId} 失败:`, e);
      }
    }
    
    this.createdByThisInstance.clear();
    this.reusedFolderIds.clear();
  }
}
```

#### 修复2：同深度文件夹并发创建（性能优化）

```javascript
/**
 * 处理文件夹选择（优化版）
 */
@action
async handleFolderSelect(files) {
  // ... 文件名校验等原有代码 ...

  // 【优化】按深度分组，同深度并发创建
  const folderPaths = [...new Set(
    files.map(f => {
      const parts = (f.webkitRelativePath || f.name).split('/');
      return parts.slice(0, -1).join('/');
    }).filter(p => p)
  )];

  // 按深度分组
  const depthGroups = new Map();
  folderPaths.forEach(path => {
    const depth = path.split('/').length;
    if (!depthGroups.has(depth)) depthGroups.set(depth, []);
    depthGroups.get(depth).push(path);
  });

  // 同深度并发，不同深度串行
  const sortedDepths = Array.from(depthGroups.keys()).sort((a, b) => a - b);
  
  try {
    for (const depth of sortedDepths) {
      const paths = depthGroups.get(depth);
      // 同深度并发创建（最多3个并发）
      const concurrencyLimit = 3;
      const chunks = [];
      for (let i = 0; i < paths.length; i += concurrencyLimit) {
        chunks.push(paths.slice(i, i + concurrencyLimit));
      }
      
      for (const chunk of chunks) {
        await Promise.all(
          chunk.map(path => this.createFolderStructure(path, targetFolderId))
        );
      }
    }
  } catch (e) {
    // 【关键】失败时回滚
    await this.rollbackCreatedFolders();
    message.error(`文件夹创建失败: ${e.message || '未知错误'}`);
    return;
  }

  // 上传文件
  await this.uploadFolderFiles(files, folderMap, targetFolderId, folderUniqueKey);
}
```

#### 优化3：页面卸载清理唯一键

```javascript
export class FolderUploadStore {
  constructor(queueStore, fileUploadStore, rootStore) {
    // ... 原有代码 ...
    
    // 【新增】页面卸载时清理唯一键
    this._cleanupOnUnload = () => {
      if (this.queueStore.uploadingUniqueKeys) {
        this.queueStore.uploadingUniqueKeys.clear();
      }
    };
    window.addEventListener('beforeunload', this._cleanupOnUnload);
  }

  // 【新增】销毁时移除监听
  destroy() {
    window.removeEventListener('beforeunload', this._cleanupOnUnload);
  }
}
```

```javascript
const defaultValidateFileName = (name) => {
  if (!name || name.length === 0) return { valid: false, message: '文件名不能为空' };
  if (name.length > 255) return { valid: false, message: '文件名超过255字符' };
  if (/[<>:"|?*\\/]/.test(name)) return { valid: false, message: '文件名包含非法字符' };
  return { valid: true };
};

// 动态获取，优先外部，兜底默认

  } catch (e) {
    console.warn('[FolderUpload] 外部校验函数不可用，使用默认实现');
  }
  return defaultValidateFileName;
};
```

## 四、实施建议

### 4.1 优先级

| 优先级 | 问题 | 工作量 | 风险 |
|--------|------|--------|------|
| P0 | 回滚数据安全 | 2小时 | 高（必须修） |
| P0 | 并发创建优化 | 2小时 | 中 |
| P0 | 失败回滚机制 | 1小时 | 中 |
| P1 | 页面卸载清理 | 30分钟 | 低 |
| P1 | 外部依赖兜底 | 30分钟 | 低 |
| P1 | 路径安全校验 | 30分钟 | 低 |

### 4.2 测试要点

1. **数据安全测试**：上传包含已有父文件夹的目录，验证回滚时不删除历史文件夹
2. **并发测试**：上传包含50+同级子文件夹的目录，验证创建时间明显缩短
3. **失败回滚测试**：在创建第N个文件夹时断网，验证已创建的N-1个文件夹被清理
4. **刷新重传测试**：上传过程中刷新页面，验证可以重新上传同一文件夹

### 4.3 回滚方案

如优化后出现问题，可直接回滚到原文件，因为优化都是新增功能而非修改核心逻辑。

---

## 五、总结

当前文件夹上传功能对于38人内部项目**基本够用**，但存在**数据安全风险**（回滚误删）和**性能瓶颈**（串行创建）。

建议至少修复**P0级问题**，P1级优化可根据时间安排逐步实施。
