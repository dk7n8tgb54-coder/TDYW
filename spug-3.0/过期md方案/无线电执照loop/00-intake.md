# 00 任务接收：无线电台执照有效期管理

## 原始需求

给平台新增一个无线电台执照有效期管理功能。

主要作用：

- 在无线电台执照到期前进行分级提醒，首个提醒节点为提前 45 天。
- 可以手动输入执照相关信息。
- 录入字段包括台站、频率、起始日期、截止日期、用途。
- 频率支持单个或多个。
- 可以附上执照相关附件。
- 附件类型包括执照、许可证、许可批复等。
- 分级提醒需要支持右下角弹窗通知。

## 任务目标

本轮目标是将“无线电台执照有效期管理”从业务描述转化为可进入开发的工程任务闭环，形成可执行的 Loop Engineering 流程资产。

具体目标：

- 明确功能边界。
- 明确系统设计。
- 明确开发任务拆分。
- 明确验证标准。
- 明确后续实现路径。

## 本轮要做

- 基于已有设计方案整理完整 Agent Loop。
- 将需求拆解为页面、接口、数据模型、定时任务、权限、测试等工程任务。
- 明确每一阶段输入、输出、检查点和退出标准。
- 输出可以指导后续编码实现的执行材料。

## 本轮不做

- 不直接实现后端代码。
- 不直接实现前端页面。
- 不执行数据库迁移。
- 不接入短信、邮件、企业微信等外部通知通道。
- 不设计复杂的频率冲突检测。
- 不实现执照在线审批流程。

## 关键业务对象

| 对象 | 说明 |
| --- | --- |
| 无线电台执照 | 需要管理有效期的主业务对象 |
| 台站 | 执照对应的无线电台站 |
| 频率 | 执照许可使用的一个或多个频率 |
| 附件 | 执照、许可证、许可批复等文件 |
| 到期提醒 | 执照到期前 45、30、15、7、1 天生成分级提醒记录 |
| 责任人 | 接收到期提醒并负责续期处理的人员 |

## 隐含要求

- 到期提醒需要自动执行，不能依赖人工打开页面才触发。
- 状态应自动计算，避免人工维护“正常/即将到期/已过期”。
- 附件下载必须走权限校验，不能暴露不受控直链。
- 多频率不能只用逗号字符串粗略保存，后续可能需要统计或查询。
- 多租户系统中必须保证租户隔离。
- 删除建议采用软删除，便于审计追溯。

## 待确认事项

| 问题 | 默认处理 | 影响 |
| --- | --- | --- |
| 提醒对象是谁 | 优先责任人，其次创建人 | 影响提醒接收逻辑 |
| 提醒时间如何设置 | 本期采用 45、30、15、7、1 天分级提醒 | 后续可配置 |
| 附件是否复用资料库 | 优先复用，若成本高则使用 media 轻量存储 | 影响附件实现复杂度 |
| 是否需要首页待办 | 本期建议列表页提醒，预留首页待办接口 | 影响前端范围 |
| 是否允许无附件保存 | 允许，但列表显示无附件 | 降低录入门槛 |

## 风险初判

| 风险 | 等级 | 初步应对 |
| --- | --- | --- |
| 定时提醒重复生成 | 高 | 增加提醒去重规则 |
| 附件越权下载 | 高 | 所有下载走鉴权接口 |
| 日期格式不一致 | 中 | 后端统一日期解析和状态计算 |
| 多频率查询困难 | 中 | 使用频率明细表 |
| 责任人为空导致无人处理 | 中 | 默认提醒创建人 |

## 退出标准

- 已明确本轮目标。
- 已明确本期做什么和不做什么。
- 已识别核心业务对象。
- 已记录待确认事项和默认处理方式。
