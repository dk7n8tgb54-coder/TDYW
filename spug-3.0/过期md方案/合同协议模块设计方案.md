# 合同协议模块设计方案

> 编写日期：2026-07-10  
> 模块名称：合同协议  
> 推荐英文模块名：contract_agreement  
> 参照模块：无线电执照模块

## 一、建设目标

新增“合同协议”模块，用于统一维护设备采购合同、信息引接合同、服务保障协议等合同及协议类资料，实现合同台账登记、有效期管理、费用信息维护、签约方记录、附件归档、在线预览、下载和状态跟踪。

本模块建议参照无线电执照模块的实现方式：

1. 合同协议主表只保存业务台账字段。
2. 附件能力复用公共附件方案和 `AttachmentService`。
3. 列表接口返回附件数量，详情页通过通用 `AttachmentManager` 管理附件。
4. 删除合同协议记录时，联动软删除公共附件记录。
5. 附件物理文件统一保存到 `/data/spug/spug_api/media/contract_agreement/` 目录下。

## 二、业务范围

合同协议模块首期覆盖以下合同类型：

| 类型编码 | 类型名称 | 说明 |
|---|---|---|
| `device_purchase` | 设备采购合同 | 设备采购、配套硬件采购等合同 |
| `info_access` | 信息引接合同 | 信息引接、数据接入、接口对接等合同 |
| `service_guarantee` | 服务保障协议 | 运维保障、服务支持、技术保障等协议 |

## 三、字段设计

### 3.1 主表字段

建议新增模型 `ContractAgreement`，数据库表名为 `tdyw_contract_agreement`。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | int | 是 | 主键 |
| `tenant_id` | int/string | 是 | 租户 ID，沿用项目租户隔离能力 |
| `contract_name` | varchar(200) | 是 | 合同名称 |
| `contract_type` | varchar(30) | 是 | 类型：设备采购合同、信息引接合同、服务保障协议 |
| `valid_start_date` | date | 是 | 起始日期 |
| `valid_end_date` | date | 是 | 截止日期 |
| `has_fee` | boolean | 是 | 是否有费用 |
| `fee_amount` | decimal(12,2) | 否 | 费用金额，仅 `has_fee=true` 时填写 |
| `fee_currency` | varchar(10) | 是 | 币种，固定为人民币 |
| `fee_detail` | text | 否 | 费用详细数据，可记录付款方式、付款节点、服务费说明等 |
| `signing_party` | varchar(500) | 是 | 签约方，可记录甲方、乙方或多方名称 |
| `status` | varchar(20) | 是 | 状态：在用、过期 |
| `last_remind_at` | varchar(20) | 否 | 最近提醒扫描时间，参照无线电执照模块 |
| `remark` | text | 否 | 备注 |
| `created_at` | varchar/datetime | 是 | 创建时间，风格参照现有模块 |
| `created_by` | FK | 是 | 创建人 |
| `updated_at` | varchar/datetime | 否 | 更新时间 |
| `updated_by` | FK | 否 | 更新人 |

字段命名说明：

1. `valid_start_date` 的页面名称和字段说明统一为“起始日期”。
2. `valid_end_date` 的页面名称和字段说明统一为“截止日期”。
3. `fee_currency` 不提供多币种选择，系统固定保存“人民币”。
4. `status` 建议由系统根据截止日期计算或刷新，不建议由用户随意手工修改。

### 3.2 类型枚举

```python
CONTRACT_TYPE_CHOICES = (
    ('device_purchase', '设备采购合同'),
    ('info_access', '信息引接合同'),
    ('service_guarantee', '服务保障协议'),
)
```

### 3.3 状态枚举

```python
STATUS_ACTIVE = 'active'    # 在用
STATUS_EXPIRED = 'expired'  # 过期

STATUS_CHOICES = (
    (STATUS_ACTIVE, '在用'),
    (STATUS_EXPIRED, '过期'),
)
```

状态判断规则：

| 条件 | 状态 |
|---|---|
| 当前日期 `<= valid_end_date` | 在用 |
| 当前日期 `> valid_end_date` | 过期 |

建议接口返回两个字段：

| 字段 | 说明 |
|---|---|
| `status` | 数据库存储状态 |
| `computed_status` | 按当前日期实时计算的状态 |

首期在列表和详情接口中实时计算 `computed_status`，并在新增、编辑后同步更新 `status`。同时增加与无线电执照模块一致的到期提醒能力，提醒判断以 `valid_end_date` 为准。

## 四、到期提醒设计

合同协议模块需要增加和无线电执照模块一样的到期提醒能力，包括即将到期提醒、过期提醒、菜单角标、弹窗提醒、用户确认处理、续期后重新提醒。

### 4.1 提醒规则

参照无线电执照模块，建议使用 60 天作为即将到期阈值：

```python
EXPIRING_DAYS_THRESHOLD = 60
```

| 条件 | 提醒状态 | 页面展示 |
|---|---|---|
| `days_left < 0` | `expired` | 已过期 |
| `0 <= days_left <= 60` | `expiring` | 即将到期 |
| `days_left > 60` | `normal` | 正常 |

其中：

```text
days_left = valid_end_date - today
```

合同协议原业务状态仍保持“在用、过期”两个值，满足字段要求：

| 条件 | 业务状态 |
|---|---|
| 当前日期 `<= valid_end_date` | 在用 |
| 当前日期 `> valid_end_date` | 过期 |

提醒状态用于弹窗、角标和剩余天数展示：

| 字段 | 说明 |
|---|---|
| `days_left` | 距离截止日期剩余天数，负数表示已过期 |
| `computed_status` | 业务状态：在用、过期 |
| `remind_status` | 提醒状态：normal、expiring、expired |

### 4.2 确认处理表

参照无线电执照模块的 `LicenseReminderAck`，建议新增合同协议提醒确认表 `ContractAgreementReminderAck`。

表名建议：

```text
tdyw_contract_agreement_reminder_ack
```

字段建议：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | int | 主键 |
| `tenant_id` | int/string | 租户 ID |
| `agreement_id` | FK | 合同协议 ID |
| `user_id` | int | 确认处理用户 ID |
| `user_name` | varchar(100) | 确认处理用户名称快照 |
| `ack_valid_end_date` | date | 确认时合同的截止日期 |
| `created_at` | varchar/datetime | 确认时间 |

唯一约束：

```python
UniqueConstraint(
    fields=['tenant_id', 'agreement_id', 'user_id', 'ack_valid_end_date'],
    name='uniq_contract_user_valid_end',
)
```

设计原则：

1. 用户点击“已处理”后，写入一条确认记录。
2. 确认记录绑定当时的 `valid_end_date`。
3. 如果合同续期，新的 `valid_end_date` 与旧确认记录的 `ack_valid_end_date` 不一致，旧确认自动失效。
4. 同一用户、同一合同、同一截止日期周期只确认一次。

### 4.3 提醒弹窗逻辑

弹窗接口实时查询当前用户需要处理的合同协议：

```text
remind_status IN ('expiring', 'expired')
AND NOT EXISTS ack
WHERE ack.agreement_id = agreement.id
  AND ack.user_id = 当前用户ID
  AND ack.ack_valid_end_date = agreement.valid_end_date
```

返回内容建议：

| 字段 | 说明 |
|---|---|
| `id` | 合同协议 ID |
| `contract_name` | 合同名称 |
| `contract_type_display` | 合同类型 |
| `valid_end_date` | 截止日期 |
| `days_left` | 剩余天数 |
| `remind_status` | expiring / expired |
| `signing_party` | 签约方 |
| `has_fee` | 是否有费用 |
| `fee_amount` | 费用金额 |

弹窗展示建议：

1. 即将到期：橙色提示，显示“距离截止日期还有 N 天”。
2. 已过期：红色提示，显示“已过期 N 天”。
3. 用户可点击“查看详情”进入合同详情。
4. 用户可点击“已处理”写入确认记录。

### 4.4 菜单角标

参照无线电执照模块菜单角标，合同协议模块也增加角标接口：

```text
GET /api/contract-agreement/badge/
```

返回当前用户未确认的提醒数量：

```json
{
  "count": 3,
  "expiring_count": 2,
  "expired_count": 1
}
```

前端在侧边菜单“合同协议”旁显示角标。只在用户具备 `contract_agreement.agreement.view` 权限时拉取。

### 4.5 扫描任务

建议新增任务：

```python
scan_single_contract_agreement(agreement)
scan_contract_agreements()
```

任务职责：

1. 根据 `valid_end_date` 计算 `days_left`。
2. 更新合同协议主表 `status`。
3. 更新 `last_remind_at`。
4. 不强制生成历史提醒记录，弹窗提醒由接口实时查询。

触发时机：

| 场景 | 动作 |
|---|---|
| 新增合同协议 | 立即扫描单条记录 |
| 编辑合同协议 | 立即扫描单条记录 |
| 每日定时任务 | 扫描全部未删除/有效合同协议 |
| 修改截止日期续期 | 旧确认自动失效，弹窗重新提醒 |

## 五、费用设计

费用只支持人民币。

页面交互建议：

1. “费用”字段使用单选或开关：有、无。
2. 选择“无”时，不展示费用金额和费用详细数据，后端保存 `has_fee=false`，`fee_amount=null`，`fee_detail=''`。
3. 选择“有”时，展示费用金额和费用详细数据，后端保存 `has_fee=true`，`fee_currency='人民币'`。
4. 费用详细数据使用多行文本，支持填写付款节点、年度服务费、一次性费用、发票说明等内容。

推荐校验：

| 场景 | 校验规则 |
|---|---|
| `has_fee=false` | 不校验 `fee_amount` |
| `has_fee=true` | `fee_amount` 建议必填且大于等于 0 |
| `fee_currency` | 固定为“人民币”，前端无需提供币种下拉 |

## 六、附件设计

### 6.1 总体原则

附件能力复用公共附件方案，参照无线电执照模块做法，不为合同协议单独设计附件业务表。

合同协议模块只声明公共附件的业务对象标识：

```python
ATTACHMENT_MODULE = 'contract_agreement'
ATTACHMENT_OBJECT_TYPE = 'agreement'
```

公共附件表按以下维度关联合同协议记录：

| 字段 | 值 |
|---|---|
| `module` | `contract_agreement` |
| `object_type` | `agreement` |
| `object_id` | 合同协议主表 ID |

### 6.2 物理目录

合同协议附件物理文件统一保存到：

```text
/data/spug/spug_api/media/contract_agreement/
```

如果公共附件服务已按模块、租户、年月、业务对象分层保存，则合同协议附件最终路径建议保持为：

```text
/data/spug/spug_api/media/contract_agreement/{tenant_id}/{yyyyMM}/agreement_{object_id}/{file_name}
```

数据库中只保存相对 `MEDIA_ROOT` 的路径，例如：

```text
contract_agreement/1/202607/agreement_1001/合同扫描件.pdf
```

### 6.3 附件限制

参照无线电执照模块，建议合同协议允许以下附件类型：

```python
allowed_extensions = (
    '.pdf', '.jpg', '.jpeg', '.png', '.gif', '.bmp', '.webp',
    '.doc', '.docx', '.xls', '.xlsx', '.ppt', '.pptx',
    '.zip', '.rar', '.7z',
)
max_size_mb = 50
```

### 6.4 附件接口

参照无线电执照模块，建议接口如下：

| 方法 | 路径 | 权限 | 功能 |
|---|---|---|---|
| `GET` | `/api/contract-agreement/<id>/attachments/` | `contract_agreement.agreement.view` | 附件列表 |
| `POST` | `/api/contract-agreement/<id>/attachments/` | `contract_agreement.attachment.upload` | 上传附件 |
| `GET` | `/api/contract-agreement/attachments/<att_id>/download/` | `contract_agreement.attachment.download` | 下载附件 |
| `GET` | `/api/contract-agreement/attachments/<att_id>/preview-url/` | `contract_agreement.agreement.view` | 获取在线预览地址 |
| `GET` | `/api/contract-agreement/attachments/<att_id>/preview-file/` | preview token | kkFileView 回调读取文件流 |
| `DELETE` | `/api/contract-agreement/attachments/` | `contract_agreement.attachment.delete` | 删除附件 |

后端实现要点：

1. 上传、列表、下载、预览、删除统一调用 `AttachmentService`。
2. 上传前必须校验合同协议记录存在，且属于当前租户范围。
3. 删除合同协议主记录时，调用 `AttachmentService.soft_delete_by_object(user, 'contract_agreement', 'agreement', id, delete_file=True)`。
4. 在线预览继续复用公共附件的 kkFileView preview token 机制。

前端实现要点：

1. 列表页使用 `AttachmentCountBadge` 展示附件数量。
2. 详情或编辑弹窗中使用通用 `AttachmentManager`。
3. `AttachmentManager` 参数示例：

```jsx
<AttachmentManager
  module="contract_agreement"
  objectType="agreement"
  recordId={info.id}
  listUrl={`/api/contract-agreement/${info.id}/attachments/`}
  uploadUrl={`/api/contract-agreement/${info.id}/attachments/`}
  deleteUrl="/api/contract-agreement/attachments/"
  downloadUrlPrefix="/api/contract-agreement/attachments/"
  previewUrlPrefix="/api/contract-agreement/attachments/"
  uploadPerm="contract_agreement.attachment.upload"
  deletePerm="contract_agreement.attachment.delete"
  previewPerm="contract_agreement.agreement.view"
  maxFileSize={50}
  accept=".pdf,.jpg,.jpeg,.png,.gif,.bmp,.webp,.doc,.docx,.xls,.xlsx,.ppt,.pptx,.zip,.rar,.7z"
/>
```

### 7.2 提醒接口

| 方法 | 路径 | 权限 | 功能 |
|---|---|---|---|
| `GET` | `/api/contract-agreement/reminders/popup/` | `contract_agreement.agreement.view` | 查询当前用户未确认的即将到期/过期合同 |
| `POST` | `/api/contract-agreement/reminders/ack/` | `contract_agreement.agreement.view` | 当前用户确认某条合同提醒已处理 |
| `GET` | `/api/contract-agreement/badge/` | `contract_agreement.agreement.view` | 当前用户未确认提醒数量 |

确认处理请求参数：

| 参数 | 说明 |
|---|---|
| `agreement_id` | 合同协议 ID |

后端处理：

1. 校验合同协议存在且当前用户有权限访问。
2. 如果合同未到期且不在 60 天提醒范围内，返回无需处理。
3. 写入 `ContractAgreementReminderAck`，`ack_valid_end_date=agreement.valid_end_date`。
4. 如果唯一约束冲突，视为已处理成功。

前端能力：

1. 登录后或布局加载后，具备 `contract_agreement.agreement.view` 权限时拉取角标数量。
2. 进入系统后查询 `/api/contract-agreement/reminders/popup/`。
3. 有未确认提醒时弹窗展示即将到期/已过期合同。
4. 用户点击“已处理”后调用 `/api/contract-agreement/reminders/ack/`。
5. 用户点击“查看详情”打开合同协议详情弹窗。
6. 合同续期后，因为 `valid_end_date` 变化，旧确认自动失效，会重新进入提醒范围。
