# 本轮已落地修复清单

## 一、已落地改动点

### 1) 前端：取消状态值统一

- 文件：`spug_web/src/pages/document/stores/upload/core/UploadStateMachine.js`
- 改动：
  - `onCancelledEntry()` 上报后端状态由 `CANCELLED` 改为 `CANCELED`
- 目的：
  - 与后端 `TransferStatus.CANCELED` 统一，避免“无效状态值/无效状态转换”。

### 2) 前端：非法状态转换不再伪成功

- 文件：`spug_web/src/pages/document/stores/upload/core/transfer.js`
- 改动：
  - `updateTransferStatus()` 捕获“无效状态转换”后，不再返回伪成功对象；
  - 改为返回显式失败结构：`{ success: false, invalidTransition: true, ... }`
- 目的：
  - 避免前后端状态漂移被吞掉，便于上层识别并处理。

### 3) 前端：取消状态回读映射修正

- 文件：`spug_web/src/pages/document/stores/upload/core/index.js`
- 改动：
  - `mapBackendStatus()` 中 `CANCELED` 从 `error` 改为 `cancelled`
- 目的：
  - 取消态不再被误判为失败态。

### 4) 后端：单条完成/取消接口统一走状态机规则

- 文件：
  - `spug_api/apps/document/views/transfer/status.py`
  - `spug_api/apps/document/views/transfer/cancel.py`
- 改动：
  - `TransferCompleteView` 与 `TransferCancelView` 引入 `is_valid_status_transition`
  - 统一按 `constants.py` 的 `ALLOWED_STATUS_TRANSITIONS` 判断合法性
- 目的：
  - 减少“单条接口绕过统一规则”的分叉行为。

### 5) 后端：批量暂停/恢复再收一轮

- 文件：`spug_api/apps/document/views/transfer/batch.py`
- 改动（批量暂停）：
  - 不再仅靠固定状态筛选，改为逐条用 `is_valid_status_transition(... -> PAUSED)` 判定；
  - 保留 `PAUSED` 幂等成功；
  - 返回 `skipped_ids` 与 `skipped_reasons`。
- 改动（批量恢复）：
  - 保留 `UPLOADING` 幂等成功；
  - 逐条用 `is_valid_status_transition(... -> UPLOADING)` 判定；
  - 返回 `skipped_ids` 与 `skipped_reasons`。
- 目的：
  - 批量接口行为与统一状态机规则对齐，且可观测。

## 二、当前风险与注意事项

1. **调用方兼容性风险（批量接口返回结构新增字段）**
   - 新增 `skipped_ids` / `skipped_reasons`，通常是向后兼容；
   - 若有强 schema 校验，需同步更新。

2. **前端上层对 `updateTransferStatus()` 返回值的使用**
   - 目前改为“非法转换返回失败结构”；
   - 若上层完全不检查返回值，仍可能只靠日志感知异常。

3. **多入口并发仍可能出现竞态**
   - 比如：同一任务同时触发单条取消与批量恢复；
   - 当前已提升规则一致性，但竞态需依赖调用顺序和事务边界控制。

## 三、建议验证步骤（手工回归）

### A. 单条接口验证

1. 新建任务后立即“暂停”
   - 预期：成功，后端状态 `PENDING -> PAUSED`。
2. 暂停后“恢复”
   - 预期：成功，后端状态 `PAUSED -> UPLOADING`。
3. 上传中“取消”
   - 预期：成功，后端状态为 `CANCELED`，前端显示 `cancelled`。

### B. 批量接口验证

1. 混合状态（`PENDING/UPLOADING/PAUSED/MERGING/COMPLETED`）执行批量暂停
   - 预期：可暂停的进入 `PAUSED`；
   - 非法项出现在 `skipped_ids`，并有 `skipped_reasons`。
2. 同一批次执行批量恢复
   - 预期：`PAUSED -> UPLOADING`；
   - 已 `UPLOADING` 项按幂等成功计入。

### C. 观测项

1. 浏览器控制台不应再出现：
   - `UPLOADING -> PENDING`
   - `PAUSED -> PENDING`
   - `无效状态值: CANCELLED`
2. 后端接口返回中应能看到批量接口 `skipped_*` 诊断信息。
