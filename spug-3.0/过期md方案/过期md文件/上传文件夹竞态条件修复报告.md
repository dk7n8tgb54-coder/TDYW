# 上传文件夹竞态条件修复报告

## 问题描述

用户发现如果点击上传文件之后，快速切换文件夹，会导致文件上传的位置不是传到原来的文件夹1里，而是上传到切换后的文件夹2中。

## 根本原因分析

### 问题定位

在`UploadCoreStore.js`中，文件上传的目标文件夹ID是通过以下方式获取的：

```javascript
const targetFolderId = folderId !== null ? folderId : navigationStore.currentFolderId;
```

**问题**：当`folderId`参数为`null`时，会动态获取`navigationStore.currentFolderId`。如果用户在上传过程中切换文件夹，`navigationStore.currentFolderId`会改变，导致：

1. 用户在文件夹1点击上传
2. 文件开始上传（队列中等待）
3. 用户切换到文件夹2
4. 后续上传的文件使用`navigationStore.currentFolderId`（已经是文件夹2的ID）
5. 文件被上传到错误的文件夹

### 涉及代码位置

1. **`processUploadQueue`方法**（第331-461行）
   - 在并发上传任务时，使用动态的`navigationStore.currentFolderId`

2. **`uploadSingleFile`方法**（第467-497行）
   - 调用时传递的`folderId`参数可能为`null`

3. **`uploadFileNormal`方法**（第503-626行）
   - 第517行：`const targetFolderId = folderId !== null ? folderId : navigationStore.currentFolderId;`

4. **`uploadFileChunked`方法**（第633-1150行）
   - 第796行：`const targetFolderId = folderId !== null ? folderId : navigationStore.currentFolderId;`

## 修复方案

### 核心思路

**在队列处理时就固定目标文件夹ID，不再动态获取`navigationStore.currentFolderId`**

### 修复内容

#### 1. `processUploadQueue`方法修复（第396-456行）

## 修复效果

### 修复前

```
用户操作流程：
1. 在文件夹1点击上传文件A
2. 文件A开始上传（在队列中等待）
3. 用户切换到文件夹2
4. 文件A实际被上传到文件夹2 ❌ 错误！
```

### 修复后

```
用户操作流程：
1. 在文件夹1点击上传文件A
2. 文件A开始上传（在队列中等待，已固定目标文件夹ID=1）
3. 用户切换到文件夹2
4. 文件A仍然被上传到文件夹1 ✅ 正确！
```

### 功能测试

1. **基本上传测试**

3. **暂停/恢复上传测试**

   - 切换到文件夹2

5. **大文件分片上传测试**

   - 在上传过程中切换到文件夹2
   - 验证文件是否上传到文件夹1
