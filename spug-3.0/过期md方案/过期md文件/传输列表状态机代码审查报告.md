## 终态统一定义

```javascript
/**
 * 终态集合（不可转换、不可操作）
 * 终态任务的特征：
 * 1. 不参与批量暂停/恢复操作
 * 2. 无效状态转换不打印警告
 * 3. 后端状态同步时跳过
 */
const FINAL_STATES = ['completed', 'error', 'cancelled'];

/**
 * 可暂停状态集合
 */
const PAUSABLE_STATES = ['waiting', 'calculating', 'uploading', 'merging'];

/**
 * 可恢复状态集合
 */
const RESUMABLE_STATES = ['paused', 'error', 'waiting'];
```

## 三、并发控制问题

### 3.1 🔴 P0: 缺少并发控制机制

> **关联问题**: [1.1 新旧逻辑并存](#11--p0-新旧两套上传逻辑并存导致冲突) - 并发控制必须在统一后的 `onStateUploading` 中实现

**问题描述**:
- 原代码中的 `_uploadStartLock` 和 `_uploadStartQueue` 被删除
- `onStateUploading` 没有并发限制检查
- `processUploadQueue` 有自己的并发控制（while循环），但与状态机无关

**代码位置**: `index.js`

**影响**:
- 超过最大并发数时所有任务同时上传
- 浏览器/服务器资源耗尽
- 上传失败率增加

**修复建议**:
```javascript
// 在 onStateUploading 中添加并发控制
async onStateUploading(uploadId, fromState) {
  const MAX_CONCURRENT = UPLOAD_CONSTANTS.MAX_CONCURRENT_UPLOADS;
  
  // 等待并发槽位
  while (this.activeUploads >= MAX_CONCURRENT) {
    await new Promise(resolve => setTimeout(resolve, 100));
  }
  
  this.queueStore.incrementActiveUploads();
  
  try {
    await this.executeUpload(uploadId, fromState);
  } finally {
    this.queueStore.decrementActiveUploads();
    // 检查队列中是否有等待的任务
    this.processPendingUploads();
  }
}
```

## 六、批量操作问题

### 6.1 🟡 P1: batchResume 没有处理 waiting 状态

> **关联问题**: [2.1 waiting缺少PAUSE](#21--p1-waiting-状态缺少-pause-转换) - 两个问题需同步修复，否则批量操作仍失效

**问题描述**:
```javascript
batchResume() {
  return this.batchTransition('RESUME', (machine) => 
    machine.canTransition('RESUME')
  );
}
```
- waiting 状态的任务不支持 RESUME 事件
- 这些任务在批量恢复时被跳过

**代码位置**: `StateMachineManager.js:161-163`

**修复建议**:
```javascript
batchResume() {
  const results = [];
  this.machines.forEach((machine, uploadId) => {
    const currentState = machine.getState();
    // waiting 状态使用 START，其他使用 RESUME
    const eventName = currentState === 'waiting' ? 'START' : 'RESUME';
    
    if (machine.canTransition(eventName)) {
      const success = machine.transition(eventName);
      results.push({ uploadId, success, state: machine.getState(), event: eventName });
    }
  });
  return results;
}
```

## 八、生产环境落地建议（补充）

### 8.1 🔴 状态机幂等性控制

快速重复点击暂停/恢复时，增加**事件防抖/锁**，防止重复触发状态转换。

```javascript
class StateMachineManager {
  constructor() {
    this._transitionLocks = new Map(); // 转换锁
  }

  async transition(uploadId, event) {
    // 获取或创建锁
    if (this._transitionLocks.get(uploadId)) {
      console.warn(`[StateMachine] ${uploadId}: 转换正在进行中，忽略重复事件: ${event}`);
      return false;
    }
    
    this._transitionLocks.set(uploadId, true);
    try {
      const machine = this.machines.get(uploadId);
      return machine?.transition(event) ?? false;
    } finally {
      this._transitionLocks.delete(uploadId);
    }
  }
}
```

### 8.2 🔴 错误兜底捕获

所有状态机回调增加 `try/catch`，防止单个任务报错阻塞整个上传队列。

```javascript
async onStateUploading(uploadId, fromState) {
  try {
    // ... 上传逻辑
  } catch (error) {
    console.error(`[UploadCoreStore] 上传失败: ${uploadId}`, error);
    // 触发错误状态转换
    const stateMachine = this.stateMachineManager?.get(uploadId);
    if (stateMachine) {
      stateMachine.transition('ERROR', { error });
    }
  }
}
```

### 8.3 🟡 特征开关灰度

严格使用 `FEATURE_FLAGS.USE_STATE_MACHINE` 管控，先小流量灰度，再全量上线。

```javascript
// 建议添加灰度控制
const FEATURE_FLAGS = {
  USE_STATE_MACHINE: process.env.REACT_APP_USE_STATE_MACHINE === 'true',
  STATE_MACHINE_LOG_LEVEL: 'warn', // debug | info | warn | error
};
```

### 8.4 🟢 旧逻辑彻底清理

修复完成后，删除 `processUploadQueue`、`_uploadStartLock` 等旧逻辑的**死代码、注释、冗余变量**。

### 8.5 🟢 状态持久化同步

状态机的当前状态与传输记录**实时持久化**，确保页面刷新后状态100%一致。

```javascript
// 状态变更时同步到后端
onStateChange(fromState, toState, event, payload, uploadId) {
  // 同步到后端传输记录
  const item = this.queueStore.findUploadItemInCurrentTenant(uploadId);
  if (item?.transferId) {
    this.transferStore.updateTransferStatus(item.transferId, toState.toUpperCase());
  }
}
```

## 报告总结

**当前状态**: 状态机实现存在**架构层面的致命冲突**（新旧逻辑并存）和**功能缺陷**（状态转换不完整）。

1. **第一阶段**: 修复P0问题，统一上传入口，确保基本功能可用
2. **第二阶段**: 修复P1问题，完善状态转换规则，批量操作正常
3. **第三阶段**: P2优化，代码重构，长期维护性提升

**关键成功指标**:
- [ ] 页面刷新后恢复的任务可正常暂停/恢复
- [ ] 批量操作无"无效状态转换"警告
- [ ] 并发数始终不超过 `MAX_CONCURRENT_UPLOADS`
- [ ] 无重复上传同一文件
