## 二、发现的问题

### 🔴 P0级问题（严重）

#### 1. 公共空间分片存储路径设计缺陷

**位置**: `document_utils.py:282-291`

```python
def get_chunk_dir_path(file_hash, is_public, request_user):
    if is_public:
        # 公共空间：租户ID + 用户ID双重隔离
        tenant_id = getattr(request_user, 'tenant_id', 'default') or 'default'
        user_id = getattr(request_user, 'id', 'anonymous') or 'anonymous'
        tenant_path = f"public_{tenant_id}_{user_id}"
```

**问题描述**:
- 公共空间的分片使用了 `tenant_id + user_id` 双重隔离
- 这导致同一文件被不同用户上传时，会存储在不同的分片目录
- 无法实现分片级别的去重和共享

**影响**:
- 同一文件被多个用户上传时，会重复存储分片，浪费存储空间
- 断点续传功能在公共空间无法跨用户共享进度

**建议修复**:
```python
if is_public:
    # 公共空间：仅使用文件hash隔离，实现分片共享
    tenant_path = f"public"
```

---

#### 2. 合并锁粒度与分片路径不一致

**位置**: `upload.py:112` 和 `document_utils.py:282`

```python
# upload.py 中的锁键
lock_key = f"{file_hash}_{'public' if is_public else 'private'}_{tenant_id or 'default'}"

# document_utils.py 中的分片路径
if is_public:
    tenant_path = f"public_{tenant_id}_{user_id}"
```

**问题描述**:
- 合并锁只使用了 `tenant_id`，但分片路径使用了 `tenant_id + user_id`
- 这导致同一租户内的不同用户可以并发合并同一文件，可能引发数据竞争

**影响**:
- 并发合并同一文件时可能导致文件损坏
- 合并状态不一致

**建议修复**:
统一锁键和分片路径的隔离级别，要么都使用用户级别，要么都使用租户级别。

---

#### 3. 普通上传缺少传输记录创建

**位置**: `file.py:131-233`

**问题描述**:
- `FileUploadView` (普通上传) 没有创建 `DocumentTransfer` 记录
- 但分片上传 (`FileChunkUploadView`) 会查询传输记录进行校验
- 这导致普通上传的文件无法被传输记录追踪

**影响**:
- 无法统一追踪所有上传操作
- 审计日志不完整

**建议修复**:
在普通上传完成后创建 `DocumentTransfer` 记录，状态为 `COMPLETED`。

---

### 🟡 P1级问题（中等）

#### 4. 分片上传缺少租户隔离验证

**位置**: `upload.py:222-253`

```python
# 【P1-1修复】校验传输记录的文件大小和总分片数
transfer = DocumentTransfer.objects.filter(
    file_hash=file_hash,
    user=request.user,
    is_public=is_public
).first()
```

**问题描述**:
- 查询传输记录时没有添加 `tenant_id` 过滤
- 虽然 `request.user` 会自然隔离，但在多租户环境下不够严谨

**建议修复**:
```python
transfer = DocumentTransfer.objects.filter(
    file_hash=file_hash,
    user=request.user,
    is_public=is_public,
    tenant_id=getattr(request.user, 'tenant_id', '')
).first()
```

---

#### 5. 文件合并任务中文件夹查询缺少租户过滤

**位置**: `tasks/merge.py:250`

```python
folder = FolderModel.objects.filter(pk=folder_id).first() if folder_id else None
```

**问题描述**:
- 在 Celery 任务中查询文件夹时没有应用租户过滤
- 虽然任务数据来自已验证的请求，但在异步执行时仍应保持一致性

**建议修复**:
```python
folder_query = FolderModel.objects.filter(pk=folder_id)
if not is_public and tenant_id:
    folder_query = folder_query.filter(tenant_id=tenant_id)
folder = folder_query.first() if folder_id else None
```

---

#### 6. 公共空间文件命名冲突处理不完善

**位置**: `upload.py:385-391` 和 `file.py:185-190`

**问题描述**:
- 公共空间上传文件时，`generate_file_names` 函数会检查同名文件
- 但没有考虑公共空间的所有用户都能看到所有文件的特点
- 可能导致不同用户上传同名文件时，后上传的用户看到自动重命名的文件名

**建议**:
- 明确公共空间文件命名策略：允许同名文件共存（使用物理文件名区分），还是强制唯一性

---

### 🟢 P2级问题（轻微）

#### 7. 日志信息不够详细

**位置**: 多处

**问题描述**:
- 部分关键操作缺少详细的审计日志
- 例如：分片上传成功时没有记录文件大小和分片索引

**建议**:
增加更详细的日志记录，便于问题排查。

---

#### 8. 异常处理不一致

**位置**: `upload.py:251-253`

```python
except Exception as e:
    logger.error(f'[Document] Failed to validate transfer record: {e}')
    # 校验失败不影响上传，继续原有逻辑
```

**问题描述**:
- 传输记录校验失败时只是记录日志，继续执行
- 这可能导致断点续传功能异常

**建议**:
根据异常类型决定是否继续，关键异常应该中断上传。

## 三、正确实现示例

### 3.1 私密空间上传流程（正确）

```python
# 1. 验证文件夹（带租户过滤）
folder_query = FolderModel.objects.filter(pk=folder_id)
folder_query = apply_tenant_filter(folder_query, request.user, strict_mode=True)

# 2. 生成文件路径（带用户隔离）
upload_dir = get_document_absolute_path(
    is_public=False,
    user_id=request.user.id,
    folder_id=folder_id
)

# 3. 创建文件记录（自动添加tenant_id）
new_file = create_model_instance(FileModel,
    name=logical_name,
    display_name=display_name,
    physical_name=physical_name,
    folder=folder,
    file_path=file_path,
    file_size=file.size,
    file_type=file.content_type,
    created_by=request.user  # tenant_id 自动从user获取
)
```

### 3.2 公共空间上传流程（正确）

```python
# 1. 验证文件夹（公共空间不带租户过滤）
folder = FolderModel.objects.filter(pk=folder_id).first()

# 2. 生成文件路径（公共空间不带用户隔离）
upload_dir = get_document_absolute_path(
    is_public=True,
    user_id=request.user.id,  # 仅用于日志记录
    folder_id=folder_id
)

# 3. 创建文件记录（公共空间无tenant_id字段）
new_file = FileModel.objects.create(
    name=logical_name,
    display_name=display_name,
    physical_name=physical_name,
    folder=folder,
    file_path=file_path,
    file_size=file.size,
    file_type=file.content_type,
    created_by=request.user
)
```

## 四、租户隔离矩阵

| 功能 | 私密空间 | 公共空间 | 实现方式 |
|------|---------|---------|---------|
| **文件夹查询** | ✅ 租户过滤 | ❌ 不过滤 | `apply_tenant_filter()` |
| **文件查询** | ✅ 租户过滤 | ❌ 不过滤 | `apply_tenant_filter()` |
| **普通上传** | ✅ 租户隔离 | ✅ 创建者记录 | `create_model_instance()` |
| **分片路径** | ✅ 租户隔离 | ⚠️ 租户+用户隔离 | `get_chunk_dir_path()` |
| **传输记录** | ✅ 租户字段 | ✅ 租户字段 | `DocumentTransfer.tenant_id` |
| **合并锁** | ✅ 租户隔离 | ⚠️ 仅租户隔离 | `get_merge_lock()` |

## 六、测试建议

1. **并发测试**: 多用户同时上传同一文件到公共空间
2. **断点续传测试**: 不同用户断点续传同一文件
3. **租户隔离测试**: 验证私密空间数据不会跨租户泄露
4. **大文件测试**: 10GB以上文件分片上传和合并
5. **异常恢复测试**: 合并过程中断，验证重试机制

## 七、结论

资料管理上传功能整体架构合理，但在**公共空间的分片存储路径设计**和**合并锁粒度**方面存在严重问题（P0级），需要优先修复。建议按照修复优先级逐步解决，并进行充分的并发测试验证。
