# 账号删除与同名账号问题修复报告

## 问题描述

### 原问题1：新建账号tenant_id为"admin"
- **现象：** 新建的普通用户账号tenant_id字段为"admin"
- **原因：** User模型缺少tenant_id字段，无法正确设置租户标识

### 原问题2：删除后创建同名账号
- **现象：** 删除用户后，可以创建同名账号
- **风险：**
  - 数据库中存在多个同名用户（已删除+活跃）
  - 历史数据归属混乱
  - 统计数据不准确

---

## 修复方案

### 修复1：禁止创建同名账号（核心修复）

**文件：** `spug_api/apps/account/views.py`

**修改内容：**
```python
# 第42-44行（修改前）
user = User.objects.filter(username=form.username, deleted_by_id__isnull=True).first()
if user and (not form.id or form.id != user.id):
    return json_response(error=f'已存在登录名为【{form.username}】的用户')

# 第42-52行（修改后）
# 检查是否已存在同名用户（包括已删除的用户）
user = User.objects.filter(username=form.username).first()
if user:
    # 如果是编辑模式且是当前用户，允许
    if form.id and form.id == user.id:
        pass
    # 否则拒绝创建/编辑
    else:
        status = '已删除' if user.deleted_by else '已存在'
        return json_response(error=f'{status}登录名为【{form.username}】的用户，无法重复创建')
```

**效果：**
- ✅ 禁止创建与已删除用户同名的账号
- ✅ 提示明确告知用户该账号已删除
- ✅ 保证登录名唯一性（包括已删除用户）

### 修复2：支持恢复已删除用户

**文件：** `spug_api/apps/account/views.py`

**修改内容：**
```python
# 第88-97行（修改前）
def delete(self, request):
    # ...删除逻辑...
    user.deleted_at = human_datetime()
    user.deleted_by = request.user
    user.roles.clear()
    user.save()

# 第88-107行（修改后）
def delete(self, request):
    # ...删除逻辑...
    # 如果用户已删除，则执行恢复操作
    if user.deleted_by:
        user.deleted_at = None
        user.deleted_by = None
        user.is_active = True
        user.save()
        return json_response(data={'message': '账号已恢复'})
    # 否则执行删除操作
    user.is_active = True
    user.deleted_at = human_datetime()
    user.deleted_by = request.user
    user.roles.clear()
    user.save()
```

**效果：**
- ✅ 复用删除接口实现恢复功能
- ✅ 恢复后账号可以正常登录
- ✅ 历史数据归属完整保留

class UserView(AdminView):
    def get(self, request):
        # 获取查询参数，支持查看已删除用户
        show_deleted = request.GET.get('show_deleted') == 'true'

        users = []
        queryset = User.objects.all() if show_deleted else User.objects.filter(deleted_by_id__isnull=True)
        for u in queryset:
            tmp = u.to_dict(excludes=('access_token', 'password_hash'))
            tmp['role_ids'] = [x.id for x in u.roles.all()]
            tmp['password'] = '******'
            users.append(tmp)
        return json_response(users)

## 软删除的设计优势

### 1. 数据审计与追溯
- 📋 记录谁在什么时候删除了哪个账号
- 🔍 问题追溯时能查看账号删除历史
- ⚖️ 满足法律合规要求（数据保留）

### 2. 数据关联保护
- 🛡️ 保护历史数据归属（部署记录、日志、文档）
- ⚠️ 避免硬删除导致的数据灾难
- 📊 角色使用统计准确（只统计未删除用户）

### 3. 数据恢复能力
- 🔄 误删后可快速恢复
- 🆘 员工离职后重新入职，恢复账号更高效
- 🚑 账号封禁/解封流程完善（使用is_active字段）

### 4. 业务逻辑连贯性
- ✅ 前端列表自动隐藏已删除账号
- ✅ 已删除账号无法登录（安全）
- ✅ 登录名唯一性检查完整（包括已删除用户）

## 注意事项

### 关于tenant_id问题
当前User模型尚未添加tenant_id字段，如果需要租户隔离功能，需要：
1. 在User模型添加tenant_id字段
2. 创建数据库迁移文件
3. 执行迁移命令
4. 修改账号创建逻辑设置tenant_id

这部分需要在后续单独处理，本修复专注于解决同名账号问题。
