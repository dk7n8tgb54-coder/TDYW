# 合并失败重试优化方案

## 方案概述

**方案名称**：前端检测方案  
**目标**：解决合并失败后重试需要重新上传所有分片的问题  
**核心思想**：重试时先检测分片是否存在，存在则直接合并，不存在则重新上传

---

## 问题背景

### 当前问题

```
用户上传文件 → 分片上传成功 → 合并阶段失败
                                      ↓
                              任务进入 error 状态
                                      ↓
                              用户点击"重试"
                                      ↓
                    ❌ 重新走完整流程：waiting → calculating → uploading → merging
                                      ↑________________________________________|
                                           不必要的重新上传
```

### 痛点

| 问题 | 影响 |
|-----|------|
| 分片已上传成功，但合并失败 | 用户需要重新上传所有分片 |
| 大文件（如10GB）重新上传 | 浪费时间和带宽 |
| 用户体验差 | 操作失败成本高 |

## 后端实现

### 1. 修改分片检测接口

**文件**: `spug_api/apps/document/views/upload/chunk_checker.py`

```python
class CheckUploadedChunksView(View):
    """
    检查已上传分片（支持合并失败后重试）
    """
    
    @auth('document.document.upload')
    def post(self, request):
        form, error = JsonParser(
            Argument('file_hash', required=True),
            Argument('total_chunks', type=int, required=True),
            Argument('transfer_id', required=False)
        ).parse(request.body)
        
        if error:
            return json_response(error=error)
        
        # 获取分片存储目录
        chunk_dir = os.path.join(
            settings.UPLOAD_ROOT, 
            'chunks', 
            form.file_hash
        )
        
        # 【新增】检查已存在的分片
        existing_chunks = self._get_existing_chunks(chunk_dir)
        
        # 【新增】判断是否所有分片都已存在
        all_chunks_ready = len(existing_chunks) >= form.total_chunks
        
        # 【新增】如果提供了 transfer_id，查询传输记录状态
        can_merge_directly = False
        error_code = None  # 【新增】错误码
        if form.transfer_id:
            try:
                transfer = DocumentTransfer.objects.get(
                    id=form.transfer_id,
                    created_by=request.user
                )
                # 【修改】更精确的状态判断
                # 只允许特定状态直接合并
                can_merge_directly = (
                    all_chunks_ready and 
                    transfer.status in ['merging', 'failed']
                    # 注意：'uploading' 状态不允许直接合并，因为分片可能未传完
                )
                
                # 【新增】返回错误码用于前端判断
                if transfer.status == 'failed' and transfer.error_message:
                    if '合并' in transfer.error_message or 'merge' in transfer.error_message.lower():
                        error_code = 'MERGE_FAILED'
                    elif '磁盘' in transfer.error_message or 'disk' in transfer.error_message.lower():
                        error_code = 'DISK_ERROR'
                
            except DocumentTransfer.DoesNotExist:
                pass
        
        return json_response(data={
            'uploaded_chunks': existing_chunks,
            'total_chunks': form.total_chunks,
            'uploaded_count': len(existing_chunks),
            'all_chunks_ready': all_chunks_ready,
            'can_merge_directly': can_merge_directly,
            'error_code': error_code,  # 【新增】错误码
            'missing_chunks': [
                i for i in range(form.total_chunks) 
                if i not in existing_chunks
            ]
        })
    
    def _get_existing_chunks(self, chunk_dir):
        """获取已存在的分片索引列表"""
        if not os.path.exists(chunk_dir):
            return []
        
        existing = []
        for filename in os.listdir(chunk_dir):
            if filename.startswith('chunk_'):
                try:
                    index = int(filename.split('_')[1])
                    existing.append(index)
                except (IndexError, ValueError):
                    continue
        return sorted(existing)
```

> **注意**: `os.listdir` 在大量分片时可能有性能问题。优化方案：
> 1. 短期：使用 Redis 缓存已上传分片列表
> 2. 长期：考虑引入 `FileChunk` 表记录分片元数据

### 2. 新增直接合并接口（可选优化）

```python
from django.db import transaction

class DirectMergeView(View):
    """
    直接触发合并（用于分片都已存在的情况）
    支持幂等性：同一 transfer_id 多次调用只执行一次合并
    """
    
    @auth('document.document.upload')
    def post(self, request):
        form, error = JsonParser(
            Argument('transfer_id', required=True),
            Argument('folder_id', type=int, required=True),
            Argument('file_name', required=True),
            Argument('file_hash', required=True),
            Argument('total_chunks', type=int, required=True),
            Argument('is_public', type=bool, default=False)
        ).parse(request.body)
        
        if error:
            return json_response(error=error)
        
        # 【P0修复】使用事务+悲观锁防止并发重复提交
        with transaction.atomic():
            # 1. 验证传输记录（加锁）
            try:
                transfer = DocumentTransfer.objects.select_for_update().get(
                    id=form.transfer_id,
                    created_by=request.user
                )
            except DocumentTransfer.DoesNotExist:
                return json_response(error='传输记录不存在')
            
            # 【P0修复】幂等性检查：如果已经在合并中，直接返回当前任务
            if transfer.status == 'merging' and transfer.task_id:
                logger.info(f'[DirectMerge] 幂等性命中: transfer={form.transfer_id} 已在合并中')
                return json_response(data={
                    'task_id': transfer.task_id,
                    'status': 'merging',
                    'message': '合并任务进行中',
                    'is_idempotent': True  # 标记为幂等响应
                })
            
            # 【P0修复】如果已完成，返回完成状态
            if transfer.status == 'completed':
                return json_response(data={
                    'status': 'completed',
                    'message': '文件已合并完成',
                    'file_id': transfer.file_id
                })
            
            # 2. 验证分片是否都存在
            chunk_dir = os.path.join(settings.UPLOAD_ROOT, 'chunks', form.file_hash)
            existing_chunks = self._get_existing_chunks(chunk_dir)
            
            if len(existing_chunks) < form.total_chunks:
                missing = set(range(form.total_chunks)) - set(existing_chunks)
                return json_response(
                    error=f'分片不完整，缺少: {sorted(missing)}',
                    code=400
                )
            
            # 3. 提交合并任务
            from ...tasks import merge_file_chunks
            task = merge_file_chunks.delay(
                transfer_id=form.transfer_id,
                folder_id=form.folder_id,
                file_name=form.file_name,
                file_hash=form.file_hash,
                total_chunks=form.total_chunks,
                is_public=form.is_public,
                request_user_id=request.user.id,
                request_tenant_id=getattr(request.user, 'tenant_id', ''),
                file_size=transfer.file_size
            )
            
            # 4. 更新传输记录状态
            transfer.status = 'merging'
            transfer.task_id = task.id
            transfer.save()
        
        return json_response(data={
            'task_id': task.id,
            'status': 'merging',
            'message': '合并任务已提交'
        })
```

> **关键修复点**：
> 1. `select_for_update()` - 悲观锁防止并发竞态条件
> 2. 幂等性检查 - 重复调用返回相同结果，不重复提交任务
> 3. 事务包裹 - 确保状态检查和更新原子性

### 1. 新增分片检测Store方法

**文件**: `spug_web/src/pages/document/stores/upload/core/stores/ChunkUploadStore.js`

```javascript
/**
 * 检测分片是否存在（用于合并失败后重试）
 * @param {Object} item - 上传项
 * @returns {Promise<Object>} 检测结果
 */
async checkChunks(item) {
  try {
    const response = await http.post(
      '/api/v1/documents/upload/check-chunks/',
      {
        file_hash: item.fileHash,
        total_chunks: item.chunkCount,
        transfer_id: item.transferId
      }
    );
    
    return {
      allChunksReady: response.all_chunks_ready,
      canMergeDirectly: response.can_merge_directly,
      uploadedCount: response.uploaded_count,
      missingChunks: response.missing_chunks,
      uploadedChunks: response.uploaded_chunks
    };
  } catch (error) {
    console.error('[ChunkUploadStore] 检测分片失败:', error);
    // 检测失败时，安全起见返回需要重新上传
    return {
      allChunksReady: false,
      canMergeDirectly: false,
      uploadedCount: 0,
      missingChunks: [],
      uploadedChunks: []
    };
  }
}
```

### 2. 修改重试逻辑

**文件**: `spug_web/src/pages/document/stores/upload/core/controls/ItemOperationController.js`

```javascript
async resumeItem(itemId) {
  this._verifyNotDestroyed();
  
  const item = this.core.queueStore.findUploadItemInCurrentTenant(itemId);
  if (!item) {
    console.warn(`[ItemOperationController] 未找到上传项: ${itemId}`);
    return;
  }
  
  // 【P0修复】防止重复点击
  if (item.isRetrying) {
    console.log('[ItemOperationController] 重试进行中，忽略重复点击');
    return;
  }
  item.isRetrying = true;
  
  try {
    // 【修改】使用错误码判断是否为合并失败（替代字符串匹配）
    if (this._isMergeFailed(item)) {
      console.log('[ItemOperationController] 检测到合并失败，先检查分片...');
      
      const checkResult = await this.core.chunkUploadStore.checkChunks(item);
      
      if (checkResult.canMergeDirectly) {
        console.log('[ItemOperationController] 分片都存在，直接触发合并');
        
        // 【P0修复】先调用接口，成功后再更新状态
        await this._directMerge(item);
        return;
      } else {
        console.log(`[ItemOperationController] 分片不完整(${checkResult.uploadedCount}/${item.chunkCount})，需要重新上传`);
        
        // 【P1修复】添加数组越界保护
        if (checkResult.uploadedChunks && checkResult.uploadedChunks.length > 0) {
          const maxChunk = Math.max(...checkResult.uploadedChunks);
          item.currentChunk = maxChunk + 1;
          item.progress = Math.floor(
            (checkResult.uploadedCount / item.chunkCount) * 100
          );
        } else {
          // 空数组保护
          item.currentChunk = 0;
          item.progress = 0;
        }
      }
    }
    
    // 同步 file_hash（原有逻辑）
    await this._syncFileHash(item);
    
    // 触发状态机转换
    await stateMachine.transition('RESUME');
  } finally {
    // 重置重试标记
    item.isRetrying = false;
  }
}

/**
 * 判断是否合并失败（使用错误码替代字符串匹配）
 * @private
 */
_isMergeFailed(item) {
  // 【修改】通过错误码判断（后端返回的标准错误码）
  if (item.errorCode === 'MERGE_FAILED' || item.errorCode === 'DISK_ERROR') {
    return true;
  }
  
  // 【保留】兼容旧版本：通过状态判断
  if (item.status === 'merging' && item.error) {
    return true;
  }
  
  // 【降级】通过错误信息判断（多语言环境下可能失效）
  if (item.error && (
    item.error.includes('合并') || 
    item.error.includes('merge') ||
    item.error.includes('文件写入')
  )) {
    console.warn('[ItemOperationController] 使用字符串匹配判断合并失败，建议后端返回错误码');
    return true;
  }
  
  return false;
}

/**
 * 直接触发合并
 * @private
 */
async _directMerge(item) {
  try {
    const response = await http.post(
      '/api/v1/documents/upload/direct-merge/',
      {
        transfer_id: item.transferId,
        folder_id: item.folderId,
        file_name: item.fileName,
        file_hash: item.fileHash,
        total_chunks: item.chunkCount,
        is_public: item.isPublic
      }
    );
    
    console.log('[ItemOperationController] 直接合并任务已提交:', response);
    
    // 【P0修复】接口调用成功后，再更新UI状态
    if (response.is_idempotent) {
      // 幂等响应：任务已在进行中
      console.log('[ItemOperationController] 任务已在进行中，继续轮询');
    }
    
    item.state = 'merging';
    item.status = 'merging';
    item.progress = 99;
    item.error = null;
    item.errorCode = null;
    
    // 开始轮询合并状态
    this.core.chunkUploadStore.startMergePolling(item);
    
  } catch (error) {
    console.error('[ItemOperationController] 直接合并失败:', error);
    
    // 直接合并失败，降级为正常重试流程
    item.error = null;
    item.errorCode = null;
    await stateMachine.transition('RESUME');
  }
}
```

> **关键修复点**：
> 1. **错误码判断** - 使用 `errorCode` 替代字符串匹配
> 2. **先调接口再改状态** - 防止界面卡死
> 3. **防重复点击** - `isRetrying` 标记避免重复提交
> 4. **数组越界保护** - 空数组时正确处理

### 分片清理（Garbage Collection）

**问题**：合并成功后，临时分片文件如果不删除，会占用磁盘空间。

**解决方案**：在合并任务最后添加清理逻辑

```python
# apps/document/tasks/merge.py

@shared_task(bind=True, max_retries=3)
def merge_file_chunks(self, transfer_id, folder_id, file_name, file_hash, ...):
    """
    合并文件分片
    """
    try:
        # ... 合并逻辑 ...
        
        # 【P1】合并成功后清理分片
        _cleanup_chunks(file_hash)
        
        # 更新传输记录状态
        transfer.status = 'completed'
        transfer.save()
        
    except Exception as e:
        logger.error(f'[Merge] 合并失败: {e}')
        raise

def _cleanup_chunks(file_hash):
    """
    清理临时分片文件
    """
    chunk_dir = os.path.join(settings.UPLOAD_ROOT, 'chunks', file_hash)
    
    if not os.path.exists(chunk_dir):
        return
    
    try:
        # 删除整个分片目录
        shutil.rmtree(chunk_dir)
        logger.info(f'[Merge] 分片清理完成: {chunk_dir}')
    except Exception as e:
        # 清理失败记录日志，不影响主流程
        logger.warning(f'[Merge] 分片清理失败: {chunk_dir}, error={e}')

# 定时清理任务（处理合并失败残留的分片）
@shared_task
def cleanup_expired_chunks():
    """
    清理过期的分片文件（超过24小时）
    """
    chunks_root = os.path.join(settings.UPLOAD_ROOT, 'chunks')
    if not os.path.exists(chunks_root):
        return
    
    expired_time = timezone.now() - timezone.timedelta(hours=24)
    cleaned_count = 0
    
    for chunk_dir in os.listdir(chunks_root):
        dir_path = os.path.join(chunks_root, chunk_dir)
        if not os.path.isdir(dir_path):
            continue
        
        # 检查目录修改时间
        stat = os.stat(dir_path)
        modify_time = timezone.datetime.fromtimestamp(stat.st_mtime)
        modify_time = timezone.make_aware(modify_time)
        
        if modify_time < expired_time:
            try:
                shutil.rmtree(dir_path)
                cleaned_count += 1
                logger.info(f'[Cleanup] 清理过期分片: {dir_path}')
            except Exception as e:
                logger.warning(f'[Cleanup] 清理失败: {dir_path}, error={e}')
    
    logger.info(f'[Cleanup] 共清理 {cleaned_count} 个过期分片目录')
```

## 实现优先级（按审查意见优化）

| 优先级 | 任务 | 预计工时 | 说明 |
|-------|------|---------|------|
| **P0** | `direct-merge` 接口幂等性与数据库锁 | 2h | 防止并发导致重复提交，数据损坏 |
| **P0** | 前端先调接口再改状态 | 1h | 防止界面卡死，提升用户体验 |
| **P0** | 前端防重复点击 | 0.5h | 避免重复提交 |

### 1. 数据库状态机的最终一致性

**问题**：如果 Celery 任务在队列中积压或 Worker 挂了，数据库状态会一直停留在 `merging`，但实际上任务没执行。

**解决方案**：增加 `updated_at` 字段和超时检测机制。

```python
# models.py 添加字段
class DocumentTransfer(models.Model):
    # ... 现有字段 ...
    updated_at = models.DateTimeField(auto_now=True)  # 自动更新时间
    
    def is_merge_timeout(self, timeout_minutes=30):
        """检查合并是否超时"""
        if self.status != 'merging':
            return False
        timeout = timezone.now() - timezone.timedelta(minutes=timeout_minutes)
        return self.updated_at < timeout


# 定时任务：检测超时合并任务
@shared_task
def check_merge_timeout():
    """
    检测合并超时的任务，重置为 failed 状态以便重试
    """
    timeout_tasks = DocumentTransfer.objects.filter(
        status='merging',
        updated_at__lt=timezone.now() - timezone.timedelta(minutes=30)
    )
    
    for task in timeout_tasks:
        logger.warning(f'[Timeout] 合并任务超时，重置为失败: transfer={task.id}')
        task.status = 'failed'
        task.error_message = '合并任务超时（30分钟）'
        task.save()
        
        # 可选：发送告警通知
        send_alert(f'合并任务超时: {task.file_name}')
```

**问题**：`os.listdir` 遍历大量分片文件时性能较差。

- 无需遍历文件夹，检测时间从 O(n) 降到 O(1)
