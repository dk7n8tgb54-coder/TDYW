## 三、详细问题分析

### P0-1: TransferFailView缺少状态转换验证

**位置**: `views/transfer/status.py` 第64-105行

**问题描述**:
```python
class TransferFailView(View):
    def post(self, request, transfer_id):
        # ... 权限检查 ...
        
        # 幂等性校验
        if transfer.status == TransferStatus.FAILED.value:
            return json_response(data={'status': TransferStatus.FAILED.value.lower()})

        # 【问题】直接更新状态，没有验证状态转换是否合法！
        transfer.status = TransferStatus.FAILED.value
        transfer.error_message = form.error_message or '上传失败'
        transfer.save()
```

**风险分析**:
1. 从终态（COMPLETED/CANCELED）可以直接标记为FAILED，违反状态机规则
2. 可能导致已完成/已取消的任务被错误标记为失败
3. 与批量操作中的状态检查逻辑不一致

**修复建议**:
```python
from apps.document.constants import is_valid_status_transition, TransferStatus

# 添加状态转换验证
current_status_enum = TransferStatus(transfer.status)
if not is_valid_status_transition(current_status_enum, TransferStatus.FAILED):
    return json_response(error=f'不能从 {transfer.status} 状态标记为失败')
```

**优先级**: 立即修复

### P1-1: 前端状态机merging状态缺少CANCEL转换

**位置**: `UploadStateMachine.js` 第112-119行

**问题描述**:
```javascript
merging: {
  entry: this.onMergingEntry.bind(this),
  exit: this.onMergingExit.bind(this),
  transitions: {
    MERGE_SUCCESS: { target: 'completed' },
    ERROR: { target: 'error' },
    // 【问题】缺少 CANCEL 转换！
  }
}
```

**风险分析**:
1. 虽然StateMachineManager.batchCancel()排除了merging状态
2. 但单个任务在merging状态时无法通过前端状态机取消
3. 与后端 ALLOWED_STATUS_TRANSITIONS 定义不一致（后端允许 MERGING -> CANCELED）

**修复建议**:
```javascript
merging: {
  transitions: {
    MERGE_SUCCESS: { target: 'completed' },
    ERROR: { target: 'error' },
    CANCEL: { target: 'cancelled', action: this.actions.onCancel }
  }
}
```

export function shouldResumeWaiting({ item, history }) {
  // 边界检查
  if (!item) {
    console.warn('[shouldResumeWaiting] item is undefined...');
    return true;
  }
  
  if (!item.file) {
    return true;
  }

  const safeHistory = Array.isArray(history) ? history : [];
  const wasWaiting = safeHistory.length > 0 && 
    safeHistory.some(h => h && (h.from === 'waiting' || h.to === 'waiting'));
  
  const hasFileHash = !!item?.fileHash;
  const currentChunk = typeof item.currentChunk === 'number' ? item.currentChunk : 0;
  const chunkCount = typeof item.chunkCount === 'number' ? item.chunkCount : 0;

### P2-5: 异常处理不够细化

**位置**: `chunkUpload.js` 第553-561行

**问题描述**:
```javascript
catch (error) {
  consecutiveErrors++;
  if (consecutiveErrors >= MAX_CONSECUTIVE_ERRORS) {
    throw new Error(`合并状态查询连续失败${MAX_CONSECUTIVE_ERRORS}次，请检查网络`);
  }
  
  const backoffTime = Math.min(1000 * Math.pow(2, consecutiveErrors - 1), 16000);
  await new Promise(resolve => setTimeout(resolve, backoffTime));
}
```

**问题**:
1. 没有区分网络错误和服务器错误
2. 没有区分可重试错误和不可重试错误
3. 用户无法区分是暂时性问题还是永久性问题

**建议**:
1. 根据HTTP状态码区分错误类型
2. 4xx错误（客户端错误）不应该重试
3. 5xx错误（服务器错误）可以有限重试
