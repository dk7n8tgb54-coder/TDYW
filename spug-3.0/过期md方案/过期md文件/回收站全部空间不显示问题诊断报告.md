# 回收站"全部空间"筛选不显示问题诊断报告

## 问题现象

非管理员用户在回收站中：
- **私密空间**：正确显示自己删除的文件（1条）
- **全部空间**：显示0条（应该显示私密空间+公共空间的文件）

## 日志分析

```
[RecycleBinStore] 收到数据: {space: 'all', items: 1, total: 1}   ← 第一次请求有数据
[RecycleBinStore] 收到数据: {space: 'all', items: 0, total: 0}   ← 后续请求数据消失
[RecycleBinStore] 收到数据: {space: 'all', items: 0, total: 0}

[RecycleBinStore] 切换空间: {from: 'all', to: 'private'}
[RecycleBinStore] 收到数据: {space: 'private', items: 1, total: 1} ← 私密空间有数据

[RecycleBinStore] 切换空间: {from: 'private', to: 'all'}
[RecycleBinStore] 收到数据: {space: 'all', items: 0, total: 0}   ← 切回全部空间无数据
```

## 根本原因

### 1. 请求竞争问题（主要原因）

前端 `store.fetchList()` 使用 `AbortController` 取消请求，但存在**竞态条件**：

```javascript
// store.js 第76-106行
@action
fetchList = async () => {
  this._abortController = new AbortController();  // 创建新控制器
  try {
    const data = await service.getRecycleBinList(params, this._abortController.signal);
    this.items = data.items || [];  // ← 问题：请求A和请求B可能乱序返回
  }
}
```

**问题场景**：
1. 用户快速切换空间：all → private → all
2. 请求A（space=all）发送，延迟返回
3. 请求B（space=private）发送，快速返回，items=1
4. 请求C（space=all）发送
5. 请求A返回，items=1，显示正确
6. 请求C返回，items=0（缓存问题），覆盖正确数据

### 2. 后端缓存键设计缺陷

```python
# recycle_bin.py 第102行
cache_key = f'recycle_bin:{request.user.id}:{cache_version}:{form.space}:{form.keyword or ""}:{form.page}:{page_size}'
```

**问题**：
- 版本号 `cache_version` 只在删除/恢复操作后递增
- 但**切换空间筛选不会使缓存失效**
- 不同空间的缓存可能互相干扰

### 3. 租户过滤不完整（已修复）

**已添加的修复**（第135、156、170、804、824、834行）：
```python
qs = apply_tenant_filter(qs, user)
```

但问题仍然存在，说明不是租户过滤的问题。

## 深层问题：请求时序与状态同步

查看前端代码发现更严重的问题：

```javascript
// index.js 第44-49行
useEffect(() => {
  store.refresh();  // 组件挂载时加载
  return () => {
    store.reset();   // 组件卸载时重置
  };
}, []);

// store.js 第365-397行 reset()
@action
reset = () => {
  this.space = 'all';  // ← 重置为'all'，但组件已卸载
  // ...
}
```

**问题**：React 组件卸载时调用 `reset()`，将 `space` 重置为 `'all'`，但如果组件快速重新挂载，可能出现状态混乱。

## 修复方案

### 方案1：前端添加请求序列号（推荐）

确保只有最新的请求能更新状态：

```javascript
// store.js
@observable _requestId = 0;

@action
fetchList = async () => {
  this.loading = true;
  const requestId = ++this._requestId;  // 生成新序列号
  
  try {
    const data = await service.getRecycleBinList(params, signal);
    
    // 只处理最新请求的结果
    if (requestId !== this._requestId) {
      console.log('[RecycleBin] 忽略过期请求结果');
      return;
    }
    
    this.items = data.items || [];
    this.total = data.total || 0;
  }
}
```

### 方案2：修复缓存键（已在代码中添加租户过滤）

确保缓存键包含足够唯一信息，或禁用有问题的缓存。

### 方案3：后端添加space参数到调试日志

修改后端以确认返回的数据与请求的空间一致：

```python
logger.info(f'[RecycleBin] 查询结果: user={user.username}, space={space}, '
           f'total={total_count}, returned={len(results)}')
```

## 已执行的修复

### 1. 后端租户过滤（已完成）

文件：`spug_api/apps/document/views/recycle_bin.py`

添加了以下位置的 `apply_tenant_filter` 调用：
- 第135行：单空间查询
- 第156行：全部空间-私有查询
- 第170行：全部空间-公共查询
- 第804行：统计-私有查询
- 第824行：统计-管理员公共查询
- 第834行：统计-普通用户公共查询

### 2. 前端请求序列号修复（已完成）

文件：`spug_web/src/pages/document/recycle-bin/store.js`

**添加请求序列号机制**：
```javascript
// 【P0修复】请求序列号，防止竞态条件
_requestId = 0;
```

**fetchList方法增强**：
- 生成请求序列号：`const requestId = ++this._requestId;`
- 响应时检查序列号，过期请求被忽略
- 记录当前请求空间用于调试

**状态变更方法增强**（递增序列号）：
- `setSpace()` - 切换空间时取消旧请求+递增序列号
- `doSearch()` - 执行搜索时递增序列号
- `setPage()` - 切换页码时递增序列号
- `setPageSize()` - 切换每页数量时递增序列号
- `reset()` - 重置状态时取消请求+递增序列号

## 结论

**根本原因是前端请求竞争**，不是后端查询逻辑问题。日志显示：
- 私密空间始终返回1条（数据存在）
- 全部空间有时返回1条有时0条（请求竞争导致过期结果覆盖）

**已实施双重修复**：
1. 后端添加租户过滤确保数据安全
2. 前端添加请求序列号机制防止竞态条件

修复后应该能正确显示：非管理员在"全部空间"看到私密空间+公共空间自己删除的文件。
