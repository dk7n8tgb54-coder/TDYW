# 资料上传问题诊断报告

**报告时间**: 2026-03-15  
**问题描述**: 
- 私密空间普通上传 ✅ 好使
- 私密空间分片上传 ❌ 不好使  
- 公共空间普通上传 ❌ 不好使
- 公共空间分片上传 ❌ 不好使

## 一、代码架构分析

上传功能使用**同一套代码**，通过 `is_public` 参数区分空间类型：

```python
# file.py 和 upload.py 都使用相同的模式
is_public = request.POST.get('is_public', 'false').lower() == 'true'
FolderModel = get_folder_model(is_public=is_public)  # DocumentFolderPrivate / DocumentFolderPublic
FileModel = get_file_model(is_public=is_public)        # DocumentFilePrivate / DocumentFilePublic
```

**关键区别**:
| 方面 | 私密空间 (is_public=False) | 公共空间 (is_public=True) |
|------|---------------------------|--------------------------|
| 文件夹模型 | DocumentFolderPrivate | DocumentFolderPublic |
| 文件模型 | DocumentFilePrivate | DocumentFilePublic |
| tenant_id字段 | ✅ 有 | ❌ 无 |
| 租户过滤 | ✅ apply_tenant_filter() | ❌ 不过滤 |
| 分片路径 | `tenant_id/file_hash/` | `public_tenant_id_user_id/file_hash/` |

## 二、可能的问题原因

### 🔴 问题1: 公共空间分片路径设计缺陷（P0级）

**位置**: `document_utils.py:282-286`

```python
if is_public:
    # 公共空间：租户ID + 用户ID双重隔离
    tenant_id = getattr(request_user, 'tenant_id', 'default') or 'default'
    user_id = getattr(request_user, 'id', 'anonymous') or 'anonymous'
    tenant_path = f"public_{tenant_id}_{user_id}"
```

**问题**:
- 公共空间分片路径使用了 `public_{tenant_id}_{user_id}` 格式
- 这导致不同用户的分片存储在不同目录
- 断点续传时可能找不到分片

**影响**: 公共空间分片上传无法正常合并

---

### 🔴 问题2: 合并锁粒度与分片路径不一致（P0级）

**位置**: `upload.py:112` vs `document_utils.py:282`

```python
# 合并锁键（只使用tenant_id）
lock_key = f"{file_hash}_{'public' if is_public else 'private'}_{tenant_id or 'default'}"

# 但分片路径使用了 tenant_id + user_id
if is_public:
    tenant_path = f"public_{tenant_id}_{user_id}"
```

**问题**: 锁粒度比路径粒度粗，可能导致并发问题

---

### 🟡 问题3: DocumentFilePublic 缺少 tenant_id 字段

**位置**: `models.py:234-382`

**问题**: 
- `DocumentFilePrivate` 有 `tenant_id` 字段
- `DocumentFilePublic` **没有** `tenant_id` 字段
- 但 `create_model_instance()` 尝试自动设置 `tenant_id`

```python
def create_model_instance(Model, **kwargs):
    if hasattr(Model, 'tenant_id') and 'tenant_id' not in kwargs:
        # 对于 DocumentFilePublic，hasattr(Model, 'tenant_id') 返回 False
        # 所以不会设置 tenant_id，这是正确的
        kwargs['tenant_id'] = user.tenant_id or ''
    return Model.objects.create(**kwargs)
```

**这个逻辑是正确的**，不会导致问题。

---

### 🟡 问题4: Celery 任务中文件夹查询缺少租户过滤

**位置**: `tasks/merge.py:250`

```python
folder = FolderModel.objects.filter(pk=folder_id).first() if folder_id else None
```

**问题**: 私密空间下查询文件夹时没有应用 `apply_tenant_filter()`

---

### 🟡 问题5: 传输记录查询缺少 tenant_id 过滤

**位置**: `upload.py:225-228`

```python
transfer = DocumentTransfer.objects.filter(
    file_hash=file_hash,
    user=request.user,
    is_public=is_public
).first()
```

**问题**: 没有添加 `tenant_id` 过滤，虽然 `request.user` 会自然隔离，但在多租户环境下不够严谨

## 四、修复建议

### 立即修复（解决公共空间上传问题）

1. **统一分片路径**（推荐方案A）:
```python
def get_chunk_dir_path(file_hash, is_public, request_user):
    if is_public:
        # 公共空间：只使用 public，不区分租户和用户
        tenant_path = "public"
    else:
        # 私有空间：租户隔离
        tenant_path = getattr(request_user, 'tenant_id', 'default') or 'default'
    
    return os.path.join(chunk_base_dir, tenant_path, file_hash)
```

2. **统一合并锁粒度**:
```python
# 锁键与路径保持一致
if is_public:
    lock_key = f"{file_hash}_public"
else:
    tenant_id = getattr(request_user, 'tenant_id', 'default') or 'default'
    lock_key = f"{file_hash}_private_{tenant_id}"
```

## 六、结论

根据代码审查，**公共空间分片路径设计** (`public_{tenant_id}_{user_id}`) 是最可能导致问题的原因。这个设计会导致：
1. 分片存储路径过于复杂
2. 与合并锁粒度不一致
3. 断点续传时可能找不到分片

建议立即修复 `get_chunk_dir_path()` 函数，简化公共空间的分片路径。
