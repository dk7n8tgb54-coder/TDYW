## 三、原方案核心问题（经核实）

### 问题 1：文件夹上传确实没有分片上传

**代码验证**（`fileUpload.js:282-322`）：
```javascript
// 当前 uploadFileToFolder 方法：直接普通上传，无大小判断
await http.post(API_ENDPOINTS.FILE_UPLOAD, formData, {
  onUploadProgress: (e) => { ... }
});
```

**正确结论**：❌ 确认缺失分片判断，需要添加。

---

### 问题 2：预加载队列方案存在时序问题

**审查报告建议**：先预加队列 → 再创建文件夹结构 → 再上传

**问题分析**：
- 预加队列时需要 `targetFolderId`，但此时文件夹结构尚未创建
- `uploadExistingItem` 需要 `folderMap` 才能确定目标文件夹
- 方案中"先预加队列再建文件夹"的时序会导致文件全部上传到根目录

**正确结论**：⚠️ 时序需调整，建议改为：**创建文件夹结构 → 预加队列 → 上传**

---

### 问题 3：`isFromFolderUpload` 标记

**审查报告**：必须添加标记用于筛选

**实际评估**：
- 当前队列实现支持多种来源（普通上传、文件夹上传、断点续传）
- 添加标记有助于后续扩展，但非阻塞性问题
- 可以用 `folderPath` 字段代替（文件夹上传必有路径）

**建议**：✅ 添加标记是好实践，但非必须

## 四、修正后的实施方案

### 方案核心调整：优化时序

```
原方案时序（有问题）：
  预加队列(waiting) → 创建文件夹 → 遍历队列上传
  问题：预加时folderMap不存在，无法确定targetFolderId

修正后时序：
  创建文件夹结构 → 预加队列(waiting, 带folderMap信息) → 遍历队列上传
```

### 修正 2：优化文件夹上传时序（folderUpload.js）

**调整顺序**：先创建文件夹结构，再预加队列

```javascript
async handleFolderSelect(files) {
  // ... 前置校验代码 ...

  // 1️⃣ 先创建文件夹结构（获取folderMap）
  const folderMap = new Map();
  for (let i = 0; i < files.length; i++) {
    const file = files[i];
    const relativePath = file.webkitRelativePath || file.name;
    const pathParts = relativePath.split('/');
    const folderPath = pathParts.slice(0, -1).join('/');

    if (folderPath && !folderMap.has(folderPath)) {
      const createdFolderId = await this.createFolderStructure(folderPath, targetFolderId);
      folderMap.set(folderPath, createdFolderId);
    }
  }

  // 2️⃣ 预加队列（此时folderMap已就绪）
  for (const file of files) {
    const uploadId = generateUploadId();
    const relativePath = file.webkitRelativePath || file.name;
    const pathParts = relativePath.split('/');
    const folderPath = pathParts.slice(0, -1).join('/');
    const targetId = folderPath ? folderMap.get(folderPath) : targetFolderId;
    
    this.queueStore.addToQueue({
      id: uploadId,
      file: file,
      name: relativePath,
      percent: 0,
      status: 'waiting',
      canAbort: false,
      isFromFolderUpload: true,      // ✅ 添加标记（可选但推荐）
      targetFolderId: targetId,       // ✅ 直接记录目标文件夹ID
      folderPath: folderPath,
      tenantId: tenantId,
      isPublic: isPublic,
    }, tenantId);
  }

  // 3️⃣ 开始上传
  await this.uploadFolderFiles(files, folderMap, targetFolderId, folderUniqueKey);
}
```

### 修正 3：简化上传方法（无需新增 uploadExistingItem）

**理由**：队列项已包含 `targetFolderId`，无需再查 `folderMap`

```javascript
// 简化后的 uploadFolderFiles
async uploadFolderFiles(files, folderMap, targetFolderId, folderUniqueKey) {
  const tenantId = this.rootStore.getCurrentTenantId?.() || 'default';
  const queue = this.queueStore.uploadQueue[tenantId];
  
  // 筛选文件夹上传的等待项
  const waitingItems = queue.filter(item => 
    item.status === 'waiting' && item.isFromFolderUpload
  );

  for (let i = 0; i < waitingItems.length; i++) {
    const item = waitingItems[i];
    this.queueStore.updateUploadItem(item.id, { 
      status: 'uploading', 
      canAbort: true 
    });

    try {
      // 直接使用 item.targetFolderId，无需再查 folderMap
      if (item.file.size > UPLOAD_CONSTANTS.NORMAL_UPLOAD_THRESHOLD) {
        await this.fileUploadStore.uploadFileChunkedToFolder(item);
      } else {
        await this.fileUploadStore.uploadFileNormalToFolder(item);
      }
      successCount++;
    } catch (error) {
      this.queueStore.updateUploadItem(item.id, { 
        status: 'error', 
        error: error.message 
      });
      failCount++;
    }
    
    this.queueStore.setFolderUploadProgress(i + 1, waitingItems.length);
  }
}
```
