## 本轮发现的问题

### 问题 1：最初文件偏模板化

现象：

- `00` 到 `06` 最初只是框架。
- 没有真正承载无线电台执照功能的具体内容。

修正：

- 已将 `00` 到 `03` 改为具体需求、上下文、计划和设计。
- 已将 `04` 到 `06` 改为自动闭环执行记录结构。

### 问题 2：缺少自动闭环运行协议

现象：

- 原流程更像阶段式项目管理。
- 没有明确"自执行 -> 自检 -> 自修正 -> 再验证"的 Agent 行为规则。

修正：

- 新增 `AUTO-LOOP-RUNBOOK.md`。
- 在主标准化设计方案中补充自动闭环说明。

### 问题 3：弹窗去重策略经历 3 次迭代

现象：

- 第 1 版：使用 `sessionStorage` 存已弹 ID → 用户反馈刷新不弹
- 第 2 版：改为模块级 `Set` → 用户反馈刷新后弹窗烦人
- 第 3 版：`sessionStorage` + token key → 页面刷新不弹，重新登录后可再弹

教训：

- 去重策略要考虑用户真实场景：刷新 vs 重新登录
- `sessionStorage` 的生命周期 = 标签页关闭时清除，不等于浏览器关闭
- Token 变化是"重新登录"的最佳信号

### 问题 4：views.py 重复赋值行

现象：

- `views.py:69` 频率列表赋值了两次（`item['frequencies'] = [f.to_view() for f in freqs]`）

修正：

- 删除重复行

教训：

- 大文件中容易产生复制粘贴错误，自检时应关注

## 可复用经验

后续创建 Agent Loop 时，应遵循：

1. `00-03` 先写具体内容，不能只放空模板。
2. `04-06` 作为执行中持续更新的活文档。
3. 必须有一个 `AUTO-LOOP-RUNBOOK.md` 定义自动闭环协议。
4. 每个 Loop 只能做一个最小可验证任务。
5. 每个 Loop 必须记录自检和自修正结果。
6. 弹窗通知去重用 token key 而非纯模块变量，确保"刷新不弹 + 重新登录再弹"。
7. Django 视图代码中避免重复赋值行，自检时重点检查。
