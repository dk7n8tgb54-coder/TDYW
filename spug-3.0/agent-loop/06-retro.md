# 06 复盘沉淀：自动闭环复盘

## 使用方式

本文件在每个大的自动闭环阶段完成后更新。

记录内容包括：

- 本轮是否达成目标。
- 自检发现了什么问题。
- 自修正是否有效。
- 哪些规则可以复用到下一次。

## 当前结论

本轮已完成 Loop Engineering 文档与自动闭环执行协议设计。

尚未进入代码开发。

## 本轮发现的问题

### 问题 1：最初文件偏模板化

现象：

- `00` 到 `06` 最初只是框架。
- 没有真正承载无线电台执照功能的具体内容。

修正：

- 已将 `00` 到 `03` 改为具体需求、上下文、计划和设计。
- 已将 `04` 到 `06` 改为自动闭环执行记录结构。

### 问题 2：缺少自动闭环运行协议

现象：

- 原流程更像阶段式项目管理。
- 没有明确“自执行 -> 自检 -> 自修正 -> 再验证”的 Agent 行为规则。

修正：

- 新增 `AUTO-LOOP-RUNBOOK.md`。
- 在主标准化设计方案中补充自动闭环说明。

## 可复用经验

后续创建 Agent Loop 时，应遵循：

1. `00-03` 先写具体内容，不能只放空模板。
2. `04-06` 作为执行中持续更新的活文档。
3. 必须有一个 `AUTO-LOOP-RUNBOOK.md` 定义自动闭环协议。
4. 每个 Loop 只能做一个最小可验证任务。
5. 每个 Loop 必须记录自检和自修正结果。
