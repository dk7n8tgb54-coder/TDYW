# 无线电台执照有效期管理功能设计方案

## 一、背景与目标

### 1.1 背景

无线电台执照、许可证或许可批复是台站合法运行的重要依据。执照通常存在明确的起始日期和截止日期，如果缺少统一管理和到期提醒，容易出现续办不及时、附件分散、历史追溯困难等问题。

平台拟新增“无线电台执照有效期管理”功能，对台站执照信息、使用频率、许可期限、用途及相关附件进行统一登记，并在执照到期前一个月自动提醒相关人员处理续期或换证工作。

### 1.2 建设目标

- 支持手动录入无线电台执照信息，包括台站、频率、起始日期、截止日期、用途等核心字段。
- 支持一个执照登记单维护单个或多个频率。
- 支持上传和管理执照相关附件，包括无线电台执照、许可证、许可批复等。
- 支持执照到期前一个月自动提醒，并在列表中直观展示即将到期、已过期、正常等状态。
- 支持查询、筛选、编辑、删除、附件查看/下载等日常管理能力。
- 保持与当前平台技术体系一致，后端使用 Django/DRF 风格能力，前端使用 React + Ant Design，定时提醒使用 Celery Beat。

## 三、业务流程

### 3.1 执照登记流程

1. 用户进入“无线电台执照管理”页面。
2. 点击“新增执照”。
3. 填写台站、频率、起始日期、截止日期、用途等信息。
4. 上传附件，可分别标记为“执照”“许可证”“许可批复”“其他”。
5. 保存后系统自动计算执照状态。
6. 记录创建人、创建时间，并写入审计日志。

### 3.2 到期提醒流程

1. Celery Beat 每天固定时间执行执照到期扫描任务。
2. 系统筛选截止日期距离当前日期小于等于 30 天且未过期的有效执照。
3. 对尚未生成当期提醒的执照创建提醒记录。
4. 在执照列表、首页待办或通知入口展示提醒。
5. 用户查看提醒后，可标记为已读、已处理，或进入执照详情执行续期更新。

### 3.3 续期处理流程

1. 用户在执照详情页点击“续期”或“编辑”。
2. 填写新的起始日期、截止日期，并上传新的执照或许可批复附件。
3. 系统保存当前执照新版本信息。
4. 原到期提醒可自动标记为已处理。
5. 续期变更进入操作日志，便于后续追溯。

## 七、到期提醒设计

### 7.1 提醒规则

基础规则：

- 每天扫描一次。
- 当前日期距离截止日期小于等于 30 天且大于等于 0 天，状态为“即将到期”。
- 截止日期早于当前日期，状态为“已过期”。
- 截止日期距离当前日期大于 30 天，状态为“正常”。

提醒生成：

- 对“即将到期”的执照生成 `expiring` 提醒。
- 对“已过期”且未生成过过期提醒的执照生成 `expired` 提醒。
- 同一个截止日期周期内不重复刷屏提醒。

### 7.2 定时任务

任务名称建议：

```text
apps.radio_license.tasks.scan_radio_license_expiration
```

执行时间建议：

```text
每天 08:00
```

任务逻辑：

1. 获取所有未删除执照。
2. 根据 `valid_to` 计算剩余天数。
3. 更新执照状态缓存字段。
4. 为符合条件且未提醒过的记录创建提醒。
5. 记录任务执行日志，包括扫描数量、生成提醒数量、异常数量。

### 7.3 提醒对象

提醒接收人优先级：

1. 执照责任人。
2. 若责任人为空，则提醒创建人。
3. 若接入部门/角色配置，则可提醒具备执照管理权限的角色。

### 7.4 提醒展示文案

即将到期：

```text
无线电台执照即将到期：XX甚高频台站，截止日期 2026-12-31，剩余 30 天，请及时办理续期。
```

已过期：

```text
无线电台执照已过期：XX甚高频台站，截止日期 2026-12-31，请尽快处理。
```

### 9.2 状态计算函数

建议封装统一函数：

```python
def calculate_license_status(valid_to, today=None):
    if today is None:
        today = date.today()
    days_left = (valid_to - today).days
    if days_left < 0:
        return 'expired', days_left
    if days_left <= 30:
        return 'expiring', days_left
    return 'normal', days_left
```

该函数应被列表展示、保存后更新、定时任务共同复用，避免不同入口状态不一致。

### 9.3 附件安全

后端需要处理：

- 文件类型白名单。
- 单文件大小限制。
- 文件名清洗，避免路径穿越。
- 下载接口鉴权。
- 删除附件时仅删除业务关联，物理文件可按平台现有策略延迟清理。

### 9.4 审计日志

新增、编辑、删除、上传附件、删除附件、处理提醒均应进入平台审计日志。若现有 AuditLogMiddleware 已覆盖非 GET 请求，本模块保持标准接口方式即可。

- 频率字段使用“添加频率”按钮动态新增行。
- 附件上传时要求选择附件类型。
- 保存时先校验起始日期不得晚于截止日期。
- 列表状态使用 Ant Design `Tag` 组件。
- 到期提醒可在列表顶部用 `Alert` 组件展示。
- 删除执照和删除附件必须二次确认。

## 十一、数据迁移与兼容

本功能为新增模块，不涉及历史数据迁移。

如后续需要从 Excel 或既有台账导入执照，可新增导入接口：

- 下载导入模板。
- 上传 Excel。
- 后端校验必填字段和日期格式。
- 返回错误行明细。
- 校验通过后批量创建执照和频率记录。

### 12.3 边界用例

## 十四、风险与注意事项

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 日期字段格式不统一 | 状态计算错误 | 后端统一使用 date 类型或统一格式转换 |
| 附件直链绕过权限 | 敏感文件泄露 | 所有下载走鉴权接口 |
| 重复提醒过多 | 用户被打扰 | 提醒记录增加去重约束 |
| 频率只保存字符串 | 后续统计困难 | 使用频率明细表保存结构化数据 |
| 责任人为空 | 提醒无人接收 | 默认发送给创建人或具备管理权限角色 |
| 多租户隔离遗漏 | 数据越权 | 所有查询、更新、下载均应用租户过滤 |

## 十五、验收标准

- 用户可以新增一条无线电台执照记录，并录入多个频率。
- 用户可以上传执照、许可证或许可批复附件，并能查看/下载。
- 列表可以正确展示执照状态和剩余天数。
- 截止日期在 30 天内的执照会被标记为即将到期。
- 截止日期早于当前日期的执照会被标记为已过期。
- 定时任务能够生成到期提醒，且同一周期不重复生成。
- 用户可以查看并处理提醒。
- 无权限用户不能查看、编辑、删除或下载其他租户执照数据。
