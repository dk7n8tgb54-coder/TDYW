# 文件夹上传问题修复方案（最终版）

## 问题确认

| 功能 | 分片上传 | 状态 |
|------|---------|------|
| **普通文件上传** | ✅ 有 | `index.js:712` 有大小判断 |
| **文件夹上传** | ❌ **无** | `fileUpload.js:282` 直接普通上传 |

## 根因

`uploadFileToFolder` 方法没有根据文件大小选择上传方式，所有文件都走普通上传。

## 修复方案（最小改动）

### 修改文件 1：`spug_web/src/pages/document/stores/upload/core/fileUpload.js`

在 `uploadFileToFolder` 方法中添加分片判断：

```javascript
async uploadFileToFolder(file, targetFolderId, folderPath, isPublic) {
  const uploadId = generateUploadId();
  const fileName = buildFolderFileName(folderPath, file.name);
  const tenantId = this.rootStore.getCurrentTenantId?.() || 'default';
  const targetIsPublic = isPublic !== null ? isPublic : this.rootStore.navigationStore?.isPublic;

  // 【关键修复】添加分片判断
  if (file.size > UPLOAD_CONSTANTS.NORMAL_UPLOAD_THRESHOLD) {
    // 大文件：先加队列，再走分片上传
    this.queueStore.addToQueue({
      id: uploadId,
      file: file,
      name: fileName,
      percent: 0,
      status: 'uploading',
      error: null,
      canAbort: true,
      uniqueKey: this.queueStore.generateUniqueKey(file, targetFolderId, targetIsPublic),
      tenantId: tenantId,
      isPublic: targetIsPublic,
    }, tenantId);

    await this.rootStore.chunkUploadStore.uploadFileChunked(
      file, targetFolderId, uploadId, targetIsPublic
    );
  } else {
    // 小文件：保持原有普通上传逻辑（第282-322行代码）
    // ... 原有代码不变 ...
  }
}
```

### 修改点说明

| 位置 | 改动 |
|------|------|
| `fileUpload.js:227-399` | 在 `uploadFileToFolder` 开头添加分片判断 |
| 大文件(>32MB) | 走 `chunkUploadStore.uploadFileChunked` |
| 小文件(≤32MB) | 保持原有普通上传逻辑 |

## 预期效果

1. 文件夹上传大文件时自动分片
2. 进度条正常显示（复用分片上传的进度绑定）
3. 小文件上传不受影响

## 风险

- 无。仅添加判断分支，不改变原有逻辑。
