# 部门值班日志模块设计方案

> 状态：方案待确认（认可后实施）
> 日期：2026-07-16
> 负责模块：`apps.duty_log`（新建独立 app）

---

## 一、背景与模块定位

项目现有两个相邻模块，需先厘清边界，避免功能重叠：

| 现有模块 | app | 定位 | 核心字段 |
|---|---|---|---|
| 值班日志 | `apps.duty` | 行政值班事项聚合记录，支持从「跨日事项跟踪/干扰记录」一键引入 | 值班人员、科室、日期、值班情况(大文本) |
| 部门值班日检查单 | `apps.checksheet` | 按「模板检查项」逐项打勾的检查表，带提交/复核/归档状态机 | 模板、年月日、检查项状态、整改情况 |

本方案新建的 **「部门值班日志」** 与上述两者不同：

- 面向 **机房/基站技术值守** 场景，需记录市电电压、UPS电压、天气等环境技术参数；
- 以 **自由文本值班记录** 为主，无检查项模板、无提交复核状态机（YAGNI）；
- 与 `duty`（行政值班事项聚合）字段语义差异大，**不应合并到同一张表**，否则会污染 `duty` 现有的导入聚合逻辑与 PDF 模板。

**结论**：新建独立 app `duty_log`，与 `duty`、`checksheet` 三者并存。

## 三、数据模型设计

### 3.1 字段总览

#### A. 用户指定的人工输入字段（7 个）

| 字段名 | 中文名 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `duty_date` | 日期 | `CharField(max_length=20)` | 是 | 存 `YYYY-MM-DD`，前端 `DatePicker`（沿用 `duty` 惯例用字符串存日期） |
| `duty_person` | 值班员 | `CharField(max_length=100)` | 是 | |
| `duty_record` | 值班记录 | `TextField(null=True, blank=True)` | 否 | 主要文字内容 |
| `remark` | 备注 | `TextField(null=True, blank=True)` | 否 | |
| `mains_voltage` | 市电电压 | `CharField(max_length=50)` | 否 | 用字符串而非数值，允许灵活输入「220V」「正常」「停电」等 |
| `ups_voltage` | UPS电压 | `CharField(max_length=50)` | 否 | 同上 |
| `weather` | 天气情况 | `CharField(max_length=50)` | 否 | 如「晴」「小雨转阴」 |

#### B. 系统补充字段（必须，非用户输入）

| 字段名 | 中文名 | 类型 | 说明 |
|---|---|---|---|
| `id` | 主键 | `AutoField`（自动） | |
| `tenant_id` | 租户标识 | `CharField(max_length=50, default='')` | **租户隔离必须**，`make_tenant_id()` |
| `created_at` | 创建时间 | `CharField(max_length=20, default=human_datetime)` | 审计追溯 |
| `created_by` | 创建人 | `ForeignKey(User, PROTECT)` | 审计追溯 |
| `updated_at` | 更新时间 | `CharField(max_length=20, null=True)` | 审计追溯 |
| `updated_by` | 更新人 | `ForeignKey(User, PROTECT, null=True)` | 审计追溯 |

> 补充理由：租户隔离是项目硬规范（`TenantModelMixin`）；`created_at/by`、`updated_at/by` 用于操作审计与追溯，与 `duty`、`runlog` 等现有模块一致。

#### C. 建议补充字段（待你确认）

| 字段名 | 中文名 | 类型 | 建议 | 说明 |
|---|---|---|---|---|
| `department` | 部门 | `CharField(max_length=100, null=True, blank=True)` | **建议加** | 模块名为「部门值班日志」，部门是核心维度。若系统多部门共用一表，需靠此字段区分与过滤；若确认仅单部门使用可不加。 |

#### D. 关于电压字段类型的选择说明

市电/UPS电压选用 `CharField` 而非 `DecimalField`，理由：
- 值班员实际填写可能是「220V」「218」「市电正常」「停电检修」等混合文本；
- 本模块以**记录**为主，首版不做电压趋势统计；
- 符合 `duty` 模块「能字符串就字符串」的惯例。

> 若未来需要电压异常分析/趋势图，可另起一个数值化字段或迁移为 `DecimalField`，首版不预设。

### 3.2 Model 代码骨架

`apps/duty_log/models.py`：

```python
# Copyright: (c) OpenSpug Organization. https://github.com/openspug/spug
# Copyright: (c) <spug.dev@gmail.com>
# Released under the AGPL-3.0 License.
from django.db import models
from libs import human_datetime
from libs.tenant_base_model import TenantModelMixin, TenantModelManager, make_tenant_id
from apps.account.models import User


class DutyLog(models.Model, TenantModelMixin):
    """部门值班日志"""
    objects = TenantModelManager()
    tenant_id = make_tenant_id()

    # ---- 用户输入字段 ----
    duty_date = models.CharField(max_length=20, help_text='值班日期')
    duty_person = models.CharField(max_length=100, help_text='值班员')
    duty_record = models.TextField(null=True, blank=True, help_text='值班记录')
    remark = models.TextField(null=True, blank=True, help_text='备注')
    mains_voltage = models.CharField(max_length=50, null=True, blank=True, help_text='市电电压')
    ups_voltage = models.CharField(max_length=50, null=True, blank=True, help_text='UPS电压')
    weather = models.CharField(max_length=50, null=True, blank=True, help_text='天气情况')

    # ---- 建议补充字段（待确认，确认后保留或删除）----
    department = models.CharField(max_length=100, null=True, blank=True, help_text='部门')

    # ---- 审计字段 ----
    created_at = models.CharField(max_length=20, default=human_datetime)
    created_by = models.ForeignKey(User, models.PROTECT, related_name='+')
    updated_at = models.CharField(max_length=20, null=True)
    updated_by = models.ForeignKey(User, models.PROTECT, related_name='+', null=True)

    def __repr__(self):
        return '<DutyLog %r %r>' % (self.duty_date, self.duty_person)

    def to_view(self):
        return self.to_dict()

    class Meta:
        db_table = 'tdyw_duty_log'
        verbose_name = '部门值班日志'
        verbose_name_plural = '部门值班日志'
        ordering = ('-duty_date', '-id',)
        indexes = [
            models.Index(fields=['tenant_id', 'duty_date'], name='dl_tenant_date_idx'),
        ]
```

> 索引说明：`(tenant_id, duty_date)` 复合索引服务于「按租户 + 日期范围」的列表查询，是该模块最高频查询路径。遵循项目规范——复合索引用 `Meta.indexes`，单列索引才用 `db_index`，避免重复索引。

### 4.2 View 设计

接口风格完全对齐 `apps/duty/views.py`（`@auth` 装饰器、`JsonParser` 参数校验、`apply_tenant_filter`/`assign_tenant_id` 租户隔离、`tenant_operation_check` 跨租户防护、`record_audit_event` 审计）。

| 方法 | 路径 | 权限 | 功能 |
|---|---|---|---|
| GET | `/api/duty-log/duty/` | `duty_log.duty_log.view` | 列表查询，附带返回去重的值班员/部门下拉项（参考 `duty`） |
| POST | `/api/duty-log/duty/` | `duty_log.duty_log.add\|edit\|del` | 统一接口：无 id=新建，有 id=编辑，`action=delete`=删除 |
| DELETE | `/api/duty-log/duty/` | `duty_log.duty_log.del` | 删除（备用，POST 已覆盖） |

`apps/duty_log/views.py` 骨架：

```python
from django.views.generic import View
from libs import json_response, JsonParser, Argument, human_datetime, auth
from libs.tenant_utils import apply_tenant_filter, assign_tenant_id
from apps.logs.audit import record_audit_event
from apps.duty_log.models import DutyLog


def tenant_operation_check(request, model, record_id, operation='操作'):
    queryset = apply_tenant_filter(model.objects.filter(pk=record_id), request.user)
    if not queryset.exists():
        return None, json_response(error='记录不存在或无权操作')
    return queryset, None


class DutyLogView(View):
    @auth('duty_log.duty_log.view')
    def get(self, request):
        records = apply_tenant_filter(DutyLog.objects.all(), request.user)
        duty_persons = [x['duty_person'] for x in records.order_by('duty_person').values('duty_person').distinct() if x['duty_person']]
        departments = [x['department'] for x in records.order_by('department').values('department').distinct() if x['department']]
        return json_response({
            'duty_persons': duty_persons,
            'departments': departments,
            'records': [x.to_view() for x in records],
        })

    @auth('duty_log.duty_log.add|duty_log.duty_log.edit|duty_log.duty_log.del')
    def post(self, request):
        import json
        try:
            req_data = json.loads(request.body)
        except Exception:
            req_data = {}

        # 删除分支
        if req_data.get('action') == 'delete':
            if not request.user.has_perms({'duty_log.duty_log.del'}):
                return json_response(error='权限拒绝：缺少删除部门值班日志权限')
            form, error = JsonParser(Argument('id', type=int, help='请提供记录ID')).parse(request.body)
            if error is None:
                queryset, error_resp = tenant_operation_check(request, DutyLog, form.id, '删除')
                if error_resp:
                    return error_resp
                queryset.delete()
            return json_response(error=error)

        # 新建/编辑分支
        form, error = JsonParser(
            Argument('id', type=int, required=False),
            Argument('duty_date', help='请选择值班日期'),
            Argument('duty_person', help='请输入值班员'),
            Argument('duty_record', required=False),
            Argument('remark', required=False),
            Argument('mains_voltage', required=False),
            Argument('ups_voltage', required=False),
            Argument('weather', required=False),
            Argument('department', required=False),
        ).parse(request.body)
        if error is None:
            if form.id:
                if not request.user.has_perms({'duty_log.duty_log.edit'}):
                    return json_response(error='权限拒绝：缺少编辑部门值班日志权限')
                queryset = apply_tenant_filter(DutyLog.objects.filter(pk=form.id), request.user)
                if not queryset.exists():
                    return json_response(error='记录不存在或无权操作')
                form.updated_by_id = request.user.id
                form.updated_at = human_datetime()
                queryset.update(
                    duty_date=form.duty_date, duty_person=form.duty_person,
                    duty_record=form.duty_record, remark=form.remark,
                    mains_voltage=form.mains_voltage, ups_voltage=form.ups_voltage,
                    weather=form.weather, department=form.department,
                    updated_at=form.updated_at, updated_by_id=form.updated_by_id,
                )
            else:
                if not request.user.has_perms({'duty_log.duty_log.add'}):
                    return json_response(error='权限拒绝：缺少新增部门值班日志权限')
                form.created_by = request.user
                assign_tenant_id(form, request.user)
                DutyLog.objects.create(**form)
        return json_response(error=error)

    @auth('duty_log.duty_log.del')
    def delete(self, request):
        form, error = JsonParser(Argument('id', type=int, help='请提供记录ID')).parse(request.GET)
        if error is None:
            queryset, error_resp = tenant_operation_check(request, DutyLog, form.id, '删除')
            if error_resp:
                return error_resp
            queryset.delete()
        return json_response(error=error)
```

> `tenant_operation_check` 在 `duty`/`fault` 等多模块重复出现，后续可抽到 `libs` 公共化，本方案不并入以保持「渐进式、不触碰其他模块」。

## 九、首版不做（YAGNI，待后续反馈再议）

以下功能用户未要求，首版不实现，避免过度设计：

1. **导出（PDF/Excel）** —— `duty` 已有 PDF 导出可参考，待需要时再加；Excel 可用公共 `ExportButton`。
2. **从其他模块引入**（运行日志/干扰记录）—— 这是 `duty` 的特色，本模块场景不同。
3. **提交/复核状态机** —— `checksheet` 已有，本模块是自由记录，不需要。
4. **唯一约束**（如 `(tenant_id, department, duty_date, duty_person)`）—— 值班日志可能一天多条（多班次），首版不加；如需防重，按迁移纪律拆步加。
5. **班次字段（早/中/夜）** —— 若一天多人多班记录再考虑。
6. **电压数值化与异常告警** —— 记录为主，统计需求出现后再做。
7. **软删除** —— 对齐 `duty`，直接物理删除（已有 `Modal.confirm` 二次确认）。

## 十、待你确认的决策点

1. **是否加 `department`（部门）字段？** 建议加（模块名含「部门」，多部门共用时需区分）。若确认单部门使用可去掉。
2. **电压字段用字符串还是数值？** 方案默认字符串（灵活），如需后续统计分析可改数值型。
3. **菜单放置位置？** 建议紧邻现有「值班日志」菜单项。

确认以上三点后即可进入实施。
