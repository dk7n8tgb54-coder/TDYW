## 2. 🔴 高优先级（P1，建议优先处理）

### H1. 回收站统计 N+1 + 内存加载（最严重）

- **位置**：`spug_api/apps/document/views/recycle_bin/stats.py:194-219`
- **问题**：
  ```python
  # stats.py:194-208
  def _calculate_folder_contents(self, folder, FolderModel, FileModel):
      total_files = 0
      total_size = 0
      folder_ids = self._get_folder_and_descendants(folder, FolderModel)  # 递归
      for folder_id in folder_ids:                                        # N+1
          files = FileModel.all_objects.filter(folder_id=folder_id, is_deleted=True)
          total_files += files.count()
      return total_files, total_size
  ```
  - 双重循环：`for folder in folder_queryset` × `for folder_id in folder_ids`
  - `_get_folder_and_descendants` 用**递归**而非迭代替代
- **影响**：删除 10 万文件的文件夹，统计一次触发 N+1+(递归深度)×2 次查询 + ORM 对象全量加载
- **修复**：
  ```python
  # 一次聚合查询搞定
  stats = FileModel.all_objects.filter(
      folder_id__in=all_descendant_ids, is_deleted=True
  ).aggregate(total_files=Count('id'), total_size=Sum('file_size'))
  ```
  顺手把两个重复的 `get_folder_and_descendants`（`permission_utils.py:102` 和这里）合并
- **优先级**：P1

### H2. 回收站列表 OOM + 缓存击穿

- **位置**：`spug_api/apps/document/views/recycle_bin/list.py:125-141`
- **问题**：

### H3. 批量删除文件夹 - 失败静默 + 数据不一致

- **位置**：`spug_api/apps/document/views/recycle_bin/folder_delete.py:64-99`
- **问题**：
  1. 异步路径提交 Celery 后**立即返回** `{async: True, task_id: ...}`，前端 `onClose` 用户不知道成功失败
  2. 同步路径 `with transaction.atomic()` 遇 `Exception` 整个回滚 — **已删的物理文件无法回滚**
- **影响**：用户以为成功实际失败；DB 记录与物理文件不一致（脏数据）
- **修复**：
  1. 同步路径用 `SAVEPOINT` 包裹每个文件夹
  2. 异步任务完成后**主动推前端通知**（WebSocket 或轮询 `task_status`）
  3. `DeleteProgressModal` 已有，加"任务失败"展示
- **优先级**：P1

### 10.2 核心设计原则（来自本项目历史教训）

1. **3 Tab 优于 4+ 分组** — 阿里云盘/百度网盘设计
2. **cancelled 应归入"失败"** — 取消也是任务终结状态
3. **paused 应归入"上传中"** — 暂停只是上传中的一种临时态
4. **MD5 是内部技术细节** — 不该向用户暴露（"准备上传"+ tooltip）
5. **合并中必须显示** — 合并耗时长（最长 5 分钟）
6. **错误分类决定 UX** — 按钮可见性由"重试能否解决"决定
7. **增量改进 > 大爆炸式重写** — 5 轮迭代独立可回滚
8. **配置化（枚举+集合）> 散落的硬编码** — 状态集合抽常量
