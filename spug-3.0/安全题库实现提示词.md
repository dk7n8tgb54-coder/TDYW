## 角色与任务

你是一名资深全栈工程师，需要在一个已有的 Django + React（MobX + Ant Design 4）项目中，从零实现一个"安全题库"业务模块。完整的设计方案已附在 `安全题库模块设计方案.md` 中，**请按照该方案实现，但下方"重要架构变更"优先级高于方案原文，与之冲突时以下方为准**。

模块涵盖：题库分类、试题管理（含图片附件）、每日一练、在线考试（含防切屏/超时自动交卷）、成绩统计与 Excel 导入导出。

## 重要架构变更：用 tenant_id 代替 department（优先级高于方案原文）

**业务背景**：本项目一个租户（`tenant_id`）就等于一个科室。因此方案中所有"部门"概念直接用 `tenant_id` 实现，**不建 `Department` 表，不在 `User` 上加 `department_id`/`department_name` 字段**。

具体调整（方案原文中出现的字段按下表替换）：

| 方案原文字段 | 实际实现 | 说明 |
|---|---|---|
| `Department` 模型（方案 5.1） | **删除，不建** | 租户即科室 |
| `User.department_id` / `User.department_name` | **不加** | 用 `User.tenant_id` |
| `SafetyQuestionCategory.owner_department_id` / `owner_department_name` | **删除** | 分类靠自身 `tenant_id` 隔离，科室管理员只能维护本 `tenant_id` 下的分类 |
| `SafetyQuestion.source_department_id` / `source_department_name` | **删除** | 靠自身 `tenant_id` 隔离 |
| `SafetyPracticeSession.department_id` / `department_name` | **删除** | 已有 `tenant_id` |
| `SafetyPracticeStat.department_id` / `department_name` | **删除** | 已有 `tenant_id` |
| `SafetyExamAttempt.department_id` / `department_name` | **删除** | 已有 `tenant_id` |
| `SafetyExamTarget.department_id` / `department_name` | 改为 `target_tenant_id`（`CharField`，与 `tenant_id` 同类型） | 考试授权"部门开放"= 指定哪些科室（`tenant_id`）可参加 |

**全平台视图如何实现**：项目的 `apply_tenant_filter(qs, user)` 对超级管理员（`is_supper`）和全局管理员（`is_global_admin`）在非严格模式下**不过滤**，自动可看所有科室数据。普通用户按 `tenant_id` 过滤，只看本科室。

- "部门内排名" = 同 `tenant_id` 内排名（普通用户默认视图）
- "全平台排名" = 超管/全局管理员跨 `tenant_id` 排名（`apply_tenant_filter` 自动放行）
- "成绩按部门统计" = 按 `tenant_id` 分组
- "考试授权部门开放" = `SafetyExamTarget.target_tenant_id` 列表

**考试授权表调整后的 `open_type` 用法**：

| `open_type` | `SafetyExamTarget` 用法 |
|---|---|
| `public` | 不写授权明细，当前所有启用用户可参加（不限 `tenant_id`） |
| `department` | 写入 `target_tenant_id`（一个科室一条记录），该科室下所有启用用户可参加 |
| `department_user` | 写入 `target_tenant_id` + `user_id`，只有选中的用户可参加 |

## 项目技术栈与必须遵守的规范

### 1. 后端

- **框架**：Django（Python），业务模块位于 `spug_api/apps/`，每个模块一个目录，含 `models.py` / `views.py` / `urls.py` / `tasks.py`（如需）。
- **根路由**：`spug_api/spug/urls.py`，用 `path('safety-question-bank/', include('apps.safety_question_bank.urls'))` 挂载。
- **租户隔离**：所有业务模型必须混入 `TenantModelMixin` + `TenantModelManager` + `make_tenant_id()`，来自 `spug_api/libs/tenant_base_model.py`。查询用 `apply_tenant_filter(qs, request.user)`，写入用 `assign_tenant_id(form, request.user)`，来自 `spug_api/libs/tenant_utils.py`。
- **权限装饰器**：`from libs import auth`，用法 `@auth('safety_question_bank.question.view')`，多权限用 `|` 分隔（如 `'safety_question_bank.question.add|safety_question_bank.question.edit'`）。超级管理员（`is_supper`）自动放行，无需配置。
- **请求解析**：`from libs import JsonParser, Argument`，用 `JsonParser(Argument('field', type=int, help='...'), ...)` 解析请求体。
- **响应**：`from libs import json_response`。
- **视图风格**：`django.views.generic.View` 子类，方法上挂 `@auth(...)`，参考 `spug_api/apps/radio_license/views.py`。
- **URL 风格**：`re_path`，参考 `spug_api/apps/radio_license/urls.py`。
- **时间字段**：用 `human_datetime`（`from libs import human_datetime`），`created_at = models.CharField(max_length=20, default=human_datetime)`，**不要用 DateTimeField 存创建时间**（项目惯例）。考试时间范围字段（`start_time`/`end_time`/`started_at`/`deadline_at`/`submitted_at`）按方案用 `DateTimeField`。
- **审计**：`from apps.logs.audit import record_audit_event`，签名 `record_audit_event(request, action, target_type, target_id=None, target_name=None, detail=None, is_success=True, error=None)`。同时在 `spug_api/apps/logs/audit.py` 的 `TARGET_MAP` 中新增 `'/safety-question-bank/': {'type': 'safety_question_bank', 'name': '安全题库'}`。
- **附件复用**：试题图片复用 `apps/evidence/attachment_service.py` 的 `AttachmentService` + `AttachmentConfig`，`module='safety_question_bank'`, `object_type='question'`, `object_id=question.id`。参考 `apps/radio_license/views.py` 的附件上传/预览/下载/删除写法。
- **Celery 定时任务**：超时自动交卷任务挂到 `spug_api/spug/celery.py` 的 `celery_beat_schedule`，参考现有 schedule 写法（项目用字典配置 beat）。任务函数放 `apps/safety_question_bank/tasks.py`。

### 2. 数据库迁移纪律（非常重要）

```bash
# 生成（必须指定 app + 手动命名，禁止 0002_auto_xxx）
docker exec tdyw-test python /data/spug/spug_api/manage.py makemigrations safety_question_bank --name <语义化名>
# 执行
docker exec tdyw-test python /data/spug/spug_api/manage.py migrate safety_question_bank
```

- 一个阶段尽量只产生一个 migration。
- migration 文件手动 `--name` 语义化命名。
- **不要**用 `makemigrations` 不带 app 名，会扫描全部 app 污染迁移历史。
- 加唯一约束必须拆步：先加非唯一字段 → 回填 → 检查重复 → 再 AlterField 加 unique。
- CharField→Date/DateTimeField 迁移必须先清洗空串。
- `Meta.indexes` 的 Index name 必须与手写 migration 一致，否则会生成 rename index 迁移。

### 3. 前端

- **框架**：React + MobX（`@observable`/`@action`，legacy decorators + class properties）+ **antd 4.21.5**（Modal 用 `visible` 不是 `open`）。
- **路由**：`spug_web/src/routes.js`，按方案 11.1 节新增菜单组，`auth` 字段用 `|` 分隔多个权限码。
- **页面目录**：`spug_web/src/pages/safetyQuestionBank/`，按方案 2.6 节的文件清单创建。
- **页面范式**：参考 `spug_web/src/pages/radioLicense/`（`index.js` + `store.js` + `Table.js` + `Form.js`）。
- **权限码**：在 `spug_web/src/pages/system/role/codes.js` 新增 `safety_question_bank` 权限组（按方案 3.2 节）。**不要**写 SQL 预置权限，超级管理员自动放行。
- **导出**：复用 `spug_web/src/components/ExportButton.js` + `spug_web/src/libs/exportFile.js`，后端用 `libs/export_utils.py`。
- **HTTP**：项目用 `axios` 封装，参考现有页面的 `http.get/post` 调用方式。

### 4. 容器与验证

- 容器名 `tdyw-test`，项目路径 `/data/spug/spug_api`，Python 3.10。
- PowerShell 调用示例：`wsl bash -c 'docker exec -e PYTHONIOENCODING=utf-8 -w /data/spug/spug_api tdyw-test python manage.py check'`（单引号避免内层双引号 EOF）。
- Python 语法检查：`docker exec tdyw-test python -m py_compile <path>`。
- JS 语法检查（ES Module + 装饰器）：用 `@babel/parser`，plugins 加 `['classProperties','decorators-legacy','dynamicImport']`。
- 数据库：MariaDB 10.8.2，不支持部分唯一索引 WHERE 条件。

## 实施范围与分阶段任务

按方案的"15. 实施计划"分四个阶段，**每个阶段独立可验收、可回滚**。每完成一个阶段向我汇报，等待确认后再进入下一阶段。

### 阶段一：基础题库（分类 + 试题 + 选项）

1. **题库分类**（方案 5.2，去掉 `owner_department_id`/`owner_department_name`）：`SafetyQuestionCategory`（`tdyw_safety_question_category`），`scope` 取值 `exam`/`daily`/`both`。分类靠自身 `tenant_id` 隔离。
2. **试题**（方案 5.3，去掉 `source_department_id`/`source_department_name`）：`SafetyQuestion`（`tdyw_safety_question`），含 `QUESTION_TYPE_CHOICES`、`QUESTION_STATUS_CHOICES`、软删除字段。
3. **试题选项**（方案 5.4）：`SafetyQuestionOption`（`tdyw_safety_question_option`）。
4. **后端接口**（方案 7.1、7.2）：分类 CRUD、试题 CRUD + 详情、试题图片附件（复用 AttachmentService，写薄视图）。
5. **前端页面**：`CategoryManager.js`（分类树/列表）、`QuestionManager.js`（列表+筛选+分页）、`QuestionForm.js`（新增/编辑表单，含题型校验）。
6. **权限码**：在 `codes.js` 加 `safety_question_bank` 组的 `category` 和 `question` 两个 page（方案 3.2）。
7. **审计**：`TARGET_MAP` 加映射；分类/试题增删改、图片上传删除、导入导出调用 `record_audit_event`。
8. **迁移**：`makemigrations safety_question_bank --name initial_models`。

验收：分类/试题可 CRUD，图片可上传预览，租户隔离生效（不同科室互不可见），权限码在角色管理可见。

### 阶段二：每日一练

1. **模型**（方案 5.5-5.7，去掉所有 `department_id`/`department_name` 字段，靠 `tenant_id` 隔离）：`SafetyPracticeSession`、`SafetyPracticeAnswer`、`SafetyPracticeStat`。
2. **接口**（方案 7.3）：`practice/start`（抽 10 题，题量不足返回明确错误）、`practice/current`、`practice/answer`（提交单题，返回答案+解析，单题锁定不可改）、`practice/complete`、`practice/stats`、`practice/rank`（`scope=department|platform`，department=同 `tenant_id` 内排名，platform=超管/全局管理员跨 `tenant_id` 排名）。
3. **前端**：`DailyPractice.js`（顶部统计 + 答题区 + 答题卡）、`PracticeRank.js`（排名）。
4. **权限码**：加 `practice` page（`view`、`rank`）。
5. **计分**：答对 +1，答错 0；多选完全一致才算对。`SafetyPracticeStat` 汇总 total_score/practice_times/answered_count/correct_count。

验收：用户可参加每日一练，提交后即时看到解析，积分和排名正确。

### 阶段三：考试管理（含防切屏/超时）

1. **模型**（方案 5.8-5.12，去掉所有 `department_id`/`department_name` 字段；`SafetyExamTarget` 的 `department_id`/`department_name` 改为 `target_tenant_id`）：`SafetyExam`、`SafetyExamTarget`、`SafetyExamPaper`、`SafetyExamAttempt`、`SafetyExamAnswer`。
2. **考试管理接口**（方案 7.4）：考试 CRUD、`publish`（发布前校验题量/时间/范围/分值）、`targets`（授权对象）、`preview-paper`。
3. **用户考试接口**（方案 7.5）：`my-exams`、`exams/<id>/start`（生成试卷快照 + attempt，`deadline_at = min(started + duration, exam.end_time)`）、`attempts/<id>/`、`attempts/<id>/answer`、`attempts/<id>/switch-screen`、`attempts/<id>/submit`、`attempts/<id>/result`。
4. **防切屏**（方案 9）：前端 `ExamRoom.js` 监听 `visibilitychange`/`blur`/`fullscreenchange`/`beforeunload`，上报 `switch-screen`；后端 `switch_count += 1`，超过 `max_switch_count` 自动交卷（`status=auto_submitted_switch`）。
5. **超时**（方案 9.3）：每次关键操作调 `ensure_attempt_not_timeout`；Celery beat 任务 `auto_submit_timeout_attempts` 每 1 分钟兜底扫描（`status=auto_submitted_timeout`）。
6. **前端**：`ExamManager.js`（列表+表单）、`ExamForm.js`（组卷配置+权限范围）、`ExamCenter.js`（我的考试）、`ExamRoom.js`（考试页，倒计时+答题卡+切屏计数，**不显示答案解析**）。
7. **权限码**：加 `exam` page（`view`/`add`/`edit`/`del`/`publish`/`answer`）。

验收：可配置发布考试，用户开始考试生成固定试卷，切屏 4 次自动交卷，超时自动交卷，交卷后可查成绩和错题。

### 阶段四：成绩统计与 Excel 导入导出

1. **成绩接口**（方案 7.6）：`scores`（列表）、`statistics`（参考人数/及格率/平均分/缺考）、`scores/export`、`wrong-questions`。
2. **Excel 导入**（方案 10.1、10.2）：`questions/import/`，按模板字段导入，全量校验返回行级错误，事务写入。
3. **Excel 导出**（方案 10.3）：`questions/export/`（按筛选条件）+ `scores/export/`。后端用 `libs/export_utils.py`，文件名 RFC 5987 中文编码。
4. **前端**：`ScoreManager.js`（成绩列表+统计+导出）、试题管理页加导入/导出按钮。
5. **权限码**：加 `score` page（`view`/`export`）。
6. **审计**：导入/导出动作写审计。

验收：可导入试题（返回错误明细），可导出试题和成绩 Excel，成绩统计口径正确。

## 关键实现约束（不可违反）

1. **答案保护**：每日一练提交单题前不返回 `correct_answer`/`analysis`；考试交卷前不返回答案解析。后端响应裁剪字段，不能只靠前端隐藏。
2. **题目快照**：`SafetyPracticeAnswer.question_snapshot` 和 `SafetyExamAnswer.question_snapshot` 必须保存题目+选项+解析快照，题库后续修改不影响历史记录。
3. **并发控制**：单题答题用唯一约束（`tenant_id + session_id + question_id` / `tenant_id + attempt_id + question_id`）防重复计分；交卷用事务 + 行锁防重复交卷。
4. **租户隔离**：所有查询 `apply_tenant_filter`，主键操作必须验证 `tenant_id`。
5. **删除策略**：已被练习/考试引用的试题只允许软删除或停用；分类下有启用试题不允许物理删除。
6. **题型校验**：单选仅 1 个正确选项，多选至少 2 个，判断题固定 2 个选项（A.正确/B.错误）。
7. **考试发布校验**：题量满足配置、时间范围合法、开放对象（`target_tenant_id`/`user_id`）存在且属于当前租户范围、及格分不超过总分。
8. **`allow_retake=False`** 时业务层保证 `tenant_id + user_id + exam_id` 唯一。
9. **前端防切屏不声明绝对防作弊**，后端以计数+审计+自动交卷形成管理闭环。
10. **不要过度设计**：方案没写的功能（如多选漏选半分、消息通知、短信邮件）首期不做，YAGNI。

## 开始方式

1. 先阅读 `安全题库模块设计方案.md` 全文 + 上方"参考文件清单"中 radio_license 模块的实现。
2. 从**阶段一**开始，先给出本阶段要创建/修改的文件清单和 migration 计划，确认后开始编码。
3. 每个阶段完成后：① 跑 `manage.py check`；② `makemigrations --check --dry-run` 确认无遗漏；③ 汇报变更文件列表和验收点，等我确认再进入下一阶段。
