# 传输状态转换逻辑检查与修复报告

## 问题结论

你在浏览器看到的：

- 无效的状态转换：`PENDING -> PAUSED`
- 无效的状态转换：`UPLOADING -> PENDING`
- 无效的状态转换：`PAUSED -> PENDING`

是**后端接口返回的错误信息**，并非纯前端日志。  
错误来源是后端 `TransferStatusUpdateView` 在校验状态机规则时返回 `json_response(error=...)`。

## 根因分析

### 1) `UPLOADING/PAUSED -> PENDING` 的根因（前端）

前端在 `UploadCoreStore.syncStateToBackend()` 中将前端 `waiting` 同步成后端 `PENDING`。  
但 `waiting` 在当前架构里是前端调度态（例如暂停恢复过程中的中间态），把它回写到后端会形成状态回退：

- `UPLOADING -> PENDING`（非法）
- `PAUSED -> PENDING`（非法）

后端状态机不允许这两种回退，因此报错。

### 2) `PENDING -> PAUSED` 的根因（前后端规则不一致）

前端状态机允许 `waiting -> paused`（即用户可在等待中直接暂停），对应后端是 `PENDING -> PAUSED`。  
但后端 `ALLOWED_STATUS_TRANSITIONS` 之前不允许这条边，导致单任务暂停时可能触发非法转换。

## 已实施修复

### 前端修复（避免回写 `PENDING`）

文件：`spug_web/src/pages/document/stores/upload/core/index.js`

- 在 `syncStateToBackend()` 中增加提前返回：`toState === 'waiting'` 时不再同步到后端
- 同时移除状态映射中的 `'waiting': 'PENDING'`

效果：不再触发 `UPLOADING/PAUSED -> PENDING` 的非法回退请求。

### 后端修复（补齐合法转换）

文件：`spug_api/apps/document/constants.py`

- 将 `PENDING` 允许目标补充为 `PAUSED`
- 规则从：
  - `PENDING -> [UPLOADING, CANCELED]`
- 调整为：
  - `PENDING -> [UPLOADING, PAUSED, CANCELED]`

效果：与前端“等待中可暂停”的交互语义对齐，不再因 `PENDING -> PAUSED` 报错。

## 影响评估

- 正向影响
  - 消除你当前看到的三类“无效状态转换”告警
  - 前后端状态机语义更一致，减少恢复/暂停竞态导致的噪音
- 风险点
  - 需要确保业务上允许“尚未开始上传的任务”进入暂停态（当前前端行为已体现允许）

## 建议验证步骤

1. 新建上传任务，不点击开始即执行暂停（或刚入队立刻暂停）  
   预期：不再出现 `PENDING -> PAUSED` 非法转换。
2. 上传中执行暂停、恢复、再暂停  
   预期：不再出现 `UPLOADING -> PENDING` / `PAUSED -> PENDING`。
3. 查看后端日志与浏览器控制台  
   预期：不再出现“无效的状态转换”相关报错。
