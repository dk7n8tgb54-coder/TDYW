> **修订记录 v1.1（2026-10-23 评审修正，方向已采纳）**：① P2 即升级协议 v2（否决"保持 v1 + 静默丢弃"），结构校验未知键由静默丢弃改为 fail-closed 拒绝；② fixed_table 列模型定稿到字段级（readonly 不入填写值 JSON、`列id__desc` 仅限 normal_abnormal 列、只读/填写列允许混排），并改为**条件性 P3**（真实表单需求确认后触发）；③ publish-check 明确为无状态提示，发布永远原子复核；④ 权限响应以 `@auth` 真实契约为准（HTTP 200 + `error='权限拒绝'`，非 401）。

## 0. 结论速览

1. 现有三种结构（固定填写项目 fields / 可重复明细 repeat / 检查对比表 matrix）覆盖当前周月/季维护台账约 80% 场景；明确缺口是"固定行 + 异构列 + 可选模板预填列"的**固定检查表**（经典「检查项目｜标准要求｜检查结果｜备注」式表格）。
2. 固定检查表推荐**方案 A：新增第四种 kind=`fixed_table`**，列为**条件性 P3**——先用 2~3 份真实维护表确认"固定行+异构列+模板只读列"确属高频且现有三种结构无法无损表达，经用户拍板后实施（届时 bump `protocol_version=3`）；过渡期用 matrix"标准值行"近似（零改动）；否决"扩展 matrix"方案（改动面相当而无语义收益）。
3. 实施分四阶段：P1 编辑器高频动作（复制/撤销重做/自动定位，纯前端）→ P2 属性与校验增强（**升级协议 v2** + 结构校验未知键 fail-closed + 发布检查中心 + 试填预览）→ P3 固定检查表（**条件性**，协议 v3）→ P4 观察项（拖拽/批量）。
4. 铁律：发布版本快照不可变；复制一律生成新结构 id、撤销恢复原对象原 id；历史台账填写值语义永不漂移；Excel 路线零接触；四种 kind 封顶，不做任意表单编辑器。

### 1.4 已确认的主要缺口（方案针对性来源）

1. 无复制（字段/分组/矩阵行列全无）、无撤销重做（全目录 grep 零命中），误删只能重建且 id 变化；
2. 新增字段/矩阵行列后不自动选中（仅新分组自动选中），需手动点击才能编辑属性；
3. 预览不能试填（`PreviewModal` 硬编码 `values={{}}`、`editable=false`）；PDF 样张基于已保存草稿、无"保存并预览"一步路径；
4. 发布/保存校验错误是后端单条 error 字符串 → http 拦截器 toast，无错误列表、无点击定位；
5. number 无范围/小数位约束、date 是纯文本输入（非 DatePicker）、textarea 行数固定 2、"异常时说明必填"不存在（后端 `_normalize_desc` 亦不校验）；
6. 矩阵行"说明"是死配置（Inspector 可填，填写页与 PDF 均不渲染——PDF `_field_label_html` 其实渲染 description，网页未对齐）；
7. 模板编辑器 `dirty` 未接入工作页签保护（`useWorkTabUnsaved` 只挂台账页）；保存草稿无 dirty 短路；
8. number 切类型后 `unit` 残留提交；排序只有相邻步进；窄屏预览未传 `narrow` 仍渲染宽表格。

## 2. 三种内容结构：定义、场景、边界与入口（方面一）

### 2.1 定义与分野

| 结构 | kind | 定义 | 适用场景 | 边界（不适用） |
|---|---|---|---|---|
| 固定填写项目 | `fields` | 模板定义一组固定字段，每份台账逐项填写一次 | 基本信息、登记信息、逐项状态检查（机壳外观/指示灯…） | 字段多且需表格化对照时阅读性下降；无"多条"概念 |
| 可重复明细 | `repeat` | 模板定义**单条记录的字段模板**，填写人增删行，每行结构相同 | 测量项目（条数不定）、缺陷/异常事项记录 | 行由填写人增删 → 不适合行数固定的检查表 |
| 检查对比表 | `matrix` | 行=检查项目（模板固定）、列=对比对象（模板固定），逐格填写，**单元格类型=所在行的类型** | 多机运行对比、多设备同项检查 | 列是同质"对象"维度 → 不能表达"每列类型不同"的表 |

本质分野是两个正交问题：**行由谁定**（模板固定 vs 填写人增删）× **列是什么**（单一值维度 vs 多个对象维度）。

### 2.2 一份模板如何混合使用三种结构

- 模板 = 有序分组列表，每组独立选择三种之一，可任意组合、不限出现次数（受 30 组 / 500 字段总数上限约束）；同一组内不可混合（kind 决定组内子结构）。
- 填写页与 PDF 按分组顺序依次渲染（PDF 以一、二、三编号，分组角标区分明细组/矩阵）。
- 组织建议：基本信息(fields) → 逐项检查(fields) → 测量记录(repeat) → 多机对比(matrix)。内置 `sample_form` 即混合范例（4 组覆盖 3 种），P2/P3 扩能力时同步扩充示例。

### 2.3 入口名称、说明文案与新增默认结构

统一一套词汇（网页入口按钮、画布组角标、PDF 角标、属性面板标题共用，消除前端 `GROUP_KIND_TEXT` 与 PDF `_KIND_TAG` 的细微不一致）：

| kind | 入口按钮文案 | 一句话说明（引导/确认文案共用） | 新增后默认结构 |
|---|---|---|---|
| fields | **固定填写项**（现"填写项目"） | "一组固定字段，每份台账填写一次" | 组名「填写项目」+ 1 个空 text 字段 |
| repeat | **可重复明细** | "同一结构可填写多条记录，条数由填写人增减" | 组名「可重复明细」+ 条目名「明细条目」+ 1 个空字段 |
| matrix | **检查对比表** | "相同检查项目对多个对象横向逐格填写：行=检查项目，列=对象" | 维持现状：行「外观检查」(normal_abnormal)、列「A 机/B 机」 |
| fixed_table（条件性 P3） | **固定检查表** | "行列均由模板固定，可含模板预填列：适合「检查项目/标准/结果/备注」式表格" | 行 3 条、列「检查结果(normal_abnormal)」+「备注(text)」 |

新建模板画布：保留空画布，把空白引导从单句升级为**三（四）结构选择卡片**（每卡一句适用场景），不预置字段（避免误建后删除成本）。

### 2.4 表达能力评估：固定行 / 异构列 / 模板只读列 / 填写列

| 能力 | fields | repeat | matrix | 缺口结论 |
|---|---|---|---|---|
| 固定行（模板定死，填写人不可增删） | ✓（字段即行） | ✗ | ✓ | — |
| 异构列（每列独立类型/单位/选项） | ✗（只有 label+value 两列） | △（行内字段本质是异构列，但行数不固定） | ✗（列同质） | **明确缺口** |
| 模板只读列（模板预填值，填写页置灰、PDF 原样印刷） | ✗（说明可近似承载，但正常态备注无处放） | ✗ | ✗ | **明确缺口** |
| 填写列 | ✓ | ✓ | ✓ | — |

现有结构近似固定检查表的写法（过渡期指引）：

- fields 近似：每个检查项目一个 `normal_abnormal` 字段，"标准要求"放字段说明。最常用，但"正常情况也要填备注"无承载（`__desc` 只在异常时出现）；
- matrix 近似："标准/参考值"作为矩阵第一行（text/number 类型，置于最上）。可行但标准值行与检查行语义混在行维度，且 matrix 行不支持 textarea/长说明排版差；
- repeat 近似：不符合（行数应固定）。

**结论：三种结构覆盖约 80% 场景；固定检查表是明确缺口，过渡期用上述近似；是否以第四种结构补齐由条件性 P3 决定（先以真实表单确认需求，见第 3 节）。**

## 3. "固定检查表"三种实现方案比较

| 能力/维度 | 方案 A：新增 kind=`fixed_table` | 方案 B：扩展 matrix（列类型化 + 预填） | 方案 C：暂不支持（近似过渡） |
|---|---|---|---|
| 固定行 | ✓ | ✓（matrix 本就是固定行） | △ matrix 标准值行近似 |
| 异构列 | ✓（每列独立 type/unit/options/required） | △ 列可选类型，但"行类型 vs 列类型"的单元格归属规则解释成本高 | ✗ |
| 模板只读列 | ✓（列带 `readonly + template_value`） | △ 同左，但语义污染 matrix | △ 说明/首行近似 |
| 填写列 | ✓ | ✓ | ✓ |
| 协议影响 | bump `protocol_version=3`（新 kind；v2 已被 P2 属性扩展占用） | 不 bump 但矩阵语义分裂 | 无 |
| 实现面 | 校验/填写值校验/终验/前端渲染器/编辑器/PDF 各加一类分支；填写值结构 `{行id:{列id:值}}` 与 matrix 完全同构，`_normalize_matrix` 可参数化复用 | 编辑器与填写页双类型判定分支，PDF/终验同样要改，收益却不比 A 多 | 零 |
| 长期语义 | 四种结构正交、命名清晰、能力封顶 | "矩阵"从此承载两种含义，文档/培训成本永久存在 | 缺口长期存在 |

**推荐：A 为目标方案（条件性 P3：先以 2~3 份真实维护表确认"固定行+异构列+模板只读列"是高频需求且三种结构无法无损表达，经拍板后再实施），C 作为 P1/P2 期间的过渡写法写进使用指引，B 否决。**理由：

1. 数据结构上 fixed_table 填写值与 matrix 同构（按行id→列id），只是**单元格类型来源从"行"换成"列"**；`__desc` 键、未知键拒绝、必填终验框架全部复用；
2. 组键 `form:<id>` 与周期生成 `template_kinds` 分桶不感知组内 kind——跨路线集成零改动（1.3 已核对）；
3. 版本不可变 + 快照内自带 `protocol_version`，v1 历史版本按 v1 语义回放，不漂移（见第 7 节）；
4. "不做成任意 Excel 编辑器"不破：四种 kind 封顶，fixed_table 不提供合并单元格、公式、自由列宽，规模上限沿用（行 ≤50、列 ≤20）。

### 3.1 fixed_table 列模型与协议草案（v3，条件性触发后定稿）

**列模型（定稿到字段级，避免 P3 启动后反复改协议）：**

| 列属性 | 类型/取值 | 约束 |
|---|---|---|
| `id` | `c_` 前缀，沿用结构 id 规则 | 全表唯一，禁 `__` |
| `name` | ≤30 字 | 必填 |
| `type` | `text / number / choice / normal_abnormal`（与矩阵行同口径；textarea/date 不开放——横排单元格空间有限） | 必填 |
| `unit` | ≤20 字 | 仅 number 列 |
| `options` | 1~50 项、去重 | 仅 choice 列 |
| `description` | ≤200 字，列头提示 | 选填 |
| `required` | 布尔，默认 false | **readonly 列必须为 false**（互斥校验） |
| `readonly` | 布尔，默认 false | true 时 `template_value` 必填 |
| `template_value` | ≤200 字 | 仅 readonly 列允许携带；非只读列出现即拒绝 |

**关键语义：**

- **行** = `fields`（仅 `id/name/description`，无类型——单元格类型由**列**定义；行 ≤50、列 ≤20，沿用既有上限）；
- **只读列不入填写值 JSON**：填写值中禁止出现只读列的任何键（含 `<列id>__desc`），后端显式拒绝（fail-closed）；展示值永远取版本快照的 `template_value`（模板内容、非台账数据），样张与台账一致，不计入填写单元与进度口径；
- **单元格异常说明**：与矩阵完全同构——`{行id: {列id: 值, 列id__desc: 说明}}`；`列id__desc` **仅允许出现在 type=normal_abnormal 的列**（非该类型列出现 desc 键即拒绝；矩阵的 desc 键同步收紧，见 §7.1）；
- **只读列与填写列允许混排**：`columns` 数组顺序即渲染顺序（「检查项目｜标准要求｜检查结果｜备注」中标准要求可居中）；只读列在填写页置灰并带"模板预填"标识，编辑器列操作（增删移复制）对只读列同等适用；
- **必填终验**：列级 required → 每行该列单元格必填（缺失标签"组名 第N行 / 列名"）；
- **填写值示例**：`{"g_checktb01": {"r_item0001": {"c_result01": "normal", "c_result01__desc": "…", "c_remark01": "…"}}}`；

```json
{
  "protocol_version": 3,
  "groups": [
    {
      "id": "g_checktb01",
      "name": "季度检查表",
      "kind": "fixed_table",
      "columns": [
        {"id": "c_std00001", "name": "标准要求", "type": "text",
         "readonly": true, "template_value": "表面无锈蚀、无变形"},
        {"id": "c_result01", "name": "检查结果", "type": "normal_abnormal", "required": true},
        {"id": "c_remark01", "name": "备注", "type": "text"}
      ],
      "fields": [
        {"id": "r_item0001", "name": "机壳外观", "description": ""},
        {"id": "r_item0002", "name": "指示灯状态", "description": ""}
      ]
    }
  ]
}
```

- **PDF**：表格渲染，列=表头；只读列样张与台账同样印刷 `template_value`（模板内容非填写值）；空填写格=待填写/未填写；fixed_table 列数 ≥6 纳入既有横向规则；
- **矩阵是否跟随单元格级必填：不跟随**（维持第一版"矩阵不做必填终验"）——若对历史已发布版本（存在 required=true 行）追溯生效，会让进行中的草稿台账突然无法完成填写，违反"历史台账语义不漂移"；fixed_table 的列 required 是 v3 新键、只存在于新快照，无追溯问题。

## 4. 模板编辑器完整交互方案（方面二、三）

### 4.1 三栏职责矩阵（任何操作只在一个栏出现，消除双入口）

| 对象/操作 | 左栏（目录） | 中栏（画布） | 右栏（属性面板） |
|---|---|---|---|
| 分组：导航/选中定位 | **✓ 点击滚动定位** | 选中高亮 | — |
| 分组：排序 | **✓ 上/下移（从画布移除）** | — | — |
| 分组：改名/说明 | — | ✓ 就地改名 | ✓ 同步编辑 |
| 分组：新增/删除 | — | ✓ 底部结构按钮 / 选中态删除 | — |
| 分组：明细条目名 | — | — | ✓（仅 repeat） |
| 字段/矩阵行：新增 | — | ✓ 组卡内底部按钮 | — |
| 字段/矩阵行：改名 | — | ✓ 就地 | ✓ |
| 字段/矩阵行：类型、必填、单位、候选项、说明、范围等 | — | — | **✓ 全部在此** |
| 字段/行：排序、删除、复制 | — | ✓ 选中态操作按钮 | — |
| 矩阵列：增删/排序/改名/属性 | — | ✓ 表头操作（改名+排序+删除+复制） | ✓ 名称（P3 后列属性升级在此） |
| 撤销/重做 | — | ✓ 顶部工具栏 + Ctrl+Z / Ctrl+Shift+Z | — |

原则：**结构操作（增删排复制）贴着内容在画布，数值配置在右栏，导航与分组排序在左栏。**

选中与定位反馈：选中对象画布描边高亮；左栏点击分组 → `scrollIntoView` + 选中；新增/复制 → 自动选中新对象 + 滚动定位（补缺口 2）；发布检查错误点击定位复用同一机制。窄屏（<992）：右栏维持 Drawer、选中即弹出、关闭清选中；预览弹窗给渲染器传 `narrow`（修缺口 8）。

### 4.2 复制动作规范（含"复制重复明细行定义"的解释）

| 动作 | 行为 | 新 id | 位置与选中 |
|---|---|---|---|
| 复制字段 | 深拷贝（类型/必填/单位/选项/说明），名称加" 副本" | 新 `f_xxx` | 原字段后，自动选中 |
| 复制分组 | 深拷贝整组（fields/columns 全部新 id），组名加"副本" | 组 + 组内全部新 id | 原组后，选中并滚动 |
| 复制明细组 | 即复制分组——明细组的"行定义"就是其 fields，复制组即复制行定义 | 同上 | 同上 |
| 复制矩阵行/列 | 行拷贝类型/单位/说明；列拷贝名称加"副本" | 新 `r_xxx` / `c_xxx` | 相邻位置，自动选中 |
| 填写页：复制上一条明细 | 台账填写侧（非模板）：按上一行值预填新行、新 `_rid` | 运行时 `_rid` | P2 |

**ID 铁律**：复制一律 `genId` 生成全新 id；绝不复用已删除对象的 id；历史版本快照与台账填写值中的旧 id 永不受编辑影响（版本不可变）。**撤销恢复的删除**恢复原对象原 id——这是撤销相对"重新添加"的核心价值。

### 4.3 撤销/重做

- 编辑器本地历史栈：每次变更前 push 整个 form 深拷贝（≤500 字段的 JSON 量级小，整快照最可靠），上限 50 步、超出丢最旧；
- 覆盖全部 mutator（增/删/移/改名/属性/复制）；Popconfirm 删除后仍可 Ctrl+Z 找回；
- 保存草稿成功**不**清空历史（服务端整体替换，撤销后再保存安全）；关闭编辑器丢弃；
- undo/redo 后经 `resolveSelection` 恢复选中（对象已不在则回退不选中，机制已有）。

### 4.4 移动与删除

- 移动：分组排序移至左栏；字段/矩阵行上下步进、矩阵列左右步进保留在画布选中态（相邻步进够用，拖拽放 P4 观察）；
- 删除影响提示分级：删分组列出规模（"组内 N 个字段 / 矩阵 M 行×K 列"）；删字段/行/列保留"已发布版本与历史台账不受影响"并补"该内容仅从当前草稿移除"。

## 5. 属性设置与校验分层、发布检查（方面四）

### 5.1 属性面板按字段类型展示（含新增配置）

| 类型 | 配置项 | 说明 |
|---|---|---|
| 通用 | 名称、说明、必填（矩阵行/固定表行除外） | 现状保留 |
| text | 最大长度固定 500（只读提示） | 协议不变 |
| textarea | **行数 rows（2~8，默认 2）** | 协议新增可选键，P2 |
| number | 单位、**数值范围 min/max（可空）、小数位 precision（0~3，可空）** | 协议新增可选键，P2；填写端 InputNumber 透传；后端 `_normalize_number` 校验范围与小数位 |
| date | 无扩展属性；填写端升级 DatePicker（提交仍 YYYY-MM-DD 字符串） | P2 |
| choice | 候选项（tags 输入，1~50 个，去重） | 现状保留 |
| normal_abnormal | **异常时说明必填 `require_desc_when_abnormal`（默认否）** | 协议新增可选键，P2，判定见 5.2 |
| 矩阵列（条件性 P3 起） | 名称 + 类型/必填/单位/选项/只读预填值（仅 fixed_table） | 条件性 P3 |

类型切换清理不适用属性（修缺口：number→其他清空 unit/min/max/precision）。矩阵行"说明"死配置：**推荐改为渲染**（填写页行头展示说明，与 PDF `_field_label_html` 对齐），而非移除配置。

### 5.2 "异常时说明必填"的定位判定

**属于字段规则**（字段级布尔属性），而非全局开关。理由：它直接改变三类行为——填写页必填星号与拦截、`missing_required_labels` 终验、PDF 呈现——三者都以字段为作用域；且不同检查项严格程度天然不同。终验规则：字段值=`abnormal` 且规则开启时 `<id>__desc` 为空 → 记入缺失清单（标签"字段「X」异常说明未填写"）。P2 即覆盖普通字段/明细字段/矩阵行三种载体，终验语义一致（值=`abnormal` ⇒ 对应说明必填；矩阵行的"值必填"仍维持不做）——规则键随协议 v2 进入快照，避免再次出现"可配置但不生效"的死配置。

### 5.3 校验分层与发布检查中心

| 层 | 时机 | 阻断项 | 非阻断 |
|---|---|---|---|
| 编辑即时校验 | 画布/右栏编辑中 | 无（不拦编辑） | 内联红字提示（名称超长、choice 空选项等） |
| 草稿保存 | PUT | 结构合法性（现 `validate_form_schema`：协议/id/类型/选项/规模） | — |
| 发布检查 | 发布前新端点 | errors：结构非法、choice 无选项等（与草稿校验同源） | warnings：normal_abnormal 字段无检查说明、矩阵列数 ≥6（PDF 将整份横向）、字段总数 ≥450（接近上限）、明细条目名仍为默认 |
| 发布执行 | POST publish | 行锁内重新执行全部校验（防线，防 check 后草稿再变） | — |

- 新端点 `POST /form-templates/<pk>/publish-check/`（权限 `ledger_template.edit`）：服务层新增 `collect_publish_issues(form)` 返回 `{'errors': [...], 'warnings': [...]}`，每项 `{code, message, anchor:{type, groupId, fieldId?, columnId?}}`；**publish-check 是无状态提示、不是放行凭证**：不落库、不产出任何"预检通过"标记，`publish_version` 在行锁内**始终**重新执行全量校验——check 通过后草稿再被修改（含并发修改），发布仍必须重新校验并阻断非法版本；
- **后端是校验唯一事实来源**：前端编辑即时提示只镜像同一规则常量，不做第二套发布判定；发布判定永不只在前端；
- 前端发布流：dirty → 先 PUT → POST publish-check → 弹窗分组列出错误/警告，**有错误禁用发布按钮**；点击条目 → 关闭弹窗 + 选中对应对象 + 滚动定位；仅警告时勾选"已知悉"可继续；
- 规则随版本固定：发布快照存规范化后的完整定义（含新增键），`missing_required_labels` 只读快照——历史台账终验口径永不漂移。

## 7. 数据结构与版本兼容方案

### 7.1 协议演进规则

- **P2 升级 `protocol_version` 1→2**（新增 `rows/min/max/precision/require_desc_when_abnormal` 可选键，默认值=现行为）：不再以"保持 v1 + 未知键静默丢弃"换取兼容——旧代码重新保存 v2 草稿会**静默丢掉新属性，属数据丢失**；版本号升级后旧校验器对 v2 草稿**整体拒绝**（"协议版本不支持（应为 1）"），fail-closed 且提示明确；
- **结构校验未知键 fail-closed（P2 修复项）**：现 `validate_form_schema` 在 top/group/field/column 各层重建 dict、未知键静默丢弃——拼写错误或新增字段会悄悄消失。改为白名单枚举各层允许键，出现未知键即报错（错误信息含键名与所在对象）。填写值校验（`validate_form_values`）**已是 fail-closed**（未知键显式拒绝），维持不变；
- **P3 fixed_table（条件性触发）bump `protocol_version` 2→3**：新 kind 必须版本化；旧校验器对未知 kind 本就 fail-closed（`kind not in GROUP_KIND_VALUES` 即拒）；
- **读取端双版本兼容**：`missing_required_labels` / `render_form_html` 等读取端同时接受 v1 与 v2/v3 快照——新增键缺省即 v1 语义，按快照内 `protocol_version` 与 kind 分派；未知 kind 防御性跳过（PDF 已如此，校验端拒绝）；
- **草稿升级路径**：P2 上线后，存量 v1 草稿由编辑器打开并保存时自然升级为 v2；直接发布存量 v1 草稿会被拒（提示"请重新编辑并保存后再发布"）——不做发布时静默自动升级，保持 fail-closed；
- **desc 键收紧（P2 伴随修复）**：现 `_normalize_matrix` 对任意行类型都接受 `<列id>__desc`——收紧为仅 normal_abnormal 行允许（与 fixed_table 列规则同构）。前端现状只对 normal_abnormal 写 desc，存量脏数据预期为空；即使存在，详情回放/PDF 只按结构取值不受影响，仅再次保存时要求清理。

### 7.2 不变量清单

1. 三表 schema 零变更（P1–P4 全程无迁移；P3 仅协议 JSON）；
2. 填写值协议零变化：id 键控 + `<id>__desc` + 明细行数组 `_rid` + 矩阵/固定表 行→列嵌套；
3. 版本快照不可变（无修改/删除版本的写路径，缺失即 405）；`template_name_snapshot` 不回溯；
4. 复制生成新 id、撤销恢复原 id、已删除 id 不复用；
5. Excel 路线零接触：form 三模型与 Excel 专属模型完全隔离；公共层仅 `libs/html_pdf`（已上提）；
6. 周期生成/模板分组/统一列表按模板 id 分桶（kind 在模板级），组内 kind 扩展零影响；
7. 权限码不新增：模板域 `ledger_template.*`、台账域 `ledger.*`；租户过滤沿用 `apply_tenant_filter`；后端独立校验保持（前端隐藏按钮不作为边界）；无权限响应按 `@auth` 真实契约=HTTP 200 + `error='权限拒绝'`；
8. 校验 fail-closed：结构校验拒绝未知键（P2 修复）与未知 kind，填写值校验拒绝未知键（既有行为）；绝不静默丢弃任何键。

1. **后端（Docker + 隔离测试库）**：协议校验正/反例（v2 新键默认值=v1 行为、非法值拒绝、**未知键与键名拼写显式拒绝**、协议版本不符整体拒绝）；**发布原子性契约**：publish-check 通过后把草稿改为非法内容再 publish → 必须重新校验并阻断（证明 check 无状态、无任何预检标记落库）；`publish-check` 结构化输出与 anchor 正确性；fixed_table 结构与填写值校验（只读列提交即拒绝、`__desc` 仅限 normal_abnormal 列、列级 required 终验；条件性，触发后补）；异常说明必填终验；既有回归全绿（`test_form_ledger_route` 16 例、`test_form_period_generate` 9 例、`test_form_ledger_pdf` 21 例）；
2. **前端 jest**：复制生成新 id 且旧 id 不复现、撤销恢复原对象原 id、错误点击定位滚动、试填预览零写请求（mock 断言）、发布弹窗错误阻断/警告放行、新属性渲染与提交；
3. **版本兼容对拍**：v1 与 v2 版本快照在新代码下 `render_form_html` / `missing_required_labels` 输出与升级前一致（防渲染与终验口径回归）；旧代码读 v2 草稿=整体拒绝（fail-closed，不作兼容承诺）；
4. **门禁**：`code_quality_check` 0 错 0 警；新文件 ≤800 行 / 函数 ≤120 行 / 复杂度 ≤15；
5. **实机验收**：E2E 全链路（建模板 → 发布 → 生成台账 → 填写 → 完成 → PDF 比对，产物留 `quality/reports/`）+ 窄屏三栏/Drawer + 工作页签脏保护拦截；
6. **权限回归**：以 `@auth` 真实契约为准——无权限返回 **HTTP 200 + `{"error": "权限拒绝"}`**（`libs/decorators.py` 现行为，与既有 `test_permission_required_for_write` 断言一致，不写死 401）；publish-check/preview 端点纳入同款断言；跨租户模板按不存在处理（沿用既有契约测试模式）。

## 10. 本轮暂不解决的内容及原因

| 项 | 原因 |
|---|---|
| Excel 模板结构自动导入/转换 | 两路线并行是既定架构；历史 Excel 差异大，转换规则无验收基准 |
| 拖拽排序（含跨组拖字段） | 步进已可用；jsdom 拖拽测试成本高收益低，放 P4 观察 |
| 多选批量操作、字段跨组移动 | 场景少，复制+删除可组合达成 |
| 矩阵单元格级必填终验 | 对历史已发布版本追溯生效会让进行中草稿突然无法完成填写，违反"历史台账语义不漂移"；fixed_table 列 required 是 v3 新键无追溯问题，矩阵维持第一版口径（随条件性 P3 一并复核） |
| 条件显隐/字段联动/计算公式 | 违背"不做任意表单引擎"原则，四种 kind 封顶 |
| 填写页草稿本地自动保存 | 未保存保护已覆盖主路径；自动保存引入多端并发冲突语义，未设计 |
| 模板版本 diff 对比、审批流 | 无用户诉求记录；版本详情快照已可查 |
| date 支持时间部分/其他格式 | 台账场景日期已足；扩格式牵动协议与 PDF |

## 11. 设计原则重申

- **三种（扩为四种）组织方式封顶**，每种有明确定义与边界，不向"任意 Excel 编辑器"漂移；
- **结构 id / 版本快照 / 历史台账语义不漂移**：版本不可变 + 快照内协议版本分派 + 复制生成新 id + 撤销恢复原 id；
- **Excel 路线零破坏**；周期生成必须区分 excel/form（既有 `template_kind` 分桶机制不动）；
- **权限、租户隔离、后端独立校验保持**：不新增权限码，复用租户过滤，发布判定永不只在前端；
- **前后端、PDF、测试同步演进**：编辑器/填写页/PDF 共用同一渲染器与同一版式函数，每个阶段配套契约测试与门禁。
