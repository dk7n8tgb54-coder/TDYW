### 2.3 备份一致性

backup_set_create.sh 执行流程：
1. 冻结应用（supervisorctl stop all）
2. mariadb-dump --single-transaction（逻辑一致性）
3. tar 归档 documents 和 media
4. 生成 manifest.json + SHA256SUMS
5. 解冻应用

**结论**：备份脚本设计了应用冻结机制，确保数据库和文件的时间点一致性。

### 3.2 恢复流程设计

数据库恢复流程（已设计，未验证）：
1. 环境安全检查（environment_guard）
2. 创建测试数据库 (CREATE DATABASE test_spug_drill)
3. 恢复 dump (gunzip -c database.sql.gz | mysql test_spug_drill)
4. 数据库验证（Django check + 表存在 + 迁移一致 + 租户/用户/权限完整）
5. 应用验证（登录 + 列表 + 详情）
6. 清理 (DROP DATABASE test_spug_drill)

文件恢复流程（已设计，未验证）：
1. 环境安全检查
2. 创建临时目录 (/tmp/drill_files/)
3. 解压归档 (tar xzf documents.tar.gz)
4. 文件验证（数量 + 大小 + 校验和 + DB 对应）
5. 下载测试
6. 清理 (rm -rf /tmp/drill_files/)

## 八、结论与建议

- **备份覆盖**：数据库和文件存储已覆盖，配置在 git 中
- **备份方式**：双重备份（tar 全量 + Borg 去重加密）

- **恢复流程**：已设计但未验证
- **RPO**：约 24 小时
- **RTO**：估算 2-4 小时（未实测）

### 8.2 关键缺口

1. **密钥管理**：BORG_PASSPHRASE 和环境变量未纳入安全备份
2. **恢复验证**：恢复流程从未在隔离环境中验证
3. **异地备份**：所有备份都在本地，无异地副本
4. **RPO/RTO 确认**：业务目标未确认

### 8.3 建议

1. **立即**：将 BORG_PASSPHRASE 和关键环境变量备份到安全离线存储
2. **短期**：在隔离环境中执行恢复演练，验证 RTO
3. **短期**：与业务确认 RPO/RTO 目标
