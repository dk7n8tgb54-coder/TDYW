## 一、新增模块：制度管理（institution）

一项制度（手册）可含多份 Word 文件，支持在线查阅、编制、修订、审批发布，与规章管理并列出现在主菜单。

- **多文件手册**：一项制度可挂多份 Word 文件，文件级编辑会话与修订；发布形成整套不可变版本快照，历史版本随时查阅。
- **文件分工与提交编制**：分工单位为整份制度文件，支持批量改派/清空负责人（即重置提交状态）；"提交编制"记录提交时的草稿修订号并按计算式失效。
- **版本与发布**：版本对比（变更状态标注）、发布前预览与分组预检、版本页签三区域展示；无内容/结构变化时拒绝重复发布。
- **草稿工作区**：草稿恢复严格优先级（三档），支持"从当前版本恢复"；原稿重建需确认/密码/会话验证。
- **详情信息层级**：当前生效文件默认页签、按文件的变更记录、原稿文件定位为"初始来源"。
- **授权模型**：手册**所有者**自动拥有该手册范围内全部权限（查看/编辑/发布/授权/分工/密码管理），按对象生效，可移交，平台超管可接管；逐本账号授权（可看/可编/可发布）作为补充；文件内容写路径按负责人独占，编辑密码为附加验证。
- **权限码**：新增 `institution.manual.*` 权限码，需在角色管理中为新角色勾选分配。
- **数据**：全新 9 张数据表 + 独立文件存储卷（`tdyw-institution`），无存量数据迁移。

## 二、设备全生命周期管理（重大改版）

### 1. 运行处置记录（整合原"故障处置"）

- 运行情况记录与设备故障合并为统一的"运行处置记录"，类型分**一般记录 / 设备故障**。
- 信息三层结构：事实 / 研判 / 处理；处理进展时间线 + 处理概览统计。
- 设备故障新增**故障等级**（一级~四级）；支持关键词草稿转正、待办/积压统一口径。
- 故障流程简化：新建即进入处理，确认恢复并结案单事务完成；新增**作废**与**撤销登记**；原因分析全流程（尚未分析/初步判断/最终原因/原因未明）。
- 详情四区块重组（运行概况/研判与处置/关联与登记/处理概览）；附件计数列与详情定位。
- 导出 xlsx：记录列展平 + 处理时间/人/内容逐行展开。

### 2. 维护台账

- **状态简化**为三态：草稿 / 已完成 / 已作废；旧状态（已提交/已复核/已退回）全部归并退役；支持台账删除与同期补建。
- **本期应填台账**重构：按模板批量生成本期应填（周/月/航季期次），生成即可填写；修复周/月台账不生成、列表一直加载的问题。
- **双视图**："按模板查看"（模板分组统计）与"本期工作"（期次维度），支持组内翻阅台账、跨分页全量浏览。
- **批量导出 PDF**：按模板多选批量导出（ZIP 打包，逐条实时复核）。
- **Excel 模板路线**：
  - 台账只使用模板当前版本；模板工作区改版（三区布局、混合选区批量绑定、字段名自动生成）。
  - 模板历史版本查看 + 复制为新草稿。
  - **统一打印布局**：网页分页参考线与 PDF 导出共用同一分页计划，浏览器无头 Chromium 出 PDF，所见即所得；支持纸张/方向/边距/缩放/居中打印参数，导出前预检。
  - 填写页新增跨表切换导航、适合页宽、纸张边界显示；保存并提交一步完成。
  - 台账明细 CSV 导出。
- **数字表单路线（新增）**：模板类型可选"数字表单"，提供可视化模板编辑器（三栏画布、矩阵表格化）、发布预检、台账在线填写（普通字段/明细行/矩阵）、**报告式 PDF**（预览与导出同一生成函数）；协议 v2 支持数值范围/小数位、异常时说明必填等规则。
- **HTML→PDF 公共适配器**：Excel 统一打印与数字表单 PDF 共用无头 Chromium 渲染层。

### 3. 系统档案

- 新增**配置变更**页签：配置变更记录（PZ 编号）、回退生成反向变更、敏感词拦截。
- 运行处置记录页签三轮改造：列对齐主列表、筛选入 store、详情动作联动刷新、`?system=` 跳转。
- 移除系统履历模块及系统档案中对已下线模块（日巡视、维护台账旧接口）的关联展示。

### 4. 升级管理

- 升级编号恢复：`SJ+日期+当日序号`，跨租户当日序号唯一。
- 工作台 UX 改造：信息栏两行、阶段操作菜单、回退预览（核对后端口径）、日志高亮、内联编辑保存。

## 部署注意事项（重要）

1. **迁移基线重建，不可直接 `migrate` 了事**：设备全生命周期（equipment_lifecycle）迁移已折叠重建为 `0001_initial + 0002`（合并原 0001~0029 全部操作），生产库目前停在旧 `0004`。升级必须按既定基线重建方案执行（同名 0001 零操作 + 0002 标记应用），**先在生产库副本上完整演练再上生产**。
2. **破坏性数据变更**：设备管理（device）、故障（fault 旧表）、日巡视、值班日志（duty）、事件管理（runlog）等历史数据表将被 DROP。**发布前必须对生产库做完整备份并确认值班日志/事件管理历史数据已按要求归档**。
3. **RELEASE_PENDING_APPS 必须摘除**：升级模块导入逻辑在待发布应用挂载时实证崩溃（`upgrade` import LifecycleSystem），发布脚本/环境变量中不得保留该列表。
4. **权限初始化**：新增 `institution.manual.*` 权限码需在角色管理中为相关角色勾选；device/fault/duty/runlog/升级统计等旧权限码已清理，角色策略中残留勾选需人工核对一遍。
5. **前端需要重新构建烤镜像**（生产为烤入式部署，非挂载）；Excel/数字表单 PDF 导出依赖容器内 Chromium，随镜像提供。
6. **OnlyOffice 10.0 自建镜像需先行准备**并完成验证（含保存竞态修复回归）；8.1 兼容已删除，生产 OnlyOffice 必须同步升到 10.0。
7. **发布前完整备份**：数据库 + media 卷 + institution 文档卷 + documents/document-chunks 卷。
8. **制度管理为全新模块**：上线后需为首批角色分配权限并指定手册所有者。
