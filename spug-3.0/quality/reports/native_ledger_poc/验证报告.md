# 原生维护台账样板验证报告（Univer 路线）

- 日期：2026-10-18
- 样板：`quality/prototypes/native_ledger/`
- 运行地址：`http://127.0.0.1:4173/`
- 产物：本目录
- 结论：**技术上可以完成“复杂模板制作 → 绑定字段 → 填写 → 保存/重开 → 指定纸张预览 → 实际 PDF”闭环，但当前只适合作为路线样板，不建议直接替换现有 Excel 模板生产链路。**

---

## 1. 技术选型与实际能力

### 1.1 最终采用

| 项 | 实际值 |
|---|---|
| 引擎 | Univer `@univerjs/presets` / `@univerjs/preset-sheets-core` **1.1.0** |
| 许可 | Apache-2.0（npm 包声明） |
| 前端 | React 18.3.1、Vite 5.4.21 |
| 打印/PDF | 自建分页 HTML + Chromium（Playwright 1.62.1）真实打印 |
| 数据 | 浏览器 `localStorage`，不调用生产 API |

样板实际使用的 Univer 能力：

- 工作簿快照 `save()` 与重建（打开/重开台账）；
- 单元格值、字体、字号、颜色、背景、对齐、换行；
- 合并单元格 `mergeData`（模板共 **62 处**，含横向、纵向、三行纵向合并）；
- 不等行高、不等列宽（27 行 × 14 列）；
- 冻结前 4 行、原生网格选中、单元格区域读取；
- 只读工作簿保护（填写视图底表只读）；
- `rowData/columnData` 渲染尺寸；
- 字段类型：文本、数值、日期、多行文本、**正常/不正常二选一**；
- 批量绑定：把当前选区（含 Ctrl 多选区）拆成每单元格 / 每合并区一个字段，
  自动跳过已绑定单元格，单次上限 200 个字段；
- 填写层随 Univer 滚动同步重算坐标，输入控件跟随单元格上下移动。

> 未把“拖拽调整行高列宽”当作已完成验收项。模板尺寸由快照数据设置；Univer 编辑器本身提供
> 行列尺寸调整入口，但本次自动化没有对鼠标拖拽做逐步断言。

### 1.2 与平台 UI 风格的对齐

样板按 `spug_web` 的实际布局参数重做外壳，而不是独立产品的视觉：

- 208px 深色侧栏（#001529），顶部 48px 白色 Header + 阴影；
- 内容区 #f0f2f5，页面卡片白底、1px #f0f0f0 边框、2px 圆角；
- 主色 #1890ff，按钮/输入框高度 32px、圆角 2px、14px 字号；
- 页签为 antd 风格下划线页签，面包屑为“首页 / 设备管理 / 维护台账 / 原生样板”；
- 打印弹窗、提示消息、表格/卡片边框同步为同一套平台视觉。

这只影响样板外观，没有把样板接入平台路由或菜单。

## 2. 代表性复杂结构

模板包含：

- 双向多级指标：`上行（发射功率 / 驻波比 / 误码率）`、`下行（接收电平 / 信噪比 / 误码率）`；
- 多级表头：标题行、台账元信息行、方向分组行、指标子表头行；
- 横向合并：标题 A1:N1、分组表头、结论区、处置区；
- 纵向合并：序号/站点/备注两行合并，异常处置区三行合并，姓名区大合并；
- 不规则尺寸：标题行 54px、子表头 52px、数据行 38–46px、姓名行 88px；列宽 44–196px；
- 大姓名区：`D26:K26` 合并，宽约 660px、高 88px；填写控件按单元格真实尺寸定位并自动缩字号；
- 12 条链路数据、6 个站点组、异常处理/备件/复测/签字第二页。

统计：**27 行、14 列、62 处合并、初始 33 个绑定字段**；单字段流程新增 1 个字段后为
**34 个**；批量绑定验证再新增 4 个“正常/不正常”字段，达到 **37 个**。

## 3. 真实浏览器验收结果

### 3.1 流程

使用 Playwright 在真实 Chromium 中执行，非接口模拟：

1. 模板视图修改标题并写入 A1；
2. 鼠标选中 E5，读取选区 `E5`；
3. 新增绑定“驻波比复核”，发布模板 **v2**；
4. 新建台账 `TX-2026-Q3-002`，使用 v2；
5. 填写 34 个字段（含姓名 `李敏`、日期 `2026-09-20`、新增字段 `1.22`）；
6. 保存；
7. 刷新页面，重新打开台账，核对 `李敏 / 2026-09-20 / 43.6 / 1.22` 全部回读；
8. 导出 A4 横向、A3 横向、A4 纵向、A4 纵向 100% 四种 PDF；
9. 900px 窄屏重新加载，检查模板编辑与填写视图；
10. 清空本地数据，确认空态，再恢复示例。

结果：全部通过，浏览器 console error / pageerror 为 **0**。

耗时（自动化动作，不含人工思考）：

| 动作 | 耗时 |
|---|---:|
| 首次加载 | 4.0 s |
| 改标题 + 新增绑定 + 发布 v2 | 3.0 s |
| 填写 34 字段 + 保存 | 1.7 s |
| A4 PDF 生成 | 1.6 s |
| A3 PDF 生成 | 1.2 s |

### 3.2 批量绑定、状态字段与滚动跟随

补充验证脚本：`tools/e2e_batch_status.mjs`（结果 `batch_status_result.json`）。

- 鼠标拖选 `M13:M16`，读取到选区 `M13:M16`；
- 使用“批量绑定”输入“链路状态”，类型选择“正常/不正常”，一次生成 **4 个字段**，
  绑定数 33 → 37；重复单元格会跳过；
- 发布 v2、新建台账后，填写层出现 4 个状态下拉框；分别选择
  `正常 / 不正常 / 正常 / 正常`，保存；
- 刷新重开，4 个值完整回读；
- 页面滚动后，填写层跟随移动：滚动量 234.1px，姓名控件 y 从 855 移到 715，
  状态下拉 y 从 555 移到 415；滚出冻结表头的字段自动隐藏。
- 浏览器 console error 为 0。

截图：`11_batch_bind_panel.png`、`12_batch_bind_result.png`、`13_status_fill.png`、
`14_fill_scrolled.png`。

### 3.3 填写清晰度

- 桌面 1440×980：底表完整，输入层与单元格边界对齐；姓名控件约 24px 字号，未撑破 88px 行高。
- 900px 窄屏：完整台账可见，姓名控件约 54.6px 高、24.6px 字号；表格数据字号偏小，见 09 图。
- 底表只读，输入控件独立于表格流式布局，因此输入长文本不会改变行高/列宽。

### 3.4 纸张与 PDF

| 导出 | 实际页面尺寸 | 页数 | 缩放 | 结论 |
|---|---:|---:|---:|---|
| A4 横向 | 297.0 × 209.9 mm | 2 | 80% | 可用；无截断，合并格跨页 0 处 |
| A3 横向 | 420.2 × 297.0 mm | 2 | 100% | 最佳；文字最大，版式完整 |
| A4 纵向（适应页宽） | 209.9 × 297.0 mm | 2 | 55% | **低于 70% 可读线**，文字过小，不推荐 |
| A4 纵向（100% 实际） | 209.9 × 297.0 mm | 2 | 100% | **右侧被裁切**：1308px 表格 / 718px 可打印宽度 |

- PDF 用 PyMuPDF 反查：A4/A3 尺寸正确；嵌入字体为 `MicrosoftYaHei` 子集；关键值 `TX-2026-Q3-002`、`李敏`、`2026-09-20`、`1.22`、`43.6` 均可从对应页提取。
- 分页器检查并显示 **合并格跨页 0 处**；第二页从“异常处理”开始，不会切断数据行的两行合并。
- 第 2 页不再重复主表头，使用文档标题 + 台账编号作为续页页眉。

### 3.5 PDF 与预览一致性

预览 iframe 和 PDF 接口使用**同一份 `renderPrintDocument()` 生成的 HTML/CSS**；PDF 通过 Chromium
按 `@page { size: ... }` 打印。预览中的纸张、方向、页边距、页数、缩放值与 PDF 一致。

## 5. 尚未解决的问题

1. **没有 Excel 导入/导出**：当前 Univer 开源核心 preset 不提供；Pro 商业包未获授权。因此不能把
   “复用现有 Excel 模板”当作此路线已实现能力。
2. **打印器是样板级**：只覆盖本模板使用到的字体/背景/边框/对齐/合并/行高列宽；不是通用
   Excel/WPS 版式还原引擎。公式、图片、图表、条件格式、页眉页脚变量均未验证。
3. **版本能力是样例级**：有快照版本、记录保留版本号；没有版本 diff、回滚、审批、审计。
4. **没有一键生成/批量生成**。
5. **A4 纵向不可用**：适应页宽 55% 过小；100% 裁切右半部分。宽表应使用 A3 横向，或重排模板。
6. **窄屏不是生产可用形态**：整页 fit 后数据区字小，缺少手势缩放/分区填写。
7. **复杂合并长文本的编辑体验一般**：模板编辑视图里三行合并的处置说明在默认行高下拥挤，
   需要人工调行高；打印视图正常。
8. **动态行增长风险**：当前分页点是“异常处理”前的固定分页；如果数据行动态增加，自动分页
   能避让合并区域并给出警告，但未做大批量行增长的回归。
9. **批量绑定仍是基础版**：一次只能选一种字段类型；字段名自动生成为“前缀 + 坐标”，
   不支持按表头命名、批量改标签、批量删除或本次操作撤销；单次上限 200 个字段。

---

## 6. 结论与建议

- 若目标是**在平台内原生制作表单、字段化填写、稳定导出 PDF**，Univer 路线可行；A3 横向已能
  达到可交付的打印质量。
- 若目标是**继续复用现有 Excel 模板资产**，本次样板不能替代 Excel 路线；必须另购/引入
  Univer Pro 的导入导出能力，并重新验证版式保真。
- 建议下一阶段只做一个方向：
  1. 将 A3 横版作为正式纸张候选，补字段模板复用、批量标签规则、版本回滚；
  2. 或保留 Excel 模板路线，把本样板仅作为字段化填写 UI 的参考。
