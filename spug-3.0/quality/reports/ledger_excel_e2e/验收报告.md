## 3. Excel/PDF 与纸质版式的差异

结构核对 27/27 通过（导出 xlsx vs 原始 xlsx）：合并、行高列宽、边框字体、
打印区域、纸张方向/大小、页边距、页眉页脚、双工作表、未绑定单元格不被
覆盖、填写值落位。

PDF 三方对比（页1）：

| 维度 | LibreOffice 导出（平台） | Excel 参考（宿主机 COM 导出） |
|---|---|---|
| 页数/纸张 | 2 页 A4 纵向 | 2 页 A4 纵向（一致） |
| 表格位置/合并/表头填充 | 一致 | 一致 |
| 页眉页脚 | 保留且渲染 | 保留且渲染（一致） |
| 填写值 | 全部落位 | 全部落位（一致） |
| 中文字体 | 宋体→Noto CJK 回退（容器无宋体） | 原生宋体 |

已知差异与处理：
1. **中文字体**：tdyw-test 容器未装宋体，LibreOffice 以 Noto Sans CJK
   回退渲染，字形粗细略有差异、无缺字。生产部署需在镜像安装
   `libreoffice-calc fonts-noto-cjk` 或统一安装宋体许可字体，即可消除。
2. 不承诺 WPS/Excel 与 LibreOffice 像素级一致（字体度量差异不可消除）；
   结构、分页、表格几何、内容完全一致，不影响使用。
3. 低分辨率下日期格出现的「;」为 pdftoppm 渲染伪影，150DPI 放大与
   pdftotext 均确认内容干净。

## 4. 尚不支持的表格特性（上传时显式拒绝，绝不静默丢失）

- 动态增行/动态填写位置（仅支持固定行列、固定填写位置）
- 公式计算（含公式缓存值丢失风险，逐项列出拒绝）
- 宏（仅接受 .xlsx，.xls/.xlsm/.docx 一律拒绝）
- 图表、图片、外部链接、透视表（openpyxl 重写会丢失/失真，检测即拒绝）

## 5. 是否建议继续采用 Excel 上传路线：**建议继续**

真实纸质台账的制作方（WPS/Excel）与平台版式完全解耦，绑定模型简单，
导出版式还原度高；原型期全部技术风险（解析/绑定/填充/PDF）已收口为
正式服务。建议下一步：生产镜像安装 LibreOffice + 中文字体、把试点入口
从「试点」标注转正、补充模板改名/停用入口。

## 6. 在线 Office 方案删除条件评估

设计器（ledger_layout 协议）与 Excel 路线已完全解耦：独立模型文件
（layout_models vs excel_models）、独立 URL（layout-templates vs
excel-templates）、独立前端目录（designer/ vs excel/），仅共享
LongTextField 与 LayoutTable/FieldPanel 两个展示组件（excel/ 从
prototype/ 导入，不依赖 designer/）。**当前具备删除条件**：删除
designer/ 前端目录、ledger_layout_views.py、layout_services.py、
layout_models.py（含 0039 迁移与 models.py 底部导入、routes.js 两行、
boundaries 测试两行）即可整体移除，不影响 Excel 路线与正式台账。
验证页 /el/ledger-designer-lab 与原型 /el/ledger-prototype 同理可独立
下线。是否执行删除留待独立任务决策。
