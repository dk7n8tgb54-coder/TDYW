# 资料库文件映射关系保障方案 V2

> **版本**: v2.0  
> **适用**: Spug 资料库模块（已实施 V2 命名优化后）  
> **目标**: 确保数据库与物理文件映射关系长期稳定，提供升级迁移的保障机制

---

## 一、现状分析与关键问题

### 1.1 当前模型状态

```python
# 当前 DocumentFilePrivate / DocumentFilePublic 字段定义
class DocumentFilePrivate(models.Model):
    name = models.CharField(max_length=64)           # 逻辑文件名
    display_name = models.CharField(max_length=128)  # 显示文件名
    physical_name = models.CharField(max_length=32, null=True, blank=True)  # 物理文件名（可为空）
    file_path = models.CharField(max_length=500)     # 完整存储路径
    folder = models.ForeignKey(...)                  # 所属文件夹
```

### 1.2 关键发现

| 维度 | 现状 | 风险等级 |
|------|------|----------|
| **物理名字段** | 允许 `null=True`，旧数据该字段为 `NULL` | ⚠️ 中 |
| **约束条件** | 无 `editable=False`，无唯一索引 | ⚠️ 中 |
| **软删除** | 缺少 `is_deleted` 字段，直接物理删除 | 🔴 高 |
| **上传逻辑** | 未使用 V2 命名，`physical_name` 为 null | 🟡 低（兼容模式） |
| **复制逻辑** | 已使用 V2 命名，生成新的 `physical_name` | ✅ 符合规范 |
| **移动逻辑** | 物理文件被移动，同时修改 `file_path` | 🔴 高 |

### 1.3 核心问题详解

#### 问题1：移动操作违反"物理名终身不变"原则

**当前代码（file.py: FileMoveView）**：
```python
# 移动物理文件（违反原则！）
shutil.move(file.file_path, new_file_path)
file.file_path = new_file_path  # 修改了路径
file.save()
```

**问题**：
- 物理文件被移动到新目录
- `file_path` 被修改
- 违反了保障方案的核心原则

**建议**：移动操作应**只改 `folder_id`**，不移动物理文件。

#### 问题2：上传未使用 V2 命名

**当前代码（file.py: FileUploadView）**：
```python
# 使用旧命名方式（name 字段存储长文件名）
unique_name = f"{file_base}_{request.user.id}_{timestamp}_{random_suffix}{file_ext}"
# physical_name 字段未被使用，保持为 null
```

**现状影响**：
- 旧文件：`physical_name` 为 null，使用 `name` 字段定位文件
- 新文件（复制）：`physical_name` 有值，使用 `physical_name` 定位文件
- 系统同时存在两种模式，需要兼容处理

## 二、核心铁律（必须遵守）

### 2.1 四大原则

```
┌─────────────────────────────────────────────────────────────┐
│  1. physical_name 一旦生成，终身不允许修改                   │
│  2. file_path 生成后应保持稳定（尽量只改 folder_id）         │
│  3. 业务名（display_name）可以随意修改                       │
│  4. 所有文件操作必须通过数据库记录驱动                       │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 操作规范矩阵

| 操作 | 物理名 | 文件路径 | 逻辑名 | 显示名 | 文件夹 | 状态 |
|------|--------|----------|--------|--------|--------|------|
| **上传** | 生成新的 | 生成新的 | 生成新的 | 原文件名 | 指定 | ⚠️ 需改进 |
| **复制** | 生成新的 | 生成新的 | 生成新的 | 原文件名 | 指定 | ✅ 已符合 |
| **移动** | ❌ 不动 | ❌ 不动 | 可修改 | 可修改 | ✅ 修改 | 🔴 当前违规 |
| **重命名** | ❌ 不动 | ❌ 不动 | 可修改 | ✅ 修改 | ❌ 不动 | ✅ 已符合 |
| **删除** | 视策略 | 视策略 | - | - | - | ⚠️ 需加软删除 |

## 三、立即修复方案

### 3.1 修复1：移动操作改为只改 folder_id

**文件**: `apps/document/views/file.py`

**当前代码（约 547-605 行）**：
```python
# 移动物理文件
shutil.move(file.file_path, new_file_path)
file.file_path = new_file_path
file.name = new_name
file.display_name = new_name
file.folder = target
file.save()
```

**修复后代码**：
```python
class FileMoveView(View):
    @auth('document.document.move')
    def post(self, request):
        # ... 权限检查代码保持不变 ...
        
        # 【修复】移动只改 folder_id，不移动物理文件
        # 原则：physical_name 和 file_path 终身不变
        
        # 如果文件已经在目标文件夹中，不需要移动
        current_folder_id = file.folder.id if file.folder else None
        if current_folder_id == target_id:
            return json_response()
        
        # 【修复】只修改文件夹关联，不移动物理文件
        if target_id:
            file.folder = target
        else:
            file.folder = None
        
        # 【可选】如果目标文件夹有同名逻辑名，生成新的逻辑名
        from ..libs.naming_utils import generate_unique_logical_name
        file.name = generate_unique_logical_name(
            FileModel, 
            file.display_name or file.name, 
            file.folder, 
            request.user
        )
        
        file.save(update_fields=['folder', 'name', 'updated_at'])
        
        log_operation(
            action="FILE_MOVE",
            user=request.user,
            resource_type="FILE",
            resource_id=file.id,
            is_public=is_public,
            target_folder_id=target_id
        )
        return json_response()
```

**修复收益**：
- ✅ 物理文件不再被移动，路径保持稳定
- ✅ 避免跨磁盘移动的性能问题
- ✅ 符合映射关系保障原则

```python
# apps/document/models.py

from django.utils import timezone
from django.db import models

class DocumentFilePrivate(models.Model):
    # ... 现有字段 ...
    
    # 软删除字段
    is_deleted = models.BooleanField(default=False, help_text='是否已删除（软删除）')
    deleted_at = models.DateTimeField(null=True, blank=True, help_text='删除时间')
    
    class Meta:
        db_table = 'spug_document_file_private'
        # 默认查询排除已删除文件
        # 注意：Django 3.2+ 可使用 managers 配置

class SoftDeletedManager(models.Manager):
    """默认只返回未删除的记录"""
    def get_queryset(self):
        return super().get_queryset().filter(is_deleted=False)

class AllObjectsManager(models.Manager):
    """返回所有记录（包括已删除）"""
    def get_queryset(self):
        return super().get_queryset()

# 在模型中添加
class DocumentFilePrivate(models.Model):
    # ... 字段定义 ...
    
    # 自定义管理器
    objects = SoftDeletedManager()  # 默认不包含已删除
    all_objects = AllObjectsManager()  # 包含所有
```

**步骤3：修改删除逻辑**

```python
# apps/document/views/file.py

def delete(self, request):
    # ... 权限检查 ...
    
    try:
        # 【修复】改为软删除
        file.is_deleted = True
        file.deleted_at = timezone.now()
        file.save(update_fields=['is_deleted', 'deleted_at'])
        
        # 物理文件暂不删除，由定时任务清理
        logger.info(f'[Document] Soft deleted file: {file.id}, physical_name={file.physical_name}')
        
        return json_response()
    except Exception as e:
        logger.error(f'[Document] Error soft deleting file: {e}')
        return json_response(error=f'文件删除失败: {str(e)}')
```

## 四、数据库层面保障

### 4.1 添加唯一索引（防止重复物理名）

```sql
-- 执行 SQL 添加唯一索引
-- 注意：执行前确保没有重复的 physical_name

-- 1. 先检查是否有重复
SELECT physical_name, tenant_id, COUNT(*) as cnt
FROM spug_document_file_private
WHERE physical_name IS NOT NULL
GROUP BY physical_name, tenant_id
HAVING cnt > 1;

-- 2. 如无重复，添加唯一索引
ALTER TABLE spug_document_file_private 
ADD UNIQUE INDEX uk_physical_tenant_private (physical_name, tenant_id);

ALTER TABLE spug_document_file_public 
ADD UNIQUE INDEX uk_physical_tenant_public (physical_name);
-- 公共表 physical_name 全局唯一（无租户隔离）
```

## 六、一致性校验机制

### 6.1 一键校验脚本

```python
#!/usr/bin/env python3
"""
check_file_mapping.py - 数据库 ↔ 物理文件映射校验

使用方式：
    python manage.py shell < check_file_mapping.py
"""

import os
import sys

os.environ.setdefault('DJANGO_SETTINGS_MODULE', 'spug.settings')
import django
django.setup()

from apps.document.models import DocumentFilePrivate, DocumentFilePublic

def check_file(file_record, model_name):
    """检查单个文件记录"""
    errors = []
    
    # 获取物理文件名（兼容新旧数据）
    physical_name = file_record.physical_name or file_record.name
    file_path = file_record.file_path
    
    # 1. 检查字段非空
    if not physical_name:
        errors.append(f"空物理名: ID={file_record.id}")
        return errors
    
    if not file_path:
        errors.append(f"空路径: ID={file_record.id}")
        return errors
    
    # 2. 检查路径是否包含物理文件名
    basename = os.path.basename(file_path)
    expected_name = physical_name
    
    if basename != expected_name:
        errors.append(
            f"路径不匹配: ID={file_record.id}, "
            f"expected={expected_name}, actual={basename}"
        )
    
    # 3. 检查物理文件是否存在（仅未软删除的）
    if not getattr(file_record, 'is_deleted', False):
        if not os.path.exists(file_path):
            errors.append(f"文件缺失: ID={file_record.id}, path={file_path}")
    
    return errors

def main():
    print("="*60)
    print("资料库文件映射关系校验")
    print("="*60)
    
    all_errors = []
    total_files = 0
    
    # 校验私有文件
    print("\n[1/2] 校验私有文件...")
    private_files = DocumentFilePrivate.objects.filter(is_deleted=False)
    for f in private_files:
        total_files += 1
        errors = check_file(f, 'DocumentFilePrivate')
        all_errors.extend(errors)
    print(f"  检查完成: {total_files} 个私有文件")
    
    # 校验公共文件
    print("\n[2/2] 校验公共文件...")
    public_files = DocumentFilePublic.objects.filter(is_deleted=False)
    for f in public_files:
        total_files += 1
        errors = check_file(f, 'DocumentFilePublic')
        all_errors.extend(errors)
    print(f"  检查完成: {total_files} 个公共文件")
    
    # 输出结果
    print("\n" + "="*60)
    print("校验结果")
    print("="*60)
    print(f"总文件数: {total_files}")
    print(f"错误数: {len(all_errors)}")
    
    if all_errors:
        print("\n发现的问题:")
        for i, error in enumerate(all_errors[:20], 1):
            print(f"  {i}. {error}")
        if len(all_errors) > 20:
            print(f"  ... 还有 {len(all_errors) - 20} 个问题")
        print("\n❌ 校验失败，请修复上述问题")
        sys.exit(1)
    else:
        print("\n✅ 校验通过，映射关系正常")
        sys.exit(0)

if __name__ == '__main__':
    main()
```

### 6.2 定时校验任务

```python
# apps/document/tasks/integrity_check.py

from celery import shared_task
from django.core.mail import send_mail
from .check_file_mapping import main as check_mapping

@shared_task
def daily_integrity_check():
    """每日映射关系校验"""
    import io
    import sys
    
    # 捕获输出
    old_stdout = sys.stdout
    sys.stdout = buffer = io.StringIO()
    
    try:
        check_mapping()
        result = buffer.getvalue()
        status = "通过"
    except SystemExit as e:
        result = buffer.getvalue()
        status = "失败" if e.code != 0 else "通过"
    finally:
        sys.stdout = old_stdout
    
    # 发送报告（如果配置了邮件）
    if status == "失败":
        send_mail(
            subject='【告警】资料库映射关系校验失败',
            message=result,
            from_email='system@spug.local',
            recipient_list=['admin@spug.local'],
            fail_silently=True
        )
    
    return {
        'status': status,
        'detail': result
    }
```
