# 回收站"全部空间"不显示问题排故方案

## 问题现象

非管理员用户在回收站中：
- **私密空间**：正确显示自己删除的文件（1条）
- **全部空间**：有时显示1条，有时显示0条（不稳定）

## 日志分析

```
[RecycleBinStore] 收到数据: {space: 'all', items: 1, total: 1}   ← 第一次请求有数据
[RecycleBinStore] 收到数据: {space: 'all', items: 0, total: 0}   ← 后续请求数据消失
```

**关键发现**：
1. 第一次请求能返回数据，说明后端查询逻辑正确
2. 后续请求返回0条，说明数据被**缓存**或**过滤**掉了

## 可能原因分析

### 原因1：后端缓存问题（最可能）

后端使用了缓存机制：
```python
# recycle_bin.py 第93-116行
cache_key = f'recycle_bin:{request.user.id}:{cache_version}:{form.space}:...'
cached_data = cache.get(cache_key)
if cached_data:
    return json_response(data=cached_data)  # ← 返回缓存数据
```

**问题**：缓存键包含 `cache_version`，但版本号只在删除/恢复时更新。如果缓存数据本身有问题（比如被错误地存了空数组），就会一直返回空数据。

### 原因2：前端请求竞争

快速切换空间时，旧请求的响应可能覆盖新请求的数据。

### 原因3：后端查询条件不一致

"全部空间"和"单空间"的查询逻辑不同，可能导致结果不一致。

## 排故步骤

### 步骤1：检查后端日志

在服务器上执行：
```bash
docker exec tdyw sh -c "grep 'RecycleBin' /data/spug/spug_api/logs/api.log | tail -50"
```

查看：
- 第一次请求和后续请求的日志差异
- 是否有缓存命中的记录
- 查询返回的 `total` 和 `returned` 数值

### 步骤2：禁用缓存测试

临时禁用缓存，看问题是否消失：

修改 `recycle_bin.py` 第94-106行：
```python
# 临时禁用缓存测试
# if request.user.is_supper:
#     cache_key = None
#     cached_data = None
# else:
#     ...

# 直接禁用所有缓存
cache_key = None
cached_data = None
```

重启容器后测试，如果问题解决，说明是缓存问题。

### 步骤3：检查缓存内容

如果确认是缓存问题，检查缓存中存了什么：

```python

docker exec -it tdyw python /data/spug/spug_api/manage.py shell

```

### 步骤4：对比查询逻辑

检查"全部空间"和"私密空间"的查询逻辑差异：


**关键区别**：全部空间还查询了公共空间并合并结果。

## 修复方案（根据排故结果）

### 如果确认是缓存问题

方案A：清空缓存
```python
# 在 Django shell 中
cache.clear()  # 清空所有缓存
```

方案B：修复缓存键设计
```python
# 修改缓存键，添加时间戳或随机数避免冲突
cache_key = f'recycle_bin:{request.user.id}:{cache_version}:{form.space}:{form.keyword or ""}:{form.page}:{page_size}:{int(time.time()) // 60}'  # 每分钟刷新
```

方案C：禁用缓存（最简单）
```python
CACHE_TTL = 0  # 禁用缓存
```

### 如果确认是查询逻辑问题

检查全部空间的合并逻辑：
```python
# 当前代码（可能有问题）
all_files = private_files + public_files
all_files.sort(key=lambda x: x.deleted_at, reverse=True)
paginated_files = all_files[offset:offset + page_size]
```

问题可能是 `offset` 计算错误导致数据被跳过。
