### 🔧 可优化建议（详细分析）

#### 建议1：数据模型层的缺失
**评审意见**：
- 文件夹树形结构如何实现？
- 缺少 Tenant 字段显式强调
- 缺少数据库索引优化

**实际情况核查**：
```python
# models.py 中的实际设计
class DocumentFolderPrivate(models.Model):
    parent = models.ForeignKey('self', null=True, blank=True, on_delete=models.CASCADE)
    tenant_id = models.CharField(max_length=50, default='')
    # ...
```

**分析**：
1. **树形结构**：使用简单的 `Parent ID` 方式（邻接表模型），而非 MPTT
   - ✅ **优点**：实现简单，插入/移动性能高
   - ⚠️ **缺点**：递归查询深度受限，路径查询需要递归
   - **适用性**：对于一般企业的文件层级（<10层），邻接表足够

2. **Tenant 字段**：`tenant_id = models.CharField(max_length=50)` 已存在

3. **索引**：需检查是否已添加

**采纳情况**：⚠️ **部分采纳**
- 补充 ER 图和索引检查
- 当前邻接表设计符合业务场景，暂不改 MPTT

#### 建议5：前端状态管理的边界
**评审意见**：是否将 File List 数据纳入 Store？目前可能是组件状态与 MobX 混用

**实际情况核查**：
```
spug_web/src/pages/document/stores/
├── index.js          # 状态统一导出
├── upload/           # 上传状态
└── navigation/       # 导航状态
```

**分析**：
- 确实有 `stores/upload/` 和 `stores/navigation/`
- **文件列表状态**：当前使用组件内部状态（`useState`）

**采纳情况**：⚠️ **暂不采纳**
- **理由**：
  - 文件列表数据量大（可能数千条），放入全局 Store 会导致不必要的重渲染
  - 文件列表生命周期绑定到页面，离开页面即销毁，适合组件状态
  - 上传状态、导航状态需要跨组件共享，适合 Store
