```sql
-- 查询1：聚合统计
SELECT
    COUNT(CASE WHEN status='in_progress' THEN 1 END) AS in_progress_count,
    COUNT(CASE WHEN status='resolved' THEN 1 END) AS resolved_count,
    COUNT(CASE WHEN severity='P0' THEN 1 END) AS p0_count,
    COUNT(CASE WHEN severity='P1' THEN 1 END) AS p1_count,
    COUNT(CASE WHEN severity='P2' THEN 1 END) AS p2_count
FROM runlog
WHERE tenant_id=1;

-- 查询2：日期分组统计
SELECT DATE(created_at) AS day, COUNT(*) AS count
FROM runlog
WHERE tenant_id=1 AND created_at >= '2026-03-12 00:00:00'
GROUP BY DATE(created_at);
```

## 七、问题排查

### 7.1 单元测试失败

**问题**：`assertNumQueries(2)` 失败

**排查**：
1. 检查是否有额外的查询（如权限查询）
2. 查看Django日志输出实际SQL
3. 确认apply_tenant_filter未触发额外查询

**解决**：
```python
# 使用select_related/prefetch_related优化关联查询
logs = apply_tenant_filter(RunLog.objects.all(), request.user)
# logs = logs.select_related('created_by')  # 如果需要
```

### 7.2 性能未达预期

**问题**：P95响应时间仍>400ms

**排查**：
1. 检查数据库索引是否存在
2. 使用EXPLAIN分析查询计划
3. 检查数据库连接池配置
4. 检查是否有慢查询

**解决**：
```sql
-- 分析查询计划
EXPLAIN SELECT
    COUNT(CASE WHEN status='in_progress' THEN 1 END) AS in_progress_count,
    ...
FROM runlog
WHERE tenant_id=1;
```

### 7.3 前端显示异常

**问题**：前端统计数据为空或格式错误

**排查**：
1. 检查API响应格式
2. 检查前端解析逻辑
3. 查看浏览器控制台错误

**解决**：
```javascript
// 确保响应格式正确
if (data.status_stats && data.severity_stats && data.trend_data) {
    // 正常渲染
} else {
    console.error('响应格式异常', data);
}
```
