### 2.4 恢复操作竞态条件 [后端-recycle_bin.py]

| 项目 | 内容 |
|------|------|
| **位置** | `spug_api/apps/document/views/recycle_bin.py` 第387-397行, 第462-473行 |
| **问题描述** | `restore()` 和 `save()` 不在同一个事务中，如果在 `restore()` 和 `save()` 之间有其他操作修改了文件，会导致数据不一致。同名冲突检查后没有再次确认。 |
| **根因分析** | 恢复操作涉及多步骤（标记恢复→生成新名称→保存），但未使用数据库事务包裹。在高并发场景下（如用户同时发起两个恢复请求），可能导致同名冲突或数据覆盖。 |
| **风险等级** | 🔴 严重 - 数据一致性风险 |
| **修复方案** | 使用数据库事务包裹，并添加行锁（`select_for_update`）： |
| **回归验证** | 1. 模拟并发场景：同时发起10个请求恢复同一文件；2. 验证只有一个请求成功，其余返回"文件已恢复"或"冲突"；3. 验证数据库中文件状态一致且无重复。 |
| **兼容性说明** | `select_for_update` 需要数据库支持行锁（InnoDB支持，MyISAM不支持）。如使用MyISAM，需先切换为InnoDB。长事务可能导致锁等待，建议设置超时时间。 |

```python
# 修复前
file_obj.restore()
# ... 生成唯一名称 ...
file_obj.name = generate_unique_logical_name(...)
file_obj.save(update_fields=['folder', 'name'])

# 修复后
from django.db import transaction

with transaction.atomic():
    # 重新查询并锁定行
    file_obj = FileModel.all_objects.select_for_update().get(id=file_obj.id)
    file_obj.restore()
    file_obj.name = generate_unique_logical_name(...)
    file_obj.save(update_fields=['folder', 'name'])
```

# 修复后
def _permanent_delete_single(file_id, user_id):
    from apps.account.models import User
    try:
        user = User.objects.get(id=user_id)
        if not user.is_active:
            return {'id': file_id, 'status': 'failed', 'error': '用户已禁用'}
    except User.DoesNotExist:
        return {'id': file_id, 'status': 'failed', 'error': '用户不存在'}
    
    if not user.is_supper and file_obj.created_by != user:
        return {'id': file_id, 'status': 'failed', 'error': '无操作权限'}

### 2.6 物理文件删除失败不影响数据库删除 [后端-models.py]

| 项目 | 内容 |
|------|------|
| **位置** | `spug_api/apps/document/models.py` 第143-170行, 第296-315行 |
| **问题描述** | 硬删除时，即使物理文件删除失败，数据库记录仍然会被删除，导致"幽灵文件"（物理文件存在但无数据库记录）。 |
| **根因分析** | 代码逻辑先尝试删除物理文件，但无论成功与否都继续删除数据库记录。这种"尽力而为"的设计在物理文件被占用（如被其他进程打开）或权限问题时会导致不一致。 |
| **风险等级** | 🔴 严重 - 数据不一致风险 |
| **修复方案** | 物理文件删除失败时标记为"待清理"，并添加定时任务重试： |

```python
# 修复前
if hard:
    try:
        if os.path.exists(self.file_path):
            os.remove(self.file_path)
    except Exception as e:
        logger.error(f'删除物理文件失败: {self.file_path}, error={e}')
    super().delete(*args, **kwargs)  # 无论成功与否都删除数据库记录

# 修复后
if hard:
    # 先尝试删除物理文件
    physical_deleted = True
    if os.path.exists(self.file_path):
        try:
            os.remove(self.file_path)
        except Exception as e:
            logger.error(f'删除物理文件失败: {self.file_path}, error={e}')
            physical_deleted = False
    
    # 只有物理文件删除成功才删除数据库记录
    if physical_deleted:
        super().delete(*args, **kwargs)
    else:
        # 标记为待清理状态
        self.is_pending_clean = True
        self.clean_retry_count = (self.clean_retry_count or 0) + 1
        self.last_clean_attempt = timezone.now()
        self.save(update_fields=['is_pending_clean', 'clean_retry_count', 'last_clean_attempt'])
        raise Exception(f'物理文件删除失败，已标记为待清理: {self.file_path}')
```

**兜底策略 - 定时任务重试清理**：

```python
# models.py 新增字段
class DocumentFilePrivate(models.Model):
    # ... 原有字段 ...
    is_pending_clean = models.BooleanField(default=False, help_text='标记为待清理')
    clean_retry_count = models.IntegerField(default=0, help_text='清理重试次数')
    last_clean_attempt = models.DateTimeField(null=True, blank=True, help_text='上次清理尝试时间')

# tasks/cleanup.py 添加定时任务
@shared_task
def retry_clean_pending_files():
    """重试清理标记为待清理的文件"""
    pending_files = DocumentFilePrivate.objects.filter(is_pending_clean=True)
    
    for file in pending_files:
        # 跳过最近1小时内已尝试的文件（避免频繁重试）
        if file.last_clean_attempt and (timezone.now() - file.last_clean_attempt).seconds < 3600:
            continue
            
        try:
            if os.path.exists(file.file_path):
                os.remove(file.file_path)
            
            # 物理文件删除成功，删除数据库记录
            file.delete(hard=True)
            logger.info(f'[Cleanup] 待清理文件删除成功: id={file.id}')
            
        except Exception as e:
            logger.error(f'[Cleanup] 待清理文件删除失败: id={file.id}, error={e}')
            
            # 更新重试计数
            file.clean_retry_count += 1
            file.last_clean_attempt = timezone.now()
            
            # 超过3次重试则告警
            if file.clean_retry_count >= 3:
                send_alert(f'文件{id=file.id}删除失败超过3次，需人工介入')
            
            file.save(update_fields=['clean_retry_count', 'last_clean_attempt'])
```

| **回归验证** | 1. 创建一个文件并获取其路径；2. 使用`lsof`或其他工具锁定该文件（模拟文件被占用）；3. 调用硬删除接口；4. 验证接口返回错误且数据库记录标记为`is_pending_clean=True`；5. 释放文件锁定，运行定时任务；6. 验证文件被成功清理。 |
