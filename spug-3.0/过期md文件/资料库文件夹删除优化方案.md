# 资料库公共空间文件夹删除优化方案

**方案编号**: 方案1-细化版  
**制定日期**: 2026-03-28  
**适用模块**: 资料库-公共空间文件夹管理  
**问题背景**: 文件夹创建者可删除包含他人文件的文件夹，导致数据误删

---

## 一、问题描述

### 当前行为
- 公共空间文件夹创建者可以删除整个文件夹
- 删除时会一并删除文件夹内所有文件（包括他人上传的）
- 他人文件会进入创建者的回收站，造成数据归属混乱

### 风险场景
```
场景1：员工A创建了"项目资料"文件夹
        ↓
      员工B、C上传了重要文档
        ↓
      员工A误操作或离职前删除文件夹
        ↓
      B、C的文件全部丢失（进入A的回收站）

场景2：恶意删除
      用户创建公共文件夹诱导他人上传
        ↓
      收集足够文件后批量删除
        ↓
      他人数据被恶意清除
```

---

## 二、优化目标

1. **防止误删**: 避免文件夹创建者意外删除他人数据
2. **权限合理**: 用户只能删除自己拥有完整权限的内容
3. **体验友好**: 提供清晰的引导和替代操作
4. **数据安全**: 确保他人数据不会因他人操作而丢失

---

## 三、详细方案设计

### 3.1 核心原则

> **"谁创建，谁负责；涉及他人，需协商"**

### 3.2 删除权限矩阵

| 场景 | 文件夹创建者 | 管理员 | 普通用户 | 操作结果 |
|------|------------|--------|---------|---------|
| 空文件夹 | ✅ 可删除 | ✅ 可删除 | ❌ 不可删除 | 直接删除 |
| 只有自己文件 | ✅ 可删除 | ✅ 可删除 | ❌ 不可删除 | 直接删除 |
| 有他人文件 | ⚠️ 受限 | ⚠️ 受限 | ❌ 不可删除 | 需处理他人文件 |
| 他人创建的文件夹 | ❌ 不可删除 | ✅ 可删除 | ❌ 不可删除 | 无权限 |

### 3.3 智能删除流程

```
用户点击"删除文件夹"
        ↓
[Step 1] 权限检查
    ├─ 是否文件夹创建者或管理员？
    ├─ 否 → 返回"无权删除"
    └─ 是 → 继续
        ↓
[Step 2] 内容扫描
    ├─ 统计文件夹内文件数量和创建者分布
    ├─ 分类：自己的文件 / 他人的文件
    └─ 统计结果
        ↓
[Step 3] 分支处理
    ├─ 场景A: 只有自己文件或空文件夹
    │       └─ 直接删除，无需确认
    │
    ├─ 场景B: 有他人文件（少量，≤10个）
    │       └─ 弹出详情对话框，提供选项
    │
    ├─ 场景C: 有他人文件（大量，>10个）
    │       └─ 强制要求先清空或移交
    │
    └─ 场景D: 包含子文件夹
            └─ 递归检查子文件夹内容
```

**强制引导操作**:

```python
def check_folder_deletable(folder, user):
    """检查文件夹是否可以直接删除"""
    
    # 1. 基础权限检查
    if not can_delete_folder(folder, user):
        return False, "insufficient_permission"
    
    # 2. 统计文件分布
    stats = analyze_folder_contents(folder)
    
    # 3. 决策逻辑
    if stats['others_files_count'] == 0:
        # 只有自己文件或空文件夹
        return True, "can_delete_directly"
    
    elif stats['others_files_count'] <= 10:
        # 少量他人文件，提供选项
        return False, "contains_others_files", stats
    
    else:
        # 大量他人文件，禁止直接删除
        return False, "too_many_others_files", stats


def delete_folder_with_options(folder, user, action, **kwargs):
    """根据选项执行删除"""
    
    if action == "move_others_first":
        # 先移出他人文件到根目录
        move_others_files_to_root(folder, user)
        # 再删除（此时只有自己文件）
        soft_delete_folder(folder, user)
    
    elif action == "delete_mine_only":
        # 只删除自己的文件
        delete_my_files_only(folder, user)
        # 如果文件夹空了，提示可以删除；否则保留文件夹
    
    elif action == "force_delete" and user.is_admin:
        # 管理员强制删除（需记录日志）
        log_admin_force_delete(folder, user)
        soft_delete_folder(folder, user)
```

def delete(self, request):
    """删除文件夹（智能版）"""
    form, error = JsonParser(...).parse(request.GET)

        return json_response(error=error)

## 六、边界情况处理

### 6.1 特殊情况

| 情况 | 处理方案 |
|------|---------|
| 文件创建者已离职 | 显示"原员工"，允许管理员处理 |
| 文件夹内全是他人文件 | 强烈建议"移出文件"，不提供"删除我的文件"选项 |
| 子文件夹有他人文件 | 递归检查，汇总显示 |
| 文件正在传输中 | 提示"有文件传输中，请稍后再试" |
| 文件夹被设置为官方 | 禁止普通用户删除，仅管理员可操作 |

### 6.2 性能考虑

- **大量文件检测**: 使用 `exists()` 和 `count()` 避免全量加载
- **递归检查深度**: 限制子文件夹检查深度（建议3层），避免递归过深
- **缓存统计结果**: 删除检查接口可缓存10秒，避免重复查询
