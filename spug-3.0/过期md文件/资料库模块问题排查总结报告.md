## 一、登录问题 - "请求超时，文件较大请重试"

### 1.1 问题现象
- 登录页面显示："请求异常: 请求超时，文件较大请重试"
- 浏览器开发者工具 Network 标签中，`/api/account/login/` 请求无状态码

### 1.2 根因分析
**Windows + Docker Desktop 的 IPv6 兼容性问题**

```
localhost  →  解析为 ::1 (IPv6)  →  Docker IPv6 映射有问题  →  连接超时
127.0.0.1  →  明确使用 IPv4    →  Docker IPv4 映射正常    →  连接成功
```

### 1.3 验证过程
```bash
# ping localhost 解析为 IPv6
正在 Ping LAPTOP-VKNVF9F3 [::1] ...

# curl localhost 超时
curl http://localhost/api/account/login/  → HTTP Code: 000, 超时 10秒

# curl 127.0.0.1 正常
curl http://127.0.0.1/api/account/login/  → HTTP Code: 200, 0.7秒
```

### 1.4 解决方案
修改 `spug_web/src/setupProxy.js`：
```javascript
// 修改前
target: 'http://localhost:80'

// 修改后
target: 'http://127.0.0.1:80'
```

### 1.5 永久解决方案
在 `C:\Windows\System32\drivers\etc\hosts` 添加：
```
127.0.0.1 localhost
```

## 二、全局管理员权限问题

### 2.1 问题现象
- 全局管理员账号看不到其他账号的内容
- 所有模块都按租户过滤，全局管理员和超级管理员权限混淆

### 2.2 根因分析
`libs/tenant_utils.py` 中的 `apply_tenant_filter` 函数设计不合理：
- 原本：全局管理员也按租户过滤
- 期望：资料库私密空间严格过滤，其他模块全局管理员可查看所有数据

### 2.3 解决方案
修改 `apply_tenant_filter` 函数，添加 `strict_mode` 参数：

```python
def apply_tenant_filter(queryset, request_user, strict_mode=False):
    """
    strict_mode: 严格模式（资料库私有空间使用）
        True: 全局管理员也按租户过滤（只有超级管理员不过滤）
        False: 全局管理员和超级管理员都不过滤
    """
    # 超级管理员始终不过滤
    if is_supper:
        return queryset
    
    # 非严格模式下，全局管理员也不过滤
    if is_global_admin and not strict_mode:
        return queryset
    
    # 严格模式下的全局管理员或普通用户，都按租户过滤
    return queryset.filter(tenant_id=tenant_id)
```

### 2.4 修改范围
资料库私密空间所有视图添加 `strict_mode=True`：
- `upload.py` - 2处
- `search.py` - 5处
- `folder.py` - 11处
- `file.py` - 10处

## 三、大文件上传合并失败

### 3.1 问题现象
- 上传文件卡在99%
- Celery Worker 没有执行合并任务
- 任务状态一直为 PENDING

### 3.2 排查过程

#### 3.2.1 检查 Celery Worker 状态
```bash
# 查看队列为空
celery -A spug inspect active     # empty
celery -A spug inspect scheduled  # empty

# 查看任务状态
AsyncResult(task_id).state  # PENDING
```

#### 3.2.2 发现 Worker 崩溃
```bash
ps aux | grep celery
# PID 470 不存在，Worker 已崩溃
```

#### 3.2.3 发现队列不匹配
```bash
# Worker 只监听默认队列
celery -A spug worker -l info --concurrency=4
# Queues: celery (默认)

# 但任务定义了专用队列
@shared_task(queue='document.merge')
def merge_file_chunks(self, job_data):
```

### 3.3 发现的相关 Bug

#### Bug 1: Worker 队列配置缺失
Worker 没有监听 `document.merge` 队列，导致任务提交后无人消费。

#### Bug 2: 变量未定义 (`merge.py`)
```python
# 第64行使用了未定义的变量
timestamp = int(time.time())      # 未定义
start_time = timestamp            # 未定义
```

#### Bug 3: 变量使用前引用 (`upload.py`)
```python
# 第496行使用了 task.id，但 task 在后面才创建
task_id: task.id  # 此时 task 还未定义

# ...

task = merge_file_chunks.delay(job_data)  # task 在这里创建
```

### 3.4 解决方案

#### 3.4.1 修改 Worker 启动脚本
修改 `spug_api/tools/start-celery.sh`：
```bash
# 修改前
exec celery -A spug worker -l info --concurrency=4

# 修改后（监听多个队列）
exec celery -A spug worker -l info --concurrency=4 -Q celery,document.merge
```

#### 3.4.2 修复变量未定义
```python
# merge.py 第64行添加
timestamp = int(time.time())
start_time = timestamp
```

#### 3.4.3 修复变量使用前引用
```python
# upload.py 调整顺序
# 1. 先提交任务
task = merge_file_chunks.delay(job_data)

# 2. 再写入任务文件（使用 task.id）
with open(merge_task_file, 'w') as f:
    f.write(json.dumps({
        'task_id': task.id  # 现在 task 已定义
    }))
```

#### 3.4.4 添加详细调试日志
在关键位置添加日志以便后续排查：
- 任务提交前后
- 分片完整性检查
- 数据库操作
- 文件合并过程

**修复方案**：修改 `spug_web/src/pages/document/store/UploadCoreStore.js`：
```javascript
// 修改前（第1处）
if (status.status === 'completed') {

// 修改后
if (status.status === 'completed' || status.status === 'success') {
```

**涉及位置**：第2处状态检查同样需要修改。
