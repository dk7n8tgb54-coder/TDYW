# 回收站P0问题修复 - 后续操作指南

## 一、数据库迁移

### 1.1 创建迁移文件
在 `spug_api` 目录下执行：

```bash
cd spug_api
python manage.py makemigrations document --name add_pending_clean_fields
```

### 1.2 应用迁移
```bash
python manage.py migrate
```

### 1.3 迁移字段说明
本次迁移为以下模型添加字段：

**DocumentFilePrivate 和 DocumentFilePublic 模型新增字段：**
- `is_pending_clean` (BooleanField): 待清理标记，默认False
- `clean_retry_count` (IntegerField): 清理重试次数，默认0
- `last_clean_attempt` (DateTimeField): 上次清理尝试时间，可为空

## 二、Celery定时任务配置

### 2.1 配置说明
已在 `spug/settings.py` 中添加定时任务配置：

```python
CELERY_BEAT_SCHEDULE = {
    # 每小时检查一次待清理文件
    'retry-clean-pending-files': {
        'task': 'apps.document.tasks.cleanup.retry_clean_pending_files',
        'schedule': 3600.0,  # 每小时执行一次

}
```

### 2.2 启动Celery Beat调度器
确保Celery Beat服务正在运行：

```bash

# 或手动启动
```

### 3.4 并发恢复竞态条件测试 (P0-4)

**测试场景：** 两个用户同时恢复同一文件

```bash
# 使用脚本并发请求
#!/bin/bash
# concurrent_restore_test.sh

TOKEN1="<用户1token>"
TOKEN2="<用户2token>"
FILE_ID=123  # 已删除的文件ID

# 同时发送两个恢复请求
curl -X POST http://localhost/api/document/recycle-bin/restore/ \
  -H "Content-Type: application/json" \
  -H "Authorization: Token $TOKEN1" \
  -d "{\"ids\": [$FILE_ID], \"space_type\": \"private\"}" &

curl -X POST http://localhost/api/document/recycle-bin/restore/ \
  -H "Content-Type: application/json" \
  -H "Authorization: Token $TOKEN2" \
  -d "{\"ids\": [$FILE_ID], \"space_type\": \"private\"}" &

wait
```

**验证点：**
- [ ] 只有一个请求成功恢复
- [ ] 另一个请求返回"文件已被恢复或不存在"
- [ ] 数据库无重复恢复记录

### 3.6 物理文件删除失败兜底测试 (P0-6)

**测试场景：** 物理文件被占用导致删除失败

**测试步骤：**

2. 使用其他进程占用该物理文件（Windows上打开文件句柄）
3. 尝试永久删除

```python
# 测试脚本（在Django shell中执行）
import os
from apps.document.models import DocumentFilePrivate

# 找一个测试文件
file_obj = DocumentFilePrivate.all_objects.filter(is_deleted=True).first()
file_path = file_obj.file_path

# 模拟文件被占用（Windows）
import subprocess
subprocess.Popen(['cmd', '/c', 'pause'], cwd=os.path.dirname(file_path))

# 尝试硬删除
try:
    file_obj.delete(hard=True)
except Exception as e:
    print(f"预期错误: {e}")

# 验证标记
file_obj.refresh_from_db()
print(f"is_pending_clean: {file_obj.is_pending_clean}")
print(f"clean_retry_count: {file_obj.clean_retry_count}")
```

**验证点：**
- [ ] 删除抛出异常
- [ ] 文件标记为 is_pending_clean=True
- [ ] clean_retry_count 增加
- [ ] last_clean_attempt 更新
