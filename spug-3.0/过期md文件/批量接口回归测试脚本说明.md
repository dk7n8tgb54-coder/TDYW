# 批量接口回归测试脚本说明

## 脚本位置

- `spug_api/verify_transfer_state_transitions.py`

## 作用

- 验证本轮状态流转修复后，以下接口是否符合预期：
  - 批量暂停：`/api/document/transfers/batch/pause/`
  - 批量恢复：`/api/document/transfers/batch/resume/`
  - 单条状态更新：`/api/document/transfers/{id}/status/`
  - 单条取消：`/api/document/transfers/{id}/cancel/`

## 运行方式

### 方式 A：Session Cookie（浏览器登录态）

```bash
cd spug_api
python verify_transfer_state_transitions.py \
  --base-url http://127.0.0.1:80 \
  --cookie "sessionid=xxx; csrftoken=xxx" \
  --csrf-token xxx \
  --transfer-ids 101,102,103
```

### 方式 B：Authorization Token

```bash
cd spug_api
python verify_transfer_state_transitions.py \
  --base-url http://127.0.0.1:80 \
  --authorization "Bearer <your_token>" \
  --transfer-ids 101,102,103
```

### 方式 C：Spug x-token（推荐）

```bash
cd spug_api
python verify_transfer_state_transitions.py \
  --base-url http://127.0.0.1:80 \
  --x-token "<your_access_token>" \
  --transfer-ids 101,102,103
```

说明：

- 脚本至少需要一种认证方式：`--cookie` / `--authorization` / `--x-token`
- 如果后端启用 CSRF 且走 cookie 鉴权，建议同时传 `--csrf-token`
- 你的项目后端中间件默认读取 `x-token`，所以优先用方式 C

### 方式 D：账号密码自动登录（免手动取 token）

```bash
cd spug_api
python verify_transfer_state_transitions.py \
  --base-url http://127.0.0.1:80 \
  --username admin \
  --password Admin888 \
  --transfer-ids 101,102,103
```

说明：

- 脚本会先调用 `/api/account/login/` 自动获取 `access_token`，再用 `x-token` 跑后续测试。

## 结果解读

- 每一步会打印：
  - HTTP 状态码
  - 接口返回 JSON
- 重点观察：
  - 批量接口是否返回 `updated/success_ids/skipped_ids/skipped_reasons`
  - 是否还出现“无效的状态转换”大面积告警
  - 单条取消后，返回是否为 `CANCELED` 语义（前端应映射为 `cancelled`）

## 建议测试数据

- 选 3~5 条不同状态的传输记录（至少包含 `PENDING`、`UPLOADING`、`PAUSED`）
- 避免使用 `COMPLETED/CANCELED` 全终态样本，否则批量恢复意义较小

## 备注

- 脚本为 smoke test，不会创建测试数据；请先准备可操作的 `transfer_id`。
