# 回收站权限问题紧急修复报告

## 修复时间
2026-03-15

## 问题概述
用户（zhangyanzhou）拥有 `document.document.delete` 权限，但在回收站执行恢复或彻底删除操作时收到"权限拒绝"错误。

## 根因分析

### 问题1：硬删除权限检查过于严格 [P0级]
**文件**：`spug_api/apps/document/views/recycle_bin.py:614-615`

**修复前的代码**：
```python
# 【P0修复】硬删除权限检查：只有管理员可以彻底删除文件
if not request.user.is_supper:
    return json_response(error='只有管理员可以彻底删除文件', code=403)
```

**问题**：
- 彻底删除功能要求用户**必须是管理员**
- 但恢复功能使用的是 `_check_permission` 方法，允许**管理员或文件所有者**操作
- 导致权限不一致：普通用户可以恢复自己的文件，但不能彻底删除自己的文件

**修复方案**：
- 删除入口处的 `is_supper` 检查
- 在 `_permanent_delete` 方法中添加与恢复功能一致的权限检查

### 问题2：租户过滤代码位置错误 [P1级]
**文件**：`spug_api/apps/document/views/recycle_bin.py:622-640`

**问题**：
- 租户过滤检查代码在 `form` 解析之后、但在 `if error:` 之前
- 如果参数解析失败，`form` 可能为 `None`，访问 `form.file_ids` 会导致 `AttributeError`

**修复方案**：
- 删除原来的租户过滤代码块
- 在 `_permanent_delete` 方法中添加租户隔离检查

## 修复内容

### 修改1：彻底删除入口方法
```python
@auth('document.document.delete')
def post(self, request):
    """彻底删除文件（支持单个、批量、异步）"""

        Argument('async_mode', type=bool, required=False, default=False)
    ).parse(request.body)
    
    if error:
        return json_response(error=error)
```

## 权限逻辑对比

| 操作 | 修复前 | 修复后 |
|------|--------|--------|
| 恢复文件 | 管理员 或 文件所有者 | 管理员 或 文件所有者 |
| 彻底删除 | 仅管理员 | 管理员 或 文件所有者 |

## 测试验证建议

1. **管理员操作**：管理员可以恢复和彻底删除任何文件
2. **文件所有者操作**：
   - 可以恢复自己删除的文件
   - 可以彻底删除自己删除的文件
3. **其他用户操作**：
   - 无法恢复他人的文件
   - 无法彻底删除他人的文件
4. **跨租户操作**：
   - 无法操作其他租户的文件

## 影响范围

- **仅影响回收站模块**的彻底删除功能
- 软删除（移入回收站）功能不受影响
- 其他资料库功能不受影响
