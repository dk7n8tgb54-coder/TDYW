### 修正2: 批量任务降级逻辑（权限校验）

**原方案问题**：降级单条删除未校验tenant_id，存在越权风险

**修正后代码**：

```python
# apps/document/tasks/batch.py

@shared_task(
    bind=True,
    max_retries=3,
    default_retry_delay=30,
    queue='document.batch',
    time_limit=300,
    soft_time_limit=240,
)
def batch_delete_transfers(self, transfer_ids, request_user_id, request_tenant_id):
    """
    异步批量删除传输记录 - 生产优化版（v4修正权限校验）
    """
    from apps.document.models import DocumentTransfer
    from apps.document.constants import TransferStatus
    from django.db import transaction
    
    logger.info(f'[Celery] Batch delete start: count={len(transfer_ids)}, tenant={request_tenant_id}')
    
    # 批量查询，强制租户过滤
    transfers = list(DocumentTransfer.objects.filter(
        id__in=transfer_ids,
        tenant_id=request_tenant_id  # 强制租户隔离
    ).select_related())
    
    # 如果查询结果数量与请求数量不符，说明有越权ID
    if len(transfers) != len(transfer_ids):
        found_ids = {t.id for t in transfers}
        invalid_ids = set(transfer_ids) - found_ids
        logger.warning(f'[Celery] Found {len(invalid_ids)} invalid/out-of-scope transfer IDs: {invalid_ids}')
    
    # 预分类
    deletable_states = {
        TransferStatus.COMPLETED.value,
        TransferStatus.FAILED.value,
        TransferStatus.CANCELED.value
    }
    
    deletable_transfers = []
    skipped_ids = []
    
    for transfer in transfers:
        if transfer.status in deletable_states:
            deletable_transfers.append(transfer)
        else:
            skipped_ids.append(transfer.id)
    
    # 文件清理在事务外
    deleted_count = 0
    chunk_cleanup_results = []
    
    BATCH_SIZE = 10
    for i in range(0, len(deletable_transfers), BATCH_SIZE):
        batch = deletable_transfers[i:i+BATCH_SIZE]
        batch_ids = [t.id for t in batch]
        
        # 事务内只做数据库操作
        try:
            with transaction.atomic():
                # 再次强制租户过滤删除
                deleted_qs = DocumentTransfer.objects.filter(
                    id__in=batch_ids,
                    tenant_id=request_tenant_id  # 双重租户验证
                )
                deleted_count += deleted_qs.count()
                deleted_qs.delete()
                
        except Exception as e:
            logger.error(f'[Celery] Batch delete error: {e}')
            
            # 【修正】降级单条删除时补充权限校验
            for transfer in batch:
                try:
                    with transaction.atomic():
                        # 重新查询并校验租户权限
                        valid_transfer = DocumentTransfer.objects.filter(
                            id=transfer.id,
                            tenant_id=request_tenant_id,  # 强制租户校验
                            status__in=deletable_states   # 再次校验状态
                        ).first()
                        
                        if valid_transfer:
                            valid_transfer.delete()
                            deleted_count += 1
                            logger.info(f'[Celery] Single delete success: {transfer.id}')
                        else:
                            logger.warning(f'[Celery] Skip delete (no permission or invalid state): {transfer.id}')
                            
                except Exception as e2:
                    logger.error(f'[Celery] Single delete failed: {transfer.id}, error: {e2}')
            continue
        
        # 事务外执行文件清理
        for transfer in batch:
            if transfer.file_hash and transfer.total_chunks > 0:
                try:
                    _cleanup_transfer_chunks(transfer)
                    chunk_cleanup_results.append({'id': transfer.id, 'status': 'cleaned'})
                except Exception as e:
                    logger.warning(f'[Celery] Chunk cleanup failed for {transfer.id}: {e}')
                    chunk_cleanup_results.append({'id': transfer.id, 'status': 'failed', 'error': str(e)})
    
    result = {
        'deleted': deleted_count,
        'skipped': len(skipped_ids),
        'total': len(transfer_ids),
        'chunk_cleaned': len([r for r in chunk_cleanup_results if r['status'] == 'cleaned']),
    }
    
    logger.info(f'[Celery] Batch delete completed: {result}')
    return result
```

### 修正3: Gunicorn配置（移除无效参数）

**原方案问题**：同步Worker配置了`--worker-connections=1000`，该参数仅对异步Worker有效

**修正后配置**：

```bash

[program:spug]
command=/path/to/venv/bin/gunicorn spug.wsgi:application \
    -b 0.0.0.0:8000 \
    --workers=4 \
    --worker-class=sync \
    --max-requests=5000 \
    --max-requests-jitter=100 \
    --timeout=60 \
    --keep-alive=2 \
    --graceful-timeout=30
    # 【修正】移除了 --worker-connections=1000 (sync模式不支持)

environment=DJANGO_SETTINGS_MODULE="spug.settings"
directory=/path/to/spug_api

autostart=true
```

```bash
# Gevent异步Worker配置（worker-connections在此有效）
[program:spug-async]
command=/path/to/venv/bin/gunicorn spug.wsgi:application \
    -b 0.0.0.0:8000 \
    --workers=4 \
    --worker-class=gevent \
    --worker-connections=1000 \      # 【有效】仅gevent/eventlet支持
```

- `--worker-connections`: 仅`gevent`/`eventlet`异步Worker支持
- `sync`模式Worker: 每个Worker同时只能处理1个请求，并发能力由`--workers`决定

### 修正4: 健康检查Celery逻辑（ping为None时返回error）

**原方案问题**：`inspector.ping()`返回None时（Worker全宕），仅标记warning，不会触发503

**修正后代码**：

```python
# apps/document/monitoring.py

def check_celery_health():
    """
    检查Celery Broker连接与Worker存活
    【修正】ping为None(Broker不可达/无Worker)时返回error而非warning
    """
    try:
        inspector = celery_app.control.inspect(timeout=5)
        ping = inspector.ping()
        
        # 【修正】严格判断：
        # - ping为None: Broker不可达或无任何Worker响应 → error
        # - ping为空字典: 有Broker但无Worker注册 → error  
        # - ping有内容: Worker正常响应 → ok
        if ping is None:
            logger.error('[HealthCheck] Celery Broker不可达或inspector调用失败')
            return {
                'status': 'error',
                'error': 'Celery Broker不可达',
                'workers': 0
            }
        
        if not ping:  # 空字典
            logger.error('[HealthCheck] Celery Broker可达但无存活Worker')
            return {
                'status': 'error',
                'error': '无存活Celery Worker',
                'workers': 0
            }
        
        # 有Worker响应，正常
        worker_count = len(ping)
        logger.info(f'[HealthCheck] Celery正常: {worker_count}个Worker存活')
        return {
            'status': 'ok',
            'workers': worker_count,
            'worker_names': list(ping.keys())
        }
        
    except Exception as e:
        logger.error(f'[HealthCheck] Celery检查异常: {e}')
        return {
            'status': 'error',
            'error': str(e),
            'workers': 0
        }
```

### 补充1: 后端幂等性校验（配合前端幂等键）

```python
# apps/document/views/transfer/batch.py

from django.core.cache import cache
from django.http import JsonResponse
from django.views.decorators.http import require_http_methods

@require_http_methods(["POST"])
def batch_delete_api(request):
    """
    批量删除API - 带幂等性校验
    """
    # 获取幂等键
    idempotency_key = request.headers.get('X-Idempotency-Key')
    if not idempotency_key:
        return JsonResponse({'error': '缺少幂等键，请检查前端配置'}, status=400)
    
    # 幂等性校验：检查是否已处理
    cache_key = f'idempotency:batch_delete:{request.user.tenant_id}:{idempotency_key}'
    existing_task_id = cache.get(cache_key)
    
    if existing_task_id:
        logger.info(f'[API] 幂等键已存在，返回已有任务: {existing_task_id}')
        return JsonResponse({
            'task_id': existing_task_id,
            'status': 'already_submitted',
            'message': '该批量删除任务已提交，请勿重复操作'
        })
    
    # 参数校验
    try:
        data = json.loads(request.body)
        transfer_ids = data.get('transfer_ids', [])
        
        if not transfer_ids:
            return JsonResponse({'error': 'transfer_ids不能为空'}, status=400)
        
        if len(transfer_ids) > 1000:  # 限制单次批量数量
            return JsonResponse({'error': '单次最多删除1000条记录'}, status=400)
            
    except json.JSONDecodeError:
        return JsonResponse({'error': '无效的JSON数据'}, status=400)
    
    # 创建Celery任务
    task = batch_delete_transfers.delay(
        transfer_ids=transfer_ids,
        request_user_id=request.user.id,
        request_tenant_id=request.user.tenant_id
    )
    
    # 写入幂等缓存（24小时过期）
    cache.set(cache_key, task.id, 86400)
    
    logger.info(f'[API] 批量删除任务创建成功: task_id={task.id}, count={len(transfer_ids)}')
    
    return JsonResponse({
        'task_id': task.id,
        'status': 'submitted',
        'message': f'批量删除任务已提交，共{len(transfer_ids)}条记录'
    })
```

```bash
echo "  innodb_buffer_pool_size: $BUFFER_POOL"

# 9. Nginx配置检查
echo ""
echo "[9/10] Nginx配置检查"
if grep -q "worker_processes" /etc/nginx/nginx.conf 2>/dev/null; then
    echo "  ✅ Nginx worker_processes已配置"
else

    ((WARNINGS++))
fi

if grep -q "worker_connections" /etc/nginx/nginx.conf 2>/dev/null; then
    echo "  ✅ Nginx worker_connections已配置"
else
    echo "  ⚠️  Nginx worker_connections未配置"
    ((WARNINGS++))
fi

# 10. 代码权限校验检查
echo ""
echo "[10/10] 代码权限校验检查"
if grep -q "tenant_id=request_tenant_id" apps/document/tasks/batch.py 2>/dev/null; then
    echo "  ✅ 降级删除逻辑已添加tenant_id校验"
else
    echo "  ❌ 降级删除逻辑缺少tenant_id校验"
    echo "     修正: 参考v4文档补充权限校验"
    ((ERRORS++))
fi

# 总结
echo ""
echo "========================================"
echo "检查完成: $ERRORS个错误, $WARNINGS个警告"
echo "========================================"

if [ $ERRORS -gt 0 ]; then
    echo "❌ 存在错误，请修正后再部署"
    exit 1
else
    echo "✅ 检查通过，可以部署"
```
