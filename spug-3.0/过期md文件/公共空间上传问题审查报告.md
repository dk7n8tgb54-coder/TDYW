# 公共空间文件上传问题审查报告

## 问题概述

用户报告公共空间（is_public=true）的普通上传和分片上传都出现"服务器内部错误"。

## 错误信息分析

```
index.js:278 Upload error: {id: '...', name: 'xxx.mp4'} 服务器内部错误
```

错误信息表明后端返回 500 错误，需要深入分析后端代码。

## 代码审查发现

### 1. 文件上传流程

#### 普通上传 (`views/file/upload.py`)
```python
# 第 30 行：获取 is_public 参数
is_public = request.POST.get('is_public', 'false').lower() == 'true'

# 第 40-41 行：获取模型
FolderModel = get_folder_model(is_public=is_public)
FileModel = get_file_model(is_public=is_public)

# 第 76 行：生成三层命名
names = generate_file_names(FileModel, file.name, folder, request.user)
```

**问题点**：
- `generate_file_names` 调用 `generate_unique_logical_name`，该函数使用了数据库事务
- 事务内部查询使用了 `tenant_id` 过滤

#### 命名工具 (`libs/naming_utils.py`)
```python
# 第 154-161 行
def generate_unique_logical_name(FileModel, original_name, folder, user, max_original_length=50):
    # ...
    with transaction.atomic():
        exact_exists = FileModel.objects.filter(
            folder_id=folder_id,
            tenant_id=tenant_id,  # 【潜在问题】公共空间所有用户的 tenant_id 可能相同
            name=exact_pattern
        ).exists()
```

### 3. 错误处理机制

#### 统一错误处理 (`libs/view_utils.py`)
```python
# 第 117-130 行
def handle_view_errors(func):
    @wraps(func)
    def wrapper(self, request, *args, **kwargs):
        try:
            return func(self, request, *args, **kwargs)
        except Exception as e:
            import json
            import traceback
            logger.error(f'[Document] 未处理的异常: {str(e)}')
            logger.error(f'[Document] 异常堆栈:\n{traceback.format_exc()}')
            from libs import json_response
            return json_response(error='服务器内部错误')
    return wrapper
```

**分析**：
- 所有上传视图都使用了 `@handle_view_errors` 装饰器
- 任何未捕获的异常都会被转换为"服务器内部错误"
- **没有记录具体是哪个异常导致的错误**

## 问题根因

### 根本原因
`DocumentFilePublic` 模型（公共空间文件模型）**没有 `tenant_id` 字段**，但 `naming_utils.py` 中的 `generate_unique_logical_name` 函数对所有模型都使用了 `tenant_id` 过滤，导致查询时报错：

```
Cannot resolve keyword 'tenant_id' into field. Choices are: ...
```

### 错误堆栈
1. `upload.py` 调用 `generate_file_names()`
2. `naming_utils.py:280` 调用 `generate_unique_logical_name()`
3. `naming_utils.py:157` 执行 `FileModel.objects.filter(tenant_id=tenant_id, ...)`
4. **错误**：`DocumentFilePublic` 没有 `tenant_id` 字段

## 临时绕过方案

如果问题紧急，可以临时在 `handle_view_errors` 装饰器中添加更详细的错误返回：

```python
# libs/view_utils.py
def handle_view_errors(func):
    @wraps(func)
    def wrapper(self, request, *args, **kwargs):
        try:
            return func(self, request, *args, **kwargs)
        except Exception as e:
            import traceback
            error_detail = traceback.format_exc()
            logger.error(f'[Document] 未处理的异常: {str(e)}\n{error_detail}')
            # 开发环境返回详细错误
            if settings.DEBUG:
                return json_response(error=f'{str(e)}\n{error_detail[:500]}')
            return json_response(error='服务器内部错误')
    return wrapper
```
