## 二、暂停机制架构

### 2.1 状态定义
```javascript
// 上传任务状态枚举
status: 'waiting'      // 等待中
      | 'calculating'  // 计算MD5中
      | 'uploading'    // 上传中
      | 'paused'       // 已暂停
      | 'merging'      // 合并中
      | 'completed'    // 已完成
      | 'error'        // 失败/错误

// 控制标志
isPausedByUser: boolean     // 用户是否手动暂停
isCancelledByUser: boolean  // 用户是否取消
abortController: AbortController  // 用于分片上传的取消控制
abortToken: CancelToken           // 用于普通上传的取消控制
```

### 2.2 暂停触发流程

```
用户点击暂停按钮
    ↓
pauseItem(itemId) 在 index.js 第682行
    ↓
【关键】先设置状态：item.status = 'paused'
                item.isPausedByUser = true
    ↓
再触发 abort：abortController.abort('用户暂停')
              abortToken.cancel('用户暂停')
    ↓
上传代码 catch 到错误
    ↓
检查 item.status === 'paused' || item.isPausedByUser
    ↓
如果是暂停状态 → 正常返回，不标记为错误
```

**修复位置**: `chunkUpload.js` 第47-58行

```javascript

    status: 'paused',
    error: '已暂停',
    canAbort: false,
```

```javascript
async pauseItem(itemId) {
  // 1. 查找上传项
  const { item, tenantId } = this.queueStore.findUploadItem(itemId);
  if (!item) return;

  // 2. 检查是否可以暂停
  if (item.status !== 'uploading' && item.status !== 'calculating') {
    return;
  }

  try {
    // 【关键修复】3. 先设置状态
    item.status = 'paused';
    item.error = '已暂停';
    item.canAbort = false;
    item.isPausedByUser = true;
    
    // 4. 再触发 abort
    if (item.abortController) {
      item.abortController.abort('用户暂停');
    }
    if (item.abortToken) {
      item.abortToken.cancel('用户暂停');
    }

    // 5. 更新后端状态
    if (item.transferId) {
      await this.transferStore.updateTransferStatus(item.transferId, 'PAUSED');
    }
  } catch (error) {
    // 幂等性处理：忽略"无效的状态转换"错误
    if (error?.message?.includes('无效的状态转换')) {
      return;
```

### 6.2 【建议】MD5计算可中断化

当前 MD5 计算无法中断，大文件计算时用户体验不佳。

#### 方案对比

| 方案 | 实现复杂度 | 用户体验 | 推荐度 |
|------|-----------|---------|--------|
| **A. 轮询检查** (已实施) | 低 | 一般 | ⭐⭐⭐ |
| **B. Promise.race + 取消监听** | 中 | 好 | ⭐⭐⭐⭐ |
| **C. Worker.terminate()** | 低 | 差 | ⭐⭐ |

#### 推荐方案 B：Promise.race + 取消监听

```javascript
// md5.js - 更优雅的取消方案
class MD5Store {
  _cancelListeners = new Map();

  calculateFileMD5(file, uploadId) {
    // 创建可取消的 Promise
    const cancelPromise = new Promise((_, reject) => {
      this._cancelListeners.set(uploadId, reject);
    });
    
    const md5Promise = this.calculateFileMD5Internal(file, uploadId);
    
    return Promise.race([md5Promise, cancelPromise]).finally(() => {
      this._cancelListeners.delete(uploadId);
    });
  }
  
  // 外部调用取消
  cancelMD5(uploadId) {
    const reject = this._cancelListeners.get(uploadId);
    if (reject) {
      reject(new Error('用户暂停'));
      this._cancelListeners.delete(uploadId);
    }
  }
  
  // 原有的计算逻辑
  async calculateFileMD5Internal(file, uploadId) {
    // ... Web Worker 计算逻辑
  }
}
```

**为什么不推荐 Worker.terminate()？**
- 虽然可以立即终止计算，但会丢失 Worker 状态
- 再次恢复上传时需要重新创建 Worker，增加开销
- 已计算的进度丢失，需要从头开始

**实施建议**: 当前方案A已满足基本需求，方案B可作为优化迭代。
