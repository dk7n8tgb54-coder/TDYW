### 2.1 优化前代码（12次查询）

# ❌ 低效实现：12次独立数据库查询
logs = apply_tenant_filter(RunLog.objects.all(), request.user)

# 按状态统计（2次查询）
for status, text in [('in_progress', '处理中'), ('resolved', '已解决')]:

for severity, text in [('P0', '紧急'), ('P1', '重要'), ('P2', '一般')]:
    count = logs.filter(severity=severity).count()

# 近7天趋势（7次查询）
for i in range(7):
    date = (datetime.now() - timedelta(days=i)).strftime('%Y-%m-%d')
    count = logs.filter(created_at__startswith=date).count()

### 2.2 优化后代码（2次查询）

```python
from django.db.models import Count, Q, DatabaseError
from collections import defaultdict
import logging

logger = logging.getLogger(__name__)

def get(self, request):
    """
    获取统计数据（优化版本）

    优化内容：
    - 2次聚合查询替代12次独立查询
    - 租户ID有效性校验
    - 7天内无数据时的边界处理
    - 数据库异常分类处理
    - 详细的日志记录
    """
    try:
        logs = apply_tenant_filter(RunLog.objects.all(), request.user)

        # 边界条件1：校验租户ID有效性
        tenant_id = getattr(request.user, 'tenant_id', None)
        if not tenant_id:
            logger.warning(f"无效的租户ID: {tenant_id}")
            return json_response(error='无效的租户ID', status=400)

        now = datetime.now()

        # 边界条件2：初始化统计结果，避免KeyError
        status_stats = {}
        for status, text in [('in_progress', '处理中'), ('resolved', '已解决')]:
            status_stats[status] = {'count': 0, 'text': text}

        severity_stats = {}
        for severity, text in [('P0', '紧急'), ('P1', '重要'), ('P2', '一般')]:
            severity_stats[severity] = {'count': 0, 'text': text}

        date_stats = defaultdict(int)
        for i in range(7):
            date = (now - timedelta(days=i)).strftime('%Y-%m-%d')
            date_stats[date] = 0

        # 查询1：聚合统计状态和级别（1次查询）
        agg_stats = logs.aggregate(
            in_progress_count=Count('id', filter=Q(status='in_progress')),
            resolved_count=Count('id', filter=Q(status='resolved')),
            p0_count=Count('id', filter=Q(severity='P0')),
            p1_count=Count('id', filter=Q(severity='P1')),
            p2_count=Count('id', filter=Q(severity='P2'))
        )

        # 更新统计结果
        status_stats['in_progress']['count'] = agg_stats['in_progress_count'] or 0
        status_stats['resolved']['count'] = agg_stats['resolved_count'] or 0
        severity_stats['P0']['count'] = agg_stats['p0_count'] or 0
        severity_stats['P1']['count'] = agg_stats['p1_count'] or 0
        severity_stats['P2']['count'] = agg_stats['p2_count'] or 0

        # 查询2：日期分组统计（1次查询，使用range优化）
        start_date = (now - timedelta(days=6)).replace(hour=0, minute=0, second=0, microsecond=0)
        end_date = now.replace(hour=23, minute=59, second=59, microsecond=999999)
        logs_by_date = logs.filter(created_at__range=(start_date, end_date)).extra(
            select={'day': 'DATE(created_at)'}
        ).values('day').annotate(count=Count('id'))

        for item in logs_by_date:
            date_str = item['day'].strftime('%Y-%m-%d')
            date_stats[date_str] = item['count']

        logger.info(f"[统计查询成功] tenant_id={tenant_id}, "
                   f"in_progress={status_stats['in_progress']['count']}, "
                   f"resolved={status_stats['resolved']['count']}")

        # 构建趋势数据（按日期正序）
        trend_data = [
            {'date': date, 'count': date_stats[date]}
            for date in sorted(date_stats.keys())
        ]

        return json_response({
            'status_stats': status_stats,
            'severity_stats': severity_stats,
            'trend_data': trend_data,
        })

    except DatabaseError as e:
        # 数据库异常
        logger.error(f"[统计接口数据库查询失败] tenant_id={tenant_id}, 错误={str(e)}", exc_info=True)
        return json_response(error='数据库查询失败', status=500)
    except Exception as e:
        # 其他未捕获异常
        logger.error(f"[统计接口未知错误] tenant_id={tenant_id}, 错误={str(e)}", exc_info=True)
        return json_response(error='服务器内部错误', status=500)
```

## 三、核心改进点

### 3.1 聚合查询优化

**优化原理**：
- 使用Django ORM的`aggregate()`方法，将多个`count()`查询合并为单个聚合查询
- 使用`Count('id', filter=Q(...))`条件计数，避免多次过滤

**SQL对比**：

优化前（12次查询）：
```sql
SELECT COUNT(*) FROM runlog WHERE tenant_id=1 AND status='in_progress';
SELECT COUNT(*) FROM runlog WHERE tenant_id=1 AND status='resolved';
SELECT COUNT(*) FROM runlog WHERE tenant_id=1 AND severity='P0';
SELECT COUNT(*) FROM runlog WHERE tenant_id=1 AND severity='P1';
SELECT COUNT(*) FROM runlog WHERE tenant_id=1 AND severity='P2';
SELECT COUNT(*) FROM runlog WHERE tenant_id=1 AND created_at LIKE '2026-03-18%';
SELECT COUNT(*) FROM runlog WHERE tenant_id=1 AND created_at LIKE '2026-03-17%';
-- ... 共12次
```

优化后（2次查询）：
```sql
-- 查询1：聚合统计
SELECT
    COUNT(CASE WHEN status='in_progress' THEN 1 END) AS in_progress_count,
    COUNT(CASE WHEN status='resolved' THEN 1 END) AS resolved_count,
    COUNT(CASE WHEN severity='P0' THEN 1 END) AS p0_count,
    COUNT(CASE WHEN severity='P1' THEN 1 END) AS p1_count,
    COUNT(CASE WHEN severity='P2' THEN 1 END) AS p2_count
FROM runlog
WHERE tenant_id=1;

-- 查询2：日期分组统计（使用range优化）
SELECT DATE(created_at) AS day, COUNT(*) AS count
FROM runlog
WHERE tenant_id=1 AND created_at >= '2026-03-12 00:00:00'
GROUP BY DATE(created_at);
```

### 3.2 异常处理增强

**改进点**：
1. **租户ID校验**：防止无效请求导致的数据库查询
2. **边界条件处理**：初始化默认值，避免7天内无数据时KeyError
3. **异常分类处理**：DatabaseError单独处理，便于日志分析
4. **详细日志记录**：记录查询结果，便于问题排查

### 3.3 日期查询优化

**优化点**：
- 使用`created_at__range`闭开区间查询，充分利用索引范围扫描特性
- 避免使用`created_at__startswith`（字符串匹配）
