# 传输列表暂停问题修复方案

## 问题描述

**现象**: 点击暂停正在传输的任务后，任务仍然会变成"传输失败"状态。

**根本原因**: 多个 catch 块在处理暂停/取消错误时，最后都会执行 `throw error`，导致错误被继续传播到上层，最终被错误地标记为传输失败。

---

## 问题分析

### 核心问题

所有错误处理函数的逻辑结构如下：

```javascript
try {
  // 上传逻辑...
} catch (error) {
  if (是暂停错误) {
    // 处理暂停...
    return;  // 应该在这里返回
  }
  
  // 处理其他错误...
  
  throw error;  // ❌ 问题：这行会执行，导致错误继续传播
}
```

问题在于 `throw error` 在条件块之外，即使前面已经处理了暂停错误并执行了 `return`，但代码逻辑错误导致 `throw error` 仍然执行。

### 受影响的文件

1. **chunkUpload.js** - `uploadFileChunked` 顶层 catch 块
2. **fileUpload.js** - `uploadFileNormal` catch 块
3. **fileUpload.js** - `uploadFileToFolder` catch 块
4. **index.js** - `resumeChunkedUpload` catch 块

---

## 修复方案

### 修复原则

1. **暂停错误不抛出**: 所有暂停/取消相关的错误都应该被捕获并处理，不再向上抛出
2. **统一错误消息检查**: 统一检查 "用户暂停"、"用户取消"、"上传取消"、"已取消" 等消息
3. **确保状态正确**: 如果是暂停错误但状态不是暂停，自动修正状态
4. **资源清理**: 暂停时正确清理 abortController 和 abortToken

**修复后**:
```javascript
} catch (error) {
  const axios = await import('axios');
  const isCancel = axios.default.isCancel(error);
  const errorMsg = error?.message || String(error);
  const isPauseMessage = errorMsg.includes('用户暂停') || errorMsg.includes('User paused');

  const item = this.queueStore.findUploadItemInCurrentTenant(uploadId);
  if (item) {
    // 【关键修复】检查是否是暂停，避免误标记为错误
    if (item.status === 'paused' || item.isPausedByUser) {
      // 已经是暂停状态，不修改状态，直接清理
      item.canAbort = false;
      item.abortToken = null;
      return;  // 【关键】暂停状态直接返回，不抛出错误
    } else if (isCancel || isPauseMessage) {
      // 【关键修复】如果是暂停导致的取消，标记为暂停而不是错误
      item.status = 'paused';
      item.error = '已暂停';
      item.canAbort = false;
      item.abortToken = null;
      return;  // 【关键】直接返回，不抛出错误
    } else {
      // 真正的错误
      item.status = 'error';
      item.error = error.message || '上传失败';
      item.canAbort = false;
      
      // 标记传输记录为失败
      if (item.transferId && this.rootStore.transferStore) {
        this.rootStore.transferStore.markTransferAsFailed(
          item.transferId, 
          error.message || '上传失败'
        );
      }
      
      // 清理唯一标识
      if (item.uniqueKey && this.queueStore.uploadingUniqueKeys) {
        this.queueStore.uploadingUniqueKeys.delete(item.uniqueKey);
      }
      
      // 只有真正的错误才抛出
      throw error;
    }
  }
  
  // 如果没有找到item，且不是取消/暂停错误，抛出
  if (!isCancel && !isPauseMessage) {
    throw error;
  }
}
```

## 修复验证清单

### 测试场景

- [ ] 小文件（<32MB）上传时暂停 → 应该变为"已暂停"状态
- [ ] 大文件（>32MB）上传时暂停 → 应该变为"已暂停"状态
- [ ] 计算MD5时暂停 → 应该变为"已暂停"状态，MD5完成后不上传
- [ ] 合并阶段暂停 → 应该变为"已暂停"状态
- [ ] 断点续传时暂停 → 应该变为"已暂停"状态
- [ ] 快速连续点击暂停/恢复 → 状态应该正确，不出现错误
- [ ] 全部暂停 → 所有任务应该变为"已暂停"状态

## 总结

### 修复要点

1. **统一错误消息检查**: 检查 "用户暂停"、"用户取消"、"上传取消"、"已取消"
2. **暂停错误不抛出**: 所有暂停相关的错误都应该在 catch 块内处理完毕，不再向上抛出
3. **确保状态正确**: 如果检测到暂停错误但状态不是暂停，自动修正为暂停状态
4. **清理资源**: 暂停时清理 abortController 和 abortToken，防止内存泄漏
