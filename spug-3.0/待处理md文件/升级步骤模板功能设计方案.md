# 升级步骤模板功能设计方案

## 一、背景与问题分析

### 1.1 现状

当前系统升级管理模块的核心流程是：

1. **创建升级表单**（`UpgradeRecord`）：填写升级单号、系统、升级类型、版本等基本信息
2. **追加升级记录**（`UpgradeRecordUpdate`）：以自由文本方式逐步记录升级过程

**核心问题**：升级记录（`UpgradeRecordUpdate`）是一个**时间线式的自由日志**，`detail_content` 是纯文本字段，没有预定义的结构和步骤顺序。每次升级都是从零手动填写，存在以下痛点：

| 痛点 | 说明 |
|------|------|
| **重复劳动** | 同类型升级（如Bug修复）每次都要手写相似的步骤描述 |
| **遗漏风险** | 没有标准化步骤指引，容易遗漏关键操作（如备份、验证） |
| **质量不均** | 不同人员记录的升级记录格式、详细程度差异大 |
| **无法对比** | 缺乏结构化步骤，难以横向对比同类升级的执行情况 |
| **升级类型无差异化** | `upgrade_type`（功能升级/Bug修复/安全补丁/性能优化）只是分类标签，不影响流程 |

### 1.2 历史教训

从迁移文件分析可见，V1版本的 `UpgradeRecord` 曾经有 `checklist`（清单）和 `dependencies`（依赖）等 JSON 数组字段，但后来被删除了。这说明：

- 曾经尝试过结构化升级内容，但方案过于"一次性表单"化（所有信息堆在主表中）
- 正确的方向应该是**可复用的模板 + 动态执行的步骤**，而不是固定字段

## 二、功能定义

### 2.1 术语定义

| 术语 | 英文 | 说明 |
|------|------|------|
| **升级模板** | Upgrade Template | 可复用的升级流程模板，包含一组有序的步骤定义 |
| **步骤定义** | Step Definition | 模板中的标准化步骤，包含步骤名称、描述、顺序、是否必须等属性 |
| **步骤实例** | Step Instance | 基于步骤定义生成的升级实例步骤，带执行状态和记录 |
| **升级记录** | Upgrade Update | 保留现有概念，作为步骤实例的执行日志补充 |

### 2.2 核心概念

```
升级模板（UpgradeTemplate）
  └── 步骤定义列表（StepDefinition[]）
        ├── 1. 升级前备份
        ├── 2. 通知相关人员
        ├── 3. 执行升级操作
        ├── 4. 升级后验证
        └── 5. 恢复服务

升级表单（UpgradeRecord）── 选择模板后
  └── 步骤实例列表（StepInstance[]）
        ├── 1. 升级前备份 ── [待执行/进行中/已完成/已跳过]
        ├── 2. 通知相关人员 ── [待执行/进行中/已完成/已跳过]
        ├── 3. 执行升级操作 ── [待执行/进行中/已完成/已跳过]
        ├── 4. 升级后验证 ── [待执行/进行中/已完成/已跳过]
        └── 5. 恢复服务 ── [待执行/进行中/已完成/已跳过]
  └── 升级记录（UpgradeRecordUpdate）── 自由日志补充
```

**关键设计决策**：步骤实例与升级记录**并存**而非替代。步骤实例提供结构化执行追踪，升级记录提供自由文本的详细日志。两者互补。

## 三、数据模型设计

### 3.1 新增模型

#### 3.1.1 UpgradeTemplate（升级模板）

```python
class UpgradeTemplate(models.Model, ModelMixin):
    """升级模板 - 定义可复用的升级流程"""
    TENANT_TYPE = TENANT_TYPE_PRIVATE
    tenant_id = models.CharField(max_length=50, default='', help_text='租户标识')
    
    # 基本信息
    name = models.CharField(max_length=200, help_text='模板名称')
    code = models.CharField(max_length=50, help_text='模板编码，如 BUG_FIX_STANDARD')
    description = models.TextField(blank=True, default='', help_text='模板描述')
    
    # 适用范围
    upgrade_type = models.CharField(max_length=50, blank=True, default='', 
                                     help_text='适用升级类型（空=通用）')
    system = models.CharField(max_length=100, blank=True, default='',
                               help_text='适用系统（空=通用）')
    
    # 模板状态
    is_active = models.BooleanField(default=True, help_text='是否启用')
    is_builtin = models.BooleanField(default=False, help_text='是否内置模板（不可删除）')
    
    # 统计
    usage_count = models.IntegerField(default=0, help_text='使用次数')
    step_count = models.IntegerField(default=0, help_text='步骤数量')
    
    # 审计
    created_at = models.CharField(max_length=20, default=human_datetime)
    created_by = models.ForeignKey(User, models.PROTECT, related_name='+')
    updated_at = models.CharField(max_length=20, null=True)
    updated_by = models.ForeignKey(User, models.PROTECT, related_name='+', null=True)
    
    class Meta:
        db_table = 'exec_upgrade_templates'
        ordering = ('-is_builtin', '-usage_count', 'name')
        unique_together = [['tenant_id', 'code']]
        indexes = [
            models.Index(fields=['tenant_id', 'is_active']),
            models.Index(fields=['tenant_id', 'upgrade_type']),
        ]
```

#### 3.1.2 StepDefinition（步骤定义）

```python
class StepDefinition(models.Model, ModelMixin):
    """步骤定义 - 模板中的标准化步骤"""
    TENANT_TYPE = TENANT_TYPE_PRIVATE
    tenant_id = models.CharField(max_length=50, default='', help_text='租户标识')
    
    # 关联模板
    template_id = models.IntegerField(help_text='关联模板ID')
    
    # 步骤内容
    name = models.CharField(max_length=200, help_text='步骤名称')
    description = models.TextField(blank=True, default='', help_text='步骤详细说明/操作指引')
    order = models.IntegerField(default=0, help_text='步骤顺序（从1开始）')
    
    # 步骤属性
    is_required = models.BooleanField(default=True, help_text='是否必须步骤（必须步骤不可跳过）')
    estimated_duration = models.IntegerField(default=0, help_text='预计耗时（分钟，0=未设定）')
    
    # 步骤分类（用于UI展示和统计）
    category = models.CharField(max_length=50, blank=True, default='', 
                                 help_text='步骤分类：准备/执行/验证/收尾')
    
    # 回滚指引
    rollback_guide = models.TextField(blank=True, default='', help_text='回滚操作指引')
    
    # 审计
    created_at = models.CharField(max_length=20, default=human_datetime)
    created_by = models.ForeignKey(User, models.PROTECT, related_name='+')
    
    class Meta:
        db_table = 'exec_upgrade_step_definitions'
        ordering = ('template_id', 'order', 'id')
        indexes = [
            models.Index(fields=['template_id']),
            models.Index(fields=['tenant_id', 'template_id']),
        ]
```

#### 3.1.3 StepInstance（步骤实例）

```python
class StepInstance(models.Model, ModelMixin):
    """步骤实例 - 升级表单中基于模板生成的执行步骤"""
    TENANT_TYPE = TENANT_TYPE_PRIVATE
    tenant_id = models.CharField(max_length=50, default='', help_text='租户标识')
    
    # 关联
    upgrade_id = models.IntegerField(help_text='关联升级表单ID')
    template_id = models.IntegerField(help_text='来源模板ID（记录来源，模板可被修改不影响已生成实例）')
    step_definition_id = models.IntegerField(help_text='来源步骤定义ID')
    
    # 步骤内容（从步骤定义复制，生成后独立）
    name = models.CharField(max_length=200, help_text='步骤名称')
    description = models.TextField(blank=True, default='', help_text='步骤说明')
    order = models.IntegerField(default=0, help_text='步骤顺序')
    is_required = models.BooleanField(default=True, help_text='是否必须步骤')
    category = models.CharField(max_length=50, blank=True, default='', help_text='步骤分类')
    rollback_guide = models.TextField(blank=True, default='', help_text='回滚指引')
    
    # 执行状态
    STATUS_CHOICES = [
        ('pending', '待执行'),
        ('in_progress', '进行中'),
        ('completed', '已完成'),
        ('skipped', '已跳过'),
        ('failed', '执行失败'),
    ]
    status = models.CharField(max_length=20, default='pending', choices=STATUS_CHOICES)
    
    # 执行信息
    started_at = models.CharField(max_length=20, null=True, blank=True, help_text='开始执行时间')
    completed_at = models.CharField(max_length=20, null=True, blank=True, help_text='完成时间')
    executed_by = models.CharField(max_length=100, blank=True, default='', help_text='执行人')
    execution_note = models.TextField(blank=True, default='', help_text='执行备注/结果记录')
    
    # 跳过原因（仅 skipped 状态时填写）
    skip_reason = models.TextField(blank=True, default='', help_text='跳过原因')
    
    # 审计
    created_at = models.CharField(max_length=20, default=human_datetime)
    created_by = models.ForeignKey(User, models.PROTECT, related_name='+')
    updated_at = models.CharField(max_length=20, null=True)
    
    class Meta:
        db_table = 'exec_upgrade_step_instances'
        ordering = ('upgrade_id', 'order', 'id')
        indexes = [
            models.Index(fields=['upgrade_id']),
            models.Index(fields=['tenant_id', 'upgrade_id']),
            models.Index(fields=['template_id']),
            models.Index(fields=['status']),
        ]
```

### 4.1 模板管理接口

#### UpgradeTemplateView

|------|-----|------|------|
| GET | `/api/upgrade/template/` | 获取模板列表/详情 | `upgrade.template.view` |
| POST | `/api/upgrade/template/` | 创建模板（含步骤定义） | `upgrade.template.add` |

### 4.3 现有接口改造

#### UpgradeRecordView 改造

**POST 创建升级表单** — 增加 `template_id` 参数：

```json
{
  "upgrade_no": "UPG-2026-001",
  "system": "核心系统",
  "upgrade_type": "Bug修复",
  "template_id": 1,  // 新增：选择模板
  "first_update": {
    "update_date": "2026-04-27",
    "recorder": "张三",
    "detail_content": "开始执行Bug修复升级"
  }
}
```

后端逻辑：
1. 校验 `template_id` 对应的模板存在且 `is_active=True`
2. 从 `StepDefinition` 批量生成 `StepInstance`（复制步骤内容到实例）
3. 更新 `UpgradeRecord.template_id`、`template_name`、`total_steps`
4. 模板 `usage_count += 1`

**不选择模板** — `template_id` 为空时，行为与现有完全一致（向后兼容）。

## 九、向后兼容性

### 9.1 核心原则：**模板是可选的增强，不是必需的替代**

| 场景 | 行为 |
|------|------|
| 创建升级表单时不选模板 | 与现有行为完全一致，不生成步骤实例 |
| 创建升级表单时选择模板 | 在现有行为基础上，额外生成步骤实例 |
| 已有升级表单（无模板） | 不受影响，正常显示，步骤Tab显示"未使用模板" |
| 模板被修改 | 不影响已生成的步骤实例（实例内容独立） |
| 模板被删除 | 不影响已生成的步骤实例（模板名称已快照） |
| 模板被停用 | 不影响已生成的步骤实例，新建表单时不可选该模板 |

### 9.2 API兼容性

- 所有现有API接口保持不变
- 新增字段均有默认值，不影响现有前端
- 新增的模板和步骤接口是独立的URL路径

## 十、实现优先级与里程碑

### Phase 1：基础框架（核心可用）

1. 创建三个新模型 + 数据库迁移
2. 内置模板初始化
3. 模板CRUD后端API
4. 升级表单创建时支持选择模板
5. 步骤实例生成逻辑
6. 步骤执行状态更新API

**交付标准**：通过API可以创建模板、创建升级表单时选择模板、更新步骤状态

### Phase 2：前端完善（用户体验）

1. 模板管理页面（列表/编辑/步骤拖拽排序）
2. 升级表单创建页 — 模板选择器 + 步骤预览
3. 升级表单详情页 — 步骤Timeline + 执行操作
4. 升级表单列表 — 步骤进度列

**交付标准**：用户可以完整使用模板功能，不使用模板时体验不变

### Phase 3：增强功能（锦上添花）

1. 模板复制功能（基于现有模板快速创建新模板）
2. 升级类型与模板自动关联（选择升级类型时自动推荐模板）
3. 步骤执行与升级记录的关联（在步骤中可以直接创建升级记录）
4. 升级进度自动更新主表单状态（所有必须步骤完成 → 自动标记"已完成"）
5. 模板使用统计和优化建议
6. 步骤超时预警（超过预计耗时提醒）

## 十一、风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 模板步骤与实际操作不符 | 步骤流于形式 | 允许跳过非必须步骤；支持执行中添加自定义步骤 |
| 步骤实例数据膨胀 | 数据库存储增加 | 步骤实例内容简洁；定期归档已完成的升级表单 |
| 用户不愿改变习惯 | 功能使用率低 | 模板完全可选，渐进式推广；内置模板降低使用门槛 |
| 模板维护成本 | 过多模板难以管理 | 内置模板不可删但可停用；定期清理低使用率模板 |

## 十二、总结

本方案的核心思路是**增量增强**而非颠覆重构：

1. **保留现有升级记录的自由日志模式** — 不破坏现有使用习惯
2. **新增模板+步骤的结构化模式** — 为需要标准化的场景提供工具
3. **两种模式并存互补** — 步骤追踪"做了什么"，升级记录记录"怎么做的"
4. **完全向后兼容** — 不选模板时行为与现有完全一致
5. **内置模板开箱即用** — 降低使用门槛，避免从零开始配置
