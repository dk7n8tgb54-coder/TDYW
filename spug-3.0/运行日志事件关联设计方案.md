# 运行日志事件关联设计方案

## 核心模型

```
运行日志事件 ────┬─── 动态1：故障发生（来自设备履历）
（如：支付故障）  ├── 动态2：排查过程（手动录入）
                ├── 动态3：系统升级（来自升级模块）
                └── 动态4：故障修复（来自设备履历）
```

**关键理解：**
- 运行日志 = 事件列表（如"支付服务故障"、"机房搬迁"）
- 事件动态 = 时间线（可来自任何模块、任何时间）
- 关联是**事件-模块**级别，不是日期级别

---

## 数据模型

### 运行日志事件表 `runlog_event`

| 字段 | 说明 |
|------|------|
| `id` | 事件ID |
| `title` | 事件标题 |
| `event_type` | 事件类型（故障/升级/干扰/其他） |
| `status` | 状态（进行中/已完成） |
| `creator` | 创建人 |
| `created_at` | 创建时间 |
| `completed_at` | 完成时间 |

### 运行动态表 `runlog_activity`

| 字段 | 说明 |
|------|------|
| `id` | 动态ID |
| `event_id` | 所属事件ID |
| `activity_type` | 动态类型（manual/auto） |
| `content` | 动态内容（手动填写或模块摘要） |
| `source_module` | 来源模块（如 fault/upgrade/interference） |
| `source_id` | 来源记录ID |
| `operator` | 操作人 |
| `created_at` | 时间 |

### 与之前方案的区别

| 维度 | 错误方案（日期聚合） | 正确方案（事件关联） |
|------|----------------------|----------------------|
| 关联粒度 | 按日期聚合 | 按事件关联 |
| 关联时机 | 查询时自动 | 录入时主动选择 |
| 灵活性 | 低（只能当天） | 高（任意时间） |
| 准确性 | 低（可能混入无关记录） | 高（精确关联） |

## 关键交互点

### 1. 快速创建事件
在模块录入时，如果没有匹配事件，可一键创建：
```
[💡 快速创建事件并关联]
标题：支付服务超时故障处置（自动取故障标题）
类型：故障处理（自动识别）
[确认创建并关联]
```

### 2. 事件选择器
搜索支持：
- 按标题模糊搜索
- 显示最近修改的10个未完成事件
- 按类型筛选

### 3. 动态同步策略
- **创建时**：模块记录创建 → 同时创建运行动态
- **更新时**：可选"更新关联动态"或"新增动态"
- **删除时**：提示"是否同步删除运行动态"

## 实施要点

1. **各模块表单改造**
   - 底部统一增加关联区域组件
   - 保存时检查是否有事件关联

2. **运行日志改造**
   - 改为事件列表页
   - 事件详情页显示动态时间线
   - 支持手动添加纯文本动态

3. **API设计**
   - `GET /runlog/events?status=ongoing` 获取未完成事件
   - `POST /runlog/events` 创建事件
   - `POST /runlog/activities` 添加动态
   - 各模块保存时传入 `runlog_event_id` 参数
