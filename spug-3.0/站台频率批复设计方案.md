# 台站频率批复 设计方案

> 模块归属：执照管理（radio_license）下的二级菜单「台站频率批复」
> 设计原则：台账记录定位，复用现有执照模块的模型/接口/前端模式增量扩展；到期提醒完全对齐合同协议（Celery 扫描 + 三态状态 + ack 确认 + 弹窗 + 红点）；附件复用公共 AttachmentService。

---

## 一、目标与范围

在「执照管理」下新增「台站频率批复」子模块，管理频率批复文件（一种官方许可批复文书）。核心诉求：

1. **台账记录**：文件名称、文件编号、批复频率、起始日期、截止日期。
2. **到期提醒**：与合同协议完全相同——Celery 每日扫描 → 三态状态（normal/expiring/expired）落库 → 弹窗提醒责任人 → 用户"已处理"写 ack → 续期后自动失效重新弹 → 菜单红点。
3. **附件功能**：复用公共附件组件 AttachmentManager，支持上传/下载/在线预览/删除。

### 人工填写字段（5 项）

| 字段 | 模型字段名 | 类型 | 说明 |
|---|---|---|---|
| 文件名称 | `name` | CharField(200) | 批复文件名称 |
| 文件编号 | `doc_no` | CharField(100) | 批复文件编号，如"工信无〔2026〕第XX号" |
| 批复频率 | `frequency_text` | CharField(200) | 批复涉及的频率，文本输入（如"137-174 MHz"或"156.8 MHz"） |
| 起始日期 | `valid_from` | DateField | 有效期起始 |
| 截止日期 | `valid_to` | DateField | 有效期截止（到期提醒依据） |

### 非人工填写字段（系统/扫描自动维护）

| 字段 | 模型字段名 | 类型 | 说明 |
|---|---|---|---|
| 责任人ID | `responsible_user_id` | IntegerField(null) | **建议人工选择**（虽不在用户列出的 5 项中，但到期提醒依赖此字段——弹窗只推送给责任人，对齐合同协议/执照） |
| 责任人姓名 | `responsible_user_name` | CharField(100) | 冗余存储，避免联表 |
| 状态 | `status` | CharField(20) | `normal`/`expiring`/`expired`，Celery 扫描任务计算落库 |
| 最近提醒时间 | `last_remind_at` | CharField(20) | 扫描任务每次执行时更新 |
| 备注 | `remark` | TextField | 可选人工填写 |
| 租户ID | `tenant_id` | CharField(50) | 租户隔离，系统自动 |
| 创建时间/人 | `created_at`/`created_by` | — | 系统自动 |
| 更新时间/人 | `updated_at`/`updated_by` | — | 系统自动 |
| 附件数 | `attachment_count` | — | **不落库**，接口实时计算 |

> **关于责任人**：合同协议和执照的到期提醒弹窗（popup 接口）都按 `responsible_user_id = 当前用户` 过滤。若不加责任人字段，提醒将无法定向推送。因此建议责任人为**必填项**（表单校验），到期提醒才能与合同协议一致。

### 不在本次范围（YAGNI）

- **不做执照双向关联**：批复是独立台账记录，用户未要求与执照关联互跳。
- **不做频率明细表**：批复频率用文本字段，符合台账简单定位；如未来需结构化管理多频率，再扩展明细表。
- **不做版本历史/证据包**：如需，后续单独迭代。

### 2.2 StationFrequencyApprovalReminderAck（提醒确认表）

完全对齐 `LicenseReminderAck`：

```python
class StationFrequencyApprovalReminderAck(models.Model, TenantModelMixin):
    """台站频率批复到期提醒确认记录

    设计原则（与 LicenseReminderAck 一致）：
    - 只保存"用户确认状态"，不保存提醒历史日志
    - 续期失效靠数据本身：ack_valid_to 记录确认时的 valid_to，
      批复 valid_to 变化（续期）后 ack 自动失效，无需手动作废

    弹窗判断逻辑（ApprovalReminderPopupView）：
        approval.status IN (expiring, expired)
        AND NOT EXISTS ack WHERE approval_id=X AND user_id=Y AND ack_valid_to=approval.valid_to
    """
    objects = TenantModelManager()
    tenant_id = make_tenant_id()

    approval = models.ForeignKey(
        StationFrequencyApproval, models.CASCADE, related_name='reminder_acks', help_text='批复')
    user_id = models.IntegerField(help_text='确认处理的用户ID')
    user_name = models.CharField(max_length=100, default='', help_text='确认处理的用户名称')
    ack_valid_to = models.DateField(help_text='确认时批复的截止日期（用于续期后自动失效）')

    created_at = models.CharField(max_length=20, default=human_datetime)

    def __repr__(self):
        return '<StationFrequencyApprovalReminderAck approval=%s user=%s valid_to=%s>' % (
            self.approval_id, self.user_id, self.ack_valid_to)

    def to_view(self):
        return self.to_dict()

    class Meta:
        db_table = 'tdyw_station_frequency_approval_reminder_ack'
        verbose_name = '频率批复提醒确认'
        verbose_name_plural = '频率批复提醒确认'
        ordering = ('-created_at',)
        indexes = [
            models.Index(fields=['tenant_id', 'user_id', 'approval'], name='tdyw_sfra_ack_user_idx'),
        ]
        constraints = [
            models.UniqueConstraint(
                fields=['tenant_id', 'approval_id', 'user_id', 'ack_valid_to'],
                name='uniq_approval_user_valid_to',
            ),
        ]
```

> 复用现有 `EXPIRING_DAYS_THRESHOLD = 60` 常量（已在 `models.py` 第 84 行定义），批复与执照/合同协议共用同一阈值。

## 三、到期提醒机制（对齐合同协议）

完整链路与合同协议/执照模块一致：

```
Celery Beat 每日扫描
    │
    ▼
scan_approval_expiration 任务
    │ 遍历所有批复，计算 days_left
    │ days_left < 0           → expired
    │ 0 <= days_left <= 60    → expiring
    │ days_left > 60          → normal
    │ 更新 approval.status + last_remind_at（落库）
    ▼
前端 ApprovalReminderNotification 组件（5 分钟轮询）
    │ GET /api/radio-license/approvals/reminders/popup/
    │   查当前用户负责的 expiring/expired 批复，排除已 ack 的
    │ antd notification 弹窗（bottomRight，不自动关闭）
    │   ├──「今日不再提醒」→ localStorage 按日期+用户+批复ID 抑制
    │   ├──「已处理」→ POST /api/radio-license/approvals/reminders/ack/
    │   │             写 ApprovalReminderAck（ack_valid_to=当前 valid_to）
    │   │             续期后 valid_to 变化 → 旧 ack 自动失效 → 重新弹窗
    │   └── 点击弹窗 → 跳转 /station-frequency-approval?id={approval_id}
    ▼
前端 ApprovalBadgeStore（5 分钟轮询）
    │ GET /api/radio-license/approvals/badge/
    │   返回即将到期 + 已过期数量
    ▼
layout/Sider.js 渲染菜单红点 Badge
```

### 3.1 后端扫描任务

在 `apps/radio_license/tasks.py` 新增（对齐现有 `scan_radio_license_expiration`）：

```python
from apps.radio_license.models import (
    RadioLicense, StationFrequencyApproval, EXPIRING_DAYS_THRESHOLD
)

def scan_single_approval(approval, today=None):
    """扫描单条批复到期状态并更新 status"""
    if today is None:
        today = timezone.now().date()
    status, days_left = calculate_license_status(approval.valid_to, today)
    # 复用 calculate_license_status（已存在，逻辑通用）

    update_data = {'last_remind_at': human_datetime()}
    updated = False
    if approval.status != status:
        update_data['status'] = status
        approval.status = status
        updated = True
    StationFrequencyApproval.objects.filter(pk=approval.id).update(**update_data)
    return {'status': status, 'days_left': days_left, 'updated': updated}


@shared_task(bind=True, soft_time_limit=300, time_limit=600, queue='radio_license')
def scan_approval_expiration(self):
    """扫描所有台站频率批复到期状态"""
    today = timezone.now().date()
    approvals = StationFrequencyApproval.objects.all().select_related('created_by')
    total = approvals.count()
    updated_count = 0
    for approval in approvals:
        result = scan_single_approval(approval, today)
        if result['updated']:
            updated_count += 1
    logger.info('[StationFrequencyApproval] scan all: total=%s, updated=%s', total, updated_count)
    return {'total': total, 'updated': updated_count}
```

### 3.3 后端提醒接口

在 `apps/radio_license/views.py` 新增三个视图（对齐 `ReminderPopupView` / `ReminderAckView` / `RadioLicenseBadgeView`）：

| 方法 & 路径 | 说明 | 权限 |
|---|---|---|
| `GET /api/radio-license/approvals/reminders/popup/` | 查询当前用户负责的 expiring/expired 批复，排除已 ack 的；返回 `records`（approval_id/name/doc_no/valid_from/valid_to/days_left/status/remind_type） | `radio_license.approval.view` |
| `POST /api/radio-license/approvals/reminders/ack/` | 用户"已处理"→ 写 `StationFrequencyApprovalReminderAck`（ack_valid_to=当前 valid_to）；唯一约束幂等 | `radio_license.approval.view` |
| `GET /api/radio-license/approvals/badge/` | 返回本租户即将到期+已过期批复数量（count/expiring_count/expired_count），实时计算 | `radio_license.approval.view` |

popup 接口核心逻辑（对齐 `ReminderPopupView`）：
```python
qs = apply_tenant_filter(StationFrequencyApproval.objects.all(), request.user)
approvals = qs.filter(
    responsible_user_id=request.user.id,
    valid_to__lte=today + timedelta(days=EXPIRING_DAYS_THRESHOLD),
)
# 排除已 ack 且 ack_valid_to 匹配当前 valid_to 的
acks = StationFrequencyApprovalReminderAck.objects.filter(
    user_id=request.user.id
).values_list('approval_id', 'ack_valid_to')
ack_set = {(aid, vid) for aid, vid in acks}
records = []
for apv in approvals:
    if (apv.id, apv.valid_to) in ack_set:
        continue
    days_left = (apv.valid_to - today).days
    records.append({
        'approval_id': apv.id,
        'name': apv.name,
        'doc_no': apv.doc_no,
        'valid_from': str(apv.valid_from),
        'valid_to': str(apv.valid_to),
        'days_left': days_left,
        'status': apv.status,
        'remind_type': 'expired' if days_left < 0 else 'expiring_daily',
    })
```
