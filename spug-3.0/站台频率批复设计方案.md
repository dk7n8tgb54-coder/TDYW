# 台站频率批复设计方案

> 模块归属：执照管理（`radio_license`）下的二级菜单“台站频率批复”
> 方案定位：独立台账，不与无线电台执照建立业务外键；复用现有租户、权限、附件和到期状态基础能力，但使用批复专属接口，避免执照权限和对象类型串用。

---

## 一、目标与设计结论

新增台站频率批复台账，提供以下能力：

1. 管理文件名称、文件编号、批复频率、起始日期、截止日期和责任人。
2. 按截止日期计算 `normal`、`expiring`、`expired` 三态。
3. 向当前责任人展示未处理的到期弹窗和菜单红点。
4. 用户确认“已处理”后，本有效期周期不再提醒；截止日期变化后自动进入新周期。
5. 通过公共 `AttachmentService` 管理附件，支持上传、列表、下载、在线预览和删除。
6. 所有数据访问必须经过租户过滤，责任人也必须属于当前租户。

### 1.1 本次明确采用的规则

| 事项 | 决策 |
|---|---|
| 台账关系 | 批复独立建表，不关联 `RadioLicense` |
| 文件编号 | 必填，去除首尾空格后在租户内唯一 |
| 批复频率 | 文本字段，不拆频率明细表 |
| 日期关系 | 允许起止日期为同一天，要求 `valid_from <= valid_to` |
| 责任人 | 必填；仅可选择当前租户内启用且未删除的用户 |
| 状态权威来源 | API 实时按 `valid_to` 计算；模型 `status` 是定时任务维护的缓存字段 |
| 提醒阈值 | 复用 `EXPIRING_DAYS_THRESHOLD = 60` |
| 红点口径 | 当前用户负责且尚未 ack 的到期/即将到期数量 |
| 删除附件文件 | 业务对象删除时只软删附件记录，物理文件按公共附件清理策略处理 |
| 导出 | 不在本次范围，不增加无实现对应项的 `approval.export` 权限 |

### 1.2 不在本次范围

- 不做批复与执照的双向关联。
- 不做频率结构化拆分或频率占用分析。
- 不做批复版本历史和证据包导出。
- 不做 OCR、文号自动识别和批量导入。

## 二、数据模型

在 `spug_api/apps/radio_license/models.py` 新增主表和提醒确认表。

### 2.1 StationFrequencyApproval

```python
class StationFrequencyApproval(models.Model, TenantModelMixin):
    """台站频率批复台账"""

    STATUS_NORMAL = 'normal'
    STATUS_EXPIRING = 'expiring'

        (STATUS_NORMAL, '正常'),
        (STATUS_EXPIRING, '即将到期'),
        (STATUS_EXPIRED, '已过期'),

    objects = TenantModelManager()

    responsible_user_id = models.IntegerField(help_text='责任人ID')
    responsible_user_name = models.CharField(max_length=100, default='', help_text='责任人姓名快照')

    status = models.CharField(
        max_length=20,

        default=STATUS_NORMAL,
        help_text='缓存状态',
    )
    remark = models.TextField(default='', blank=True, help_text='备注')

    created_at = models.CharField(max_length=20, default=human_datetime)
    created_by = models.ForeignKey(User, models.PROTECT, related_name='+')

    def __repr__(self):
        return '<StationFrequencyApproval %r>' % self.name

    def to_view(self):
        return self.to_dict()

    class Meta:
        db_table = 'tdyw_station_frequency_approval'
        verbose_name = '台站频率批复'
        verbose_name_plural = '台站频率批复'
        ordering = ('-created_at', '-id')
        constraints = [
            models.UniqueConstraint(
                fields=['tenant_id', 'doc_no'],
                name='uniq_sfa_tenant_doc_no',
            ),
        ]
        indexes = [
            models.Index(
                fields=['tenant_id', '-created_at', '-id'],
                name='sfa_tenant_created_idx',
            ),
            models.Index(
                fields=['tenant_id', 'responsible_user_id', 'valid_to'],
                name='sfa_owner_expiry_idx',

            models.Index(
                fields=['tenant_id', 'valid_to'],
                name='sfa_tenant_expiry_idx',
            ),
        ]
```

说明：

- `responsible_user_name` 是选择责任人时的姓名快照，不能直接采用客户端提交值。
- 不保留 `last_remind_at`。当前机制是前端轮询，不存在准确的“服务端已提醒时间”；每日给所有记录写扫描时间也会产生无意义写放大。
- `attachment_count`、`days_left`、`computed_status` 都是接口计算字段，不落库。

### 2.2 StationFrequencyApprovalReminderAck

```python
class StationFrequencyApprovalReminderAck(models.Model, TenantModelMixin):
    """用户对某一批复有效期周期的提醒确认"""

    objects = TenantModelManager()
    tenant_id = make_tenant_id()

    approval = models.ForeignKey(
        StationFrequencyApproval,
        models.CASCADE,
        related_name='reminder_acks',
        help_text='批复',
    )
    user_id = models.IntegerField(help_text='确认用户ID')
    user_name = models.CharField(max_length=100, default='', help_text='确认用户姓名快照')
    ack_valid_to = models.DateField(help_text='确认时的截止日期')
    created_at = models.CharField(max_length=20, default=human_datetime)

    def __repr__(self):
        return '<StationFrequencyApprovalReminderAck approval=%s user=%s valid_to=%s>' % (
            self.approval_id, self.user_id, self.ack_valid_to)

    def to_view(self):
        return self.to_dict()

    class Meta:
        db_table = 'tdyw_station_frequency_approval_reminder_ack'
        verbose_name = '频率批复提醒确认'
        verbose_name_plural = '频率批复提醒确认'
        ordering = ('-created_at', '-id')
        constraints = [
            models.UniqueConstraint(
                fields=['tenant_id', 'approval', 'user_id', 'ack_valid_to'],
                name='uniq_sfa_ack_cycle',
            ),
        ]
        indexes = [
            models.Index(
                fields=['tenant_id', 'user_id', 'approval'],
                name='sfa_ack_user_approval_idx',
            ),
        ]
```

有效期周期由 `(approval_id, user_id, valid_to)` 标识：

- 用户确认时保存当前 `valid_to`。
- 批复续期后 `valid_to` 改变，旧 ack 不再匹配，新周期重新提醒。
- 更换责任人后，新责任人没有对应 ack，也会收到提醒。
- 删除批复时，外键级联删除 ack。

## 三、服务端校验与状态计算

### 3.1 责任人校验

新增 `_validate_and_fill_approval_responsible_user(form, request_user)`，规则如下：

1. 使用 `responsible_user_id` 查询用户。
2. 用户必须 `is_active=True` 且 `deleted_by_id IS NULL`。
3. 用户的 `tenant_id` 必须等于 `request_user.tenant_id`。
4. 服务端用 `nickname or username` 回填 `responsible_user_name`。
5. 请求体中的 `responsible_user_name` 不作为可信输入，可直接从 API 参数中移除。

即使前端下拉框已经过滤租户，后端仍必须执行上述校验，防止构造请求提交其他租户用户 ID。

### 3.2 日期和文本校验

- `name`、`doc_no`、`frequency_text` 去除首尾空格后不能为空。
- `valid_from` 和 `valid_to` 必须是合法日期。
- `valid_from <= valid_to`。
- 创建和编辑都检查租户内 `doc_no` 重复；编辑时排除自身。
- 数据库唯一约束作为并发请求下的最终保护，捕获 `IntegrityError` 后返回明确的“文件编号已存在”。

### 3.3 状态计算

复用 `apps.radio_license.tasks.calculate_license_status(valid_to, today)` 的通用计算逻辑，但所有调用方统一传入 `timezone.localdate()`：

```text
days_left < 0                    -> expired
0 <= days_left <= 60            -> expiring
days_left > 60                   -> normal
```

约束：

- 列表、详情、popup、badge 以实时计算结果为准。
- 列表的状态筛选直接转换成 `valid_to` 日期条件，不依赖缓存 `status`。
- 创建和编辑成功后立即调用 `scan_single_approval()` 更新缓存状态。
- Celery 每日扫描只是状态缓存兜底，不能成为提醒是否出现的前置条件。

## 四、后端 API

所有批复接口位于 `/api/radio-license/approvals/` 下。

### 4.1 CRUD 和责任人

| 方法和路径 | 权限 | 说明 |
|---|---|---|
| `GET /api/radio-license/approvals/` | `radio_license.approval.view` | 分页列表 |
| `POST /api/radio-license/approvals/` | 分支校验 `approval.add` 或 `approval.edit` | 新增/编辑，`id` 可选 |
| `GET /api/radio-license/approvals/<pk>/` | `radio_license.approval.view` | 详情 |
| `DELETE /api/radio-license/approvals/` | `radio_license.approval.del` | 删除，参数 `id` |
| `GET /api/radio-license/approvals/responsible-users/` | `radio_license.approval.view` | 当前租户可选责任人 |

列表支持以下参数：

| 参数 | 规则 |
|---|---|
| `name` | `icontains` |
| `doc_no` | `icontains` |
| `status` | `normal/expiring/expired`，转换为实时日期范围 |
| `valid_to_start` | 截止日期下界 |
| `valid_to_end` | 截止日期上界 |
| `page` | 最小为 1 |
| `page_size` | 1 到 100，默认 20 |

每条记录返回：

```text
id/name/doc_no/frequency_text/valid_from/valid_to
responsible_user_id/responsible_user_name/remark
status/days_left/computed_status/attachment_count
created_at/created_by_name/updated_at/updated_by_name
```

附件数不能逐条调用 `AttachmentService.count()`。应对当前分页的批复 ID 一次性查询 `EvidenceAttachment`，按 `object_id` 聚合后回填，避免列表 N+1 查询。

### 4.2 新增和编辑事务

统一 POST 接口沿用现有模块模式，但必须在分支内二次检查具体权限：

```text
有 id    -> 必须拥有 radio_license.approval.edit
没有 id  -> 必须拥有 radio_license.approval.add
```

新增和编辑在 `transaction.atomic()` 中执行：

1. 解析并标准化参数。
2. 校验责任人、日期和文件编号。
3. 使用 `assign_tenant_id()` 设置租户；禁止接受客户端 `tenant_id`。
4. 保存主记录。
5. 调用 `scan_single_approval()` 即时更新 `status`。
6. 写入创建或更新审计事件。

### 4.3 删除

删除流程：

1. 使用 `apply_tenant_filter()` 查找批复，不允许直接按主键删除。
2. 在数据库事务中软删 `module='radio_license'`、`object_type='approval'` 的附件记录。
3. 删除批复，数据库级联删除 ack。
4. 写入删除审计事件，至少记录文件名称、文件编号和截止日期。

业务对象删除时附件使用 `delete_file=False`，避免数据库事务回滚后物理文件已经丢失。物理文件由公共附件保留/清理策略统一处理。

## 五、附件接口

公共附件表无法感知批复页面权限和业务对象归属，因此不能直接把现有执照附件 View 原样复用。新增批复专属的薄桥接视图，内部复用 `AttachmentService`。

固定标识：

```python
APPROVAL_ATTACHMENT_MODULE = 'radio_license'
APPROVAL_ATTACHMENT_OBJECT_TYPE = 'approval'
```

### 5.1 接口

| 方法和路径 | 权限 | 额外校验 |
|---|---|---|
| `GET /approvals/<pk>/attachments/` | `approval.view` | 批复属于当前租户 |
| `POST /approvals/<pk>/attachments/` | `approval.view` AND `attachment.upload` | 批复属于当前租户 |
| `GET /approvals/attachments/<id>/download/` | `approval.view` AND `attachment.download` | 附件类型为 `approval`，父批复可访问 |
| `GET /approvals/attachments/<id>/preview-url/` | `approval.view` | 附件类型为 `approval`，父批复可访问 |
| `GET /approvals/attachments/<id>/preview-file/` | preview token | token 中对象类型与数据库一致 |
| `DELETE /approvals/attachments/` | `approval.view` AND `attachment.delete` | 附件类型为 `approval`，父批复可访问 |

后端 `@auth` 当前只表达 OR 权限。需要 AND 权限的附件操作，应由装饰器检查动作权限，再在方法内显式检查 `approval.view`；不能把两个权限用 `|` 连接。

### 5.2 对象归属校验

下载、预览和删除不能只按附件 ID 调用公共 Service。桥接视图必须先确认：

```text
attachment.module == 'radio_license'
attachment.object_type == 'approval'
attachment.object_id 对应的批复属于当前用户可访问租户
```

附件删除审计事件必须使用附件记录中的真实 `module/object_type/object_id`，禁止硬编码成 `license`。

### 5.3 配置

新增 `ApprovalAttachmentConfig`，当前允许：

```text
.pdf .jpg .jpeg .png .gif .bmp .webp
.doc .docx .xls .xlsx .ppt .pptx
.zip .rar .7z
```

单文件最大 50 MB。配置可与执照附件保持同值，但使用独立常量，后续调整不会互相影响。

## 六、到期提醒

### 6.1 每日状态扫描

在 `spug_api/apps/radio_license/tasks.py` 新增：

```python
def scan_single_approval(approval, today=None):
    if today is None:
        today = timezone.localdate()
    status, days_left = calculate_license_status(approval.valid_to, today)
    updated = approval.status != status
    if updated:
        StationFrequencyApproval.objects.filter(pk=approval.pk).update(status=status)
        approval.status = status
    return {'status': status, 'days_left': days_left, 'updated': updated}


@shared_task(bind=True, soft_time_limit=300, time_limit=600, queue='radio_license')
def scan_approval_expiration(self):
    # 遍历全部租户数据，只更新状态发生变化的记录。
    ...
```

全量任务不使用请求租户过滤，因为它负责维护所有租户；`TenantModelManager.objects.all()` 本身不会自动过滤租户。数据量增长后使用 `iterator(chunk_size=500)`，避免一次加载全部对象。

在 `RADIO_LICENSE_BEAT_SCHEDULE` 中新增每天 08:05 的任务，并确认部署环境存在消费 `radio_license` 队列的 worker。

### 6.2 Popup

`GET /api/radio-license/approvals/reminders/popup/`

权限：`radio_license.approval.view`。

查询条件：

```text
tenant_id = 当前租户
responsible_user_id = 当前用户
valid_to <= local_today + 60 天
不存在 tenant_id + approval_id + user_id + ack_valid_to=当前 valid_to 的 ack
```

返回字段：

```text
approval_id/name/doc_no/valid_from/valid_to
days_left/status/remind_type/reminder_cycle
```

其中：

```text
status          = 实时计算状态
remind_type     = expired 或 expiring_daily
reminder_cycle  = "{approval_id}:{valid_to}"
```

ack 查询必须包含 `tenant_id`，不能只按 `user_id` 查询。

### 6.3 Ack

`POST /api/radio-license/approvals/reminders/ack/`

请求参数：`approval_id`。

服务端依次校验：

1. 批复属于当前租户。
2. 当前用户仍是 `responsible_user_id`。
3. 实时状态是 `expiring` 或 `expired`。
4. 使用 `get_or_create()` 写入当前 `valid_to` 周期的 ack，重复请求幂等成功。
5. 写入提醒确认审计事件。

非责任人或正常状态记录不得写入 ack，防止提前确认后在未来错误抑制提醒。

### 6.4 Badge

`GET /api/radio-license/approvals/badge/`

权限：`radio_license.approval.view`。

红点与 popup 使用同一口径：只统计当前用户负责且当前周期未 ack 的记录。返回：

```json
{
  "count": 3,
  "expiring_count": 2,
  "expired_count": 1
}
```

实现可使用 `Exists` 和 `OuterRef` 排除当前周期 ack，避免先加载全部 ack 到 Python。用户点击“已处理”成功后立即刷新 badge，因此数量会同步减少。

```text
文件名称、文件编号、批复频率、起始日期、截止日期、责任人、备注
```

前端日期校验用于即时反馈，后端仍执行最终校验。责任人下拉使用批复专属 `/approvals/responsible-users/` 接口。

附件只在记录已经创建并取得 `id` 后显示。`AttachmentManager` 使用当前组件真实支持的参数：

```jsx
<AttachmentManager
  module="radio_license"
  recordId={info.id}
  listUrl={`/api/radio-license/approvals/${info.id}/attachments/`}
  uploadUrl={`/api/radio-license/approvals/${info.id}/attachments/`}
  deleteUrl="/api/radio-license/approvals/attachments/"
  downloadUrlPrefix="/api/radio-license/approvals/attachments/"
  previewUrlPrefix="/api/radio-license/approvals/attachments/"
  uploadPerm="radio_license.approval.view&radio_license.attachment.upload"
  deletePerm="radio_license.approval.view&radio_license.attachment.delete"
  previewPerm="radio_license.approval.view"
  downloadPerm="radio_license.approval.view&radio_license.attachment.download"
  maxFileSize={50}
  multiple
  accept=".pdf,.jpg,.jpeg,.png,.gif,.bmp,.webp,.doc,.docx,.xls,.xlsx,.ppt,.pptx,.zip,.rar,.7z"
/>
```

`objectId`、`objectType`、`permPrefix` 不是当前组件接口，不得使用。

### 9.3 提醒组件

新增 `spug_web/src/components/ApprovalReminderNotification.js`。

关键规则：

1. 仅有 `radio_license.approval.view` 时才启动轮询。
2. 首次进入延迟 2 秒请求，之后每 5 分钟轮询。
3. 弹窗 key、内存去重 key 和 localStorage mute key 都使用 `reminder_cycle`，不能只使用 `approval_id`。
4. `reminder_cycle` 包含 `valid_to`，因此同一页面生命周期内续期后仍能弹出新周期提醒。
5. “今日不再提醒”的日期使用本地日历日期，不能使用 UTC 的 `toISOString().slice(0, 10)`。
6. ack 成功后关闭弹窗并刷新 badge；ack 失败时保留弹窗并显示错误。
7. 已过期与即将到期使用不同文案，禁止出现“将于 -3 天后到期”。
8. 点击弹窗跳转 `/station-frequency-approval?id={approval_id}`。

### 9.4 二级菜单红点

新增 `spug_web/src/layout/ApprovalBadgeStore.js`，接口为 `/api/radio-license/approvals/badge/`。

`Sider.js` 当前只在顶层 `menus.map()` 中注入红点，而台站频率批复是 `children` 中的二级菜单。实现时必须递归遍历菜单树或专门映射父菜单的 `children`，把 badge 注入 `/station-frequency-approval`，仅向顶层集合增加路径不会生效。

`layout/index.js` 负责：

- 挂载 `<ApprovalReminderNotification />`。
- `approvalBadge.start()`。
- 组件卸载时 `approvalBadge.stop()`。

## 十二、自动化测试

后端测试至少覆盖：

### 12.1 模型和状态

- `days_left` 为 `61/60/0/-1` 时状态边界正确。
- 同租户重复 `doc_no` 被拒绝，不同租户可使用相同编号。
- 起止日期相同允许，起始日期晚于截止日期拒绝。
- 创建已到期批复后立即得到 `expired`，不等待 Celery。
- 编辑截止日期后缓存状态立即变化。

### 12.2 租户和权限

- 普通用户不能查看、编辑、删除其他租户批复。
- 不能把其他租户用户设置为责任人。
- 只有 `approval.view` 的角色可以看到责任人列表和使用批复预览接口。
- 只有 add 权限不能走编辑分支，只有 edit 权限不能走新增分支。
- 附件动作同时校验页面查看权限和附件动作权限。

### 12.3 提醒

- popup 只返回当前用户负责的记录。
- 正常状态不能 ack，非责任人不能 ack。
- 重复 ack 幂等且只有一条记录。
- ack 后 popup 和 badge 同时排除该记录。
- 修改 `valid_to` 后旧 ack 失效，popup 和 badge 重新出现。
- 更换责任人后新责任人收到提醒，旧责任人不再收到。

### 12.4 附件

- 列表只返回 `object_type='approval'` 的附件。
- 不能通过批复附件接口访问同租户执照附件。
- 删除附件审计事件归属为 `approval`。
- 删除批复后附件记录软删，ack 级联删除。
- 列表附件数量聚合正确且不存在逐条 count 查询。
