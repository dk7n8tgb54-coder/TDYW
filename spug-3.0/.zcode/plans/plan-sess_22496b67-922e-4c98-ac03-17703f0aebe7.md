# 设备全生命周期：系统健康状态拆分 + 今日巡检改值班巡检单 实施方案

## 0. 现状确认与前提

- `git status` 干净：原快照中的"未提交改动"已在今日 HEAD `d0656048` 落库。本方案基于 HEAD 前进，不回滚、不 commit、不覆盖任何已有修改。
- 健康状态唯一写入方 = `fault_services.py`（GET_LOCK 全局锁 + 事务 + select_for_update + SystemEvent 履历 + 审计），健康枚举已是 normal/degraded/fault/repairing/interrupted/unknown，**无需改枚举，只改计算语义**。
- 工单已有 `affects_system_operation`（默认 False，手工建单前端默认已关）；故障无此字段。故障转工单默认值现跟随"故障未恢复→影响运行"（work_order_views.py:1133-1140），需改。
- 今日巡检现完全建立在台账模型上（明细 `system` FK 必填、CHECK 约束、大量 stable_contract），改造为**独立巡检模型**（风险更低、历史兼容更好）；周/月/季维护台账链路零改动。
- 全仓库无排班/值班人员模型（duty/department_duty_log 均为日志记录非排班）。

**未获答复按推荐默认执行（可在审批意见中否决）：**
1. 巡检单唯一范围 = 值班日+模板，**多人登记在同一张单**（人员子表+姓名快照）；
2. 值班人员 = 账号多选（存账号ID+姓名快照）+ 允许手工补录姓名（仅快照）；
3. 工单勾选影响运行 → 固定计入「维修中」（不加影响程度字段；更重程度由关联故障表达）；
4. 存量故障回填 affects=True（保留现有健康状态与历史语义）；
5. 旧"巡检台账"停止新增、保留历史查看（列表/详情/导出/作废）。

## 1. 第一部分：系统运行状态与部件维修状态分离

### 1.1 模型（models.py + 迁移 0019）
- `SystemFault.affects_system_operation = BooleanField(default=False, help_text='是否影响系统运行；False=部件故障/离线维修，不参与健康状态计算')`
- `SystemFault.impact_status` 默认改 `''`（=未影响系统运行），CHECK `el_fault_impact_valid` 扩为 3 值+`''`；affects=True 时后端强制校验必填 降级/故障/中断，affects=False 时后端强制写 `''`（不信任前端）。
- 工单不加字段。

### 1.2 服务（fault_services.py，锁/事务/履历/审计机制不动）
- `collect_active_impacts()` 增加 `affects_system_operation=True` 过滤 → 部件故障不再参与健康计算。
- `derive_health_status` 优先级 中断>维修中>故障>降级、`REPAIRING_WORK_ORDER_FILTER`、`recompute_systems_health`、`create_fault_record`（新增 affects 参数，默认 False）均保持既有结构。
- 触发点不变：fault/工单全部动作视图仍持锁重算。

### 1.3 视图
- `FaultView.post` / `FaultDetailView.put`：解析 affects（默认 False）+ 影响程度条件必填。
- `FaultCreateWorkOrderView._build_data`：默认 affects 改为 **False**（删除"跟随故障活跃状态"规则），显式传值仍支持。
- `views.py` systems 列表/详情响应增加 `component_maintenance: {fault_count, repairing_count}`（有效且不影响运行的故障数 / 执行中且不影响运行的维修工单数），每页系统仅 2 次分组查询（系统量 ~10）。

### 1.4 前端
- `FaultForm.js`：新增「影响系统运行」Switch（默认关）+ 影响程度 Select（开启才显示/必填）；列表与详情展示「不影响系统运行」标签，部件故障不再显示成系统"维修中"。
- `FaultWorkOrders.js` FaultConvertModal：默认 affects 改 false；`WorkOrderForm.js` 默认已 false，更新提示文案；`WorkOrderDetail.js` 标签保留。
- `el/Table.js`、`SystemDetail.js`：健康状态旁独立展示部件维护标签（"部件故障 N"红/“部件维修中 N”蓝），与系统健康 Tag 并列。
- 扩展点（本次不实现）：人工运行状态调整 = 独立模型（系统/目标状态/原因/权限 `system.adjust`/审计+履历事件），作为 derive 最高优先级输入。

### 1.5 迁移 0019（equipment_lifecycle）
AddField affects(default False) → RunPython 全量回填 True（历史故障均按影响运行，当前健康状态不变）→ AlterField impact_status(default '') → 替换 impact CHECK。

## 2. 第二部分：今日巡检 → 独立值班巡检单

### 2.1 数据结构（迁移 0020，全部继承 TenantModelMixin）
- **InspectionTemplate**：name、description、is_active、审计字段。
- **InspectionTemplateDevice**（设备名称层）：template FK CASCADE、device_name、display_order、is_active；unique(template, device_name)。不关联 LifecycleSystem。
- **InspectionTemplateItem**（检查内容层）：device FK CASCADE、name、input_type(choice|text)、unit、choices(JSON 固定 正常/不正常)、is_required(默认True)、abnormal_rule(检查规则)、operation_guide(操作说明)、display_order、is_active。
- **InspectionDutySheet**（值班巡检单）：duty_date(值班日)、template FK PROTECT、status(draft→submitted；draft/submitted 可受控作废 void，作废留档)、submitted_at/by、voided_*、client_token、version 乐观锁、审计字段。唯一约束经 `uniq_key = "{duty_date}|{template_id}"`（void 后加 `|voided_{pk}` 后缀释放，沿用项目 `__deleted_{id}` 惯例）实现 (租户, 值班日, 模板) 唯一。
- **InspectionDutyPerson**：sheet FK CASCADE、user FK SET_NULL(可空，手工补录人员无账号)、person_name 姓名快照；unique(sheet, user)。
- **InspectionRecord**（明细，一行=检查内容×轮次）：sheet FK CASCADE、round 固定枚举 r1=11:00 / r2=16:00 / r3=22:00 / r4=次日06:30（归属 duty_date 单，不存实际填写时间、不判迟填，created_at 仅审计）、template_item FK SET_NULL、is_temporary、**快照**：device_name/item_name/input_type/unit/choices/is_required/abnormal_rule/operation_guide/display_order（模板后续修改不影响历史）、value_text/value_number/value_bool、result(后端派生：choice 填"不正常"→abnormal，同 ledger 规则)、abnormal_desc、onsite_action(现场处理)、client_key（手工行幂等）；unique(sheet, round, template_item)（手工行 template_item 为 NULL 不受限）。
- 来源追溯：`SystemFault.source_inspection_record` FK PROTECT + source_type 扩 `inspection_record`；`SystemWorkOrder.source_inspection_record` FK PROTECT + SOURCE_VALUES/`el_work_order_source_consistent` CHECK 重建；SystemEvent source_type 扩 `inspection_record`（action convert_to_fault/convert_to_work_order 已有）。

### 2.2 服务与端点（新 inspection_services.py / inspection_views.py + urls）
- `/inspection-templates/` CRUD（模板+设备分组+检查内容一次聚合提交，参照系统聚合提交模式）。
- `/inspection-sheets/`：GET 列表(duty_date 筛选)、POST 建单(duty_date+template+persons，client_token 幂等)、GET 详情、PUT 记录(version 并发校验；模板行按 (template_item, round) upsert，手工行按 client_key)、submit、void。提交后不可再改。
- **转故障/转工单** `/inspection-sheets/{pk}/records/{rk}/convert-to-fault|work-order/`：仅 submitted 单 + result=abnormal 可转；**system_id 必填**（校验存在/本租户/未停用，设备名称不推断系统）；不选系统可只现场处理不转单；affects 默认 False（True 时影响程度必填）；client_token 幂等；重复转换防重复用 ledger `_check_item_redispose` 同模式（已有未取消目标拒绝、取消后重转须 re_dispose_reason）；双权限 `inspection.handle_exception` + `fault.add`/`work_order.add`；同事务写目标系统 SystemEvent + 健康重算；故障/工单详情回显巡检来源（单号/值班日/轮次/检查内容），巡检记录动态计算处置状态（同 ledger 模式）实现双向追溯。
- 新权限码：`equipment_lifecycle.inspection.{view,add,edit,del,submit,handle_exception}` + `inspection_template.{view,add,edit,del}`；旧角色 JSON 残留码按惯例惰性不洗。

### 2.3 前端
- 新 `InspectionWorksheet.js` 替换 `LedgerWorksheet.js`（同路由 /el/inspection-today）：模板选择（默认上次）、值班日（默认今天，可切前一值班日补第四轮，附跨夜提示）、值班人员多选（账号下拉+可手工补录姓名）、按设备名称分组展示检查内容、四轮固定列填写、记录/提交分离、localStorage 暂存（沿用空骨架不入暂存/跨日弃用）、异常行高亮；**无系统选择器、无填写时间、无迟填标记**；提交后异常记录显示转单按钮，弹窗内才出现必选系统下拉。
- 新巡检模板管理页（设备→检查内容两级编辑，录入类型两种、必填勾选、启停、排序）；routes.js 增「巡检模板」菜单，今日巡检 auth 改 `inspection.view`。
- 旧巡检台账：`LedgerForm` 对 inspection 类型隐藏「新增」，列表/详情/导出/作废保留；周/月/季维护 LedgerForm/LedgerIndex 零改动。
