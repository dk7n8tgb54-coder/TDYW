# 合同协议模块变异测试执行计划

## 目标

对 `spug_api/apps/contract_agreement` 执行真实变异测试（工具 mutmut 2.x），产出：变异分数、HTML 报告（quality/reports/mutation/）、幸存变异体逐条分析（测试缺口 / 等价变异体 / 待议）。本次只出报告和分析，补杀伤测试另行确认。

## 已探测/实测的关键事实

- 核心代码：models.py 171 行 + views.py 816 行 + tasks.py 106 行；杀伤套件 stable_contract 215 个测试，tdyw-test 容器内实测 12.9 秒/轮 → 预计 800~1500 个变异体，总时长 4~7 小时，后台跑。
- 三个目标文件当前 git 干净（未提交修改全在 equipment_lifecycle，互不影响）→ mutmut 原地变异中断也可 `git checkout --` 安全恢复。
- 根目录无 setup.cfg → 新建一个仅含 `[mutmut]` 段的配置，对其他工具惰性。
- Windows 侧 docker npipe 不可用 → 全部 docker 操作走 `wsl docker`；mutmut 装在 WSL（python 3.10 兼容 parso，宿主 3.14 不装）。
- 容器/WSL 均无现成 mutmut/coverage。

## 执行步骤

1. **环境安装（可逆，不碰业务代码）**
   - WSL：`python3 -m pip install --user "mutmut<3"`；若 WSL 无 PyPI 出网（历史上有 winnat 事故），回退路径：Windows 侧 `pip download` 纯 Python wheel 到临时目录，再从本地文件装入 WSL。
   - 容器（临时，重启即失）：`pip install coverage`，仅用于覆盖剪枝。
2. **新建根目录 setup.cfg**：`[mutmut]` 段 —— paths_to_mutate=models.py,views.py,tasks.py；tests_dir=stable_contract；runner=`wsl docker exec … tdyw-test sh -c "python manage.py test apps.contract_agreement.tests.stable_contract --keepdb --parallel 1"`（不用 `time`，容器 sh 无此内建）。
3. **.gitignore 追加** `.mutmut-cache`、`.coverage`（运行产物不进 git）。
4. **基线验证**：手动执行一次 runner 确认 215 个测试全绿，再启动 mutmut。
5. **覆盖剪枝（fail-safe）**：容器内 `coverage run manage.py test …` 生成 `.coverage`，mutmut 加 `--use-coverage` 只变异被覆盖行；任何一步失败则跳过剪枝直接全量跑，不阻断。
6. **后台执行 mutmut run（预计 4~7 小时，缓存可断点续跑）**
   - runner 用包装脚本：先探活 tdyw-test（`docker exec … true`），失败则 `docker start tdyw-test` 重试一次——防止用户日常容器重启把所有变异体误判为 killed（假满分信号）。
   - 阶段性检查进度；若出现「几乎全部 killed」这类假信号，立即停止排查 Docker 状态。
7. **完成后校验**
   - `git diff` 确认三个目标文件无残留变异内容，`git diff --check` 确认无 CRLF；有残留则 `git checkout -- spug_api/apps/contract_agreement/` 恢复。
   - `mutmut results` + `mutmut html` → `quality/reports/mutation/contract_agreement_20260921/`。
8. **幸存变异体分析**：逐条分类，重点核对三态边界（expiring 窗口）、long_term 分支、费用文本校验、提醒 ack 去重的实际杀伤力；最终答复给出变异分数、热点清单和补测试建议清单（待你确认后才动手）。

## 纪律与验证

- 全程只碰 test_spug（--keepdb --parallel 1），不违反「禁止 flush dev 库」。
- 不创建 commit、不 push；运行期间不并行改动 contract_agreement（源码处于变异状态）。
- 结束时 git status 仅含：setup.cfg（新增）、.gitignore（2 行）、quality/reports/mutation/ 产物；业务代码零改动。
