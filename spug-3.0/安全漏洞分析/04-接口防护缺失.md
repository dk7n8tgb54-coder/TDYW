# 🟠🟡 04-接口防护缺失

> 风险等级：P1 + P2
> 涉及漏洞编号：#7、#8、#16

---

## 漏洞 #7：限流功能被禁用 - 压测后未恢复（P1）

### 风险描述
回收站模块的限流函数被临时禁用用于压力测试，但测试完成后未恢复。函数直接 `return True`，完全跳过限流逻辑。

### 涉及文件

**文件：`spug_api/apps/document/views/recycle_bin/utils.py` 第49-84行**
```python
def check_rate_limit(user_id, rate_limit_config):
    """
    检查限流 - 使用Redis原子操作防止竞态条件
    ...
    NOTE: 临时禁用限流以进行压力测试
    """
    # TEMPORARILY DISABLED FOR LOAD TESTING
    # 压测完成后请恢复原始限流逻辑
    return True
    
    # 原始限流逻辑（压测后恢复）：
    # key = f'rate_limit:restore:{user_id}'
    # ...（全部被注释）
```

### 攻击场景
1. 攻击者发现回收站接口无限流保护
2. 发起大量恢复/删除请求
3. 消耗服务器资源，影响其他用户正常使用
4. 可能触发数据库锁竞争，导致服务不可用

## 漏洞 #8：缺少CSRF保护中间件（P1）

### 风险描述
Django的CSRF中间件 `django.middleware.csrf.CsrfViewMiddleware` 未在MIDDLEWARE列表中启用。虽然系统使用自定义Token认证（非Cookie），但缺少Origin/Referer验证仍存在跨站请求伪造风险。

### 涉及文件

**文件：`spug_api/spug/settings.py` 第62-68行**
```python
MIDDLEWARE = [
    'django.middleware.security.SecurityMiddleware',
    'django.middleware.common.CommonMiddleware',
    'libs.middleware.AuthenticationMiddleware',
    'libs.tenant_middleware.TenantMiddleware',
    'apps.logs.middleware.AuditLogMiddleware',
    'libs.middleware.HandleExceptionMiddleware',
]
```

### 风险分析
- 系统使用 `X-Token` Header进行认证，浏览器不会自动附加此Header
- 但如果Token存储在localStorage中，恶意页面可通过XSS读取Token后发起请求
- 缺少Origin验证意味着无法检测请求是否来自合法来源

## 漏洞 #16：dev环境Nginx限流配置全部被注释（P2）

### 风险描述
开发环境Nginx配置中，所有限流相关配置均被注释（标注为"TEMPORARILY DISABLED FOR LOAD TESTING"），如果此配置被误用于生产环境，将完全失去Nginx层面的防护。

### 涉及文件

**文件：`config/dev/nginx.conf` 第29-31行**
```nginx
# Rate limiting configuration - TEMPORARILY DISABLED FOR LOAD TESTING
# limit_req_zone $binary_remote_addr zone=api_limit:10m rate=50r/s;
# limit_req_zone $binary_remote_addr zone=login_limit:10m rate=5r/m;
# limit_req_zone $binary_remote_addr zone=general_limit:10m rate=30r/s;
```

**第86-87行（API限流）：**
```nginx
# Rate limiting for API endpoints (strict) - TEMPORARILY DISABLED
# limit_req zone=api_limit burst=100 nodelay;
```

**第133-134行（通用限流）：**
```nginx
# Rate limiting for general requests (relaxed) - TEMPORARILY DISABLED
# limit_req zone=general_limit burst=100 nodelay;
```

**第146-147行（登录限流）：**
```nginx
# Strict rate limiting for login (prevent brute force) - TEMPORARILY DISABLED
# limit_req zone=login_limit burst=3 nodelay;
```

### 对比：生产环境Docker配置
`docker/config/nginx.conf` 中限流配置是**启用**的：
```nginx
limit_req_zone $binary_remote_addr zone=api_limit:10m rate=10r/s;
limit_req_zone $binary_remote_addr zone=login_limit:10m rate=5r/m;
limit_req_zone $binary_remote_addr zone=general_limit:10m rate=30r/s;
```
但API location中并未使用 `limit_req` 指令，限流定义了但未应用。

### 风险
- dev配置如果被复制到生产环境，将完全无限流保护
- 生产Docker配置虽然定义了限流zone，但HTTPS server block中未对API应用限流
