# 🟠🟡 03-生产环境配置安全

> 风险等级：P1 + P2
> 涉及漏洞编号：#5、#6、#15、#17

---

## 漏洞 #5：DEBUG=True在settings.py默认开启（P1）

### 风险描述
Django的DEBUG模式在生产环境开启会导致：
- 详细的错误堆栈信息暴露给用户（包含源码路径、变量值）
- 所有SQL查询被记录在内存中（内存泄漏）
- 静态文件服务绕过Nginx直接由Django处理（性能下降）
- 404页面显示所有URL路由配置

### 涉及文件

**文件：`spug_api/spug/settings.py` 第31行**
```python
DEBUG = True
```

虽然 `overrides.py` 中设置了 `DEBUG = False`，但：
1. `overrides.py` 的导入在 `settings.py` 末尾，使用 `try/except ImportError`
2. 如果 `overrides.py` 文件不存在或导入失败，DEBUG将保持True
3. 默认值应该是安全的（False），而非不安全的（True）

### 攻击场景
1. 攻击者访问一个不存在的URL
2. Django返回详细的404页面，列出所有URL路由
3. 攻击者据此发现隐藏的管理接口
4. 触发500错误时，获取完整的堆栈信息和局部变量

## 漏洞 #6：ALLOWED_HOSTS包含通配符'*'（P1）

### 风险描述
`ALLOWED_HOSTS = ['127.0.0.1', 'localhost', '*']` 中包含通配符 `*`，等同于允许任何Host头。这使得系统容易受到HTTP Host头注入攻击。

### 涉及文件

**文件1：`spug_api/spug/settings.py` 第33行**
```python
ALLOWED_HOSTS = ['127.0.0.1', 'localhost', '*']
```

**文件2：`spug_api/spug/overrides.py` 第4行**
```python
ALLOWED_HOSTS = ['127.0.0.1', 'localhost', '*']
```

**文件3：`docker/docker-compose.yml` 第37行**
```yaml
- ALLOWED_HOSTS=*
```

### 攻击场景
1. 攻击者发送带有恶意Host头的请求
2. Django使用Host头生成绝对URL（如密码重置链接）
3. 用户收到包含攻击者域名的重置链接
4. 用户点击后，重置Token被发送到攻击者服务器

## 漏洞 #15：异常处理暴露内部错误信息（P2）

### 风险描述
`HandleExceptionMiddleware` 将完整的异常信息返回给客户端，包括内部类名、文件路径、数据库错误等敏感信息。

### 涉及文件

**文件：`spug_api/libs/middleware.py` 第19-20行**
```python
def process_exception(self, request, exception):
    traceback.print_exc()
    return json_response(error='Exception: %s' % exception)
```

### 信息泄露示例
```json
{
  "error": "Exception: (1146, \"Table 'spug.apps_document_file' doesn't exist\")"
}
```
攻击者可从中获取：数据库名称、表结构、内部模块路径等。

## 漏洞 #17：数据库端口对外暴露（P2）

### 风险描述
Docker Compose配置中数据库端口绑定到所有网络接口（`0.0.0.0:3308`），而非仅绑定到localhost。

### 涉及文件

**文件：`docker/docker-compose.yml` 第82行**
```yaml
ports:
  - "3308:3306"  # 数据库端口
```

### 攻击场景
1. 服务器防火墙配置不当，3308端口对外开放
2. 攻击者直接连接数据库（结合泄露的密码）
3. 完全控制数据库数据

### 正确配置
```yaml
ports:
  - "127.0.0.1:3308:3306"  # 仅本机可访问
```
