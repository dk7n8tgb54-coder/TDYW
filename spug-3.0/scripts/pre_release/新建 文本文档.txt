`W342` 是 Django 的系统检查警告，意思是**"在 ForeignKey 上设 unique=True 等同于 OneToOneField，建议改用 OneToOneField"**。

## 这个字段是什么

`DocumentSystemFolder` 是"系统目录绑定"表，把系统级目录（如"党建文档"）绑定到一个 `DocumentFolder`：

```
DocumentSystemFolder
  ├── id
  ├── code = 'party_building_documents'   # 系统目录代码
  └── folder = ForeignKey(DocumentFolder, unique=True)  # 绑定的文件夹
```

业务含义：**一个文件夹只能被一个系统目录绑定**（1:1 关系）。

## 为什么报 W342

Django 认为：既然你要 1:1 关系，应该用 `OneToOneField` 而不是 `ForeignKey(unique=True)`。两者在数据库层面完全一样（都是外键 + 唯一索引），但 `OneToOneField` 在 ORM 层面更语义化（反向访问返回单个对象而不是 QuerySet）。

## 为什么不改

| 改成 OneToOneField | 保持 ForeignKey(unique=True) |
|---|---|
| 需要写 migration | 不需要 migration |
| 数据库无变化 | 数据库无变化 |
| ORM 反向访问变 `.folder_binding`（单对象） | ORM 反向访问变 `.folder_binding_set`（QuerySet） |
| 业务代码可能要改 | 业务代码不用改 |

这是 2026-07-17 党建文档逻辑隔离时加的约束（migration 0012）。当时用 `ForeignKey(unique=True)` 是为了快速加约束不改业务代码。改成 `OneToOneField` 是"更好"但没有实际收益的改动，所以一直没动。

**结论**：警告可以忽略，不影响功能、不影响性能、不影响生产部署。如果你想消除警告，我可以帮你改成 OneToOneField（需要一个 migration + 检查业务代码的反向访问），但不建议在上线前做这种无功能收益的改动。
