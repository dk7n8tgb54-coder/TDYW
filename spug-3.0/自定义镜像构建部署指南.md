# 自定义镜像构建与部署指南

## 背景说明

官方 Spug 镜像不包含 `reportlab` 依赖，无法导出 PDF。本指南说明如何构建包含 `reportlab` 和 checksheet 模块的自定义镜像。

## 数据持久化保证

**重要：重新构建镜像不会影响已有数据**

- ✅ 数据库数据存储在 `mysql-data` Volume
- ✅ 应用数据存储在 `tdyw-data` Volume
- ✅ 文档文件存储在 `document-files` Volume
- ✅ Volume 独立于镜像，容器重启后数据仍然存在

## 部署步骤

### 步骤 1：构建自定义镜像

```bash
# 进入项目目录
cd e:/TDYW/spug-3.0

# 构建自定义镜像（首次构建需要 10-20 分钟）
docker-compose -f docker-compose.custom.yml build

# 验证镜像是否创建成功
docker images | grep tdyw-spug
```

### 步骤 2：备份当前数据（可选但推荐）

```bash
# 备份数据库
docker exec tdyw-db mysqldump -u root -p spug > backup_$(date +%Y%m%d_%H%M%S).sql

# 备份 Volume（可选）
docker run --rm -v tdyw-data:/data -v $(pwd):/backup alpine tar czf /backup/tdyw-data-$(date +%Y%m%d).tar.gz /data
```

### 步骤 3：停止并删除旧容器

```bash
# 停止容器
docker-compose -f docker-compose.prod.yml down

# 查看容器状态（确认已停止）
docker ps -a | grep tdyw
```

### 步骤 4：启动新容器

```bash
# 使用自定义镜像配置启动
docker-compose -f docker-compose.custom.yml up -d

# 查看容器状态
docker-compose -f docker-compose.custom.yml ps

# 查看日志（确保启动正常）
docker-compose -f docker-compose.custom.yml logs -f spug
```

### 步骤 5：验证部署

```bash
# 检查容器是否运行
docker ps | grep tdyw

# 检查 reportlab 是否已安装
docker exec tdyw pip list | grep reportlab

# 测试访问
# 在浏览器中访问 http://您的服务器IP
# 进入检查表模块，尝试导出 PDF
```

## 常见问题

### Q1：重新构建镜像后数据会丢失吗？

**不会**。您的配置使用 Docker Volume 持久化数据：
- `mysql-data`：数据库数据
- `tdyw-data`：应用数据
- `document-files`：文档文件

镜像只是代码层，Volume 是独立的数据存储层。

### Q2：如何确认 Volume 仍然存在？

```bash
# 查看所有 Volume
docker volume ls

# 查看 Volume 详细信息
docker volume inspect mysql-data
docker volume inspect tdyw-data
docker volume inspect document-files
```

### Q3：如果新容器启动失败怎么办？

```bash
# 查看日志
docker-compose -f docker-compose.custom.yml logs spug

# 如果需要回退到旧配置
docker-compose -f docker-compose.custom.yml down
docker-compose -f docker-compose.prod.yml up -d
```

### Q4：如何更新代码和依赖？

```bash
# 1. 修改代码或依赖后
# 2. 重新构建镜像
docker-compose -f docker-compose.custom.yml build --no-cache

# 3. 重启容器（无需删除 Volume）
docker-compose -f docker-compose.custom.yml up -d
```

## 技术细节

### Dockerfile 说明

```dockerfile
FROM registry.cn-hangzhou.aliyuncs.com/openspug/spug-service  # 基于官方镜像
COPY spug_api/requirements.txt ...                               # 复制依赖文件
RUN pip install ...                                               # 安装 reportlab
COPY spug_api/apps/checksheet ...                                 # 复制 checksheet 模块
```

### Volume 数据位置

```bash
# 查看 Volume 实际存储位置
docker volume inspect mysql-data
# 输出示例：
# {
#   "Mountpoint": "/var/lib/docker/volumes/mysql-data/_data"
# }
```

### 数据备份策略

**日常备份：**
```bash
# 每日自动备份（添加到 crontab）
0 2 * * * cd /opt/spug && docker exec tdyw-db mysqldump -u root -p$MYSQL_ROOT_PASSWORD spug > backups/spug_$(date +\%Y\%m\%d).sql
```

**手动备份：**
```bash
# 备份 Volume
docker run --rm -v mysql-data:/data -v $(pwd):/backup alpine tar czf /backup/mysql-$(date +%Y%m%d).tar.gz /data
```

## 版本管理

### 镜像版本管理

```bash
# 给镜像打标签
docker tag tdyw-spug:latest tdyw-spug:v1.0.0

# 推送到私有仓库（可选）
docker tag tdyw-spug:latest your-registry.com/tdyw-spug:latest
docker push your-registry.com/tdyw-spug:latest
```

### 回滚到旧版本

```bash
# 如果使用旧镜像配置
docker-compose -f docker-compose.custom.yml down
docker-compose -f docker-compose.prod.yml up -d

# 如果需要回滚到旧的 Volume 数据
docker run --rm -v mysql-data:/data -v $(pwd):/backup alpine tar xzf /backup/mysql-YYYYMMDD.tar.gz -C /
```

## 维护建议

1. **定期备份**：每天备份数据库和 Volume
2. **测试升级**：在测试环境先验证新镜像
3. **监控日志**：定期检查容器日志
4. **安全更新**：定期更新基础镜像
5. **文档记录**：记录每次升级的变更内容
