```python

FolderModel.objects.filter(
    id__in=folder_ids_to_search,
    name__icontains=keyword  # 不区分大小写的包含匹配
)

# 文件匹配
FileModel.objects.filter(
```

## 二、功能缺陷分析

### 🔴 严重缺陷（影响使用体验）

#### 缺陷1：搜索范围局限
- **问题**: **无明确的"全库搜索"入口**，用户易误以为只能搜索当前文件夹
- **场景**: 用户在根目录想搜索整个资料库，必须先进入某个文件夹
- **影响**: 使用不便，用户难以找到文件
- **技术说明**: 技术上支持从根目录递归搜索，但交互层面缺乏明确引导

#### 缺陷2：无高亮显示（⚠️ 需防范XSS）
- **问题**: 搜索结果中**关键词没有高亮**
- **场景**: 搜索"设计"，结果列表中"设计"二字没有特殊标记
- **影响**: 难以快速定位匹配位置
- **⚠️ 安全提醒**: 实现高亮时必须**先对用户输入进行HTML转义**，再替换关键词，防止XSS攻击

#### 缺陷3：无排序功能
- **问题**: 搜索结果**没有排序选项**（时间、大小、名称）
- **场景**: 搜索结果多时，无法按相关度或时间排序
- **影响**: 难以找到最相关或最新的文件

#### 缺陷4：搜索条件单一
- **问题**: 只能按**名称**搜索，不支持:
  - 按文件类型搜索（如只搜PDF）
  - 按文件大小搜索（如大于10MB）
  - 按创建时间搜索（如最近7天）
  - 按创建者搜索（如张三上传的）

---

### 🟡 中等缺陷（可以优化）

#### 缺陷5：搜索模式简单（⚠️ 存在性能风险）
- **问题**: 只支持简单的`icontains`包含匹配
- **不支持**:
  - 模糊搜索（如输入"xmzl"匹配"项目资料"）
  - 拼音搜索（如输入"x"匹配"项目"）
  - 多关键词搜索（如"设计 2024"）
  - 排除搜索（如"-草稿"排除草稿文件）
- **⚠️ 性能风险**: `name__icontains`会导致数据库**全表扫描**，数据量增大时性能急剧下降
- **优化建议**:
  - **短期**: 为`name`字段添加前缀索引，或使用MySQL的`FULLTEXT`全文索引
  - **长期**: 考虑引入Elasticsearch（避免过度设计）

#### 缺陷6：无搜索历史
- **问题**: 没有保存用户的搜索历史
- **场景**: 用户需要重复搜索相同内容
- **影响**: 使用效率低

#### 缺陷7：无搜索建议/自动补全
- **问题**: 输入时没有智能提示
- **场景**: 用户不记得完整文件名
- **影响**: 需要输入完整关键词

#### 缺陷8：搜索结果展示不友好
- **问题**: 
  - 虽文件夹在前，但**视觉区分度不足**（如无图标/颜色区分）
  - 没有显示文件缩略图（图片/视频）
  - 没有显示文件大小/时间等关键信息

## 六、安全与权限考虑

### 6.1 搜索权限检查
- **现状**: 已实现租户隔离（私有空间）和公共空间权限控制
- **建议**: 若资料库存在细粒度权限（如某些文件夹仅特定用户可见），需确认搜索结果是否已严格过滤无权限内容

### 6.2 XSS防护（高亮功能）
实现关键词高亮时，必须遵循以下安全实践：
```javascript
// ❌ 错误做法 - 存在XSS风险
const highlighted = text.replace(keyword, '<span class="highlight">$&</span>');

// ✅ 正确做法 - 先转义再高亮
function escapeHtml(text) {
  const div = document.createElement('div');
  div.textContent = text;
  return div.innerHTML;
}
function highlightText(text, keyword) {
  const escapedText = escapeHtml(text);
  const escapedKeyword = escapeHtml(keyword);
  return escapedText.replace(
    new RegExp(escapedKeyword, 'gi'),
    match => `<span class="highlight">${match}</span>`
  );
}
```
