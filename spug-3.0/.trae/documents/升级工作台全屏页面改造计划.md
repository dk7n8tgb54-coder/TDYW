# 升级工作台全屏页面改造计划

## Context

用户希望将"升级工作台"从 Modal 弹窗改为全屏页面，以获得更大的操作空间和更好的用户体验。具体需求：
- 点击升级记录行 → 跳转到全屏工作台页面
- 新建按钮 → 跳转到新建页面
- 保存/关闭后 → 返回升级表单列表页
- URL 可访问，便于分享

---

## 技术方案

**新增路由**：
- `/upgrade/workbench/:id` - 查看/编辑已有升级记录
- `/upgrade/new` - 新建升级记录

**新建文件**：
- `src/pages/upgrade/Workbench.js` - 全屏工作台组件

**修改文件**：
- `src/routes.js` - 添加新路由
- `src/pages/upgrade/store.js` - 添加工作台数据加载方法
- `src/pages/upgrade/Table.js` - 修改行点击行为
- `src/pages/upgrade/index.js` - 修改新建按钮行为
- `src/pages/upgrade/RecordForm.js` - 保留 Modal 弹窗（快速查看场景）

---

## 分步实施计划

### 步骤 1：创建全屏工作台组件

**新建文件：** `src/pages/upgrade/Workbench.js`

核心逻辑：
- 从 URL 参数获取 record ID（`/upgrade/workbench/:id`）
- 如果是新建模式（`/upgrade/new`），显示新建表单
- 复用 `RecordForm.js` 中的 `renderWorkbench()` 方法
- 添加顶部导航栏（返回按钮、标题、操作按钮）
- 响应式布局支持

```jsx
// 页面布局结构
<Layout>
  <Header>
    <Button icon={<ArrowLeft />} onClick={() => history.push('/upgrade')}>返回列表</Button>
    <span>升级工作台 - {record.upgrade_no}</span>
    <Space>
      {canEdit && <Button type="primary" onClick={handleSave}>保存</Button>}
    </Space>
  </Header>
  <Content>
    {renderWorkbench()}  // 复用 RecordForm 中的方法
  </Content>
</Layout>
```

### 步骤 2：添加新路由

**修改文件：** `src/routes.js`

```jsx
import Workbench from './pages/upgrade/Workbench';

export default [
  // ... 现有路由保持不变
  
  // 新增全屏工作台路由
  { path: '/upgrade/new', component: Workbench },
  { path: '/upgrade/workbench/:id', component: Workbench },
]
```

### 步骤 3：修改 Store

**修改文件：** `src/pages/upgrade/store.js`

新增方法：
- `fetchRecord(id)` - 加载单个升级记录详情
- `loadWorkbench(id)` - 加载工作台所需的所有数据（记录+步骤+时间线）

```javascript
// 新增
fetchRecord = (id) => {
  return http.get(`/api/upgrade/records/${id}/`)
    .then(data => {
      this.record = data;
      return data;
    });
}

loadWorkbench = (id) => {
  return Promise.all([
    this.fetchRecord(id),
    this.fetchRecordSteps(),
    this.fetchStatusLogs(),
  ]);
}
```

### 步骤 4：修改 Table.js

**修改文件：** `src/pages/upgrade/Table.js`

修改行点击行为：
- 双击行 → 跳转到工作台页面
- 移除原来的 `onRow` 双击打开 Modal 逻辑

```jsx
onRow={record => ({
  onDoubleClick: () => { 
    history.push(`/upgrade/workbench/${record.id}`);  // 改为跳转
  },
  style: { cursor: 'pointer' }
})}
```

### 步骤 5：修改 index.js

**修改文件：** `src/pages/upgrade/index.js`

修改新建按钮：
- 点击新建按钮 → 跳转到 `/upgrade/new`

```jsx
// 原代码
<AuthButton auth="upgrade.upgrade.add" type="primary" icon={<PlusOutlined/>} 
  onClick={() => store.showForm({}, false)}>新建</AuthButton>

// 修改为
<AuthButton auth="upgrade.upgrade.add" type="primary" icon={<PlusOutlined/>} 
  onClick={() => history.push('/upgrade/new')}>新建</AuthButton>
```

### 步骤 6：简化 RecordForm.js

**修改文件：** `src/pages/upgrade/RecordForm.js`

保留 Modal 弹窗用于：
- 快速预览（可选，取决于用户体验是否需要）
- 其他可能触发弹窗的场景

如果决定完全移除 Modal，可以删除此文件的相关 Modal 包装，只保留 `renderWorkbench()` 方法供 Workbench.js 调用。

### 步骤 7：添加样式文件

**新建文件：** `src/pages/upgrade/Workbench.module.less`

全屏页面的样式：
- Header 固定定位
- Content 内容区域滚动
- 响应式 padding

## 验证方式

1. **启动开发服务器**：`cd spug_web && npm start`
2. **测试新建流程**：
   - 点击"新建"按钮 → 跳转到 `/upgrade/new` → 填写表单 → 保存 → 返回列表页
3. **测试查看/编辑流程**：
   - 在列表页双击某行 → 跳转到 `/upgrade/workbench/:id` → 查看/编辑 → 返回列表页
4. **测试 URL 访问**：
   - 直接访问 `/upgrade/workbench/1` → 能正常加载数据
5. **测试响应式**（如果需要移动端适配）
