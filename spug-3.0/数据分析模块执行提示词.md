## 强制约束

1. 当前工作区不是干净状态，且 `spug_api/spug/settings.py`、`spug_api/spug/urls.py`、`spug_web/src/routes.js`、`spug_web/src/pages/system/role/codes.js` 已包含其他功能的未提交修改。必须在现有内容上做最小增量合并，禁止覆盖、回滚、删除或顺手格式化任何无关改动。
2. 不创建业务 model 或 migration，不修改四个来源模块的数据，不实现 CRUD、导出或明细下钻。
3. 不伪造当前数据模型不支持的指标：故障未闭合数/处理时效/故障类型、设备分类/在用数、升级设备覆盖率均不在本期范围。
4. 后端内部不得调用现有 View，也不得通过 HTTP 请求本项目自己的接口。统计逻辑放在 `apps.data_analysis.services`，View 只做权限、参数、缓存编排和响应。
5. 每个来源 QuerySet 必须排除软删除，并在任何聚合前使用 `apply_tenant_filter`。缓存 scope 必须区分普通租户和可见全租户的超级管理员/全局管理员，严禁缓存串租户。
6. 日期严格按方案使用半开区间，不得使用 `__date`、`__startswith` 或拼接 `23:59:59`；趋势一次聚合并补零，不得循环查询形成 N+1。
7. 使用现有 Django/React/MobX/Ant Design/BizCharts 版本和仓库写法，不升级依赖，不引入新状态库或图表库，不修改共享 `auth` 装饰器。

9. 实现完整的 loading、error、empty、重试、响应式布局和快速请求防旧响应覆盖，不能只做“有数据时能显示”的理想路径。
