# TDYW 全量备份维护手册

## 1. 当前方案

系统只使用 `backup_set_create.sh` 创建备份。每次任务生成一个可独立恢复的 schema 5 全量备份集，不依赖前一天或任何父备份。

每个成功备份集包含：

- `database.sql.gz`：`mariadb-dump` 逻辑全量，始终生成；
- `database.mariabackup.tar.gz`：可选的 MariaDB 实例物理全量；
- `documents.tar.gz`、`documents.manifest.json`：documents 完整归档与文件哈希；
- `media.tar.gz`、`media.manifest.json`：media 完整归档与文件哈希；
- `manifest.json`：数据库、镜像、文件集和一致性信息；
- `SHA256SUMS`：以上所有正式产物的 SHA-256。

不再生成增量包、delta 清单或父链。旧的 documents 独立备份和恢复脚本已经删除。

## 2. 一致性原理

正式任务先停止应用入口、Celery beat、worker 和应用容器，使数据库与文件卷不再发生业务写入。数据库容器保持运行，用 `mariadb-dump --single-transaction` 导出；随后从停止的应用容器只读挂载 documents/media 卷并创建完整归档。

因此脚本不修改数据库表结构，也不要求修改业务容器镜像或业务代码。它会：

- 临时把只读 client cnf 复制到数据库容器 `/tmp`；
- 读取数据库并短暂增加数据库 CPU、磁盘和 I/O 负载；
- 停止并在成功后重启应用容器；
- 读取并压缩 documents/media 卷。

只有所有产物校验成功且应用恢复健康，临时目录才会发布为正式 `backup_set_YYYYmmdd_HHMMSS`。

## 3. 准备凭据

在 Linux 主机创建 `/etc/tdyw-backup/tdyw_backup.cnf`：

```ini
[client]
user=tdyw_backup
password=替换为真实密码
host=127.0.0.1
port=3306
```

```bash
sudo chown root:root /etc/tdyw-backup/tdyw_backup.cnf
sudo chmod 600 /etc/tdyw-backup/tdyw_backup.cnf
```

账号至少需要读取目标库以及导出 routines、triggers、events 所需权限。启用 `DB_BACKUP_MODE=both` 时，还需要满足 `mariabackup_backup.sh` 中的物理备份权限。

## 4. 执行备份

先做 dry-run：

```bash
BACKUP_CLIENT_CNF=/etc/tdyw-backup/tdyw_backup.cnf \
BACKUP_ROOT=/data/backups/tdyw/backup_sets \
./backups/backup_set_create.sh
```

正式逻辑全量：

```bash
BACKUP_CLIENT_CNF=/etc/tdyw-backup/tdyw_backup.cnf \
BACKUP_ROOT=/data/backups/tdyw/backup_sets \
DB_BACKUP_MODE=logical DRY_RUN=NO \
./backups/backup_set_create.sh
```

逻辑全量加物理全量：

```bash
BACKUP_CLIENT_CNF=/etc/tdyw-backup/tdyw_backup.cnf \
BACKUP_ROOT=/data/backups/tdyw/backup_sets \
DB_BACKUP_MODE=both DRY_RUN=NO \
./backups/backup_set_create.sh
```

上线初期建议每天使用 `logical`。只有物理恢复演练通过后再定期使用 `both`，因为物理恢复会覆盖整个 MariaDB 数据卷，而非单个数据库。

## 5. 调度与保留

参考 `tdyw-backup.cron.example` 每天调度一次。任务使用 `${BACKUP_ROOT}/.backup.lock`，备份和还原不能并发。

`RETENTION_DELETE=NO` 是默认值。完成多次恢复演练并确认异地副本后，才考虑启用：

```bash
RETENTION_DAYS=30 RETENTION_DELETE=YES
```

保留清理只删除超过期限且通过完整 SHA-256、manifest 和 schema 5 校验的独立全量备份。建议至少采用 3-2-1 原则：主机本地一份、另一介质或服务器一份、至少一份异地。当前脚本只负责生成本地一致性备份集，不等同于异地容灾；后续引入 restic 时，可直接把完整备份集作为备份源。

## 6. 每日检查

每次任务至少检查：

```bash
tail -n 200 /var/log/tdyw-backup/backup_set.log
find /data/backups/tdyw/backup_sets -maxdepth 1 -type d -name 'backup_set_*' -printf '%TY-%Tm-%Td %TH:%TM %p\n' | sort
```

成功目录必须有 `manifest.json`、`SHA256SUMS`、数据库备份、两个 tar 和两个 fileset manifest。`.inprogress` 或 `.failed` 不能作为可恢复备份。

只生成备份不算完成。至少每月执行一次 drill，记录恢复耗时、表数量、文件数量、抽样下载结果和应用健康状态。
