# 部门值班日志 — 未覆盖边界情况说明

> 仅列出当前代码中**缺失**的边界逻辑 / 异常输入 / 极端场景；不含修复方案，供另一 Agent 定向修复。
> 基于 `spug_api/apps/department_duty_log` 与 `spug_web/src/pages/departmentDutyLog` 源码静态核对。
> 已覆盖的校验（未来日期被 `_parse_date` 拒绝、`mains_voltage/ups_voltage/weather` 后端必填、edit/sign/delete 的 version 乐观锁、软删除仅限草稿、受保护字段拒绝、分页 1–100、关键字/姓名长度上限、导出 500 条上限、状态机单向转换）**不在此列**。

---

## 一、审计与合规

### B1 · PDF 导出无审计记录 【高】
- **描述**：`DepartmentDutyLogPdfExportView` 与 `services.export_pdf` 全程不调用 `record_audit_event`，导出行为（操作用户、时间、筛选条件、导出条数、PDF 哈希）无留痕。
- **缺失的预期行为**：导出含电子签名的正式记录应写入审计事件，便于追溯“谁在何时导出了哪些记录”。
- **触发条件**：任意拥有 `department_duty_log.department_duty_log.export` 权限的用户执行一次 PDF 导出。

### B2 · 签名图片读取无审计 【低】
- **描述**：`signature-image` 接口仅做可见性 + 业务坐标校验后返回 PNG，不记录读取行为。
- **缺失的预期行为**：（可选）敏感签名图片的查看应留痕，尤其跨值班员访问场景。
- **触发条件**：任意 view 权限用户通过详情抽屉或 PDF 读取某条记录的签名图片。

---

## 二、导出与签名证据韧性

### B3 · 单条签名异常导致整批导出失败 【高】
- **描述**：`export_pdf` 逐条调用 `get_signature_image_for_global_business`，任一记录返回错误（附件被删、文件哈希不符、attachment 缺失）即整体返回失败，无跳过 / 部分导出 / 降级占位。
- **缺失的预期行为**：应支持跳过异常记录（并在结果中标注）或提供“仅导出无异常记录”的选项，而非一损俱损。
- **触发条件**：某条 signed/void 记录的签名附件物理文件丢失、哈希与固化值不符，或 EvidenceAttachment 记录不存在。

### B4 · PIL / 图片读取失败致整批导出失败 【中】
- **描述**：`pdf_export._build_signature_image` 在 PIL 不可用或图片打开失败时返回 `None`，`export_pdf` 将 `None` 视为致命错误并中止整个导出。
- **缺失的预期行为**：签名图不可用时应在该记录处留空占位（标注“签名图缺失”），继续完成其余记录，而非整体失败。
- **触发条件**：运行环境缺少 PIL 库，或某签名 PNG 文件损坏无法被 PIL 打开。

### B5 · 大批量导出同步阻塞 / 请求超时 【中】
- **描述**：导出在 HTTP 请求内同步完成：最多 500 条，每条需读取签名图 + 计算 SHA256 + 排版。无异步任务、无流式响应。
- **缺失的预期行为**：接近上限的导出应改为后台任务（Celery）或分块流式返回，避免阻塞 worker 与触发网关超时。
- **触发条件**：筛选命中接近 500 条且多数含签名图片时，单次导出耗时显著增长。

## 三、并发与乐观锁一致性

### B6 · 作废（void）缺少乐观锁版本校验 【中】
- **描述**：`void_signed_record` 不接收也不校验客户端 `version`；而 `update` / `sign` / `delete` 均做 version 校验。void 的并发防护不一致。
- **缺失的预期行为**：作废应携带 version 并与记录当前版本比对，版本冲突时返回 409 而非静默执行。
- **触发条件**：并发或对“已被变更的记录”发起来源陈旧的作废请求。注：因作废后 `status≠signed`，第二次作废会因状态校验失败而返回错误，故无数据破坏，但行为与其他操作不一致。

### B7 · 签名成功后网络超时的客户端重试不友好 【低】
- **描述**：若客户端未传 `request_id`，后端每次生成新 UUID；签名成功但响应超时后客户端重试会再调 `apply_signature`（新 request_id）。因记录 `status` 已变 signed，第二次 sign 被状态拦截返回错误，而非返回已签记录。
- **缺失的预期行为**：重试时应识别“已签署”并返回既有记录，而非抛错。
- **触发条件**：签名成功但 HTTP 响应在客户端侧超时，客户端自动/手动重试。

## 四、输入与字段约束

### B8 · duty_person_name 长度未校验（可致 DB 报错） 【高】
- **描述**：`create_draft` 直接用 `user.nickname or user.username` 写入 `CharField(max_length=100)`，无任何长度检查；昵称超长会在写入时触发数据库层错误。
- **缺失的预期行为**：写入前应按 100 字符上限截断或返回明确错误。
- **触发条件**：账号昵称长度超过 100 字符的用户新建一条值班日志草稿。

### B9 · duty_date 无下限 / 业务有效性校验 【低】
- **描述**：`_parse_date` 仅拒绝晚于今天的日期（`allow_future=False`），允许任意极早的过去日期。
- **缺失的预期行为**：可按业务规则限定最早可填日期（如系统上线日、某年）。
- **触发条件**：客户端提交如 `1970-01-01` 之类的历史日期。

### B10 · 同人同日可建多条草稿，无去重 【中】
- **描述**：`duty_date` 上无唯一约束，代码也未校验 `(duty_person, duty_date)` 是否已存在草稿，同一用户可为同一天创建多条草稿。
- **缺失的预期行为**：可在创建草稿时校验“该值班人当日是否已有草稿”，避免重复值班记录。
- **触发条件**：同一用户为同一天（如 2026-07-21）连续创建第二条草稿。

### B11 · 自由文本字段无受控词表（数据质量） 【低】
- **描述**：`weather` / `mains_voltage` / `ups_voltage` 均为自由文本，无枚举或格式校验，取值口径不统一。
- **缺失的预期行为**：可对这类字段设枚举或格式正则，保证统计/展示一致。
- **触发条件**：不同用户填写“晴”/“晴天”/“sunny”或“220V”/“正常”等不一致表述。

## 五、功能覆盖（未接线能力）

### B12 · “更正”（supersedes）能力未实现 【中】
- **描述**：模型已定义 `supersedes` 自关联与 `corrections` 反向关系，但 create / 更正流程均不写入该字段，前端也无入口；更正链为死代码。
- **缺失的预期行为**：作废后应能基于原记录新建“更正”草稿并填充 `supersedes_id`，使更正记录可追溯到被更正记录。
- **触发条件**：用户试图对已作废记录发起“更正”，当前无对应端点/按钮，能力不可用。

---

## 六、可见性与权限（需确认的边界）

### B13 · 跨值班员 / 跨部门的全量可见 【中】
- **描述**：模型无 `tenant_id`，`get_visible_department_duty_logs` 对任意拥有 view 权限的用户返回全部 signed/void 记录及其签名图片，无部门/值班员级过滤。
- **缺失的预期行为**：若业务要求部门隔离，应补充可见性过滤（如按值班员所属部门）。当前疑似为“全局共享台账”的设计意图，需与业务方确认。
- **触发条件**：任意 view 权限用户查看 / 导出其他部门或其他值班人的日志与签名图片。

---

## 七、性能边界

### B14 · 导出日期范围无宽度上限 【低】
- **描述**：列表默认 31 天但允许任意起止范围；导出 `_parse_export_filters` 不限制日期跨度，可扫描极宽区间（虽有 500 条数上限兜底，但大范围查询本身有成本）。
- **缺失的预期行为**：可对导出/列表的日期跨度设上限，或在大跨度时强制分页/后台任务。
- **触发条件**：导出 `start_date=2000-01-01 ~ 2026-07-21` 这类超大范围。
