# 执照管理模块（apps/radio_license）边界缺失清单

> 用途：供修复 Agent 逐项针对性修复。本文档**只列出遗漏的边界逻辑**，不含修复代码与实现方案。
> 覆盖范围：`views.py`（无线电台执照）、`approval_views.py`（台站频率批复）、`models.py`、`tasks.py`。已排除测试文件。
> 生成日期：2026-07-21。
> 说明：多处对照可见「批复侧已做、执照侧未做」的不对称，修复时优先向严格的一侧对齐。

## 详细清单

### GAP-01 执照列表分页参数无校验
- **位置**：`views.py` 列表 `get`（`page = int(request.GET.get('page', 1))` / `page_size = int(... 'page_size', 20)`）。
- **触发条件**：`page=abc`（非数字）、`page=-1`/`page=0`、`page_size=999999`。
- **预期行为**：非法/非数字回退默认值；`page>=1`；`page_size` 设上下限（对照批复侧 `try/except` + clamp 1..100）。当前非数字直接抛 `ValueError` → 500；超大 `page_size` 无保护。

### GAP-02 列表日期区间参数未校验
- **位置**：执照 `views.py get`（`valid_to__gte/lte`）；批复 `approval_views.py get` 同名过滤。
- **触发条件**：`valid_to_start=abc` 或非法日期（如 `2026-13-40`）。
- **预期行为**：非法日期应被忽略或返回友好 400；当前直接进入 ORM `filter`，非法值会抛异常 → 500。

### GAP-03 创建/编辑日期格式与跨字段未校验
- **位置**：执照 `post`（仅当 `valid_from` 与 `valid_to` 同时存在时做字符串比较）；批复 `post` 同。
- **触发条件**：① `valid_to="2026-13-40"` 非法日期 → 存 `DateField` 时报错 500；② **编辑时只传 `valid_to`**（早于库中已存 `valid_from`）不会被拦截。
- **预期行为**：校验日期格式合法；编辑单端更新时应与库中另一端比较，保证 `valid_from <= valid_to`。

### GAP-04 频率数值未校验
- **位置**：`views.py` 频率创建（`frequency_value` 取自 `freq_data.get('frequency_value', 0)` 写入 `DecimalField(max_digits=12, decimal_places=4)`）。
- **触发条件**：`frequency_value="abc"`（非数字）、超过 12 位/4 位小数、负数。
- **预期行为**：应校验为非负数、位数不超限；当前非法值会在 Decimal 转换/入库时抛异常 → 500 或静默异常。

### GAP-05 频率列表可为空且无数量上限
- **位置**：`views.py` 创建/编辑对 `frequencies` 的处理。
- **触发条件**：`frequencies=[]`（业务通常要求至少 1 条）；或提交数万条。
- **预期行为**：应要求至少 1 条频率，并对数量设上限，防止空数据与批量插入性能问题。

### GAP-06 执照责任人校验弱于批复
- **位置**：`views.py` `_validate_and_fill_responsible_user`（仅校验 `is_active=True`）。
- **触发条件**：把**已软删用户**（`deleted_by_id` 非空）或**跨租户用户**指派为责任人。
- **预期行为**：对齐批复侧 `_validate_and_fill_approval_responsible_user`：校验 `deleted_by_id__isnull=True` 且租户一致（超管除外）。

### GAP-07 执照创建/编辑非原子
- **位置**：`views.py` 创建/编辑主流程（执照写入、版本快照、频率删/建、扫描、证据事件分步执行，无 `transaction.atomic`）。
- **触发条件**：频率创建或版本快照中途抛异常。
- **预期行为**：全流程事务包裹，失败整体回滚（对照批复侧已用 `transaction.atomic`）。当前会残留半成品（如执照已建但无频率）。

### GAP-08 执照删除非原子且无审计日志
- **位置**：`views.py` `delete`（附件软删 + 主记录 `delete()`，无事务、无 AuditLog）。
- **触发条件**：附件软删后主删失败；或需要事后追溯删除操作。
- **预期行为**：删除应在事务内完成并写审计日志（对照批复 `delete` 已记录审计）。

### GAP-09 版本号计算竞态
- **位置**：`views.py` 版本快照（`version_no = 现有 max + 1` 查询后创建，`(license, version_no)` 无唯一约束）。
- **触发条件**：同一执照的并发编辑。
- **预期行为**：应有唯一约束或加锁，避免重复/跳号版本。

### GAP-10 执照编辑无并发保护
- **位置**：`views.py` 编辑（直接 `update()`，无版本/时间戳乐观锁）。
- **触发条件**：两名用户同时编辑同一执照。
- **预期行为**：应做并发冲突检测（乐观锁/版本比对），当前后提交者静默覆盖前者（lost update）。

### GAP-11 执照提醒确认未校验责任人与状态
- **位置**：`views.py` 提醒确认（ReminderAck 写入）。
- **触发条件**：非责任人对执照点确认；对 `normal`（未到期）执照点确认。
- **预期行为**：应仅允许**责任人**、且执照处于 `expiring/expired` 时确认（对照批复 ack 已校验 `responsible_user_id == 当前用户` 且状态非 normal）。当前任意具 view 权限用户可对任意执照写 ack。

### GAP-12 执照角标不扣除已确认且与弹窗口径不一致
- **位置**：`views.py` 角标视图（统计全租户 `expiring+expired`，不排除已 ack；弹窗视图按责任人过滤）。
- **触发条件**：责任人已确认后角标不减少；或角标数与弹窗记录数不一致。
- **预期行为**：角标应与弹窗口径一致并排除已确认项（对照批复角标已用 `Exists` 排除 ack）。

### GAP-13 提醒弹窗无分页
- **位置**：执照与批复的提醒弹窗视图。
- **触发条件**：单个责任人负责数千条到期记录。
- **预期行为**：应分页或设返回上限，避免一次性返回超大列表。

### GAP-14 证据包 id 参数未做整数校验
- **位置**：`views.py` 执照证据包视图（`license_id` 直接用于 `filter(pk=...)`）。
- **触发条件**：`?id=abc` 非数字。
- **预期行为**：应校验为整数，非法返回 400；当前非数字会抛 `ValueError` → 500。

### GAP-15 批复创建未校验必填日期
- **位置**：`approval_views.py` 创建（仅校验 `name/doc_no/frequency_text` 非空）。
- **触发条件**：提交不含 `valid_from` 或 `valid_to`。
- **预期行为**：应显式校验两个日期必填并友好报错；当前缺失时 `DateField` 非空约束在入库处报错 → 500。

### GAP-16 批复编辑可将必填字段置空
- **位置**：`approval_views.py` 编辑（未对 `name/doc_no/frequency_text` 做 strip 与非空校验，空串因非 None 通过过滤）。
- **触发条件**：编辑提交 `name=""` 或全空白。
- **预期行为**：编辑应与创建一致地做非空/去空白校验，防止把已有必填字段清空。

### GAP-17 执照列表 N+1 查询
- **位置**：`views.py` 列表循环内逐条查询频率与 `AttachmentService.count`。
- **触发条件**：`page_size` 较大时。
- **预期行为**：应批量聚合频率数与附件数（对照批复侧已做批量处理），降低查询次数。

### GAP-18 字符串字段超长未在应用层校验
- **位置**：执照 `station_name(100)/purpose(500)`；批复 `name(200)/doc_no(100)/frequency_text(200)` 及各 remark。
- **触发条件**：超过 `max_length` 的输入。
- **预期行为**：应用层应做长度校验并友好报错；当前依赖数据库，MySQL 下可能报错或按配置静默截断。

### GAP-19 临界日期语义待确认
- **位置**：到期状态计算（`days_left < 0 → expired`；`0 <= days_left <= 60 → expiring`；`61 → normal`）。
- **触发条件**：`valid_to == 今天`（`days_left==0`）判为 `expiring` 而非 `expired`；`days_left==60` 为 `expiring`、`==61` 为 `normal`。
- **预期行为**：需与产品确认「当天到期」是否应算 `expired`，并明确 60 天边界含义（当前为文档记录项，非必定缺陷）。

### GAP-20 超管跨租户 ack 过滤按请求者租户
- **位置**：`approval_views.py` 弹窗/角标中的 ack 过滤（`tenant_id = 请求用户 tenant_id`）。
- **触发条件**：超管跨租户查看其他租户批复的提醒时。
- **预期行为**：ack 排除应按**记录所属租户**而非请求者租户，避免跨租户查看时排除不准确。

### GAP-21 last_remind_at 无写入逻辑
- **位置**：`models.py` 执照模型 `last_remind_at` 字段，全代码无赋值点。
- **触发条件**：任何提醒流程后该字段仍为初始值。
- **预期行为**：需确认该字段是否应在提醒/扫描时更新；若确为遗留字段应清理（当前为待确认项）。

### GAP-23 执照列表 status 过滤与展示状态不一致
- **位置**：`views.py` 列表 `status` 过滤使用**存储字段** `filter(status=...)`，而展示列返回**实时计算** `computed_status`。
- **触发条件**：缓存字段 `status`（由定时任务每 6 小时维护）滞后于实时状态时。
- **预期行为**：过滤应与展示口径一致（对照批复侧按实时区间过滤）。当前可能出现「过滤 expiring 却混入实际 normal/expired」的结果。

| 能力 | 批复（approval_views.py） | 执照（views.py） |
|---|---|---|
| 分页参数容错 + clamp | 已做 | **缺失（GAP-01）** |
| 创建/编辑事务原子性 | 已做 | **缺失（GAP-07）** |
| 删除审计日志 | 已做 | **缺失（GAP-08）** |
| 责任人软删/租户校验 | 已做 | **缺失（GAP-06）** |
| 提醒确认责任人/状态校验 | 已做 | **缺失（GAP-11）** |
| 角标排除已确认 | 已做 | **缺失（GAP-12）** |
| 列表按实时状态过滤 | 已做 | **缺失（GAP-23）** |
