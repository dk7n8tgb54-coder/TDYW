# 操作审计模块 — 未覆盖边界情况清单

> 用途：交由另一 Agent 进行针对性修复。本文档**仅罗列遗漏的边界/异常/极端场景**，不含修复代码或实现方案。
> 涉及代码：`spug_api/apps/logs/{audit.py, middleware.py, hash_chain.py, views.py, tasks.py, models.py}`、`spug_api/apps/account/views.py`（登录/登出审计）。
> 编号规则：`BC-XX`，便于另一 Agent 引用。严重度：🔴高 / 🟡中 / 🟢低。

---

## 一、哈希链与写入核心（audit.py / hash_chain.py）

### BC-01 🔴 哈希链并发分叉
- **描述**：`save_audit_log` 在 `transaction.atomic()` 内用乐观查询 `filter(tenant_id).order_by('-id').first()` 取 `prev_hash`，未加行锁（无 `select_for_update`）。
- **预期行为**：同租户并发写入时，每条日志的 `prev_hash` 应唯一指向真正的上一条 `log_hash`，链不分叉。
- **触发条件**：同一租户在极短时间内并发产生多条写操作（两个请求读到同一 `last_log`，得到相同 `prev_hash`）。

### BC-02 🔴 哈希链为无密钥纯 SHA256，可被重算伪造
- **描述**：`compute_log_hash` 仅用 SHA256，无 HMAC 密钥、无外部时间戳/CA 锚定。
- **预期行为**：拥有 DB 写权限者篡改字段后不能重算出一致的 `log_hash`。
- **触发条件**：攻击者直接改写 `audit_logs` 表某条记录并重算其后所有 `log_hash`/`prev_hash`。

### BC-03 🔴 保留期清理会永久断裂哈希链且无锚点
- **描述**：`cleanup_old_audit_logs` 物理删除旧记录，删除后剩余最早一条的 `prev_hash` 指向已不存在的前驱。无删除前的链摘要/锚点（checkpoint）机制。
- **预期行为**：合法清理不应被 `verify_hash_chain` 误判为篡改断链。
- **触发条件**：执行定时清理后再运行链校验，边界处报 `broken_at`（假阳性）。

### BC-04 🟡 fork 与删除无法与真实篡改区分
- **描述**：`verify_hash_chain` 仅按 id 升序比对 `prev_hash == 上一条 log_hash`，对"分叉""中间删除""篡改"报同类错误。
- **预期行为**：应能区分链断裂的成因（并发分叉 / 合法清理 / 恶意篡改）。
- **触发条件**：链中存在分叉记录或缺失记录时执行校验。

### BC-05 🔴 校验能力完全未接入（无任务/API/UI/Beat）
- **描述**：`verify_log_hash` / `verify_hash_chain` 已实现但无任何调度、接口或页面调用；Celery Beat 仅注册了 `cleanup_old_audit_logs`。
- **预期行为**：篡改应能被常态化（周期性或按需）发现并告警。
- **触发条件**：日志被篡改后，系统无任何路径主动检测。

### BC-06 🟡 写入失败静默丢失
- **描述**：`save_audit_log` 捕获所有异常仅 `logger.error`，无告警/重试/降级落盘。
- **预期行为**：审计写入失败应可被感知（告警或兜底），不可无声丢失。
- **触发条件**：DB 不可用、字段超长、编码异常等导致 `AuditLog.objects.create` 抛错。

### BC-07 🟡 detail 脱敏关键词双份且不一致 + 中间件版本为死代码
- **描述**：`middleware.py` 定义了 `SENSITIVE_KEYWORDS`/`_is_sensitive_field` 但从未调用（真正脱敏走 `audit.py` 的 `sanitize_audit_detail`）；两处关键词集合不一致（`audit.py` 多出 `captcha/cookie/session`）。
- **预期行为**：脱敏规则应单一来源、集合一致。
- **触发条件**：新增敏感字段命名时仅改其中一处，导致遗漏或困惑。

## 二、字段长度 / 类型越界（models.py + 写入路径）

### BC-08 🔴 target_id 超长导致整条审计丢失（批量删除）
- **描述**：`target_id` 为 `CharField(max_length=50)`；`_extract_id_from_query` 将 `?ids=1,2,3,...` 原样作为逗号串写入。
- **预期行为**：批量删除应完整记录被删对象或安全截断，不应因超长写库失败。
- **触发条件**：`DELETE ?ids=...` 携带较多 id，逗号串超过 50 字符 → 写库报错 → 审计记录静默丢失（见 BC-06）。

### BC-09 🟡 username / ip / user_agent 超长
- **描述**：`username(100)`、`ip(50)`。`user_agent` 已在 `_extract_user_agent` 截断至 500，但 `username`（登录失败可为任意输入）与 `ip`（伪造超长 X-Forwarded-For 链）无截断保护。
- **预期行为**：超长输入应截断入库，不影响审计落库。
- **触发条件**：登录失败时提交 >100 字符用户名；请求头携带超长 XFF。

### BC-10 🟢 非数字/UUID 主键对象无法从路径提取 target_id
- **描述**：`_extract_detail` 仅当路径末段 `isdigit()` 才取为 `target_id`。
- **预期行为**：字符串/UUID 主键对象也应能记录 target_id。
- **触发条件**：对以 UUID 或字符串为主键的资源做 RESTful 操作。

## 三、中间件采集逻辑（middleware.py）

### BC-11 🔴 登出被重复记录且动作错误
- **描述**：`/account/logout/` 未在 `AUDIT_EXCLUDES`，且 `logout` 视图调用 `save_audit_log` 后未置 `request._audit_handled=True`；中间件对该 POST 再记一条（`resolve_action` → `create`，target=`auth`）。
- **预期行为**：一次登出仅产生一条 `logout/auth` 记录。
- **触发条件**：任意用户登出。

### BC-12 🟡 DELETE 请求体（JSON body）内容未采集
- **描述**：`_extract_from_request_body` 对非 POST/PUT/PATCH 直接返回，DELETE 携带的 JSON body（如 `{ids:[...]}`）detail 不被提取，且其 `action` 也不参与 body 覆盖。
- **预期行为**：DELETE with body 的关键参数应可记录。
- **触发条件**：以 DELETE + JSON body 传参的批量删除接口。

### BC-13 🟡 状态变更型 GET 请求不被审计
- **描述**：中间件只记录 POST/PUT/PATCH/DELETE。
- **预期行为**：任何会改变服务端状态或导出数据的操作都应被审计。
- **触发条件**：通过 GET 触发导出/状态变更的端点。

### BC-14 🟡 未认证写请求（401）不被审计
- **描述**：`if not user or not hasattr(user, 'id'): return`，匿名/鉴权失败的写请求直接跳过（登录失败另有专门记录）。
- **预期行为**：对受保护写接口的未授权访问尝试宜留痕（安全盲区）。
- **触发条件**：携带无效/过期 token 对写接口发起 POST/PUT/PATCH/DELETE。

### BC-15 🟡 is_success 依赖 `json_response(error=...)` 约定
- **描述**：`_resolve_success_and_error` 仅识别响应体顶层 `error` 字段判失败。
- **预期行为**：非该约定的失败（如 `{errors:[...]}`、`{message:...}`、部分成功）也应正确判为失败。
- **触发条件**：视图返回非标准错误结构，或 HTTP 200 内含业务失败。

### BC-16 🟡 大响应体计算 response_hash 的性能与副作用
- **描述**：每个写请求都对 `response.content` 全量 SHA256。
- **预期行为**：大响应不应显著拖慢请求或触发对惰性内容的意外读取。
- **触发条件**：批量创建/更新返回大列表的接口。

### BC-17 🟢 resolve_target 使用子串包含匹配（`prefix in path`）
- **描述**：`resolve_target` 用 `in` 子串匹配而非前缀锚定，依赖 dict 插入顺序取首个命中。
- **预期行为**：路径应精确映射到唯一对象类型，避免误配。
- **触发条件**：新增路径含既有 key 子串（如含 `exec`/`home`/`apis` 片段）时可能误判类型。

### BC-18 🟢 未登记路径归为 target_type='unknown'
- **描述**：`TARGET_MAP` 未覆盖的新模块路径记为 `unknown`。
- **预期行为**：新模块上线时对象类型应可识别。
- **触发条件**：新增业务模块后未同步更新 `TARGET_MAP`。

## 四、查询 / 导出（views.py）

### BC-19 🔴 start_time/end_time 非法格式导致 500
- **描述**：两处 `datetime.strptime` 二次尝试后仍无 try 兜底，非 `YYYY-MM-DD[ HH:MM:SS]` 格式（如 `2026/01/01`、乱码）会抛 `ValueError` 未捕获。
- **预期行为**：非法时间参数应返回友好错误，而非 500。
- **触发条件**：查询/导出接口传入非法 `start_time` 或 `end_time`。

### BC-20 🟡 is_success 布尔参数解析歧义
- **描述**：`Argument('is_success', type=bool)` 来自 GET query 字符串，`bool('false')` 为 True。
- **预期行为**：`is_success=false` 应筛选失败记录。
- **触发条件**：前端/调用方以 `?is_success=false` 传参（需确认 `JsonParser` 的 bool 解析行为）。

### BC-21 🟡 导出静默截断为 5000，无提示
- **描述**：导出 `queryset[:5000]` 硬上限，无强制时间范围；超出部分被丢弃且不告知用户结果被截断。
- **预期行为**：结果超限应明确提示或强制收窄条件。
- **触发条件**：无窄条件导出、匹配记录 > 5000。

### BC-22 🟡 keyword 无法检索 IP / request_id / action
- **描述**：`keyword` 仅覆盖 `username / target_name / detail`。
- **预期行为**：安全排查常需按 IP、请求 ID 检索。
- **触发条件**：调查者按来源 IP 或 request_id 搜索。

### BC-23 🟡 detail__icontains 全表扫描 + 深分页 OFFSET 慢
- **描述**：`detail`（TextField）无索引，`keyword` 触发 `LIKE %kw%`；分页用 `[start:end]` 大 OFFSET。
- **预期行为**：大表下查询应保持可接受性能。
- **触发条件**：审计表数据量大时进行关键词搜索或翻至很深的页码。

### BC-24 🟢 page_size / page 静默钳制无反馈
- **描述**：`page=max(page,1)`、`page_size=min(max(page_size,10),100)`，越界被静默修正。
- **预期行为**：越界参数宜有反馈或按约定处理。
- **触发条件**：请求 `page_size<10` 或 `>100`、`page<1`。

### BC-25 🟢 verify 校验端点缺失（前端若存在校验入口）
- **描述**：`urls.py` 未注册链校验路由；若前端存在"验证/verify"入口则会 404。
- **预期行为**：前端可用的校验入口应有对应后端路由。
- **触发条件**：前端触发链完整性校验请求。

## 五、定时清理（tasks.py）

### BC-26 🟡 清理动作自身未被审计
- **描述**：`cleanup_old_audit_logs` 删除审计记录但未调用 `save_audit_log`。
- **预期行为**："谁/何时/删除多少条审计"应可追溯。
- **触发条件**：每次定时清理执行后，审计表内无该操作痕迹。

### BC-27 🟡 名为"归档"实为物理删除，数据不可恢复
- **描述**：docstring 称"归档清理"，实际仅 `delete()`，无冷存储/导出归档。
- **预期行为**：合规审计数据应归档而非直接销毁（或明确保留策略）。
- **触发条件**：达到保留期的记录被永久删除。

### BC-28 🟢 dry_run 与 days 钳制交互
- **描述**：`days = max(days, 30)` 在 dry_run 前生效，预演结果反映的是钳制后的天数而非请求值。
- **预期行为**：预演应清晰反映实际将执行的参数。
- **触发条件**：以 `days<30` 调用 dry_run 预演。

## 六、登录 / 登出审计（account/views.py）

### BC-29 🟡 登录成功/失败、登出记录缺 request_id / user_agent
- **描述**：`handle_user_info`、`handle_login_record`、`logout` 中的 `save_audit_log` 未传 `request_id`/`user_agent`，这些记录相关字段为空，与中间件记录不一致。
- **预期行为**：认证类记录应与其他审计记录字段口径一致，便于按请求关联。
- **触发条件**：每次登录（成功/失败）、登出。

### BC-30 🟢 未知账号登录失败仅超管可见
- **描述**：不存在的用户名登录失败写入 `default` 租户（产品定义），租户管理员看不到针对本系统的未知账号爆破。
- **预期行为**：需确认是否要向租户侧暴露此类攻击线索（当前为有意设计，列出供复核）。
- **触发条件**：使用不存在用户名的登录失败尝试（含跨租户爆破）。
