# 设备履历模块 — 边界条件缺口清单（交接修复用）

> 本文件仅列举当前代码**未覆盖/处理不当**的边界条件、异常输入与极端场景，供另一 Agent 做针对性修复。
> 不包含修复代码与实现方案。每条含：位置、描述、触发条件、预期行为、当前行为（缺口）、严重级。
>
> 涉及文件：
> - 后端：`spug_api/apps/device/{models.py, views.py, validators.py, exporters.py, pdf_export.py, urls.py}`
> - 前端：`spug_web/src/pages/device/{Form.js, EventForm.js, store.js, components/EventFormFields.js}`
>
> 编号规则：`BC-<模块>-<序号>`。模块：DEV=设备档案、EVT=事件、EXP=导出/证据包、FE=前端、X=跨领域。
> 严重级：高（数据错误/500/证据链断裂/越权面）、中（校验缺失/体验误导）、低（健壮性/文案）。

---

## 一、设备档案 CRUD（`views.py:DeviceResumeView` / `Form.js`）

### BC-DEV-01 字符串字段长度超限未校验（新增/编辑）｜高
- **位置**：`views.py` `post`(102-213) / `put`(215-324)；长度定义见 `models.py:40-56`
- **描述**：除 `device_purpose`(500)、`remark`(1000) 外，`device_sn`(50)/`device_name`(50)/`device_model`(50)/`frequency`(30)/`call_sign`(30)/`install_location`(200)/`geo_coordinate`(100)/`manufacturer`(100)/`install_unit`(100)/`use_unit`(100)/`install_time`(20)/`enable_time`(20) 均无长度校验。
- **触发条件**：API 或前端（前端这些字段也未设 `maxLength`）提交超过 `max_length` 的值。
- **预期行为**：提交前逐字段长度校验，返回精确字段级错误。
- **当前行为（缺口）**：入库触发 MySQL `DataError`（`DatabaseError` 子类），被 `except (IntegrityError, DatabaseError)` 捕获，新增时返回"**设备资产编号已存在，请重试**"、编辑时返回"数据关联冲突"——错误信息严重误导。

### BC-DEV-02 install_time / enable_time 无格式与逻辑校验｜高
- **位置**：`post`/`put` 对两字段仅 `type=str`；`models.py:51-52`（`CharField`）
- **描述**：安装时间、启用时间为纯字符串，既不校验 `YYYY-MM-DD` 格式，也不校验 `enable_time >= install_time`。
- **触发条件**：API 传任意字符串；或启用时间早于安装时间。
- **预期行为**：校验日期格式；启用时间不早于安装时间。
- **当前行为（缺口）**：任意字符串原样入库，时间顺序颠倒不报错。

### BC-DEV-03 geo_coordinate 经纬度格式/范围未校验｜中
- **位置**：`post`/`put` `geo_coordinate`；`Form.js:104-109`（仅 placeholder）
- **描述**：文档格式为"经度,纬度"，但前后端均不校验格式与经纬度范围（lng -180~180 / lat -90~90）。
- **触发条件**：提交 `abc` 或超范围坐标。
- **预期行为**：校验格式与数值范围。
- **当前行为（缺口）**：任意字符串入库。

### BC-DEV-04 responsible_user_name 后端未强制必填｜中
- **位置**：`post:122-124` / `put:234-235`（`required=False`）；`models.py:55`（无 null/blank）
- **描述**：前端必填，但后端 `responsible_user_name`/`responsible_user_id` 均 `required=False`，缺省回落为 `''`。
- **触发条件**：API 不传该字段直接创建/编辑。
- **预期行为**：与业务一致，后端强制必填（或明确允许为空）。
- **当前行为（缺口）**：可创建/保存无负责人的设备，绕过前端约束。

### BC-DEV-05 必填字符串未去空白（纯空格绕过必填）｜中
- **位置**：所有 `type=str` 必填参数（如 `device_sn`、`device_name`）
- **描述**：`JsonParser(type=str)` 不做 `strip`，纯空格串可通过必填校验。
- **触发条件**：`device_sn="   "` 等。
- **预期行为**：`strip` 后判空。
- **当前行为（缺口）**：空白值入库，产生"看似有值实为空"的脏数据。

### BC-DEV-06 详情查询 id 非数字导致未捕获 500｜高
- **位置**：`get:40-48`，`request.GET.get('id')` 后 `filter(pk=record_id)`（未经 `JsonParser`，无 try）
- **描述**：详情接口直接用原始 id 查询。
- **触发条件**：`GET ...?id=abc`。
- **预期行为**：非数字返回友好错误（如"参数错误"）。
- **当前行为（缺口）**：`filter(pk='abc')` 抛 `ValueError` → HTTP 500。

### BC-DEV-07 恢复软删除记录时不写证据事件（证据链不对称）｜高
- **位置**：`post` 恢复分支 `152-180`
- **描述**：复用已软删除编号会"恢复重建"（复用原 ID），但不调用 `record_evidence_event`；而"删除"与"状态变更"均写证据事件。
- **触发条件**：以已软删除设备的 `device_sn` 重新创建。
- **预期行为**：恢复/重建写入证据事件（before=deleted，after=active）。
- **当前行为（缺口）**：证据链缺失"恢复/重建"节点，删除→复用之间存在空档。

### BC-DEV-08 编辑无乐观锁（并发丢失更新）｜中
- **位置**：`put`（无 `version` 字段，`models.py` 未定义版本）
- **描述**：并发编辑无冲突检测。
- **触发条件**：两用户几乎同时编辑同一设备。
- **预期行为**：版本/时间戳校验，冲突时提示。
- **当前行为（缺口）**：后写静默覆盖先写。

### BC-DEV-09 状态变更证据事件为 best-effort（可静默丢失）｜高
- **位置**：`put:292-316`（`try/except` 仅记录日志）
- **描述**：状态变更写证据事件与业务保存不在同一事务。
- **触发条件**：`record_evidence_event` 抛异常。
- **预期行为**：证据写入与业务同事务/失败回滚/补偿重试。
- **当前行为（缺口）**：状态已变更但证据事件缺失，仅有一条错误日志。

### BC-DEV-10 delete_reason 超长（>500）未校验｜低
- **位置**：`delete:329-331`；`models.py:61`（`max_length=500`）
- **触发条件**：删除时传超长原因。
- **预期行为**：长度校验并返回字段级错误。
- **当前行为（缺口）**：`DataError` → 返回"删除设备失败，请重试"（误导）。

### BC-DEV-11 软删除设备的事件仍可编辑/删除（一致性）｜中
- **位置**：`DeviceEventView.put:509-549` / `delete:551-580`（仅按 event pk+tenant 过滤，不校验关联设备是否已软删除）
- **描述**：设备软删除后，其历史事件仍可被修改/物理删除；而新增事件（`post:453-455` 用 `objects`）会被拒。
- **触发条件**：对已软删除设备的事件调用编辑/删除接口。
- **预期行为**：明确策略——软删设备的事件应只读或联动处理。
- **当前行为（缺口）**：行为不一致，已删设备的履历仍可被改写。

### BC-DEV-12 模型注释与软删除实现不符 + 事件展示策略未定义｜低
- **位置**：`models.py:110-115` 注释称"删除设备时在 views 层事务内级联删除事件"，实际 `delete` 为**软删除且不动事件**；`DeviceEventView.get:411-419` 亦不过滤软删设备的事件。
- **触发条件**：软删除设备后查询/展示其事件。
- **预期行为**：更正注释；明确软删设备事件是否在列表/时间线中展示。
- **当前行为（缺口）**：注释误导后续维护；软删设备事件仍出现在事件列表。

## 二、设备事件（`views.py:DeviceEventView` / `validators.py` / `EventFormFields.js`）

### BC-EVT-01 event_time 格式仅对检修类型校验｜高
- **位置**：`validators.py:validate_time_logic:56-80`（仅当 `repair_time` 与 `event_time` 同时存在才校验）
- **描述**：类型 1（重大故障维修）、2（设备更新）无 `repair_time`，故 `event_time` 完全不做格式校验。
- **触发条件**：类型 1/2 经 API 提交非法 `event_time`。
- **预期行为**：所有事件类型均校验 `event_time` 格式（`YYYY-MM-DD HH:MM`）。
- **当前行为（缺口）**：类型 1/2 的 `event_time` 任意字符串原样入库。

### BC-EVT-02 未来时间仅对检修类型拦截｜中
- **位置**：`validate_time_logic:74-75`（仅在 repair/event 均存在时判断未来）；前端 `EventFormFields.js` 所有 `DatePicker` 无 `disabledDate`
- **描述**：类型 1/2 的 `event_time` 可为未来时间。
- **触发条件**：类型 1/2 选择/提交未来时间。
- **预期行为**：统一拦截未来时间（或明确业务允许）。
- **当前行为（缺口）**：类型 1/2 未来时间不拦截，前端也不禁用未来日期。

### BC-EVT-03 事件时间早于设备安装/启用时间未校验｜中
- **位置**：`post`/`put` 及 `validators.py`（无跨表时间校验）
- **描述**：事件 `event_time` 可早于所属设备的 `install_time`/`enable_time`。
- **触发条件**：为设备添加发生在其安装之前的事件。
- **预期行为**：事件时间应不早于设备安装时间（至少给出告警）。
- **当前行为（缺口）**：不校验，可产生时间线倒置的履历。

### BC-EVT-04 事件字段长度超限未校验｜高
- **位置**：`post`/`put`；`models.py:117-128`；前端 `EventFormFields.js` 无 `maxLength`
- **描述**：`event_title`(100)/`fault_part`(100)/`fault_phenomenon_cause`(1000)/`maintenance_measures`(2000)/`related_user_name`(100)/`remark`(500) 无长度校验。
- **触发条件**：超长文本提交。
- **预期行为**：字段级长度校验。
- **当前行为（缺口）**：`DataError` → "创建事件失败，数据关联冲突，请联系管理员"（误导）。

### BC-EVT-05 related_user_name 后端未强制必填｜中
- **位置**：`_parse_event_form:499-500`（`required=False`）；`models.py:126`（无 null/blank）
- **描述**：前端必填，后端可缺省为 `''`。
- **触发条件**：API 不传记录人/检修人。
- **预期行为**：后端强制必填（或明确允许为空）。
- **当前行为（缺口）**：可创建无记录人的事件。

### BC-EVT-06 事件列表 device_resume_id 可选 → 返回全租户事件｜中
- **位置**：`get:403,413-415`（`device_resume_id` `required=False`）
- **描述**：不传 `device_resume_id` 时返回该租户全部设备的事件。
- **触发条件**：`GET /device-event/` 不带 `device_resume_id`。
- **预期行为**：明确是否允许全量；如非预期应强制该参数。
- **当前行为（缺口）**：可一次性拉取租户内所有事件（性能与浏览面隐患）。

### BC-EVT-07 编辑事件直接改写，绕过"更正机制"（证据不可变性）｜高
- **位置**：`put:537-547` 直接 mutate；`models.py:131-135` 定义了 `correction_event_id`/`correction_reason`/`corrected_by_id`/`corrected_at` 但**无任何视图使用**
- **描述**：履历事件本应不可变，修改应走"更正事件"链；当前直接原地修改，更正字段是死代码。
- **触发条件**：编辑任一历史事件。
- **预期行为**：历史事件不可变，修改生成指向原事件的更正记录。
- **当前行为（缺口）**：历史被静默篡改，证据闭环更正机制未落地。

### BC-EVT-08 删除事件无证据事件/审计｜高
- **位置**：`delete:551-580`（硬删除）
- **描述**：物理删除事件，既不写 `record_evidence_event` 也不写审计日志。
- **触发条件**：删除任一历史事件。
- **预期行为**：删除写入证据事件或审计日志，保留痕迹。
- **当前行为（缺口）**：履历可被无痕抹除。

### BC-EVT-09 event_type 过滤值无枚举校验｜低
- **位置**：`get:404,417-419`；PDF 导出 `event_type`
- **描述**：过滤用 `event_type` 不校验是否合法枚举（仅返回空集）。
- **触发条件**：`event_type=99`。
- **预期行为**：非法枚举返回错误或忽略。
- **当前行为（缺口）**：静默返回空（低危，仅体验）。

### BC-EVT-10 repair_time 等于 event_time 的边界需确认｜低
- **位置**：`validate_time_logic:71`（`repair_time < event_time` 才判错，相等放行）
- **描述**：修复时间与故障时间相等被允许。
- **触发条件**：两时间取同一分钟。
- **预期行为**：确认业务是否允许"零耗时修复"。
- **当前行为（缺口）**：允许相等（可能非预期）。

## 三、导出与证据包（`DeviceResumeExportView` / `DeviceEvidencePackageView` / `exporters.py`）

### BC-EXP-01 PDF 导出 device_id 非数字 → 未捕获 500｜高
- **位置**：`views.py:627` `filter(pk=device_id)`（在 `json.loads` 的 try 之外，无独立 try）
- **触发条件**：请求体 `{"device_id":"abc"}`。
- **预期行为**：校验数字/捕获异常，返回友好错误。
- **当前行为（缺口）**：`ValueError` → HTTP 500。

### BC-EXP-02 PDF 导出 event_type 非数字 → 未捕获 500｜高
- **位置**：`views.py:642` `events_qs.filter(event_type=event_type)`
- **触发条件**：请求体 `{"device_id":1,"event_type":"abc"}`。
- **预期行为**：校验/捕获后返回友好错误。
- **当前行为（缺口）**：`ValueError` → HTTP 500。

### BC-EXP-03 证据包 id 非数字 → 未捕获 500｜高
- **位置**：`views.py:764-768` `request.GET.get('id')` 后 `filter(pk=device_id)`
- **触发条件**：`GET ...evidence?id=abc`。
- **预期行为**：非数字返回友好错误。
- **当前行为（缺口）**：`ValueError` → HTTP 500。

### BC-EXP-04 证据包审计日志回退过宽（证据串味）｜高
- **位置**：`views.py:785-790`（`target_id` 无命中时回退查询"全租户所有 device 类型审计日志"）
- **描述**：回退把其他设备的审计日志一并打入本设备证据包。
- **触发条件**：目标设备无 `target_id` 精确命中的审计记录。
- **预期行为**：回退限定本设备，或不回退。
- **当前行为（缺口）**：证据包被无关设备审计日志污染，损害证据可信度。

### BC-EXP-05 软删除设备证据包不可导出（与 PDF 不一致）｜高
- **位置**：证据包 `views.py:768` 用 `objects`（排除软删）；PDF `views.py:627` 用 `all_objects`（含软删）
- **描述**：同为取证场景，两处对软删设备的可见性不一致。
- **触发条件**：对已软删除设备导出证据包。
- **预期行为**：取证场景统一用 `all_objects`。
- **当前行为（缺口）**：证据包返回"设备不存在"，已删设备无法取证 → 证据链断裂。

### BC-EXP-06 PDF/证据包无事件数量上限（极端场景）｜中
- **位置**：`views.py:641-648`（PDF 全量事件）、`700-748`（快照全量事件）、`792-799`（附件）
- **描述**：全量加载事件/附件构建 PDF/ZIP，无上限。
- **触发条件**：单设备存在上万事件或大量附件。
- **预期行为**：设置上限或流式/分卷处理。
- **当前行为（缺口）**：内存占用与请求超时风险。

### BC-EXP-07 PDF 长文本截断丢失信息｜低
- **位置**：`pdf_export.py:_value:504-505`（`>200` 字符截断加 `...`）
- **描述**：单元格超 200 字符直接截断，信息丢失。
- **触发条件**：`maintenance_measures`（可达 2000 字符）等长文本导出。
- **预期行为**：换行/分段完整展示，或明确注明截断。
- **当前行为（缺口）**：内容被静默截断。

### BC-EXP-08 Excel 导出无枚举/字段一致性问题｜低（对照项，当前较健壮）
- **位置**：`exporters.py`（已用 `check_export_limit` 限流、空数据友好提示）
- **说明**：`current_status` 多选仅用于 `__in` 过滤，无枚举校验但不致错。此处主要作为对照，风险低。

## 四、前端（`Form.js` / `EventForm.js` / `EventFormFields.js` / `store.js`）

### BC-FE-01 关键输入无 maxLength（与 BC-DEV-01/BC-EVT-04 对应）｜中
- **位置**：`Form.js`（除 `device_purpose`/`remark`）、`EventFormFields.js`（全部 Input/TextArea）
- **触发条件**：用户输入超过模型 `max_length`。
- **预期行为**：前端 `maxLength` 限制，前置拦截。
- **当前行为（缺口）**：越过前端直达后端 `DataError`，报错信息误导。

### BC-FE-02 日期选择器无 disabledDate（允许未来/任意日期）｜中
- **位置**：`Form.js:151,158`（安装/启用时间）、`EventFormFields.js:24,70,114`（事件/修复时间）
- **触发条件**：选择未来日期或不合理日期。
- **预期行为**：禁用未来日期、约束合理范围。
- **当前行为（缺口）**：无 `disabledDate`，前端不拦截。

### BC-FE-03 enable_time/install_time 无前端顺序校验｜中
- **位置**：`Form.js:146-159`
- **触发条件**：启用时间早于安装时间。
- **预期行为**：跨字段校验，提示顺序错误。
- **当前行为（缺口）**：不校验。

### BC-FE-04 修复时间与故障时间无前端顺序校验｜低
- **位置**：`EventFormFields.js`（`repair_time` vs `event_time`）
- **描述**：仅后端校验，前端提交后才报错。
- **预期行为**：前端跨字段即时校验，改善体验。
- **当前行为（缺口）**：需往返后端才提示。

### BC-FE-05 负责人/记录人为自由文本，不校验真实用户｜中
- **位置**：`Form.js:190-199`（`UserSelect` 实为普通 `Input`）、`EventFormFields.js`（`related_user_name` Input）
- **触发条件**：输入不存在/错拼的人名。
- **预期行为**：可选真实用户或校验存在性。
- **当前行为（缺口）**：任意姓名字符串入库，责任人不可追溯。

### BC-FE-06 "重大故障维修"（类型1）不采集故障结构化字段｜低（设计确认项）
