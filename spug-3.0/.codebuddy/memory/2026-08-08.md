# 2026-08-08 党建根目录上传 bug 修复

## 根因
`is_folder_in_scope(folder_id, code, include_root=True)` 中 `folder_id` 来自 `request.POST.get('folder_id')` 为**字符串**（如 `'1'`），而 `root_id` 来自数据库为**整数**（如 `1`）。Python 3 中 `'1' == 1` 为 `False`，导致上传到**党建根目录**时 scope 校验误拒，返回 "无权访问党建文档目录外的资料"。

子文件夹上传不受影响（`_is_descendant_of` 中 `parent_id` 和 `root_id` 都是 DB 整数，`1 == 1` 成立）。

## 修复
`apps/document/services/system_folder_service.py` 的 `is_folder_in_scope()` 增加 `int(folder_id)` 类型转换。

## 验证
- `is_folder_in_scope('1', PB)` 修复前=False，修复后=True
- Django check 通过
- 6/6 复制作用域测试仍通过

## 根因链
1. http.js 拦截器自动注入 `system_folder` 到所有 `/api/document/*` 请求
2. 但**不注入** `is_public`
3. `TransferListView` 调用 `validate_system_folder_context(system_folder, is_public)`
4. 当 `system_folder='party_building_documents'` 但 `is_public=False`（未提供默认 False）时返回错误
5. 轮询每 5 秒重复，持续 120 次（10 分钟）

## 修复（前后端双修）
- **前端** `useFileOperations.js`：轮询请求增加 `is_public: isPublic` 参数
- **后端** `transfer/list.py`：`system_folder` 有值但 `is_public` 未提供时默认 `True`（系统文件夹本身是公共空间）

# 2026-08-08 前端开发服务器代理卡死修复

## 问题
WSL2 环境下重启 Docker 容器后，前端 `npm start` 开发服务器无限加载（不报错不超时）。

## 根因
`http-proxy-middleware@0.19.2`（旧版）内部 `http-proxy` 不自动清理死连接。Docker 容器重启时代理与后端的 TCP 连接变半开，代理仍复用死连接发送请求 -> 浏览器无限等待。

## 修复
`spug_web/src/setupProxy.js` 给 `/api` 代理增加 `proxyTimeout: 10000`（10s）+ `timeout: 30000`（30s）超时配置，使连接失败时快速返回 503 而非无限等待。

## 运维建议
- 重启 Docker 容器后**同时重启 `npm start`**（`pkill -f "react-app-rewired"` 然后 `npm start`）
- 若 WSL2 网络层卡死：`wsl --shutdown` 重置
