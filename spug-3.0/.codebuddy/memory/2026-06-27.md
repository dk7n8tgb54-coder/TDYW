# 2026-06-27 工作日志

## 干扰模块 P2 问题修复（依据《干扰模块修复建议.md》）

修复《干扰模块修复建议.md》中的 3 个 P2 问题。P0/P1 在之前会话已修复（权限二次校验、服务端筛选分页、导出接口）。

### P2-1：表格序号翻页后仍从 1 开始
- 位置：`spug_web/src/pages/interference/Table.js`
- 根因：render 里读 `store.pagination || {}`，但 store 上根本没有 `pagination` 字段，真实字段是 `pageNum`/`pageSize`，导致 `currentPage` 永远回退成 1
- 修复：改为 `(store.pageNum - 1) * store.pageSize + index + 1`
- 验证：第 2 页第一条序号应为 11，每页 20 条时第 2 页第一条序号应为 21

### P2-2：统计接口按完整时间聚合后再截断日期，日维度数据会重复
- 位置：`spug_api/apps/interference/views.py` InterferenceStatisticsView
- 根因：`filtered_records.values('datetime', 'frequency').annotate(count=Count('id'))` 按 datetime 完整字符串（含时分秒）分组，同一天不同时间会产生多条相同 `date+frequency` 行，Python 层 `datetime[:10]` 截断只改了 key 不合并 count
- 修复：用 `Substr('datetime', 1, 10)` 在数据库层 annotate 出 `date` 字段，再 `values('date', 'frequency').annotate(count=Count('id'))`，数据库直接按日期聚合
- 验证：同一天同频率创建 3 条不同时间记录，统计接口应返回 1 条该日期该频率记录 count=3

### P2-3：日期使用 CharField 保存（短期加格式校验）
- 位置：`spug_api/apps/interference/views.py` InterferenceView.post
- 根因：datetime 是 CharField，列表/统计/首页/值班都依赖 "YYYY-MM-DD HH:MM:SS" 格式，非标准格式会导致筛选失准、排序错乱、今日统计匹配不到
- 短期修复：post 方法在 form 解析后、业务逻辑前用 `datetime.strptime(form.datetime, '%Y-%m-%d %H:%M:%S')` 校验，失败返回错误提示
- 未做：DateTimeField 迁移（中长期，需新增 occurred_at 字段 + 数据迁移 + 前后端切换）

### 验证
- 前端 read_lints 0 错误
- 后端 py_compile COMPILE_OK（tdyw-test 容器）

### 关键经验
- MobX store 字段名要和前端代码严格对应，`store.pagination` 这种不存在的字段会静默回退到默认值，难以发现
- CharField 存日期做聚合时，Python 层截断字符串只改 key 不合并数据，必须在 SQL 层用 Substr 聚合
- 字段类型与业务语义不符（CharField 存日期）是技术债，短期用校验兜底，长期应迁移字段类型

3. **Django 3.2 内置迁移 auth.0012**：first_name max_length 30->150，正常升级迁移，已应用
