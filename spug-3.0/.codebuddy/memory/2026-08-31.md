## 数据质量巡检孤儿文件核查（只读调查，未改代码）

用户问"数据质量巡检那些孤儿文件都是什么"。在 `tdyw` 容器实际执行
`manage.py data_quality_check --check orphan_disk_files`，结果 27 个孤儿，扫描 845 个文件。

**结论：27 个全部是误报（false positive）。**

- 27 个文件 100% 是 `thumbnails/*_thumb.jpg` 缩略图：
  - `public/folder-95/thumbnails/` ×1（CA证书安装步骤）
  - `party_building_documents/files/folder-9/thumbnails/` ×21（人名命名的批量导入，2026-07-25）
  - `folder-76` ×2、`folder-83` ×2、`folder-86` ×1（2026-07-31 前后）
- 根因：`apps/alert/management/commands/data_quality_check.py` 的
  `check_orphan_disk_files()` 收集 known_paths 时只查了 `tdyw_document_file_public.file_path`，
  **漏了同表的 `thumbnail_path` 字段**（`DocumentFilePublic.thumbnail_path`，存绝对路径，max_length=500）。
- 验证：把 `thumbnail_path` 纳入后重新扫描，DB 中 thumbnail 记录恰好 27 条，孤儿数 = **0**。

**同类问题（未修）**：`check_file_db_consistency()` 也只查 `file_path`，
缩略图在磁盘丢失不会被发现（反向漏检）。修法同为补 `thumbnail_path`。

**环境操作经验**：
- `wsl bash -c 'docker exec ... > /tmp/x.json'` 的重定向发生在 WSL 而非容器内，
  文件落在 WSL `/tmp`，用 `cp /mnt/e/...` 取出即可，不要 `docker cp` 容器路径。
- 内联 `python -c "...exec(open(...))..."` 引号嵌套在 WSL+PowerShell 下必炸，
  改用 `docker exec -i ... python manage.py shell < /mnt/e/xxx.py`（stdin 方式）可行。

## 数据分析时间跨度 1 年 → 5 年

用户："数据分析模块能查看的时间跨度只有 1 年，希望多一点"。

**结论：上限卡在后端 `parse_date_range`，前端无限制也无快捷选项（选超 1 年直接后端报错）。**

改动 5 个文件（+71/-11）：
- `apps/data_analysis/services/common.py`：新增常量 `DEFAULT_RANGE_DAYS=365` /
  `MAX_RANGE_DAYS=1826`（约 5 年，含起止日）；校验改为 `span_days=(end-start).days+1 > MAX`
  → 报错文案 `f'日期范围不能超过 {MAX_RANGE_DAYS} 天（约 5 年）'`。
  **默认区间仍 1 年**（用户只说上限，YAGNI 不动默认）。
- `spug_web/.../store.js`：导出 `DEFAULT_RANGE_DAYS`/`MAX_RANGE_DAYS`/`getDatePresets()`
  （近半年/1年/2年/3年/5年，函数形式避免模块加载后日期不更新）。
- `spug_web/.../index.js`：RangePicker 加 `ranges` + `disabledDate` + `onCalendarChange`。
- `spug_web/.../components/TrendChart.js`：`<Axis name="month" label={{ autoHide: true }} />`
  （5 年 = 60 个月点，X 轴标签会重叠，需自动抽稀）。
- `apps/data_analysis/tests.py`：把"超 366 天"用例改为"超 5 年"，新增 3 年区间放行 +
  MAX 边界（end-(MAX-1) 天）放行用例。

**踩坑（重要）：antd 4.21.5 的 RangePicker `disabledDate` 没有第二参数 `info`**
- rc-picker 2.6.11 的 `hooks/useRangeDisabled.js` 里是 `disabledDate(date)` 只传日期；
  antd `generatePicker/generateRangePicker.js` 也没包装。网上"disabledDate(current, info)"写法
  **在 antd 4.21 不生效**（那是 antd 5 / rc-picker 新版）。
- ✅ 正确解法（antd 官方限制区间示例）：`useState` 存 `onCalendarChange` 的日期，
  `disabledDate` 内读该 state 计算。不能用 `useRef`（ref 变化不触发重渲染，面板禁用态不刷新）。
- rc-picker 的 `onCalendarChange(values, strs, info)` 里 `info.range = 'start'|'end'`；
  面板关闭用 `onOpenChange` 清空 state。
- 另加"禁止选未来日期"（`current.isAfter(moment(),'day')`）。

验证：
- `manage.py test apps.data_analysis.tests --noinput --keepdb` → 21/21 OK。
- 容器内真实跑 service（dev 库只读，admin）：3 年→32 个月点、5 年→60 个月点、
  超 5 年→`日期范围不能超过 1826 天（约 5 年）`。临时脚本已删。
- 全部趋势都是 `build_monthly_trend`（TruncMonth 按月），跨度大不增加 SQL 分组负担，
  只增加 X 轴点数，故 5 年上限安全。

加强后的 `.formContainer` 配方（4 层叠加，缺一不像玻璃）：
1. **渐变磨砂底**（比纯色通透）：
   `linear-gradient(135deg, rgba(255,255,255,.72) 0%, rgba(255,255,255,.42) 100%)`
2. **模糊**：`backdrop-filter: blur(22px) saturate(180%)`（saturate 让透出的蓝更亮，是"玻璃"关键）
3. **蓝白双描边 + 顶部内高光**（用 box-shadow 多层，不用 border，避免被 background 渐变切断）：
   ```
   0 0 0 1px rgba(255,255,255,.65),   /* 白描边 */
   0 0 0 2px rgba(24,144,255,.18),    /* 蓝描边 */
   0 12px 40px rgba(16,60,130,.18),   /* 外投影 */
   inset 0 1px 0 rgba(255,255,255,.9) /* 顶部内高光（玻璃反光） */
   ```
4. **子元素必须一起半透明**，否则 antd 实心白输入框会在玻璃上割裂成白块：
   - Input：`.45` 白 + 白描边 `.75`；hover `.55`；focus `.62` + 蓝色 3px 光晕

   - 主按钮改渐变 `linear-gradient(135deg,#2e9bff,#096dd9)` + `border:none`

**关键认知**：玻璃质感的成败不在卡片本身，而在**卡片内所有子元素是否同步半透明**。
只给卡片加 backdrop-filter 而子元素是实心，视觉上是"白板贴了层膜"。

**第三轮：用户要求"液态玻璃（liquid glass）" + 追问标题字体/颜色要不要改。**

**液态玻璃 = 磨砂玻璃 + 5 个增量特征**（缺哪些就不像"液态"）：
1. **圆角更大**（24px vs 14px）—— 模拟液体表面张力，这是最显著的区别
2. **模糊更强**：`blur(30px) saturate(200%) brightness(1.06)`（磨砂版是 22px/180%）
3. **三段渐变底**（`.58 → .26 → .48% → .42`）—— 中间比两端更透，做出"液面凹陷"的折射不均
4. **镜面高光光斑**（`::before` 双层 radial-gradient）：
   - 左上主光斑 `radial-gradient(130% 85% at 12% -8%, rgba(255,255,255,.8), transparent 58%)`
   - 右下蓝折射 `radial-gradient(95% 65% at 88% 108%, rgba(24,144,255,.18), transparent 62%)`
5. **底部聚光弧**（`::after`）：`left/right:14%; bottom:0; height:2px` 的横向渐隐亮线

**关键技术点（踩坑记录）**：
- 伪元素高光**必须 `z-index: -1`**，否则会覆盖在输入框/文字上洗白内容。
  同时父元素要 `isolation: isolate` 创建 stacking context，否则 -1 会跑到父背景之后看不见。
  绘制顺序：父背景 → z-index:-1 子元素 → 普通内容。正好是"高光在玻璃上、在文字下"。
- 用 `top/right/bottom/left: 0` 而非 `inset: 0`（后者需 Safari 14.1+，企业内网浏览器保守起见）
- 四边用 4 条 `inset` 不同亮度的白线（上 .95 / 左 .55 / 右 .38 / 下 .6）模拟玻璃厚度与光照方向
- `overflow: hidden` 让圆角裁剪高光；登录表单无下拉，安全

**⚠️ 已验证的禁用组合**：`-webkit-background-clip: text` + `-webkit-text-fill-color: transparent`
的元素上**不要加 `filter: drop-shadow()`** —— filter 会创建独立渲染层，可能导致渐变文字整体透明不可见。
（我加了又撤掉了。）要加投影只能用 `text-shadow`，但同样会透出实心影子，最终选择只靠加深颜色。

**PowerShell 教训**：路径含中文（机场通信导航部...jpeg）在 PS 命令里会因编码

**再次踩坑（第 N 次）**：`replace_in_file` 把整个 index.js 从 LF 转成了 CRLF。
查法：`git show HEAD:<path> | Select-String "`r"` 计数（0=原文件是 LF）。
修法：PowerShell `[IO.File]::WriteAllText($p, $t, (New-Object Text.UTF8Encoding($false)))`
（第三个参数 `UTF8Encoding($false)` = 无 BOM）。修完 diff 从全文件变成 48+/43-。
