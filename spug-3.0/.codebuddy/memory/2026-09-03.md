## 附件数量不即时刷新（radioLicense / stationFrequencyApproval / contractAgreement）
- 现象：详情弹窗里上传/删除附件后，列表页「附件」列要刷新页面或切换模块才更新
- 结论：**不是公共组件 bug**。AttachmentManager 早已提供 `onCountChange` 回调（upgrade 模块已接 `store.setAttachmentCount`），这三个模块没接
- 修法：新增 `spug_web/src/libs/attachmentCount.js` 导出 `syncAttachmentCount(store, recordId, count)`；三个 store 各加一行 `updateAttachmentCount`；三个 Form 的 `<AttachmentManager>` 加 `onCountChange`
- ⚠️ **MobX 5 坑（本次修复失败一次的根因）**：原地改数组元素 `store.records[i] = {...}` **不会**触发列表页 observer 重渲染，因为列表页只读 `store.records` 这个属性引用，MobX 5 追踪只到这一层。必须整体替换引用：`store.records = records.map(...)`。行对象也要换新引用（否则 antd Table 该行不重渲染）
- 测试 `spug_web/src/libs/__tests__/attachmentCount.test.js`（14 例通过，含一条反例固化 MobX 行为）
- 干扰管理同批次修完：bridge/air 的 store 由 `pages/interference/businessStore.js` 的 `createBusinessStore()` 工厂创建，**只改工厂一处**两个业务同时生效（公共化落点选工厂比各 store 各加一行更好）；两个 Form 的 `attachmentProps` 加 `onCountChange`
- 新建态 `attachmentRecordId` 是 `temp-xxx` 临时 ID，helper 在列表里查不到就跳过，无需特判
- 测试扩到 18 例（含 ground/air 各 2 例）全部通过
- ⚠️ 命令写法教训：不要把 `Remove-Item` 与文件路径列表写在同条命令里，用户会误以为要删业务代码；拆成单条明确命令

### 方案选型：附件数量同步该"全公共"还是"公共 helper + 分模块接线"
- 用户问既然每模块都要接，不如做成公共的。**结论：维持"公共 helper（`libs/attachmentCount.js`）+ 每模块 2 行显式接线"**
- 否决"全自动"方案的理由：AttachmentManager 不认识列表 store，要做成零改动只能引入全局附件计数缓存（module+recordId 为 key），随之带来缓存失效与一致性问题（重新 fetch 列表后旧缓存会盖掉后端新值）、隐式耦合难调试，违背 React 显式数据流惯例
- 也否决 store mixin/基类：收益只是省掉每个 store 的一行，却要给 3~5 个 store 改 class 声明，结构性改动换一行，不划算
- 判断标准：**公共化的是"逻辑"（只此一份），接线必须显式（数据流可见、漏接能被 review 发现）**
