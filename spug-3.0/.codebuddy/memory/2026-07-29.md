# 2026-07-29 工作日志

## 幂等性审计（依据 CRUD 系统可靠性指南 1.3 节）

### 审计范围
- 全项目 17 个 Celery @shared_task
- spug_web 前端所有 POST 表单
- 后端所有 CREATE/UPDATE 操作

### 确认的风险点（4 个测试全部通过验证）

| # | 风险点 | 级别 | 测试结果 | 根因 |
|---|--------|------|----------|------|
| 1 | DutyRecord 双重 POST 产生重复值班日志 | 高 | **确认** | `duty/views.py:144` 直接 `objects.create()`，模型无唯一约束，前端无 loading |
| 2 | FaultPart 双重 POST 产生重复故障件 | 高 | **确认** | `fault/views.py:147` 直接 `objects.create()`，模型无唯一约束，前端无 loading |
| 3 | DocumentFilePrivate 模型无 (name,folder) 唯一约束 | 高 | **确认** | Celery `merge_file_chunks` 有 max_retries=3，重试后 `_create_file_instance` 会静默创建重复文件记录 |
| 4 | FileRecordCreator._create_file_instance 无 get_or_create | 高 | **确认** | 代码检查证实无 FileModel 存在性查询 |

### 做得好的方面
- `signature` 模块有完整 request_id 幂等机制（唯一约束 + 去重测试），是项目最佳实践
- 14/17 个 Celery 任务幂等性设计良好
- UPDATE 操作用 F() 表达式主要是 CheckConstraint 和乐观锁（department_duty_log version），非不安全增量
- 24 个前端表单有 loading/confirmLoading 防护

### 测试文件
- `spug_api/apps/idempotency_risk_tests.py`（4 个 TestCase，Docker 验证通过）
- 运行：`docker exec tdyw-test python manage.py test apps.idempotency_risk_tests --noinput -v2`

### 待修复建议
1. DutyRecord/FaultPart：加前端 loading + 后端业务唯一约束或 request_id 去重
2. merge_file_chunks：在 `_create_file_instance` 前加 `FileModel.objects.filter(name=..., folder=...).exists()` 检查，或用 `get_or_create`
3. DocumentFilePrivate：考虑加 (name, folder, tenant_id) 唯一约束（需处理软删除场景）
