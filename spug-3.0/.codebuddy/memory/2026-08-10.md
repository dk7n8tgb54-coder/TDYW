## 容错测试补充（T21 + T22，5 个测试）

### 背景
用户询问"容错测试够用吗"，系统性扫描后发现 2 个高优先级盲区：
1. 合并超时检测（`check_merge_timeout`）- MERGING 超 30min 自动重置 FAILED，用户实际会遇到
2. 清理重试上限（`MAX_RETRY_COUNT=3`）- 超限后只 log CRITICAL，运维需知道此行为

### 新增测试
`test_full_regression.py` 新增 T21 + T22 两个测试类，5 个测试：

| 类 | 测试 | 验证内容 |
|---|---|---|
| T21 | `test_合并超时_自动重置为FAILED` | MERGING 超 30min -> check_merge_timeout 重置 FAILED + error_message 含"超时" |
| T21 | `test_未超时任务_不被重置` | MERGING 5min -> 不被重置，reset_count=0 |
| T21 | `test_僵尸任务24h自动清理` | MERGING 超 24h -> cleanup_stale_merging_tasks 批量清理为 FAILED |
| T22 | `test_重试达上限_不删除DB记录` | clean_retry_count>=3 + mock 删除失败 -> DB 记录保留 + CRITICAL 日志 |
| T22 | `test_冷却期内_跳过重试` | last_clean_attempt 在 3600s 内 -> 跳过，clean_retry_count 不变 |

### 关键技术点
- `auto_now=True` 字段无法通过 `save()` 设旧值，需用 `DocumentTransfer.objects.filter(id=...).update(updated_at=old_time)` 绕过
- `pending_files.py` 的 `safe_delete_document_file` 是模块级 import，mock 需同时 patch 两处：
  1. `apps.document.tasks.cleanup.pending_files.safe_delete_document_file`（模块级）
  2. `apps.document.libs.document_utils.safe_delete_document_file`（mixin 内 local import）
- Celery `@shared_task(bind=True)` 可直接调用，`self` 由 Celery 自动绑定
