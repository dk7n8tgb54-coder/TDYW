## 离开页面时全局暂停上传任务 (pauseForPageLeave)

### 问题
用户从文档管理/党建工作切换到其他页面时，上传任务逐个"上传失败"。根因：
1. `UploadPanel.componentWillUnmount` 通过 `pauseItem()` 逐个暂停（200ms 防抖），非同步
2. `ItemOperationController.pauseItem` 对无状态机的 waiting 任务直接 return
3. 未设置全局 `isPaused = true`，`startWaiting()/processPending()` 继续启动新任务
4. 页面离开后导航上下文被清理，新启动的任务失败

### 修复方案
新增 `UploadCoreStore.pauseForPageLeave()` 方法（core/index.js +77 行）：
1. **同步**设置 `this.isPaused = true`（在任何异步操作之前）
2. 遍历**所有租户**队列（不仅限于当前租户）
3. 有状态机的走 `transition('PAUSE')`（内部 bumpOperationVersion + abort 请求）
4. 无状态机的（waiting 懒创建）直接写本地 paused 状态 + bump operationVersion
5. 跳过终态（completed/error/cancelled）和 merging
6. 幂等（PAUSEABLE_STATUSES 不含 paused，已暂停的不会被重复处理）
7. 无通知（不弹"已暂停 N 个任务"）
8. fire-and-forget 后端同步（失败不影响本地暂停）

### 恢复链修复
`ItemOperationController.resumeItem` 增加对 pauseForPageLeave 暂停的无状态机任务的处理：
- 重建状态机后同步更新 item 状态（status=waiting, isPausedByUser=false）
- 否则 `canStart()` 检查 `item.status === 'waiting'` 会失败

### 前端异步复制完成提示（2026-08-07 深夜补充）

**问题**：大文件异步复制只提示"后台复制中"，完成后没有提示，用户不知道何时结束。

**修复**：`useFileOperations.js` 新增 `pollAsyncCopyStatus` 轮询函数
- 收到 `pending` + `transfer_id` 后，每 5 秒轮询 `GET /api/document/transfers/?transfer_type=COPY`
- COMPLETED -> `message.success("文件名 复制完成")` + 刷新目录
- FAILED -> `message.error("文件名 复制失败: 错误信息")`
- CANCELED -> 静默停止
- 最多轮询 120 次（10 分钟超时）
- `pollingCopyTransfersRef` (useRef Set) 防重复轮询
- `handleCopyItems` 和 `resolveConflicts` 都收集 `asyncTransferIds` 并触发轮询

### 修复：轮询找不到 transfer 记录（2026-08-07 深夜补充 2）

**根因**：`DocumentTransfer.objects.create()` 时未设置 `tenant_id`，模型默认 `tenant_id=''`。但 `TransferListView._build_queryset` 按用户真实 `tenant_id`（如 `'admin'`）过滤，导致空 `tenant_id` 的 COPY 记录查不到，轮询永远找不到已完成任务。

**修复**：
- `copy.py` 和 `folder_copy_service.py` 创建 transfer 时添加 `tenant_id=getattr(user, 'tenant_id', '') or ''`
- 脚本修复了 7 条历史记录

**教训**：创建有 `tenant_id` 字段的模型记录时，必须显式传入 `user.tenant_id`，不能依赖模型 default。
