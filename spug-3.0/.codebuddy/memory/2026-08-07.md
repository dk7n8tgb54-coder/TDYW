## 离开页面时全局暂停上传任务 (pauseForPageLeave)

### 问题
用户从文档管理/党建工作切换到其他页面时，上传任务逐个"上传失败"。根因：
1. `UploadPanel.componentWillUnmount` 通过 `pauseItem()` 逐个暂停（200ms 防抖），非同步
2. `ItemOperationController.pauseItem` 对无状态机的 waiting 任务直接 return
3. 未设置全局 `isPaused = true`，`startWaiting()/processPending()` 继续启动新任务
4. 页面离开后导航上下文被清理，新启动的任务失败

### 修复方案
新增 `UploadCoreStore.pauseForPageLeave()` 方法（core/index.js +77 行）：
1. **同步**设置 `this.isPaused = true`（在任何异步操作之前）
2. 遍历**所有租户**队列（不仅限于当前租户）
3. 有状态机的走 `transition('PAUSE')`（内部 bumpOperationVersion + abort 请求）
4. 无状态机的（waiting 懒创建）直接写本地 paused 状态 + bump operationVersion
5. 跳过终态（completed/error/cancelled）和 merging
6. 幂等（PAUSEABLE_STATUSES 不含 paused，已暂停的不会被重复处理）
7. 无通知（不弹"已暂停 N 个任务"）
8. fire-and-forget 后端同步（失败不影响本地暂停）

### 恢复链修复
`ItemOperationController.resumeItem` 增加对 pauseForPageLeave 暂停的无状态机任务的处理：
- 重建状态机后同步更新 item 状态（status=waiting, isPausedByUser=false）
- 否则 `canStart()` 检查 `item.status === 'waiting'` 会失败

## 关键根因
- Issue 1: `FolderView.get` 在 `system_folder=party_building_documents` 且 `id=None` 时强制设置 `form.id=root_id`，导致 `all=true` 走 `_get_folder_contents`（只返回一级）而非 `_get_all_folders`（返回全部后代）
- **Issue 2 真正根因（MobX observe 确认）**: `useSorting.js` 创建临时行 `{id: null, isFolder: true, isTemp: true}`，用户点击输入框时 click 事件冒泡到行级 `onClick` → `handleRowClick(tempRecord)` → `enterFolder(null, '')` → `currentFolderId = null`。修复：`handleRowClick` 增加 `if (record.isTemp || record.id == null) return;`
- Issue 3: HTTP 拦截器对所有错误调用 `message.error`，包括过期请求。空间切换时 Explorer 和 FolderTree 的旧请求都返回错误，产生两次提示
- Issue 4: 所有端点已有 scope 校验，测试验证 15+ 种拒绝场景

## 修复要点
- Issue 2: (a) `handleCreateFolder` 用 `withSystemFolderParams` 显式注入 system_folder; (b) `effectiveCurrentFolderId` 在党建模式下回退到 `lockedRootFolderId`
- Issue 3: (a) `requestFolderList`/`fetchChildFolders` 添加 `skipErrorNotification: true`; (b) `http.js` 添加 `showErrorOnce` 去重（2秒窗口内相同消息只弹一次）; (c) `useDataFetching` catch 块对活跃请求做去重提示
