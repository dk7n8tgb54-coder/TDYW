### migration 字段定义一致性教训

手写 migration 时 CharField 的 `blank=True` 必须与 model 严格一致，否则 Django 会生成"Alter field" 假 migration：
- model 中 `CharField(default='', blank=True, ...)` → migration 必须也带 `blank=True`
- model 中 `CharField(default='', ...)`（无 blank） → migration 不能带 `blank=True`
- IntegerField 的 `blank=True` 对应 null=True 的字段，CharField 的 blank 是独立的表单验证标志

本次修正了 4 个字段：interference 的 report_channel/report_no/void_reason 和 radio_license 的 delete_reason（model 有 blank=True，migration 漏写）。

1. **新增 `apps/runlog/services.py`**（运行日志模块对外服务层）
   - 暴露 `get_duty_import_items(date, user)`
   - 内部封装 RunLogUpdate 查询 + RunLog 批量查询（构建 id→event_title 映射，避免 N+1）+ 租户过滤 + 字段映射
   - 返回稳定 DTO 列表，不暴露模型对象，字段：id/source/title/sequence/recorder/content
   - 标题优先取事件表（事件可能改名），兜底用动态冗余 event_title 字段

2. **新增 `apps/duty/import_services.py`**（值班日志聚合层）
   - 暴露 `get_import_records(date, user)`，返回 `{'date', 'runlog': [...], 'interference': [...]}`
   - 运行日志走 `apps.runlog.services.get_duty_import_items`（规范要求）
   - 干扰记录暂保留 `_get_interference_items` 过渡实现（直接查 Interference 模型），已标注 TODO 待 interference 模块提供 services 后迁移
   - 设计原因：本次任务范围仅"重写值班日志引入运行日志信息"，按 YAGNI 不扩大改动到干扰记录

3. **重写 `apps/duty/views.py` DutyImportView.get**
   - 移除 `from apps.runlog.models import RunLog, RunLogUpdate` 和 `from apps.interference.models import Interference`
   - 改为 `from apps.duty.import_services import get_import_records` + `get_import_records(target_date, request.user)`
   - 视图层只剩参数解析 + 调聚合层 + json_response，符合"视图层保持简单"
