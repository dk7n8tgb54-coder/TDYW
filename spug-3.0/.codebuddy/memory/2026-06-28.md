### 关键设计决策

1. **状态流转用 select_for_update 防并发**：干扰管理 InterferenceStateView 在事务内 `select_for_update()` 锁定记录，避免并发状态流转导致状态错乱
2. **提交时计算 snapshot_hash**：干扰管理 submit 动作先临时设置 status 再构建快照，保证快照与落库值一致
3. **执照版本历史**：每次编辑前保存修改前完整快照（version_no 递增），snapshot_hash 防快照被篡改；查询时按 -version_no 倒序
4. **附件软删除保留证据链**：无线电执照附件删除改为 is_deleted=True，保留物理文件和 DB 记录，证据包导出时可重新校验 SHA256
5. **续期事件 vs 通用更新事件**：执照 valid_to 变化写"续期"事件（含 before/after valid_to）；其他字段变更写"更新"事件（含 changed_fields 列表）
6. **关键字段锁定**：干扰管理 submitted 后 7 个核心字段（frequency/datetime/coordinates/interference_type/phenomenon/flight_number/aircraft_type）不可直接覆盖，需先驳回回 draft 或发起更正
7. **删除策略**：干扰管理仅 draft/voided 可删除，其他状态需先作废；无线电执照附件软删除；设备管理已在前次会话改为软删除

### migration 字段定义一致性教训

手写 migration 时 CharField 的 `blank=True` 必须与 model 严格一致，否则 Django 会生成"Alter field" 假 migration：
- model 中 `CharField(default='', blank=True, ...)` → migration 必须也带 `blank=True`
- model 中 `CharField(default='', ...)`（无 blank） → migration 不能带 `blank=True`
- IntegerField 的 `blank=True` 对应 null=True 的字段，CharField 的 blank 是独立的表单验证标志

本次修正了 4 个字段：interference 的 report_channel/report_no/void_reason 和 radio_license 的 delete_reason（model 有 blank=True，migration 漏写）。

### 重构教训
- 状态流转类接口复杂度高，主要来自"多个 action 分支 + 嵌套 try/except + 映射 dict"

- 编辑接口的"校验→检测变更→更新→写证据事件"链路适合拆分为多个独立函数

## P1 安全修复：OR 权限 + 统一接口越权漏洞

**问题**：`@auth('xxx.add|xxx.edit')` 是 OR 权限，只拥有 add 或只拥有 edit 的账号都能进入同一个 `post` 方法，方法内未按 `form.id` 分支二次校验，导致越权。

**修复策略**：保留统一接口，但在 `if form.id` 分支强制校验 `edit`，新增分支强制校验 `add`，使用 `request.user.has_perms({'xxx.edit'})`（set 形式，与 interference 模块既有写法一致）。
