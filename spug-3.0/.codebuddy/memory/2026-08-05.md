### 关键教训
1. **`await` 完成 ≠ 业务成功**：`updateTransferStatus()` 返回 `{success:false}` 而非 throw，try/catch 不捕获，需检查返回值
2. **fire-and-forget Promise 是隐形炸弹**：`pollMergeStatus()` 不加 `.catch()` 时，reject 被 Node.js `unhandledRejection` 静默吞掉
3. **幂等响应需区分状态**：`is_idempotent:true` 可能是 completed 或 merging，需检查 `response.status` 决定走 MERGE_SUCCESS 还是继续轮询
4. **Error 对象不能直接写入 item.error**：UI 调用 `item.error.includes()` 会抛 TypeError，需 `instanceof Error` 提取 `.message` + `String()` 转换
5. **Celery revoke ≠ 即时停止**：`revoke(terminate=True)` 发 SIGTERM 有竞态窗口，需在任务关键步骤间加 DB 取消检查点
