**问题**：记录状态后必须点保存或刷新页面才显示新状态。之前的 `fetchStatusLogs()` 异步请求可能存在竞态或未触发重渲染。

## 记录状态不显示的真正根因修复（mobx 竞态）

**问题**：上一轮修复后仍不显示，点保存才出现。

**根因**：`store.record.status = updated.status` 直接修改 mobx observable，触发 observer 组件重渲染，与 `setStatusLogs` 的 React state 更新产生竞态——mobx 重渲染可能用了旧的 statusLogs 闭包，"覆盖"了 state 更新。

**修复**：
- 新增 `currentStatus` React state，顶部信息条和打印改读 `currentStatus`（不再读 `info.status`/`store.record.status`）
- `handleAddStatusLog` 用 `res.to_status` 直接 `setCurrentStatus`（同步 state 更新，不依赖 mobx）
- 去掉 `store.record.status = updated.status` 的直接修改（mobx 反模式）
- `store.fetchRecords()` 只刷新列表，不再手动改 store.record

**效果**：`setStatusLogs` 和 `setCurrentStatus` 都是 React state 更新，在同一批次内提交，无竞态。记录状态后时间线和顶部状态立即更新。

## 升级工作台 WorkbenchForm.js 核心 bug 修复 + 代码质量整改

**背景**：用户反馈升级工作台记录状态后不立即显示，需点保存或刷新页面才出现。由另一个 AI 生成的工作台代码（Workbench.js/WorkbenchForm.js/Workbench.module.less 三件套）质量差。

**核心 Bug 根因**：`WorkbenchForm.js` 导出时**漏了 `observer` 包裹**（`export default WorkbenchForm`），而组件内部读的是 mobx 的 `store.statusLogs`。非 observer 组件不感知 mobx 状态变化，所以 `store.fetchStatusLogs()` 更新数据后组件不重渲染，只有触发其他 state 变化（保存→loading 变化）或刷新页面（重新挂载）时才显示。

**修复内容（6 项）**：

1. **核心 bug**：`export default WorkbenchForm` → `export default observer(WorkbenchForm)`，函数体改 `forwardRef` 包裹（因需暴露 submit 给父组件）

2. **window 全局变量反模式**：`Workbench.js` 用 `window._upgradeWorkbenchFormRef = { submit: handleSubmit }` 传 form ref → 改为 React 标准 `forwardRef + useImperativeHandle + useRef`

3. **StepStatusTag 定义在组件函数内部**：每帧重建组件类型导致无谓卸载/挂载 → 提取到 `shared.js` 模块顶层

4. **后端已返回新日志数据，前端忽略再请求**：`WorkbenchForm.js` 的 `handleAddStatusLog` 调 `store.fetchStatusLogs()` 二次请求 → 改用后端返回的 `res` 直接 `store.statusLogs = [res, ...store.statusLogs]` prepend

5. **RecordForm.js 残留 console.log**：删除 5 处 `console.log/console.error` 调试代码

6. **WorkbenchForm.js 与 RecordForm.js 大量重复**：提取 `shared.js`，复用 ACTION_COLOR/getActionColor/STANDARD_FLOW/STATUS_TAG_COLOR/StepStatusTag

**新增文件**：`spug_web/src/pages/upgrade/shared.js`（公共常量 + StepStatusTag 组件）

**验证**：前端 Lint 零错误

**教训**：
- mobx 的 `observer` 是最容易漏的装饰器——组件读 store 但不重渲染时，第一时间检查 `observer` 是否包裹
- `window._xxx` 全局变量传 ref 是反模式，应始终用 `forwardRef + useImperativeHandle`
- 后端已返回完整数据的接口，前端不应再发二次请求（浪费往返 + 竞态风险）
- 纯展示组件应定义在模块顶层，不要定义在组件函数内部
