## 修复：地面干扰 Unknown column 'handling_method'（迁移未应用）

**现象**：页面报 `Exception: (1054, "Unknown column 'tdyw_bridge_interference_records.handling_method' in 'field list'")`

**根因**：迁移 `0016` 未应用到数据库。两类容器状态不同：
- `tdyw-test`（bind mount，代码最新）→ 代码有 handling_method 字段，但 DB 未迁移 0016 → **报错来源**
- `tdyw`（无 bind mount，镜像内代码停在 interference 0009）→ 根本没有新字段，不可能报此错

**修复**：`docker exec tdyw-test python manage.py migrate interference` → `Applying interference.0016... OK`
- SQL 为 `ALTER TABLE ADD COLUMN ... longtext DEFAULT '' NOT NULL` ×2，非破坏性
- 验证：dev 库 ground 记录 68 条，新列值均为 `''`（无数据损失）；ORM 查询正常

**教训**：
1. **改模型字段后必须确认迁移已应用到实际运行库**——代码更新（bind mount 自动生效）与数据库 schema 是两件事，前者即时生效、后者需要 migrate
2. **排查报错先分清是哪个后端**：`manage.py showmigrations <app>` 看容器内迁移文件与已应用状态，能立刻判断容器代码新旧（无 bind mount 的 tdyw 代码固定在镜像版本）
3. 迁移前用 `manage.py sqlmigrate <app> <编号>` 预览 SQL，确认非破坏性再执行
4. PowerShell → wsl → docker exec → python -c 的多层引号嵌套无法用转义解决；改用临时 `.py` 脚本（bind mount 目录内）执行后删除
