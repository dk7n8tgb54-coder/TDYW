## 无线电执照删除 bug 修复

**问题**：删除无线电执照时，频率明细表（`tdyw_radio_license_frequency`）的记录不会被删除。

**根因**：
- `RadioLicenseView.delete`（views.py:140）使用软删除（`update(is_deleted=True)`），不会触发 Django ORM 的 `CASCADE` 级联
- 原代码只清理了 `RadioLicenseReminder`（提醒）和 `RadioLicenseAttachment`（附件，含物理文件）
- **遗漏了 `RadioLicenseFrequency`（频率明细表）的清理**

**模型外键设置**（仅供理解，本次未改）：
- `RadioLicenseFrequency.license` → `models.CASCADE`
- `RadioLicenseReminder.license` → `models.CASCADE`
- `RadioLicenseAttachment.license` → `models.CASCADE`
- 注意：`CASCADE` 只在 ORM `delete()` 时触发，`update(is_deleted=True)` 软删除不会触发

**修复**：在 `views.py` delete 方法的 else 分支中，于清理 Reminder 之前补充一行：
```python
RadioLicenseFrequency.objects.filter(license_id=form.id).delete()
```

**设计决策**：遵循现有代码的"软删主表 + 物理清理子表"模式，与 Reminder/Attachment 处理方式保持一致。

**影响范围**：仅 1 个文件（views.py），1 行新增。

## 无线电执照：软删除改为全硬删除

**背景**：用户确认该功能仅用于内部执照到期提醒，不涉及外部监管核查/审计留痕。设计文档（`无线电执照loop/无线电台执照有效期管理功能设计方案.md:357`）中的软删除意图（"避免审计链路断裂"）在此场景下不必要。原实现还是"半吊子"状态（主表软删但子表物理删），既丢审计完整性又没换来简洁性。

**改动策略**：全硬删除 — 主表 `delete()` 后 Django `CASCADE` 自动级联清理三张子表（Frequency/Attachment/Reminder），代码更简洁，杜绝孤儿数据。

**改了哪些文件**（4 个文件）：

1. `models.py`：移除 `RadioLicense.is_deleted` 字段，`to_view` 去掉 `excludes=('is_deleted',)`
2. `views.py`（8 处改动）：
   - 列表查询：移除 `filter(is_deleted=False)`
   - delete 方法：`update(is_deleted=True)` → `license_obj.delete()`（先删附件物理文件，再删主表触发 CASCADE）
   - 详情/附件列表/附件上传/附件下载/附件删除：移除所有 `is_deleted=False` 过滤
   - 提醒列表：移除 `license__is_deleted=False` 过滤
3. `tasks.py`：`filter(is_deleted=False)` → `all()`，更新注释
4. `migrations/0004_remove_is_deleted.py`（新增）：先 RunPython 删除 `is_deleted=True` 记录，再 RemoveField

**迁移设计**：
- 先 `RunPython`：`RadioLicense.objects.filter(is_deleted=True).delete()` — CASCADE 级联删子表
- 再 `RemoveField`：移除 `is_deleted` 列
- reverse = `noop`（删除不可逆）

**验证**：
- `py_compile` 4 个文件：exitCode=0
- `makemigrations --check --dry-run`：No changes detected（迁移与模型一致）
- `migrate --plan`：迁移链正确（0004 = RunPython + RemoveField）
- `read_lints`：无新增错误（均为项目既有的 basedpyright 类型存根问题）

**Docker 容器路径**：`/data/spug/spug_api/`（工作目录 `/data/spug`）

**关键教训**：
- 软删除 + 手动清理子表容易遗漏（本次 bug 就是这样产生的）
- 全硬删除 + CASCADE 级联是最简洁可靠的方案，适合不需要审计留痕的内部功能
- 迁移移除字段前必须先清理 `is_deleted=True` 的记录，否则这些记录会"复活"
