## P1-4 修复：私有文件夹唯一约束 + 公共空间约束 bug 修复

### 问题：
1. `DocumentFolderPrivate` 缺少同级同名唯一约束（Public 有 `UniqueConstraint(fields=['name','parent'])`，Private 无任何约束）
2. `DocumentFolderPublic` 的 `UniqueConstraint(fields=['name','parent'])` 缺少 `condition=Q(is_deleted=False)`，软删除的文件夹仍占位导致 IntegrityError
3. **MariaDB 10.8 不支持部分唯一索引（WHERE 条件）**，Django 的 `UniqueConstraint(condition=...)` 在 MariaDB 上静默跳过

### 方案（unique_key MD5 哈希）：
- 新增 `unique_key = CharField(max_length=32, null=True, unique=True)` 字段
- 未删除记录：`unique_key = MD5("tenant_id:created_by_id:name:parent_id")`（Private）/ `MD5("name:parent_id")`（Public）
- 已删除记录：`unique_key = NULL`（MySQL 中 NULL 不参与唯一索引，不占位）
- `save()` 自动计算 unique_key，`delete(hard=False)` 和 `restore()` 自动更新

### 关键技术决策：
1. **拆分根目录/子目录约束？** 不需要。MD5 哈希天然解决了 `parent=NULL` 时 NULL!=NULL 的问题，因为 `parent_id=None` 会被编码为 `"ROOT"` 字符串
2. **MySQL 唯一 CharField 限制 max_length ≤ 255？** 用 MD5 哈希（32 字符）绕过
3. **save() 中 update_fields 处理？** `save()` 自动将 `unique_key` 追加到 `update_fields`

### 迁移链：
- `0004_folder_unique_constraints.py`：添加条件约束（MariaDB 无效，但需保留以维护迁移历史）
- `0005_folder_unique_key.py`：删除无效条件约束 + 添加 unique_key 字段 + 回填数据

### 涉及文件：
- **修改** `models.py`（DocumentFolderPrivate + DocumentFolderPublic 各加 unique_key 字段、_compute_unique_key()、save() 重写）
- **新增** `migrations/0004_folder_unique_constraints.py`
