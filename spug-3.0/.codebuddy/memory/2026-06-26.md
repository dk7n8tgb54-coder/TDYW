## 操作审计模块 P0 修复（依据《操作审计模块修复建议.md》）

修复 3 个 P0 问题，仅改动 `apps/logs/audit.py` 和 `apps/logs/middleware.py` 两个文件，未触碰无关模块。

### P0-1 业务失败被审计为成功
- 根因：`json_response(error=...)` 默认返回 HTTP 200，原中间件只看 status_code 无法识别业务失败。
- 修复：新增 `_resolve_success_and_error(response)`，HTTP≥400 判失败；否则解析 `response.content` JSON，存在非空 `error` 字段则 `is_success=False` 并提取错误信息。
- 兼容：无 `content` 属性（StreamingHttpResponse/FileResponse）、非 JSON 响应（文件下载）均按状态码视为成功，解析异常绝不影响主请求（外层已有 try/except）。
- 错误信息合并：新增 `_merge_error_into_detail(detail, error_msg)`，业务失败时把 error 写入 detail（dict/None/str 三种情况），便于审计页面展示失败原因。

### P0-2 DELETE 无法记录 query 参数中的对象 ID
- 根因：原 `_extract_detail` 只从 URL 路径段和 POST/PUT/PATCH body 提取 ID，DELETE ?id=xxx 取不到。
- 修复：新增 `_extract_id_from_query(request)`，从 `request.GET` 提取 `id`（单个）或 `ids`（批量，记录为逗号分隔字符串）。
- 优先级：URL 路径段 > 响应体 data.id > query 参数 > 请求体 id，RESTful 路径 `/user/5/` 仍能正确提取。

### P0-3 POST + action=delete 被记录为 create
- 根因：`resolve_action(method)` 只按 HTTP 方法映射，POST 固定 create。
- 修复：`resolve_action(method, body_data=None)` 优先读 body 的 `action` 字段，支持 delete/export/import/approve（大小写兼容），无 action 或不在映射内则回退到 METHOD_ACTION_MAP。普通 POST 新增仍是 create。
- 中间件新增 `_parse_body(request)` 解析请求体 JSON（失败返回 None，不影响主流程），解析结果同时用于 resolve_action 和 _extract_detail（避免重复解析）。

### 排查命令
- `git check-ignore -v <file>`：确认文件被哪条规则忽略
- `git ls-files <dir>`：确认文件是否被跟踪（返回空=未跟踪）
- `Get-ChildItem -Recurse -Directory -Filter "logs"`：找所有 logs 目录

### gitignore 规则要点
- `logs/`（无前导斜杠）匹配任意层级的 logs 目录，危险
- `/logs/`（前导斜杠）只匹配当前 .gitignore 所在目录的 logs
