## 批量去除 Python 源文件 UTF-8 BOM

lint 报告 21 个 `.py` 文件首行 `invalid non-printable character U+FEFF`（UTF-8 BOM）。涉及 `apps/document` 和 `apps/regulation` 两个 app。

PowerShell 一行命令扫描并去除 BOM（保留其余字节不变）：
```powershell
Get-ChildItem -Path 'e:\TDYW\spug-3.0\spug_api' -Recurse -Filter *.py | ForEach-Object {
    $b=[System.IO.File]::ReadAllBytes($_.FullName)
    if($b.Length -ge 3 -and $b[0]-eq0xEF -and $b[1]-eq0xBB -and $b[2]-eq0xBF){
        [System.IO.File]::WriteAllBytes($_.FullName,$b[3..($b.Length-1)])
        Write-Output $_.FullName
    }
}
```

被截断未列出的第 21 个文件是 `apps/document/management/commands/init_document_system_folders.py`。

验证流程：
1. 二次扫描确认 `NO_BOM_REMAINING`
2. `python -m compileall -q apps/document apps/regulation` 全部通过
3. `read_lints` 抽样 models.py / urls.py 无错误

教训：编辑器/工具保存 .py 时若默认带 BOM，会触发 Python 语法错误。项目应统一 UTF-8 无 BOM 编码。

## regulation/views.py put 方法复杂度治理

`RegulationDetailView.put`（原 444 行）圈复杂度 20（限制 15）。四块字段处理（普通/分类/日期/状态）嵌套大量分支。

重构手法：按字段类型抽 4 个 applier 方法，统一签名 `(self, regulation, form) -> (error, changed_partial)`：
- `_apply_plain_fields`：title/rule_no/issuing_authority/biz_type（rule_no strip+非空）
- `_apply_category`：校验叶子分类
- `_apply_date_fields`：日期格式校验，空串→None
- `_apply_status`：枚举值校验

`put` 改为编排：`for applier in (...): err, partial = applier(...); if err: return; changed.update(partial)`。

字段映射抽类常量 `_PLAIN_FIELD_MAP` / `_DATE_FIELD_MAP`。

逻辑等价性：处理顺序（plain→category→date→status）、error 即时返回、changed 累积、`changed or {'summary':'无变更'}` 全部保留。put 复杂度降至约 7，各 applier 均 ≤7。

## 资料库拖拽上传功能实现

**需求**：为资料库模块（普通文档管理 + 党建文档）增加拖拽上传能力，覆盖多文件/文件夹/混合拖入，复用现有上传队列，固化目标上下文避免切换目录/离开页面导致位置错误。

**核心机制 — 目标上下文固化（targetContext）**：
- drop 时立即调用 `uploadCoreStore.captureUploadTargetContext()` 捕获不可变快照（folderId/isPublic/tenantId/systemFolderCode）
- 快照写入每个队列项（queueItem.systemFolderCode）
- 后续 transfer create / file upload / chunk upload / merge / merge_status / folder create 请求**优先从队列项读 systemFolderCode**，不依赖全局 `systemFolderContext`（党建任务离开党建路由后仍携带正确上下文）
- 提取为独立纯函数 `captureUploadTargetContext.js`（便于单元测试，避免装饰器 babel 配置问题）

**新增文件**：
- `pages/document/components/DocumentDropUploadLayer.js` + `.module.less` — 拖拽投放层（深度计数、遮罩、禁用提示）
- `pages/document/utils/dropUpload.js` — DataTransfer 递归解析（webkitGetAsEntry，循环 readEntries，深度/条目数上限）
- `pages/document/stores/upload/core/captureUploadTargetContext.js` — 纯函数上下文捕获
- `pages/document/utils/__tests__/dropUpload.test.js` — 27 个测试（路径校验/多文件/嵌套目录/混合/多批读取/空目录/深度超限/条目超限/读取异常/回退）
- `pages/document/stores/upload/core/__tests__/targetContext.test.js` — 12 个测试（普通/党建/显式覆盖/freeze/tenantId/folderId/降级）

**修改文件**：
- `pages/document/index.js` — .explorerArea 接入 DocumentDropUploadLayer，新增 targetPathLabel 计算 + captureDropTargetContext + handleDropUpload
- `stores/upload/core/index.js` — captureUploadTargetContext 委托纯函数；handleFileSelect/handleFolderSelect 接受可选 targetContext；新增 handleFolderEntries
- `stores/upload/core/coordinators/FileUploadCoordinator.js` — handleFileSelect/processUploadQueue/_processUniform/_processBatch 接受 targetContext，把 systemFolderCode 写入队列项
- `stores/upload/core/folderUpload.js` — handleFolderSelect/handleFolderEntries 共用 _processFolderUpload，支持 File[] 和 {file,relativePath,rootName}[] 两种格式
- `stores/upload/core/folder/FolderStructureBuilder.js` — build 接受 systemFolderCode，_createOne 显式传 system_folder；_extractDepthGroups 支持条目格式
- `stores/upload/core/transfer.js` — createTransfer/checkUploadedChunks 接受 systemFolderCode 显式传参
- `stores/upload/core/fileUpload.js` — uploadFileNormal 从队列项读 systemFolderCode 显式传给 createTransfer 和 FormData
- `stores/upload/core/chunkUpload.js` — uploadFileChunked/uploadSingleChunk/mergeChunks/pollMergeStatus 从队列项读 systemFolderCode 显式传参

**关键设计决策**：
1. **不新建第二套队列/协调器**：拖拽和按钮上传共用 uploadCoreStore，handleFolderEntries 走同一 FolderStructureBuilder + FileUploadCoordinator._processBatch
2. **systemFolderCode 双轨**：队列项有值时用队列项（拖拽固化），无值时回退全局 systemFolderContext（按钮上传老逻辑，向后兼容）
3. **relativePath 格式**：`顶层目录/子目录/文件.pdf`（含顶层目录名，FolderStructureBuilder 据此创建子目录）；traverseEntry 的 initialPath 恒为空（isDirectory 分支会拼 entry.name，避免重复）
4. **保护上限**：MAX_DROP_DEPTH=20、MAX_DROP_ENTRIES=5000、每 50 条目让出事件循环
5. **禁用场景**：无权限/搜索中/党建未就绪 → 遮罩显示原因，drop 仍 preventDefault 阻止浏览器打开文件
