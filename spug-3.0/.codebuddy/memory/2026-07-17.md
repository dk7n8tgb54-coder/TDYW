## 传输记录列表复杂度治理

`spug_api/apps/document/views/transfer/list.py` 的 `TransferListView.get` 圈复杂度 16（限制 15）。

重构手法：关注点分离，拆出两个私有方法：
- `_build_queryset(self, request, form, system_folder)`：公共/私有/未指定三分支 + 可选筛选 + 租户隔离 + 排序截断
- `_serialize(self, t)`：单条记录字典映射（无分支）

`get` 仅保留参数解析 + 上下文校验 + 编排。

顺带清理：
- 删除未使用的 `from ...constants import TransferStatus` import
- `DocumentTransfer` import 下移到 `_build_queryset` 内
- 时间格式串抽类常量 `_DATETIME_FMT`
- `if system_folder: filter(...) else: filter(system_folder='')` 合并为 `filter(system_folder=system_folder or '')`
- `hasattr(form, 'is_public') and form.is_public is not None` 简化为 `getattr(form, 'is_public', None) is not None`

逻辑等价性已逐分支核对，行为不变。

## 批量去除 Python 源文件 UTF-8 BOM

lint 报告 21 个 `.py` 文件首行 `invalid non-printable character U+FEFF`（UTF-8 BOM）。涉及 `apps/document` 和 `apps/regulation` 两个 app。

PowerShell 一行命令扫描并去除 BOM（保留其余字节不变）：
```powershell
Get-ChildItem -Path 'e:\TDYW\spug-3.0\spug_api' -Recurse -Filter *.py | ForEach-Object {
    $b=[System.IO.File]::ReadAllBytes($_.FullName)
    if($b.Length -ge 3 -and $b[0]-eq0xEF -and $b[1]-eq0xBB -and $b[2]-eq0xBF){
        [System.IO.File]::WriteAllBytes($_.FullName,$b[3..($b.Length-1)])
        Write-Output $_.FullName
    }
}
```

被截断未列出的第 21 个文件是 `apps/document/management/commands/init_document_system_folders.py`。

验证流程：
1. 二次扫描确认 `NO_BOM_REMAINING`
2. `python -m compileall -q apps/document apps/regulation` 全部通过
3. `read_lints` 抽样 models.py / urls.py 无错误

教训：编辑器/工具保存 .py 时若默认带 BOM，会触发 Python 语法错误。项目应统一 UTF-8 无 BOM 编码。

## regulation/views.py put 方法复杂度治理

`RegulationDetailView.put`（原 444 行）圈复杂度 20（限制 15）。四块字段处理（普通/分类/日期/状态）嵌套大量分支。

重构手法：按字段类型抽 4 个 applier 方法，统一签名 `(self, regulation, form) -> (error, changed_partial)`：
- `_apply_plain_fields`：title/rule_no/issuing_authority/biz_type（rule_no strip+非空）
- `_apply_category`：校验叶子分类
- `_apply_date_fields`：日期格式校验，空串→None
- `_apply_status`：枚举值校验

`put` 改为编排：`for applier in (...): err, partial = applier(...); if err: return; changed.update(partial)`。

字段映射抽类常量 `_PLAIN_FIELD_MAP` / `_DATE_FIELD_MAP`。

逻辑等价性：处理顺序（plain→category→date→status）、error 即时返回、changed 累积、`changed or {'summary':'无变更'}` 全部保留。put 复杂度降至约 7，各 applier 均 ≤7。
