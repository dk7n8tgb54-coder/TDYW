# 2026-07-05 工作日志

## 资料库删除文件夹后物理目录残留修复

### 问题根因
`PhysicalFolderCleaner.delete()` 用 `settings.DOCUMENT_STORAGE_PATH`（默认 `/data/spug/documents`，但 settings 未定义该变量）作为 base，且路径格式 `folder_{id}`（下划线）。实际上传路径用 `os.path.join(settings.BASE_DIR, 'storage', 'documents')` 为 base，格式 `public/folder-{id}` 或 `private/user-{user_id}/folder-{id}`（短横线）。双重不匹配导致物理目录残留。

### 修改文件（3 个业务文件 + 1 个测试）
- `spug_api/apps/document/services/cleanup_service.py`（+170/-35）
  - 新增 `_get_storage_documents_base()`：统一获取 `storage/documents` 根目录
  - 新增 `cleanup_parent_dirs_safe(parent_dirs)`：基于真实 file_path 父目录的兜底清理（模块级，供所有删除流程复用）
  - 重写 `PhysicalFolderCleaner.delete(folder, is_public=None, user_id=None)`：优先复用 `get_document_absolute_path()` 规则（folder-{id} 短横线），保留旧格式 `folder_{id}` 兼容清理
  - `ContentDeleter` 增加 `is_public` 参数 + `delete_files_in_folder` 收集 file_path 父目录并兜底清理
  - `FolderCleanupService` 传入 `is_public`
- `spug_api/apps/document/tasks/cleanup/base.py`（+9）
  - `_delete_physical_folder_safe(folder, is_public=None, user_id=None)` 向后兼容签名
- `spug_api/apps/document/views/folder/views.py`（+22）
  - `FolderView._delete_folder` 第三步传 `is_public`/`user_id`
  - 第二步收集 file_path 父目录，第三步后调用 `cleanup_parent_dirs_safe`
- `spug_api/tests/test_physical_folder_cleanup.py`（新增，7 个场景 16 项断言）

### 安全设计
- 所有待删除路径必须通过 `is_safe_path(storage/documents, target)` 校验
- 跳过空路径、根存储目录（`storage/documents` 本身）、不存在的路径
- 不使用用户输入直接拼接删除路径
- 用 `seen` 集合去重，避免重复处理

### 兼容设计
- 保留旧格式 `folder_{id}`（下划线）清理能力，用于历史残留目录
- 不影响 `file.delete(hard=True)` 现有逻辑
- 不改变数据库模型结构、不改变上传路径生成规则
- `PhysicalFolderCleaner.delete` 新增参数有默认值（None），向后兼容旧调用
