**任务**：依据 `资料库并发上传与状态机修复方案.md` 第 5.2 节，实施 P0-2 修复。

**目标**：合并写入时同步 `md5.update(data)`，合并完直接得到 MD5，`verify_file_md5` 直接比对，省掉合并后的二次全量读盘。

**修改文件**：`spug_api/apps/document/tasks/merge.py`（4 处改动）

1. 顶部新增 `import hashlib`
2. `ChunkMerger` 类：
   - `__init__` 新增 `self.merged_md5 = None`
   - `merge_chunks`：全量 MD5 文件初始化 `hashlib.md5()`，sv1_ 抽样 MD5 跳过计算；合并完 `self.merged_md5 = md5_hash.hexdigest()`

**关键正确性保证**：`hashlib.md5().update()` 是流式的，分段 update 与一次 update 结果一致，所以合并期用 8MB 缓冲 update 与 `calculate_file_md5` 用 1MB update 结果相同。容器内单元测试验证通过（全量 MD5 一致 + sv1_ 跳过）。

**向后兼容**：`execute(get_models, create_instance, get_mime_type, calculate_file_md5)` 外部签名不变，`calculate_file_md5` 参数在 pipeline 内部不再使用但保留，避免破坏 `merge_file_chunks` 的延迟导入链。

**重要教训 — IDE 空缓冲区覆盖文件**：
- 问题：`write_to_file` 写入 `start-celery-batch.sh` 报告成功，但文件始终 0 字节
- 根因：IDE 当前打开着该文件且内存缓冲区为空（total lines: 0），写入后立即被 IDE 空缓冲区保存覆盖
- 证据：LastWriteTime 不变（18:59:26），其他 3 个未在 IDE 打开的脚本写入正常
- 解决：改用 PowerShell `[System.IO.File]::WriteAllText()` 直接写入（UTF8Encoding $false 无 BOM，LF 换行），绕过 IDE 文件监视
- 注意：bash 脚本不能用 `Set-Content -Encoding UTF8`（PS 5.x 带 BOM 会破坏 shebang），不能用 `WriteAllLines`（Windows 默认 CRLF，bash 脚本需 LF）

## 容器启动故障排查：celery-merge/batch/general 退出

**现象**：tdyw-test 容器启动后，spug-celery-merge 和 spug-celery-batch exit 127，spug-celery exit 2。

**根因 1 — 镜像 tag 写死旧版**：
- `docker-compose.yml:13` 写死 `image: tdyw:0617`，该镜像 6/17 构建，不含新建的 `start-celery-merge.sh` / `start-celery-batch.sh`
- supervisord.conf 通过 volume 实时挂载（新配置引用新脚本），但旧镜像里没这两个脚本 → bash 找不到文件 → exit 127
- 修复：改 tag 为 `tdyw:0622`（已含新脚本）

**根因 2 — start-celery.sh 是 CRLF 行尾**：
- Windows 编辑器把 `start-celery.sh` 和 `start-celery-worker.sh` 改成了 CRLF
- bash 把行尾 `\r` 当成参数传给 celery，`\` 续行符失效，`-Q`/`-n` 被截断 → exit 2
- 而 `start-celery-merge.sh` / `start-celery-batch.sh` 是新建文件碰巧 LF → 正常运行
- 修复：全部 8 个 tools/*.sh 转 LF，用 `write_to_file` 重写（注意 write_to_file 在 Windows 上可能写 CRLF，需用 PowerShell 字节级操作兜底）

**关键教训**：
1. `docker-compose.yml` 的 `image:` tag 必须随镜像构建更新，否则新代码进不去容器
2. Windows 上编辑 bash 脚本必须确保 LF 行尾——CRLF 会让 `\` 续行失效，celery 参数解析失败
3. 验证行尾的脚本：`[System.IO.File]::ReadAllBytes()` 逐字节扫 `0D 0A` vs `0A`
4. `write_to_file` 工具在 Windows 上可能写 CRLF，不能完全依赖它写 bash 脚本
5. supervisord.conf 没有 `[unix_http_server]` 段时 `supervisorctl` 无法使用，需 `docker restart` 重启
6. `docker cp` + `docker restart` 可快速验证脚本修复（容器层文件在 restart 后保留，但 down/up 或 rm 后丢失）
