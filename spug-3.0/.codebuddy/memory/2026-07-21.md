## 资料库 DiskUsageView 多账号上传变慢修复

**背景**：审阅同事报告"多账号同时上传变慢"，核实后确认根因为 DiskUsageView 聚合查询全表扫描。

**核实结论**：
- 同事代码事实基本准确：disk.py:61 聚合 `filter(is_deleted=False)`+tenant 不带 folder_id，走不上 `doc_pri_file_list_idx=(folder_id, tenant_id, is_deleted, ...)` 左前缀 → 全表扫描
- disk.py:67 的 `query.count()` 仅打日志，多一次全扫（已删）
- useDiskSpace.js 30s 轮询，N 浏览器 = N×2 次查询/30s
- 合并锁 merge.py:723 按 `file_hash+public/private+tenant_id` 分键，跨账号不串行（同事行号引错：说 537 实为 723）
- 同事建议公共表加 `(is_deleted)` 索引不靠谱（选择性极差，优化器会放弃），公共表靠缓存解决
- 因果链薄弱点：InnoDB 聚合 SELECT 是 MVCC 快照读不阻塞 INSERT；测试库小数据量无开销。用户确认现象在生产环境 → 根因成立

**修复（3 文件）**：
1. `apps/document/views/disk.py`：删 `query.count()`；加 Redis 缓存（复用 `libs/cache_utils.py`），key 按 `is_public + 租户维度`分键（超管/全局管理员 `private:all`，普通用户 `private:{tenant_id}`，公共 `public`），TTL 60s；缓存命中直接返回，storage_dir 现拼（user 相关）；错误结果不缓存
2. `apps/document/migrations/0013_disk_usage_aggregate_index.py`：私有文件表加覆盖索引 `(tenant_id, is_deleted, file_size)`，让 `SUM(file_size)` 纯索引扫描不回表；公共表不加（is_deleted 选择性差）
3. `apps/document/models.py`：DocumentFilePrivate.Meta.indexes 同步新增 `doc_pri_file_diskusage_idx`，与迁移一致

**验证**：py_compile OK；`makemigrations document --check` → No changes detected；models.py lint 0；disk.py lint 无新增 error（预存 basedpyright type stub 问题）

**未做（YAGNI）**：未在上传/删除路径加主动缓存失效——60s TTL 被动过期即可，磁盘用量是监控指标非业务关键；未改前端 30s 轮询间隔（后端缓存后命中率高，无需改前端）
