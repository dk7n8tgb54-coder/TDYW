### 关键技术决策
1. **增量发现用 `-newermt/@epoch -o -newerct/@epoch`，不用 `-cnewer marker`**：标记文件经 `docker cp` 进入容器时 ctime 被重置为当前时间，`-cnewer` 比较 marker ctime 会失效（捕获不到任何文件）。改用宿主机 marker 的 mtime epoch 作为基准字符串，通过 `-newermt`/`-newerct` 比较，时区无关。WSL 实测验证：旧 mtime 的复制文件能被 `-newerct` 捕获，纯 `-newermt` 漏掉（证明原 mtime-only 有 bug）。
2. **manifest = TSV 4 列**：`relative_path\tsize\tmtime_epoch\tctime_epoch`。单次 `find -printf` 生成，再用 `cut -f1` 派生 tar 文件列表（避免二次扫描）。sha256 暂不实现（每文件 docker exec 太慢），ctime 已满足"更好"要求，留 schema 字段便于扩展。
3. **meta = key=value**，记录 backup_type/起止时间/容器/路径/文件数/归档名/manifest名/基准时间。
4. **0 文件增量**：不生成 tar.gz 与 manifest，仍生成 meta（审计）。
5. **find 错误屏蔽**：`generate_manifest` 中 `docker exec find` 用 `if ! ...; then log_warn; fi` 包裹，避免个别权限错误（find 返回非零）在 `set -e` 下中止整个备份。原脚本靠 `build_file_list` 末尾 `echo` 掩码，新写法显式且等价。
6. **restore 增量筛选按文件名时间戳**：`extract_backup_ts` 用 sed 提取 `YYYYmmdd_HHMMSS`，`>=` 全量时间戳才纳入，按文件名 sort 即时间顺序。比原 `-newer full`（依赖文件 mtime，复制后会失效）更可靠。
7. **manifest 校验**：收集 full+所有 incr 的 manifest，`cut -f1` 取并集 `sort -u`，与容器实际 `find -printf %P` 列表 `comm -23` 求缺失，写入 `${RESTORE_TMP_DIR}/manifest_missing.txt`。
8. **恢复前 `tar tzf` 校验全量+所有增量**，校验在清空目标目录之前完成。

## 总控备份/恢复（backup_set）实现

### 背景
数据库备份和 documents 物理文件备份是独立脚本，手动分别执行/恢复容易错配（DB 有记录但文件缺失，或文件存在但 DB 无记录）。新增总控脚本将两者绑定到同一备份集目录。

### 新增文件
- `backups/backup_set_create.sh`：总控备份脚本
- `backups/backup_set_restore.sh`：总控恢复脚本

### 关键设计
1. **backup_set_id = `backup_set_YYYYmmdd_HHMMSS`**，目录 `backups/backup_sets/<id>/`
2. **目录结构**：`backup_set.meta` + `database/` + `documents/{full,incremental}/` + `logs/`
3. **DB_MODE=dump（默认）/mariabackup**，调用现有子脚本，通过 `BACKUP_DIR` 环境变量指向 backup_set 子目录
4. **DOCUMENTS_MODE=full（默认）/incremental**，通过 `BACKUP_DIR` 指向 backup_set/documents
5. **backup_set.meta 记录**：backup_set_id/status/db_mode/database_backup_file/documents_full_backup_file 等绑定关系
6. **恢复默认 dry-run**，`FORCE_RESTORE=YES` 才执行；恢复顺序 DB→documents
7. **现有脚本零改动**：documents_incremental_backup.sh 已支持 BACKUP_DIR+manifest+meta+mtime/ctime；documents_restore.sh 已有 manifest 校验；mariadump/mariabackup backup 脚本已支持 BACKUP_DIR

### 踩坑
- `write_to_file` 在 Windows 上写 CRLF 行尾，`bash -n` 会报语法错误（行尾 `\r` 被当作字符），需 `sed -i 's/\r$//'` 转 LF
- backup_set_restore.sh 第 89 行有手误 `DOCUMENTS_INCREMENTAL_COUNT=0"`（多余引号），导致 bash 解析器认为后续所有内容都在字符串内，报 `syntax error near unexpected token '('`。用 awk 扫描"奇数双引号行"快速定位
