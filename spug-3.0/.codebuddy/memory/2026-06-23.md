## 无线电台执照提醒弹窗重构：执照中心模型

**问题**：弹窗 days_left 不随 valid_to/日期变化（读快照），content 拼死，作废/去重逻辑复杂。

**根因**：RadioLicenseReminder 表混合了派生数据、通知事件、用户确认状态三个概念。

**方案**：执照中心模型——派生数据不存储，状态与事件分离，续期失效靠数据本身。

### 新增 LicenseReminderAck 表

```
LicenseReminderAck
  - license_id        ← 外键
  - user_id           ← 确认用户
  - ack_valid_to      ← 确认时的 valid_to（续期后自动失效）
  - tenant_id, created_at
  UNIQUE(tenant_id, license_id, user_id, ack_valid_to)
```

**弹窗判断**：license.status IN (expiring, expired) AND NOT EXISTS ack WHERE (license_id, user_id, ack_valid_to=license.valid_to)
**续期失效**：license.valid_to 变化 → 旧 ack 的 ack_valid_to ≠ 新 valid_to → 自动失效

### Django 2.2 兼容性教训

- `UniqueConstraint` 必须放 `Meta.constraints`，不能放 `indexes`（否则 `_check_indexes` 报 `AttributeError: 'UniqueConstraint' object has no attribute 'fields_orders'`）
- `indexes` 里外键字段用实际字段名 `license`，不能用 `license_id`（报 `models.E012 nonexistent field`）

### 设计原则

1. **派生数据不存储** — days_left 是 valid_to 的函数，存就失真
2. **状态与事件分离** — ack 是状态（会变），reminder 是事件（只增）
3. **单一真相源** — valid_to 唯一，其他都从它派生
4. **续期失效靠数据本身** — ack_valid_to 字段，不需反推/作废
