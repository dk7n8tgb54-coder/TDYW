- dev：`config/dev/supervisor/conf.d/*.conf`（按编号拆分，如 `11-celery-merge.conf`）
- `docker/config/supervisord.conf` — 新增 `[program:spug-celery-thumbnail]`

### 关键设计

1. **复用 thumbnail_service**：`generate_document_thumbnail` 内部调用 `generate_thumbnail_for_file`，不重写图片处理逻辑。
2. **transaction.on_commit**：保证事务提交后才投递任务，避免任务查不到文件记录。auto-commit 模式下回调立即执行，行为无变化。
3. **软删除安全**：`FileModel.objects` 默认是 `SoftDeletedManager`，已删除文件查不到，任务自动安全退出。
4. **幂等保护**：任务内检查 `thumbnail_path` 已存在则跳过。
5. **失败隔离**：缩略图生成失败只记日志，不重试（图片损坏重试无意义）；数据库更新失败才重试。
6. **投递函数独立**：`_dispatch_thumbnail_task` 独立成函数，延迟 import 任务模块，避免 on_commit lambda 闭包内重 import。

### 变更文件清单

修改（3 个文件，纯配置调整，无业务逻辑变更）：
1. `spug_api/tools/start-celery-merge.sh` — 默认并发 4→2，更新注释
2. `config/dev/supervisor/conf.d/11-celery-merge.conf` — `CELERY_MERGE_CONCURRENCY="4"`→`"2"`，更新注释

### 关键决策

- **默认值选 2 而非 1**：1 太保守（单大文件合并 5-10 分钟，排队体验差），4 太激进（8G 服务器磁盘打满），2 是平衡值
- **不改 `pressure.py` 阈值**：当前 `MERGE_BUSY_THRESHOLD=4` / `MERGE_CRITICAL_THRESHOLD=8` 仍合理（并发 2 时积压 4 个已算 busy）
- **不改业务逻辑**：纯配置调整，`merge.py` 零改动

| 服务器规格 | 推荐并发 |
|---|---:|
| 8G + 机械盘 | 1 |
| 8G + SSD | 2（默认） |
| 16G+ + NVMe | 3-4 |

## 修复 FilterBar 卸载后 setState 警告（已完成）

**背景**：控制台报 `Warning: Can't perform a React state update on an unmounted component`，调用栈指向 `device/index.js` 使用的公共组件 `FilterBar.js` 里的 Select。

**根因**：`FilterBar.js` 里有一段反模式代码：
```js
const [mounted, setMounted] = React.useState(true);
React.useEffect(() => {
  return () => setMounted(false);   // ← 元凶
}, []);
// ...
<Select open={mounted ? undefined : false} />
```

作者意图"卸载时强制关闭下拉避免遗留浮层"，但在 useEffect cleanup 里调 setState，而 cleanup 执行时组件已卸载，必然触发警告。

**关键判断**：这段代码**本身就无用**——组件卸载后不再 render，`open={mounted ? ...}` 这行根本不会重新求值。antd 的 Select/DatePicker 自身在卸载时会清理浮层，无需手动处理。

**这不是框架 bug**，是项目代码的反模式。

**修复**：删除 `mounted` state、useEffect、以及 Select/RangePicker 上的 `open={mounted ? undefined : false}` 三处。

**教训**：
1. `useEffect` cleanup 里**绝对不能**调 `setState`——cleanup 执行时组件已卸载
2. 想控制浮层开关，应在事件处理/可见性状态里控制，不是在卸载 cleanup 里
3. antd 的 Select/DatePicker/Tooltip 等浮层组件自带卸载清理，无需手动兜底
