## 7.3 异步操作加版本号 — 前端上传状态机并发安全修复

### 背景
资料库上传状态机的上传、分片上传、合并、轮询均为异步操作。用户在旧请求未返回时执行暂停/取消/恢复/重试，旧回调可能覆盖新状态（如取消后旧上传成功回调把任务改成 completed）。

### 实现方案
每个上传 item 增加 `operationVersion` 字段（初始 0），版本号方法集中在 `UploadQueueStore`（queue.js）：
- `bumpOperationVersion(uploadId)` — 递增并返回新版本
- `getOperationVersion(uploadId)` — 获取当前版本
- `isCurrentOperation(uploadId, version)` — 判断回调是否仍属于当前操作

### 递增版本的事件（在 UploadStateMachine.transition 中统一处理）
- `START` — 新一轮生命周期
- `RESUME` — 恢复（含重试，error→RESUME→waiting→START）
- `PAUSE` — 让正在返回的回调失效
- `CANCEL` — 让所有旧回调失效

### 绕过状态机的取消路径（需显式递增）
- `ItemOperationController.cancelItem` — 直接出队，需 `bumpOperationVersion`
- `QueueOperationController.cancelAll` — 批量直接写 error，需为每个 item `bumpOperationVersion`

### 异步链路版本检查（捕获+检查+丢弃）
1. **MD5 计算**（`UploadLifecycle.onCalculating`）— 捕获版本，await 后检查，过期不写 fileHash / 不触发 MD5_COMPLETE
2. **普通上传**（`fileUpload.js uploadFileNormal`）— 捕获版本，http.post 返回后检查，过期不触发 UPLOAD_COMPLETE
3. **分片上传**（`chunkUpload.js uploadFileChunked`）— 捕获版本，每个分片循环前检查，进度回调检查，完成后检查
4. **合并**（`StateChangeHandler.handleMergingState` → `chunkUpload.js mergeChunks`）— 捕获版本，mergeResult 返回后检查
5. **合并轮询**（`chunkUpload.js pollMergeStatus`）— 接收 uploadId + operationVersion，每次循环前+await 后检查版本，检查 celeryTaskId 是否匹配
6. **StateChangeHandler.handleUploadingState / startUpload** — 捕获版本传给 uploadFileNormal/uploadFileChunked，catch 中检查版本

### 状态机兜底（两层防护）
- **第一层**：调用点 `isCurrentOperation` 检查，过期直接 return
- **第二层**：`transition(event, payload)` 中检查 `payload.operationVersion`，不匹配当前版本则拒绝转换（metrics.staleCallbackRejected 统计）

### 向后兼容
- `payload.operationVersion` 为 undefined 时不做版本检查（旧调用方/测试 mock 不受影响）
- `queueStore?.bumpOperationVersion?.()` 使用可选链，mock 无此方法时为 no-op
- 无版本号的 transition 正常执行

## 日检查单模块 P0-1 修复：右键标记异常传参错误

### 问题
`CheckSheet.js` 调用 `useCheckSheetUI(allProjectsData, loaded, confirmedOperator, updateDailySummaryField)`，第四个参数错传成 `updateDailySummaryField`；而 `useCheckSheetUI.js` 把第四个参数命名为 `updateCellStatus`，在 `handleRightClick` 中调用 `updateCellStatus(project, itemIndex, 'ABNORMAL')`。

后果：右键标记异常时实际执行 `updateDailySummaryField(project, itemIndex, 'ABNORMAL')`，把所有项目的 `dailySummary[project]` 字段写成了 `itemIndex`，既不更新检查项状态，又污染日汇总数据。

### 修复
1. `CheckSheet.js`：从 `useCheckSheetData()` 解构出 `updateCellStatus`，调用改为 `useCheckSheetUI(loaded, updateCellStatus)`。
2. `useCheckSheetUI.js`：参数列表从 `(allProjectsData, loaded, confirmedOperator, updateCellStatus)` 精简为 `(loaded, updateCellStatus)`，移除未使用的 `allProjectsData` 和 `confirmedOperator`，降低再次传错概率。

### 验证
- `useCheckSheetUI` 仅在 `CheckSheet.js` 一处调用，参数精简无副作用。
- 两文件 lint 均通过。
- 对应建议文档验证用例 4：右键某检查项标记异常，确认表格状态变为异常，保存后刷新仍为异常。

## 日检查单模块 P0-3 修复：模板项目名允许重复导致后端 500

### 问题
`CheckSheetTemplate.project` 无唯一约束，但后端多处用 `CheckSheetTemplate.objects.get(project=...)` 查询。创建同名模板后，`get()` 抛 `MultipleObjectsReturned`，最终返回 500。

### 修复
1. **模型层**：`models.py` 给 `project` 加 `unique=True`。
2. **迁移**：`makemigrations checksheet`（指定模块名，避免扫描其他 app）→ 生成 `0002_auto_20260625_2355.py`（含 AlterField + AlterModelOptions 同步 ordering）。迁移前用脚本确认数据库无重复项目名，安全应用。
3. **后端 `TemplateView.post`**：创建前 `filter().exists()` 预校验 + `IntegrityError` 并发兜底，返回 `json_response(error='项目模板已存在')`。
4. **后端 `TemplateDetailView.put`**：改名时（`form.project != template.project`）校验唯一（排除自身）+ `IntegrityError` 兜底。
5. **导入**：`from django.db import transaction, IntegrityError`。
6. **前端 `TemplateForm.js`**：`.catch(() => {})` 静默，因为 `http` 拦截器已对后端 `error` 字段调用 `message.error` 并 reject，避免重复弹"保存失败"。

### 修改文件（4 个）
- `spug_api/apps/checksheet/models.py` — project 加 unique=True
- `spug_api/apps/checksheet/migrations/0002_auto_20260625_2355.py` — 新增迁移
- `spug_api/apps/checksheet/views.py` — post/put 加校验 + IntegrityError 兜底
- `spug_web/src/pages/checksheet/TemplateForm.js` — catch 静默

### 验证
- 容器内验证：`IMPORT_OK` → `FIRST_CREATE_OK` → `UNIQUE_CONSTRAINT_OK: IntegrityError 已正确抛出` → `CLEANUP_OK`
- 前后端 lint 通过
- 对应建议文档验证用例 3：尝试创建同名模板，确认前端提示友好错误，不出现接口 500

### 关键经验
- 加唯一约束前**必须先检查数据库是否有重复数据**，否则 migrate 会失败。用 `values('project').annotate(c=Count('id')).filter(c__gt=1)` 查询。
- `makemigrations` **必须指定模块名**（`makemigrations checksheet`），否则会扫描所有 app 生成意外迁移（记忆教训）。
- http 拦截器对 `response.data.error` 会自动 `message.error` + `reject`，业务层 catch 不应再弹通用错误，避免重复提示。
- `IntegrityError` 兜底用于并发场景（校验与创建之间存在竞态），即使有预校验也需保留。

## 日检查单模块 P1 修复（4 项）

### P1-1 项目名 URL 编码（store.js）
`fetchCheckRecords` 原直接拼接 URL，项目名含 `& ? # + 空格` 时被截断。改用 axios `params`：`http.get('/api/checksheet/record/', { params: { year, month, project, day } })`，axios 自动 URL 编码且 day 为空时自动忽略。

### P1-2 后端参数转换校验（views.py）
新增通用 `_parse_int(value, name, min_value, max_value)` 函数，返回 `(result, error)`。应用到：
- `RecordListView.get` 的 day（1-31）
- `TemplateView.get` 的 page（≥1）和 page_size（1-200，原 `min(page_size, 200)` 内联逻辑移除）
非法输入返回 `json_response(error=...)` 而非 500。`summary_filter` 复用已校验的 `day_value`，避免重复 `int()`。

### P1-3 统计口径修复
- `useCheckSheetData.js calculateStats`：原只遍历 `checkData` 已存在记录。改为按 `template.check_items.length` 遍历，缺失项视为 `UNCHECKED`，解决"模板 20 项但无记录时统计显示总数 0"。
- `useDataViewQuery.js calculateTotalStats`：原只统计后端已有 records。改为按 `模板检查项数 × 当月实际天数` 统计（`new Date(year, month, 0).getDate()` 取当月天数），records 建索引 `${item_index}_${day}`，缺失视为 `UNCHECKED`。依赖项增加 `selectedYear, selectedMonth`。

### P1-4 导出按钮权限对齐（QueryControls.js）
后端 `export_pdf` 已是 `@auth('checksheet.checksheet.edit')`，但前端导出按钮是普通 `Button`，无 edit 权限的用户也能看到。改为 `<AuthButton auth="checksheet.checksheet.edit">`，无权限时隐藏。

### 修改文件（5 个）
- `spug_web/src/pages/checksheet/store.js` — fetchCheckRecords 改 axios params
- `spug_api/apps/checksheet/views.py` — 新增 _parse_int + 应用到 day/page/page_size
- `spug_web/src/pages/checksheet/hooks/useCheckSheetData.js` — calculateStats 按模板项补齐
- `spug_web/src/pages/checksheet/hooks/useDataViewQuery.js` — calculateTotalStats 按 模板项×当月天数 补齐

### 验证
- 5 文件 lint 全通过

### 关键经验
- axios `params` 会自动跳过 `undefined/null` 值，适合可选参数（如 day），无需手动拼 `&day=`。
- `new Date(year, month, 0).getDate()` 是取当月天数的惯用法（month 传 1-12，第 0 天回退到上月末尾即当月天数）。
- `calculateTotalStats` 的 useCallback 依赖项增加 `selectedYear/selectedMonth`，否则切换月份后统计不更新。
