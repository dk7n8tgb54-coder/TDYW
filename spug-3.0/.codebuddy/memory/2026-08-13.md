## Docker 容器资源配置升级（8G → 32G 服务器）
服务器规格从 8G 内存升级到 4核4线程 32G 内存，调整 `docker/docker-compose.yml` 和 `docker/config/mysqlnew.cnf`。

### docker-compose.yml 改动
| 容器 | 旧 limits | 新 limits | 旧 reservation | 新 reservation |
|---|---|---|---|---|
| tdyw（主应用） | 2G | 4G | 512M | 1G |
| tdyw-db（数据库） | 3G | 8G | 1G | 2G |
| kkfileview | 1500M | 2G | 512M | 768M |

- CPU limits 保持不变（tdyw:4, tdyw-db:2, kkfileview:2，共 8 超分 4C2x，Docker 权重调度可接受）
- `tdyw-db.stop_grace_period` 60s → 90s（buffer_pool 6G 刷盘时间变长）

### mysqlnew.cnf 改动
- `innodb_buffer_pool_size`: 2G → 6G（32G 服务器下显著提升缓存命中率）
- `max_connections`: 300 → 500（注释从"8G 服务器"更新为"32G 服务器"）

### 32G 内存预算分配
- 系统/OS: 2G
- tdyw: 4G
- tdyw-db: 8G（buffer_pool 6G + 连接/日志/OS 2G）
- kkfileview: 2G
- 合计 16G，留 16G 余量

### 生效方式
⚠️ `docker compose restart` 不会重新读取 `deploy.resources`，必须 `docker compose down && docker compose up -d`。MySQL buffer_pool 修改后需重启数据库容器。

## binlog 备份价值评估（用户质疑）
用户质疑：每天全量备份，当天的 binlog 不会被备份（实际会被--FLUSH BINARY LOGS 轮转后复制），前一天的 dump 已有也不需要 binlog。

### binlog 位置动态获取
- volume 名通过 `MYSQL_DATA_VOLUME` 环境变量传入（默认 `docker_tdyw-mysql-data`）
- 实际挂载点路径由 `docker volume inspect -f '{{.Mountpoint}}'` 动态解析
- 脚本直接从宿主机文件系统 `cp` binlog（需 root 权限访问 `/var/lib/docker/volumes/`）

### 价值分析结论
binlog 备份在"每日全量 + 38人小库"场景下是**边际保险**，非必需：
- 当天误删当天发现：volume 里 binlog 还在（MariaDB 保留 7 天），不需要 borg 里的
- 昨天误删今天发现：用昨天全量 dump 恢复即可
- 整机损坏：borg 里的 binlog 只到备份时刻，之后的全丢，无法 PITR
- 唯一有用场景：volume 里 binlog 损坏/被清理 + 需要恢复到历史精确时刻（概率极低）

建议：加 `SKIP_BINLOG=YES` 环境变量开关让 binlog 备份变成可选步骤，manifest 里的 binlog 位点记录保留（不占空间，PITR 起点标记）。待用户确认是否实施。

## borgbackup 配置外置化到 borg.env
将脚本中所有 `${VAR:-default}` 环境变量写入 `borg.env`，分 4 组：
1. **Borg 仓库**（原有）：`BORG_REPO`/`BORG_PASSPHRASE`/`BORG_REMOTE_REPO`/`PUSH_REMOTE`/`BORG_RSH`
2. **容器与卷名**：`APP_CONTAINER`/`DB_CONTAINER`/`DOCUMENTS_VOLUME`/`MEDIA_VOLUME`/`MYSQL_DATA_VOLUME`
3. **数据库**：`DB_NAME`（留空自动探测）/`BACKUP_CLIENT_CNF`
4. **备份参数**：`BORG_COMPRESSION`/`APP_STOP_TIMEOUT`/`HEALTH_TIMEOUT`/`MIN_FREE_PERCENT`

- `BORG_ENV_FILE` 本身不放入 env（鸡生蛋问题），默认 `/opt/docker/borgbackup/borg.env`
- 生产/开发各一份 `borg.env`，改容器名/卷名/路径即可，脚本代码不用改
- docker-compose 项目名 `docker` 自动给 volume 加前缀 -> `docker_tdyw-mysql-data` 等

## borg.env 修复：BORG_RSH 缺引号
- `BORG_RSH=ssh -o ...`（无引号）-> shell 把 `ssh` 赋值后尝试执行 `-o`，报 `-o: command not found`
- 修复：`BORG_RSH="ssh -o BatchMode=yes -o StrictHostKeyChecking=accept-new"`（加双引号）
- 教训：env 文件中值含空格必须加引号，和 shell 赋值规则一致

## borgbackup 脚本 DB_NAME 被覆盖 bug 修复
- **根因**：`borg.env` 中 `DB_NAME=`（空赋值）在 `load_borg_env()` 执行时覆盖了之前从容器 MYSQL_DATABASE 自动探测到的值
- **现象**：`SELECT CURRENT_USER()` 能过（不需要库），`SELECT 1 FROM django_migrations` 失败（需要库上下文），脚本报 "lacks SELECT privilege"（误导性）
- **修复 1**：borg.env 直接填 `DB_NAME=tdyw`
- **修复 2**：脚本中 DB_NAME 自动探测移到 `load_borg_env()` 之后（防止被覆盖）
- **修复 3**：SELECT 检查失败时捕获 stderr 显示真实错误，不再只报笼统的 "lacks SELECT privilege"
- **教训**：env 文件中的空赋值 `VAR=` 会覆盖之前设置的值，`set -a; . file; set +a` 不区分 "未设置" 和 "设置为空"
