## 附件上传按钮消失 bug 修复（权限码错配）

**现象**：用户反馈系统升级模块附件 Tab"连上传按钮都没有"。

**根因**：附件上传/删除权限误用 `upgrade.upgrade.add`（新建记录权限），但附件操作只发生在**已存在记录**上（附件 Tab 仅在 `store.record.id` 存在时渲染）。用户有 `.edit`（能打开编辑表单）却可能没 `.add`，导致 `readOnly=true` → `canUpload=false` → 整个上传区（按钮+大小提示 Tag）不渲染。

**spug 权限码语义**：`.view`=查看 / `.add`=新建 / `.edit`=编辑 / `.del`=删除。附件是"修改已存在记录的附属数据"，语义属"编辑"。

**修复**（附件相关 `.add` → `.edit`）：
- 后端 `apps/upgrade/views/upload.py`：`AttachmentListView.post`（上传）、`AttachmentDeleteView.delete`（删除）2 处 `@auth` 改 `.edit`。旧版无关联上传 `AttachmentUploadView` 保留 `.add`（新建场景语义正确）。
- 前端 `spug_web/src/pages/upgrade/RecordForm.js`：查看模式 + 编辑模式各 1 组（`readOnly` + `uploadPerm` + `deletePerm`）共 6 处改 `.edit`。步骤操作的 `.add`（添加步骤）保持不变。
- 设计文档 `附件功能公共化设计方案.md`：视图清单表格同步更新。

**教训**：附件/子资源操作的权限码要跟随"操作对象所在生命周期"，而非"创建动作"。操作已存在记录的附属数据 → `.edit`；操作新建中记录的数据 → `.add`。后续模块接入附件时，`uploadPerm`/`deletePerm` 应传 `.edit` 而非 `.add`（纠正本日志上方早期示例）。

## 升级状态时间线功能（状态变更日志）

**需求**：用户要求状态变更有记录，如"什么时候升级测试、什么时候回退、什么时候又测试了"，形成时间线。

**方案确认过程**：
1. 用户问"备用系统试运行算不算灰度发布" → 确认算，灰度=部分环境先验证
2. 用户问"灰度时测试怎么弄" → 动作原子化，不强制顺序，"灰度发布"+"升级测试"两条日志靠时间+备注还原环境，同一动作可多次
3. 用户要求加"上线观察期"
4. 主表 status：用户选 B（加"已回退"态）

**最终动作清单（12 种）**：
开始升级/备份/灰度发布/全量发布/升级测试/测试通过/测试失败/回退/暂停/继续/上线观察期/完成

**关键设计**：
- 动作是独立原子记录，用户按实际发生顺序逐条添加，系统不强制动作先后
- 同一动作可多次出现（如多次"升级测试"），靠时间顺序+备注还原
- 仅"回退"和"完成"联动主表 status（→已回退/已完成），其余动作只写日志不动主表
- 主表 status 新增"已回退"态，流转路径：处理中↔已回退↔已完成（互相可转，支持回退后再推进）

## 升级列表显示附件数（仿 radio_license）

**需求**：用户要求仿照无线电执照模块，在升级管理列表上显示每条记录的附件数。

**参考实现**：`radioLicense/Table.js` 用 `record.attachment_count` + `<Badge count={count} size="small"><PaperClipOutlined /></Badge>`，无附件显示 `-`。后端在列表序列化时逐条 `RadioLicenseAttachment.objects.filter(license=record).count()` 注入。

**upgrade 适配（附件在 evidence 通用表）**：
- 后端 `record_service.get_list`：批量查询当前页所有 record_id 的附件数（一次 group by，避免 N+1），注入 `attachment_count`。查询条件 `module='upgrade'/object_type='record'/object_id__in=[...]/is_deleted=False`，带 `apply_tenant_filter` 租户隔离。
- 前端 `Table.js`：`renderAttachmentCount` 方法 + `<Table.Column title="附件" width={60} render={...}/>`，插在"负责人"列后、"操作"列前。

**关键技术点**：
- `object_id` 在 evidence 表是 CharField，查询时需 `str(rid)`，且 `object_id__in=[str(rid) for rid in record_ids]`
- 用 `values_list('object_id').annotate(c=Count('id'))` 一次查询拿到所有计数，转 dict 后注入，O(1) 查找
- 序列化器保持纯净（`to_list_view` 不含 count），count 在 service 层注入
