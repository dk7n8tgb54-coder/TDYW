# 2026-07-18 部门值班日志详情页值班记录不显示修复

## 问题
列表（值班表单）值班记录显示正常，但点击"查看"打开详情抽屉后值班记录显示 `--`。

## 根因
- 列表接口 `serialize_list_item` 只返回 `duty_record_summary`（前100字摘要），**不返回** `duty_record` 全文和 `remark`
- 详情接口 `serialize_department_duty_log` 返回 `duty_record` / `remark` 全文
- HEAD 版本 `store.showDetail` 直接用列表 record 占位且不异步拉详情接口 → 详情页 `record.duty_record` 为 undefined → 显示 `--`

## 修复（4 文件）
1. `departmentDutyLogStore.js`：`showDetail` 改为异步 `http.get` 详情接口覆盖 `this.record`；新增 `detailLoading` observable；加 `.catch` 失败时关闭抽屉避免占位误导（http 拦截器已 message.error）
2. `DepartmentDutyLogDetail.js`：`<Spin spinning={store.detailLoading}>` 包裹；值班记录绑定 `record.duty_record`（原已正确）
3. `DepartmentDutyLogSignModal.js`：签署弹窗接收列表 record，"值班记录摘要"改用 `record.duty_record_summary`（原误用 `record.duty_record` 为 undefined）
4. `tests.py`：新增 `test_detail_returns_full_duty_record_remark_and_signature`，验证草稿态/已签态详情接口返回 duty_record/remark 全文 + 签署信息

## 验证
- 后端详情测试单独跑通过（`Ran 1 test OK`）
- JS 语法（Babel parser + jsx 插件）三个文件 OK
- lint 0 错误
- 全套 52 测试：2 个**预先存在**失败（`test_create_audit`/`test_edit_audit`，测试数据缺 `mains_voltage`/`ups_voltage`/`weather` 必填字段，被 `validate_payload` 拒绝），与本次修改无关（services.py 未改，tests.py diff 只新增详情测试）

## 教训
- **列表返回 summary、详情返回全文**的模式下，前端详情页必须异步拉详情接口，不能直接复用列表 record（对比 regulation 模块列表返回完整字段所以不需要异步）
- 诊断此类"列表正常详情不显示"问题的步骤：先跑详情接口测试确认后端返回字段 → 再查前端 store 是否异步拉详情 + 组件字段绑定
- spug 的 `http` 拦截器对 `/api/` 内部请求返回 `response.data.data`，失败时 `Promise.reject` + `message.error`，store 异步请求应加 `.catch` 清理状态

## 后续排查：签名文件消失 + 普通账号权限拒绝（跑测试导致）

### 背景
完成上述详情页修复后，跑 `manage.py test apps.department_duty_log.tests --keepdb` 验证。之后用户反馈两个问题：
1. 普通账号又出现权限拒绝
2. 值班日志电子签名的物理文件夹消失

### 根因1：签名文件消失（100% 确认，测试 tearDown 直接删生产文件）
- `tests.py:632-635` `DepartmentDutyLogSignatureTests.tearDown`：
  ```python
  sig_base = os.path.join(settings.MEDIA_ROOT, sig_services.SIGNATURE_MODULE)
  if os.path.exists(sig_base):
      shutil.rmtree(sig_base, ignore_errors=True)
  ```
- `SIGNATURE_MODULE='account_signature'`，`MEDIA_ROOT='/data/spug/spug_api/media'`
- 测试**没有** `@override_settings(MEDIA_ROOT=...)` 隔离
- dev compose 是 bind mount（`/mnt/e/TDYW/spug-3.0/spug_api -> /data/spug/spug_api`），容器内 `shutil.rmtree` = 删宿主机文件
- 每个测试方法执行后都删一次整个 `account_signature/` 文件夹
- 证据链：SignatureUsage 记录显示 09:07-09:09 签署成功（apply_signature 校验文件 SHA256 通过，文件还在）；media 目录 mtime=09:45（测试运行时间）；宿主机 `media/account_signature/` 已不存在；DB 里 AccountSignature(id=3, attachment_id=15) 和 EvidenceAttachment(id=15, file_path='account_signature/tongxinke/202607/user_signature_2/0ef82af3...png') 记录还在但物理文件丢失

### 根因2：权限拒绝（高度怀疑测试污染 Redis 缓存）
- 测试用 Django Client 请求，中间件触发 `request.user.page_perms` 计算 → 写 Redis `perms_{test_user_id}`
- test DB 用户 id 可能与生产用户 id 冲突（如都是 2 = linjie）
- test DB Role.save() 自增 perms_version 到 1，与生产 Role perms_version=1 **恰好匹配**
- 生产用户 linjie 读到 test 用户 signer_ddl 的残缺权限（只有 `department_duty_log`）→ 其他模块权限拒绝
- 版本校验机制无法救场（version 都是 1，判定缓存有效不重算）
- Redis 是**共享的**（不在 Django 事务内），测试写的缓存永久残留

### 关键教训
1. **测试必须隔离 MEDIA_ROOT**：用 `@override_settings(MEDIA_ROOT=tempfile.mkdtemp())` 或在 setUp 用临时目录，**绝不能** tearDown `shutil.rmtree` 生产 MEDIA_ROOT 子目录
2. **测试必须隔离 Redis 缓存**：用 `@override_settings(CACHES={...})` 指向独立 Redis db，或测试基类 setUp 前 `cache.clear()`、tearDown 后 `cache.clear()`
3. **dev bind mount 的双刃剑**：便于代码热重载，但测试写的文件/删的文件直接影响宿主机
4. **版本校验机制的盲区**：perms_version 比对只在 Role.page_perms 变化时 bump，test DB 新建 Role 的 version 从 0→1，可能与生产 Role version=1 碰撞
5. 诊断方法：`docker exec redis-cli -n 1 KEYS 'perms_*'` + `GET :1:perms_2` 看缓存内容；`ls -la media/` 看文件夹 mtime
