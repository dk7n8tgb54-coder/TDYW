## 修复 groupStepsByPhase 组顺序 bug

用户反馈：升级启动阶段步骤序号显示 2，备份显示 1，顺序混乱。

### 根因
`groupStepsByPhase` 用 `presetPhases`（来自旧 `UPGRADE_PHASES` 固定顺序：升级启动→备份→灰度...）强制排组，而步骤 `sequence` 是用户拖拽顺序。两者冲突时组按固定顺序、步骤序号按 sequence，导致前置组序号大、后置组序号小。

### 修复（shared.js）
`groupStepsByPhase` 组顺序改为**按步骤首次出现顺序**（即 sequence 顺序，因 recordSteps 按 sequence 排序），去掉 presetPhases 强制排序。presetPhases 参数保留兼容（AutoComplete 候选用）但不再影响分组顺序。

### 影响
- renderStepsPanel 步骤清单分组、handlePrintSteps 打印分组、computeStepFlowState 参考条节点顺序均改为按 sequence，序号连续
- 用户拖拽顺序决定组顺序，预设阶段不再强制固定在前

用户问预设步骤 + phase 字段是否有租户隔离，查证结论：**完备**。
- UpgradePlanStep/UpgradeRecordStep 模型有 tenant_id 字段；plan_service.py 所有查询都 apply_tenant_filter；create 写 tenant_id；方案名唯一校验按 tenant_id
- phase 是步骤行上的文本字段，无独立表，通过所属步骤行 tenant_id 间接隔离；get_filter_options 合并历史 phase 已 filter(tenant_id)
