## 附件预览：图片/PDF 不走 kkFileView，改浏览器原生预览

**背景**：用户反馈图片/PDF 没必要走 kkFileView（多一层中转、慢、依赖外部服务），应直接浏览器内联预览。

**改动方案**（5 文件，+81/-20 行）：

### 后端
1. `apps/evidence/attachment_service.py` — `download_response` 新增 `inline=False` 参数
   - `inline=True` 时用 `mimetypes.guess_type` 推断 Content-Type，`Content-Disposition: inline`
   - `inline=False` 保持原逻辑（`application/octet-stream` + `attachment`）
2. 三个模块的 `AttachmentDownloadView` 透传 `inline` 参数：
   - `apps/upgrade/views/upload.py`
   - `apps/radio_license/views.py`
   - `apps/contract_agreement/views.py`
   - 统一写法：`inline = request.GET.get('inline') in ('1', 'true', 'True')`

### 前端
`spug_web/src/components/AttachmentManager.js`（公共组件，改一处全模块生效）：
- 新增 `IMAGE_EXTENSIONS` / `PDF_EXTENSIONS` 常量 + `isImageFile` / `isPdfFile` 辅助函数
- `handlePreview` 分流：
  - 图片/PDF → 拼下载 URL `?x-token=...&inline=1`，设 `previewType='image'/'pdf'`
  - 其他类型 → 仍调 `preview-url` 接口走 kkFileView
- `AttachmentPreviewModal` 新增 `previewType` prop：
  - `image` → `<img>` 渲染
  - `pdf` / `kkfileview` → `<iframe>` 渲染
- 预览按钮条件从 `previewUrlPrefix` 放宽为 `(previewUrlPrefix || downloadUrlPrefix)`

**设计原则**：
- 图片/PDF 浏览器原生支持，不需要 kkFileView 转换
- Office 文档（doc/xls/ppt 等）仍需 kkFileView 转换为 HTML/PDF
- inline 模式复用下载接口鉴权（x-token），无需额外预览令牌
