## ERROR_CODES 错误分类（接续 error 字段统一清理）

**用户反馈**："改吧" — 在讨论"11 个文件"夸张说法后，开始真正的 error code 分类改造。

**实际改动 4 个文件**（不是我之前说的 11 个）：
1. `upload-core-constants.js` — 新增 ERROR_CODES 枚举（10 种）+ RETRYABLE/NON_RETRYABLE 集合 + ERROR_CODE_MESSAGES 映射
2. `components/TransferItem.js` — canRetry 改为基于 errorCode 判断，displayError 用友好文案
3. `stores/upload/core/chunkUpload.js` — 错误产生点附带 errorCode（CHUNK + HTTP 状态码推断）
4. `stores/upload/core/fileUpload.js` — 错误产生点附带 errorCode

**ERROR_CODES 设计**：
- NETWORK / SERVER / CLIENT / PERMISSION / QUOTA / MD5_MISMATCH / CHUNK / MERGE / CANCELLED / UNKNOWN
- RETRYABLE：NETWORK / SERVER / MD5_MISMATCH / CHUNK / MERGE / UNKNOWN
- NON_RETRYABLE：CLIENT / PERMISSION / QUOTA / CANCELLED

**HTTP 状态码推断**：
- 401/403 → PERMISSION
- 413 → QUOTA
- 4xx → CLIENT
- 5xx → SERVER
- 文本匹配 'timeout'/'网络' → NETWORK
- 其他 → CHUNK/UNKNOWN

**向后兼容**：
- 老错误无 errorCode → 默认可重试（与之前行为一致）
- 老字符串 error 保留作为 displayError 降级

**用户体验**：
- 权限错误 → 提示"联系管理员"，无重试按钮
- 配额满 → 提示"清理后重试"，无重试按钮
- 网络错误 → 提示"检查网络后重试"，有重试按钮
- 错误文案更友好（不再显示后端原始 "ECONNRESET" 等）

**验证结果**：
- Lint: 0 errors

## 不自动弹出传输列表（2026-06-06 22:10）

**用户反馈**："上传文件能不能像上传文件夹一样，不要把传输列表自动弹出来"

**根因**：
- `FileUploadCoordinator.js:54-55` 在单文件上传时调用 `showUploadPanel()` → 强制展开抽屉
- `folderUpload.js:94-96` 在文件夹上传时也调用 `showUploadPanel()` → 同样展开
- 用户感受到：文件夹上传没弹出是因为某些原因没走该路径；单文件弹出很干扰

**修复**（2 个文件）：
1. `coordinators/FileUploadCoordinator.js:54-56` — 删除 `showUploadPanel()` 调用块
2. `core/folderUpload.js:93-96` — 删除 `showUploadPanel()` 调用块

**新行为**：
- 新增上传任务时，**只显示底部 mini bar**（不展开抽屉）
- 用户主动点击 mini bar → 展开
- 用户按 `Ctrl+Shift+U` → 展开
- 与百度网盘行为一致：不打扰当前浏览

**全局扫描**（反思清单 #6）：
- 7 处 `panel.expanded` / `panel.expand` / `panel.show` 引用
- 剩余 5 处都是合理（Drawer 绑定、Flash 条件、用户主动点击、兼容 getter）
- 没有任何代码再调用 `showUploadPanel()`（方法本身保留兼容）

**验证**：
- Babel: 2/2 OK
- Lint: 0 errors

**行业惯例支撑**：百度网盘/阿里云盘新增任务时只显示底部小条，不强制展开列表。强制展开是对用户浏览的"打断"。
