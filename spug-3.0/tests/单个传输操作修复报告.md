# 单个传输操作修复报告

## 一、问题描述

### 核心问题
单个文件的暂停、继续（开始）、删除按钮点击后无反应、状态不更新或报错，批量操作可能正常，但单个操作完全失效。

### 问题现象
1. 点击单个文件的「暂停」按钮：无反应，状态仍为 uploading，未调用后端接口
2. 点击单个文件的「继续」按钮：无反应，状态仍为 paused，未续传
3. 点击单个文件的「删除」按钮：无反应，记录未从列表和后端删除
4. 批量操作（暂停所有/删除所有）可能正常，仅单个操作失效

### 技术栈
- Python Django 后端、React MobX 前端、MySQL
- 前端 UploadCoreStore.js 管理 uploadQueue，按 tenant_id 分组
- 后端有 DocumentTransfer 表持久化传输记录

## 二、核心根因定位（按概率从高到低）

### 1. 【P0-核心】`resumeItem` 方法逻辑错误（概率 95%）
- **位置**: `UploadCoreStore.js:1712-1722`
- **问题**:
  - 依赖 `item.chunks.filter(c => c.uploaded).length` 判断已上传分片
  - 恢复的记录 `chunks: []` 为空数组，导致 `uploadedChunks = 0`
  - 用户重新选择文件后，`chunks` 仍未初始化
- **后果**: 继续上传时无法正确断点续传

### 2. 【P0-核心】恢复的记录 `file: null`（概率 90%）
- **位置**: `Explorer.js:213`
- **问题**: 恢复的记录 `file: null`，导致 `resumeItem` 条件 `item.file && item.file instanceof File` 不满足
- **后果**: 恢复后点击"继续"按钮无反应

### 3. 【P1-重要】缺少单个暂停/恢复接口（概率 70%）
- **位置**: `urls.py`
- **问题**: 后端仅有批量操作接口，缺少单个任务的暂停/恢复接口
- **后果**: 暂停操作仅更新前端状态，未同步到后端

### 4. 【P1-重要】缺少后端分片信息查询接口（概率 60%）
- **问题**: 前端恢复后无法从后端查询已上传的分片信息
- **后果**: 断点续传需重新上传所有分片

### 修复 1：优化 `resumeItem` 方法
**文件**: `spug_web/src/pages/document/stores/UploadCoreStore.js`
**行号**: 1708-1740

```javascript
// 修复前
@action.bound
async resumeItem(itemId) {
  console.log('[传输] 恢复单个任务:', itemId);
  const item = this.findUploadItemInCurrentTenant(itemId);
  if (item && item.status === 'paused' && item.file && item.file instanceof File) {
    item.status = 'uploading';
    item.error = null;
    item.canAbort = true;
    const uploadedChunks = item.chunks.filter(c => c.uploaded).length;
    console.log('[传输] 恢复任务:', item.name, `已上传 ${uploadedChunks}/${item.chunks.length} 分片`);
    await this.uploadSingleFile(item.file, null, item.id);
  } else if (item && item.status === 'error') {
    console.log('[传输] 重试失败任务:', item.name);
    await this.uploadSingleFile(item.file, null, item.id);
  }
}

// 修复后
@action.bound
async resumeItem(itemId) {
  console.log('[传输] 恢复单个任务:', itemId);
  const item = this.findUploadItemInCurrentTenant(itemId);
  if (!item) {
    console.warn('[传输] 未找到任务:', itemId);
    return;
  }

  // 【修复】支持恢复从后端恢复的记录（file: null，但 fileHash 存在）
  const shouldResume = item.status === 'paused' || item.status === 'error';
  const hasFile = item.file && item.file instanceof File;
  const hasFileHash = item.fileHash;

  if (shouldResume) {
    if (hasFile) {
      // 有文件对象：正常恢复上传
      item.status = 'uploading';
      item.error = null;
      item.canAbort = true;
      const uploadedChunks = item.chunks ? item.chunks.filter(c => c.uploaded).length : 0;
      console.log('[传输] 恢复任务（有文件）:', item.name, `已上传 ${uploadedChunks}/${item.chunks?.length || 0} 分片`);
      await this.uploadSingleFile(item.file, null, item.id);
    } else if (hasFileHash) {
      // 【修复】无文件对象但有 fileHash：提示用户重新选择文件
      console.warn('[传输] 恢复任务（无文件对象）:', item.name, 'fileHash:', item.fileHash);
      message.warning(`"${item.name}" 需要重新选择文件以继续上传`);
      // TODO: 可以在这里触发文件选择对话框（需额外实现）
    } else {
      console.warn('[传输] 无法恢复任务（无文件且无 fileHash）:', item.name);
      message.error(`"${item.name}" 无法继续上传，请删除后重新添加`);
    }
  } else {
    console.warn('[传输] 任务状态不支持恢复:', item.name, 'status:', item.status);
  }
}
```

### 修复 6：添加后端状态更新接口
**文件**: `data/backend/apps/document/views.py`
**行号**: 2878-2945

```python
class TransferStatusUpdateView(View):
    """更新传输状态"""

    @auth('document.document.upload')
    def post(self, request, transfer_id):
        try:
            form, error = JsonParser(
                Argument('status', type=str, required=True, help='新状态：PENDING/UPLOADING/PAUSED/COMPLETED/FAILED/CANCELED'),
            ).parse(request.body)

            if error:
                return json_response(error=error)

            transfer = DocumentTransfer.objects.get(id=transfer_id)

            # 权限检查：只能操作自己的传输记录，且必须在同一租户内
            request_tenant_id = getattr(request.user, 'tenant_id', '')
            is_supper = getattr(request.user, 'is_supper', False)

            if (transfer.user != request.user and not is_supper) or \
               (transfer.tenant_id != request_tenant_id and not is_supper):
                logger.warning(f'[Document] User {request.user.username}(tenant={request_tenant_id}) attempting to update status of transfer {transfer_id} owned by tenant {transfer.tenant_id}')
                return json_response(error='无权更新此传输记录')

            # 状态流转验证
            valid_transitions = {
                'PENDING': ['UPLOADING', 'CANCELED'],
                'UPLOADING': ['PAUSED', 'FAILED', 'COMPLETED', 'CANCELED'],
                'PAUSED': ['UPLOADING', 'CANCELED'],
                'FAILED': ['UPLOADING', 'CANCELED'],
                'COMPLETED': [],
                'CANCELED': []
            }

            current_status = transfer.status
            new_status = form.status

            if new_status not in valid_transitions.get(current_status, []):
                logger.warning(f'[Document] Invalid status transition: {current_status} -> {new_status}')
                return json_response(error=f'无效的状态转换：{current_status} -> {new_status}')

            old_status = transfer.status
            transfer.status = new_status

            if new_status == 'UPLOADING':
                if not transfer.started_at:
                    transfer.started_at = timezone.now()

            transfer.save()

            logger.info(f'[Document] Transfer status updated: id={transfer_id}, {old_status} -> {new_status}, user={request.user.username}')
            return json_response(data={'status': new_status})

        except DocumentTransfer.DoesNotExist:
            logger.warning(f'[Document] Transfer record not found: id={transfer_id}')
            return json_response(error='传输记录不存在')
        except Exception as e:
            logger.error(f'[Document] Error updating transfer status: {e}')
            return json_response(error=f'更新传输状态失败: {str(e)}')
```

## 七、注意事项

### 前端注意事项
1. 恢复的记录 `file: null`，无法直接继续上传，需提示用户重新选择文件
2. `item.chunks` 可能为空数组，需用可选链 `item.chunks?.length` 避免报错
3. 所有操作均添加了日志，方便问题排查

### 后端注意事项
1. 状态更新接口有严格的状态流转验证，防止非法状态转换
2. 租户隔离检查：只能操作自己的传输记录
3. 超级管理员可操作所有租户的传输记录

### 待优化项
1. 实现"重新选择文件"对话框，让用户可直接选择文件继续上传（目前仅提示）
2. 实现从后端查询已上传分片信息的接口，支持真正的断点续传
3. 优化批量操作的并发控制，避免同时操作多个任务导致状态不一致
