## 三、技术细节

### 3.1 性能优化

1. **进度更新节流**
   - 每 5% 更新一次后端，减少 API 调用次数
   - 节流时间间隔 500ms（复用原有逻辑）

2. **异步处理**
   - 创建传输记录使用 `async/await`，不阻塞上传流程
   - 进度更新使用静默处理，失败不影响上传

3. **错误处理**
   - API 调用失败时记录日志，不中断上传流程
   - 所有 API 方法都有 try-catch 包裹

---

### 3.2 数据流

```
用户选择文件
  ↓
processUploadQueue()
  ↓
createTransfer() → 创建后端传输记录 → 获取 transferId
  ↓
uploadFileChunked() / uploadFileNormal()
  ↓
uploading...
  ↓
updateTransferProgress() → 每 5% 更新进度
  ↓
complete / cancel
  ↓
completeTransfer() / cancelTransfer() → 更新后端状态
  ↓
用户删除任务
  ↓
deleteTransfer() → 删除后端记录（仅已完成/失败）
```

---

### 3.3 租户隔离

所有 API 调用都自动携带租户信息：
- `is_public`: 从 `navigationStore.isPublic` 获取
- `tenant_id`: 从 `localStorage.getItem('tenant_id')` 获取
- 后端自动根据租户过滤数据
