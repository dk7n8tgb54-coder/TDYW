# 多租户资料库传输列表刷新恢复修复报告

**修复时间**: 2026-03-01
**修复人员**: AI Assistant
**问题等级**: P0（核心功能）

---

## 一、问题描述

### 🔴 问题1：刷新后任务无法恢复（最严重）

**现象**：
1. 刷新前是「上传中（UPLOADING）」的任务，刷新后按钮显示不正常，无法点击继续上传
2. 刷新前是「暂停（PAUSED）」的任务，刷新后点击继续上传时报错：`无法恢复任务（无文件且无 fileHash）`
3. 日志显示 `hash: ` 为空，说明后端未返回 `file_hash` 字段或前端未正确映射

**日志关键信息**：
```
[Explorer] 恢复传输记录: 17-【理论】第3周，周四，如何看懂一份训练计划？.mp4 状态: PENDING 进度: 0% hash:
```

---

### 🟡 问题2：刷新后按钮显示逻辑异常

**现象**：
- 刷新前是上传/暂停状态的任务，刷新后按钮（暂停/继续/取消/删除）的显示/禁用状态不正常
- `waiting` 状态没有显示操作按钮
- 没有 `fileHash` 的任务继续按钮未禁用

---

### 🟢 问题3：刷新后历史上传完成的记录不显示

**现象**：
- 刷新页面后，传输列表只显示未完成的记录（PENDING/UPLOADING/PAUSED）
- 已完成（COMPLETED）、失败（FAILED）、取消（CANCELED）的记录完全不显示

---

## 二、根因分析

### 根因 1（P0）：旧数据库记录缺少 file_hash 字段

**位置**: 数据库记录（历史遗留数据）

**问题**:
- 旧版本创建的传输记录没有保存 `file_hash` 字段
- 后端 `TransferListView` 虽然返回了 `file_hash`，但数据库中旧记录的值为空
- 前端恢复后 `fileHash: null`，导致无法断点续传

**影响**:
- 用户刷新页面后无法继续上传
- 需要重新选择文件才能续传

---

### 根因 2（P0）：waiting 状态没有操作按钮

**位置**: `spug_web/src/pages/document/UploadPanel.js:102`

**问题**:
- `waiting` 状态（后端 `PENDING`）没有显示操作按钮
- 用户无法点击开始上传

**影响**:
- 刷新后的 `PENDING` 任务无法继续上传

---

### 根因 3（P0）：resumeItem 不支持 waiting 状态

**位置**: `spug_web/src/pages/document/stores/UploadCoreStore.js:1902`

**问题**:
- `resumeItem` 只允许 `paused` 或 `error` 状态恢复
- `waiting` 状态点击继续时报错

**影响**:
- `waiting` 状态的任务无法恢复上传

---

### 根因 4（P1）：Explorer 只恢复未完成的记录

**位置**: `spug_web/src/pages/document/Explorer.js:176`

**问题**:
- 过滤条件只包含 `['PENDING', 'UPLOADING', 'PAUSED']`
- 已完成/失败/取消的记录被过滤掉

**影响**:
- 用户看不到历史上传记录

---

### 根因 5（P1）：没有 fileHash 的任务继续按钮未禁用

**位置**: `spug_web/src/pages/document/UploadPanel.js:125-147`

**问题**:
- 没有检查 `fileHash` 是否存在
- 用户点击继续按钮后报错"需要重新选择文件"

**影响**:
- 用户体验差，点击按钮后才发现无法继续

---

## 三、修复方案

### 修复 1：添加重新选择文件功能（核心修复）

**文件**: `spug_web/src/pages/document/stores/UploadCoreStore.js`

**修改内容**:
```javascript
/**
 * 【P0修复】为恢复的任务重新选择文件后继续上传
 * @param {number} itemId - 任务ID
 * @param {File} file - 新选择的文件
 */
@action.bound
async replaceFileAndResume(itemId, file) {
  console.log('[传输] 重新选择文件并恢复任务:', itemId, file.name);
  const item = this.findUploadItemInCurrentTenant(itemId);
  if (!item) {
    console.warn('[传输] 未找到任务:', itemId);
    return false;
  }

  // 检查任务状态是否允许重新选择文件
  if (!['paused', 'waiting', 'error'].includes(item.status)) {
    console.warn('[传输] 任务状态不允许重新选择文件:', item.name, 'status:', item.status);
    message.warning(`"${item.name}" 当前状态不支持重新选择文件`);
    return false;
  }

  // 检查是否有 transferId
  if (!item.transferId) {
    console.warn('[传输] 任务没有传输记录，无法续传:', item.name);
    message.warning(`"${item.name}" 无法续传，请删除后重新添加`);
    return false;
  }

  // 计算新文件的 MD5
  try {
    runInAction(() => {
      item.status = 'calculating';
      item.error = null;
    });
    console.log('[传输] 开始计算新文件 MD5:', file.name);

    const hash = await this.calculateFileMD5(file, item.id);
    console.log('[传输] 新文件 MD5:', hash);

    // 检查文件是否匹配
    if (item.fileHash && item.fileHash !== hash) {
      console.warn('[传输] 文件不匹配:', '旧hash:', item.fileHash, '新hash:', hash);
      runInAction(() => {
        item.status = 'paused';
        item.error = '文件不匹配，请选择原文件';
      });
      message.error(`"${item.name}" 文件不匹配，请选择原文件`);
      return false;
    }

    // 更新任务信息
    runInAction(() => {
      item.file = file;
      item.fileSize = file.size;
      if (!item.fileHash) {
        item.fileHash = hash;  // 如果原记录没有fileHash，使用新计算的
      }
      item.status = 'paused';
      item.error = null;
    });

    // 自动恢复上传
    await this.resumeItem(itemId);
    return true;
  } catch (error) {
    console.error('[传输] 重新选择文件失败:', error);
    runInAction(() => {
      item.status = 'paused';
      item.error = '文件处理失败';
    });
    message.error(`"${file.name}" 文件处理失败: ${error.message}`);
    return false;
  }
}
```

**修改位置**: `UploadCoreStore.js`，行号 2010-2070，新增约 60 行

### 修复 5：优化恢复提示信息

**文件**: `spug_web/src/pages/document/Explorer.js`

**修改内容**:
```javascript
// 修复前
const needReuploadCount = pendingTransfers.filter(t => !t.file_hash).length;
if (needReuploadCount > 0) {
  message.warning(`已恢复 ${pendingTransfers.length} 条传输任务，其中 ${needReuploadCount} 条需重新选择文件`);
} else {
  message.info(`已恢复 ${pendingTransfers.length} 条传输任务，请手动点击继续`);
}

// 修复后：统计各状态的记录数，提供详细的恢复信息
const stats = {
  completed: pendingTransfers.filter(t => t.status === 'COMPLETED').length,
  unfinished: pendingTransfers.filter(t => ['PENDING', 'UPLOADING', 'PAUSED'].includes(t.status)).length,
  failed: pendingTransfers.filter(t => ['FAILED', 'CANCELED'].includes(t.status)).length,
  needReupload: pendingTransfers.filter(t => !t.file_hash && ['PENDING', 'UPLOADING', 'PAUSED'].includes(t.status)).length
};

let messageText = `已恢复 ${pendingTransfers.length} 条传输记录`;
const parts = [];
if (stats.completed > 0) parts.push(`${stats.completed} 条已完成`);
if (stats.unfinished > 0) parts.push(`${stats.unfinished} 条未完成`);
if (stats.failed > 0) parts.push(`${stats.failed} 条失败`);
if (parts.length > 0) messageText += `（${parts.join('，')}）`;

if (stats.needReupload > 0) {
  message.warning(messageText + `，其中 ${stats.needReupload} 条需重新选择文件`);
} else {
  message.info(messageText);
}
```

## 七、注意事项

### 1. 旧数据兼容性
- 数据库中旧记录的 `file_hash` 字段可能为空
- 前端恢复时会提示用户重新选择文件
- 用户选择文件后会计算 MD5 并续传

### 2. 文件匹配检测
- 重新选择文件时会计算 MD5 并与原记录对比
- 如果 MD5 不匹配，会提示用户选择原文件
- 避免用户错误地选择不同的文件续传

### 3. MobX 依赖
- `UploadCoreStore.js` 已正确导入 `runInAction`：`import { observable, action, runInAction, computed } from 'mobx';`
- 使用 `runInAction` 包裹状态更新，确保 MobX 响应式追踪

### 3. 状态映射一致性
- 后端状态：`PENDING` → 前端 `waiting`
- 后端状态：`UPLOADING` → 前端 `paused`（恢复时避免自动上传）
- 后端状态：`PAUSED` → 前端 `paused`
- 后端状态：`COMPLETED` → 前端 `completed`
- 后端状态：`FAILED` → 前端 `error`
- 后端状态：`CANCELED` → 前端 `error`

### 4. 时间过滤保留
- 仍然保留 30 分钟时间过滤
- 避免恢复过久未完成的任务
- 用户可以手动删除旧记录

### 5. 租户隔离
- 公共空间/私有空间记录独立恢复
- 跨租户数据隔离正确
- 不影响原有租户过滤逻辑
