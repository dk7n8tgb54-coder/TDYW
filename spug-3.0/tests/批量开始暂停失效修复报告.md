## 一、问题描述

### 🔴 问题1：批量开始（全部开始）完全失效

**现象**：
- 点击「全部开始」按钮后，没有任何任务恢复上传
- 日志显示 `恢复 0 个暂停的任务`、`待处理文件已在队列中，跳过`
- 刷新后的 `PENDING` 状态任务（映射为 `waiting`）无法恢复

**日志关键信息**：
```
[传输] 点击全部开始，当前暂停状态: true 待处理文件数: 1
[传输] 恢复 0 个暂停的任务
[传输] 待处理文件已在队列中，跳过
[传输] 全部开始操作完成
```

---

### 🟡 问题2：批量暂停（全部暂停）完全失效

**现象**：
- 点击「全部暂停」按钮后，没有任何任务被暂停
- 日志显示 `取消 0 个上传任务`
- `waiting` 状态的任务无法被暂停

**日志关键信息**：
```
[传输] 点击全部暂停，当前队列: 1 个租户，活跃上传: 0
[传输] 暂停操作完成，取消 0 个上传任务
```

---

## 二、根因分析

### 根因 1（P0）：批量开始只过滤 paused 状态

**位置**: `spug_web/src/pages/document/stores/UploadCoreStore.js:1633`

**问题**:
```javascript
// 修复前
const items = this.uploadQueue[tenantId].filter(item => item.status === 'paused');
```

**影响**:
- 刷新后从后端恢复的 `PENDING` 状态任务被映射为 `waiting`
- 批量开始时过滤掉了 `waiting` 状态的任务
- 只恢复了 `paused` 状态的任务，导致日志显示 `恢复 0 个暂停的任务`

---

### 根因 2（P0）：批量暂停只处理 uploading 状态

**位置**: `spug_web/src/pages/document/stores/UploadCoreStore.js:1590`

**问题**:
```javascript
// 修复前
if (item.status === 'uploading' && item.canAbort && item.abortToken) {
  item.abortToken.cancel('用户暂停');
  item.status = 'paused';
  item.error = '已暂停';
  cancelCount++;
}
```

**影响**:
- `waiting` 状态的任务无法被暂停
- 只暂停了 `uploading` 状态的任务
- 导致日志显示 `取消 0 个上传任务`

---

### 根因 3（P1）：pauseAll 未使用 AbortController

**位置**: `spug_web/src/pages/document/stores/UploadCoreStore.js:1590-1595`

**问题**:
- 只使用了旧的 `abortToken.cancel()` 方法
- 没有使用新的 `abortController.abort()` 方法
- 与单个暂停逻辑不一致

**影响**:
- `waiting` 状态的任务暂停时没有触发中止信号
- 任务可能继续执行暂停后的逻辑

---

## 三、修复方案

### 修复 1：批量开始支持 paused/waiting/error 状态

**文件**: `spug_web/src/pages/document/stores/UploadCoreStore.js`

**修改内容**:
```javascript
// 修复前
const items = this.uploadQueue[tenantId].filter(item => item.status === 'paused');

// 修复后：支持 paused、waiting、error 状态
const items = this.uploadQueue[tenantId].filter(item =>
  ['paused', 'waiting', 'error'].includes(item.status)
);
```

**修改位置**: `UploadCoreStore.js`，行号 1632-1634，修改 1 行

---

### 修复 2：批量暂停支持 uploading 和 waiting 状态

**文件**: `spug_web/src/pages/document/stores/UploadCoreStore.js`

**修改内容**:
```javascript
// 修复前
if (item.status === 'uploading' && item.canAbort && item.abortToken) {
  item.abortToken.cancel('用户暂停');
  item.status = 'paused';
  item.error = '已暂停';
  cancelCount++;
  // 【P1-3修复】收集transferId用于后端同步
  if (item.transferId) {
    transferIds.push(item.transferId);
  }
}

// 修复后：支持 uploading 和 waiting 状态，使用 AbortController
if ((item.status === 'uploading' || item.status === 'waiting') && item.canAbort) {
  if (item.abortController) {
    item.abortController.abort('用户暂停');
    console.log('[传输] 已中止AbortController:', item.name);
  }
  if (item.abortToken) {
    item.abortToken.cancel('用户暂停');
  }
  item.status = 'paused';
  item.error = '已暂停';
  cancelCount++;
  // 【P1-3修复】收集transferId用于后端同步
  if (item.transferId) {
    transferIds.push(item.transferId);
  }
}
```

**修改位置**: `UploadCoreStore.js`，行号 1590-1600，修改约 10 行

## 七、注意事项

### 1. 状态一致性
- 批量开始的状态过滤与 `resumeItem` 方法保持一致
- 批量暂停的状态判断与 `pauseItem` 方法保持一致
- 使用 `includes` 方法统一处理多状态

### 2. 租户隔离
- 批量操作正确遍历 `Object.keys(this.uploadQueue)`
- 每个租户的队列独立处理
- 不影响单个任务的租户隔离逻辑

### 3. 向后兼容
- 保留旧的 `abortToken.cancel()` 支持
- 同时使用新的 `abortController.abort()` 方法
- 兼容新旧代码逻辑

### 4. 错误处理
- 批量开始时检查文件对象有效性
- 批量暂停时检查 `canAbort` 标志
- 无效的任务会被跳过并记录日志
