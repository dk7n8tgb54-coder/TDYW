# 批量删除超时问题修复报告

**修复日期**: 2026-02-28
**问题类型**: 前端超时导致删除操作失败
**风险等级**: P2 - 功能可用性

---

## 问题描述

### 错误表现
前端批量删除文件/文件夹时，出现"请求超时，文件较大请重试"错误：
```
Explorer.js:408  删除失败: 请求异常: 请求超时，文件较大请重试
```

### 问题原因
1. **前端超时配置不足**：
   - `Explorer.js`中定义了`API_TIMEOUT_MS: 300000`（5分钟）
   - 但实际HTTP请求使用的是axios默认的30秒超时（`http.js:49`）
   - 删除大文件夹时，后端递归删除所有子文件和子文件夹需要较长时间

2. **后端删除流程耗时**：
   - 删除文件夹需要递归删除所有子文件夹
   - 每个文件夹需要删除其中的所有文件
   - 包括：删除秒传缓存、删除物理文件、删除数据库记录

```javascript
// 新增：超时校验函数（带参数校验和环境适配）
static getDeleteTimeout() {
  // 1. 从常量取基础超时，默认兜底5分钟
  const baseTimeout = ExplorerClass.CONSTANTS.API_TIMEOUT_MS || 300000;
  // 2. 参数校验：确保是正数
  const validTimeout = Number.isInteger(baseTimeout) && baseTimeout > 0
    ? baseTimeout
    : 300000;
  // 3. 环境适配：开发/测试环境缩短超时，生产环境用配置值
  return process.env.NODE_ENV === 'production'
    ? validTimeout
    : Math.min(validTimeout, ExplorerClass.CONSTANTS.API_TIMEOUT_MS_DEV);
}
```

```javascript
const batchSize = ExplorerClass.CONSTANTS.BATCH_DELETE_SIZE;  // 5
for (let i = 0; i < selectedKeys.length; i += batchSize) {
  const batch = selectedKeys.slice(i, i + batchSize);
  // 并发删除当前批次
  await Promise.all(batchPromises);
  // 批次之间添加短暂延迟（100ms）
```
