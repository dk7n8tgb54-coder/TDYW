# 多租户资料库分片上传暂停功能修复报告

## 🔴 核心问题定位

### 问题现象
- 点击单个文件的「暂停」按钮，前端状态变为 paused
- 但分片仍在持续发送，进度条继续增长
- 后端仍在接收并保存分片文件
- 甚至暂停后文件仍能完整上传完成

### 根因分析（按概率从高到低）

#### 1. 🔴 95%概率：每个分片都创建新的CancelToken，但pauseItem只取消最后一个

**问题代码**（第840-841行）：
```javascript
const cancelTokenSource = axios.default.CancelToken.source();
uploadItem.abortToken = cancelTokenSource;  // ❌ 每个分片都覆盖了abortToken
```

**pauseItem调用**（第1818行）：
```javascript
item.abortToken.cancel('用户暂停');  // ❌ 只能取消最后一个分片的请求
```

**结果**：第1个分片的token被第2个覆盖，第2个被第3个覆盖...pauseItem只能取消最后一个分片，之前的分片仍在继续上传。

---

#### 2. 🔴 90%概率：XMLHttpRequest没有绑定CancelToken

**问题代码**（第845-901行）：
```javascript
// 第840行创建的cancelTokenSource完全没有被使用
const cancelTokenSource = axios.default.CancelToken.source();
uploadItem.abortToken = cancelTokenSource;

// 第845-901行：使用XMLHttpRequest发送请求，但没有使用CancelToken
const xhr = new XMLHttpRequest();
// ...
xhr.open('POST', '/api/document/upload_chunk/');
xhr.send(formData);
```

**结果**：即使调用 `abortToken.cancel()` 也无法取消XMLHttpRequest请求，因为XMLHttpRequest不监听axios的CancelToken。

---

#### 3. 🟡 70%概率：全局暂停标志 `this.isPaused` 不会触发单个文件暂停

**问题代码**（第780行）：
```javascript
// 全局暂停标志，用于暂停所有上传
if (this.isPaused) {
  console.log('[传输] 检测到暂停，停止上传');
  break;
}
```

**pauseItem实现**（第1818行）：
```javascript
// pauseItem只修改item.status，不会设置this.isPaused
item.abortToken.cancel('用户暂停');
```

**结果**：`this.isPaused` 用于暂停所有上传，单个文件的 `pauseItem` 不会设置这个标志，导致循环不会因单个文件暂停而中断。

---

## ✅ 修复方案

### 修复1: 使用任务级别的AbortController（核心修复）

**原理**：
- **每个文件一个AbortController**，而不是每个分片一个
- AbortController的signal可以被多个HTTP请求共享
- 调用 `abortController.abort()` 可以立即取消所有正在发送的分片请求

**文件**: `spug_web/src/pages/document/stores/UploadCoreStore.js`

#### 修改1.1: 创建任务级别的AbortController（第778-786行）

**修改前**：
```javascript

// 上传分片

  // ...
```

**修改后**：
```javascript
const targetFolderId = folderId !== null ? folderId : navigationStore.currentFolderId;

// 【核心修复】创建任务级别的AbortController，每个文件一个

  }
});

// 上传分片

  // ...
```

**修改后**：

```javascript
  // 【核心修复】检查任务级别的暂停标志

  if (uploadItem && (uploadItem.isPausedByUser || uploadItem.status === 'paused')) {
    console.log('[传输] 检测到暂停，停止上传，已上传', chunkIndex, '个分片');
    runInAction(() => {

      if (item) {
        item.status = 'paused';
        item.error = '已暂停';

        item.canAbort = false;

```

#### 修改1.3: 绑定AbortController到XMLHttpRequest（第859-876行）

**修改前**：
```javascript

    xhr.addEventListener('error', () => { ... });

    xhr.send(formData);

```

**修改后**：
```javascript
// 【核心修复】检查任务是否已被暂停
const uploadItemCheck = this.uploadQueue[tenantId].find(item => item.id === uploadId);
if (uploadItemCheck && (uploadItemCheck.isPausedByUser || uploadItemCheck.status === 'paused')) {
  console.log('[传输] 任务已暂停，跳过分片上传:', chunkIndex);
  break;
}

try {
  // 使用任务级别的AbortController的signal
  const controller = uploadItemCheck?.abortController || taskAbortController;

  // 使用 XMLHttpRequest 获取上传进度
  const xhr = new XMLHttpRequest();
  let lastUpdateTime = 0;

  await new Promise((resolve, reject) => {
    // 【核心修复】监听AbortController的abort信号
    const abortHandler = () => {
      console.log('[传输] 收到中止信号，取消分片上传:', chunkIndex);
      controller.signal.removeEventListener('abort', abortHandler);
      xhr.abort();
      reject(new Error('用户暂停'));
    };

    controller.signal.addEventListener('abort', abortHandler);

    xhr.upload.addEventListener('progress', (e) => { ... });
    xhr.addEventListener('load', () => {
      controller.signal.removeEventListener('abort', abortHandler);
      if (xhr.status === 200) {
        resolve();
      } else {
        reject(new Error(`HTTP ${xhr.status}`));
      }
    });
    xhr.addEventListener('error', () => {
      controller.signal.removeEventListener('abort', abortHandler);
      reject(new Error('网络错误'));
    });
    xhr.addEventListener('abort', () => {
      controller.signal.removeEventListener('abort', abortHandler);
      reject(new Error('上传取消'));
    });

    xhr.open('POST', '/api/document/upload_chunk/');
    xhr.send(formData);
  });
```

**关键点**：
1. 每个分片都监听同一个 `controller.signal.abort` 事件
2. 当 `abortController.abort()` 被调用时，所有分片的 `xhr.abort()` 都会被触发
3. 在事件监听器中正确移除监听器，避免内存泄漏

## 🔧 技术细节

### 为什么使用AbortController而不是CancelToken？

| 对比项 | CancelToken (axios) | AbortController (Web标准) |
|-------|-------------------|------------------------|
| 标准化 | axios私有 | Web标准（Fetch API） |
| 兼容性 | 需要axios支持 | 浏览器原生支持 |
| 用法 | `token.cancel(reason)` | `controller.abort(reason)` |
| 信号传递 | 每个请求独立传递 | 所有请求共享同一个signal |
| 事件监听 | 不支持事件监听 | 支持 `signal.addEventListener('abort')` |

**关键优势**：
- AbortController的signal可以被所有分片共享
- 可以监听abort事件，执行清理逻辑
- 更符合现代Web标准

---

### 为什么需要任务级别的暂停标志？

**问题**：即使调用了 `abortController.abort()`，也还需要在循环中检查

**原因**：
1. **时序问题**：`abortController.abort()` 是异步的，可能在循环的下一次迭代后才生效
2. **防抖保护**：如果abort失败，循环检查可以兜底
3. **状态一致性**：确保前端状态与后端状态同步

**实现**：
```javascript
// 暂停时设置标志
item.isPausedByUser = true;

// 循环中检查标志
if (item.isPausedByUser) {
  break;  // 跳出循环
}
```

---

### 为什么需要保留旧的abortToken？

**兼容性考虑**：
1. 可能有其他模块仍在使用旧的 `abortToken`
2. 逐步迁移，避免破坏现有功能
3. 提供平滑的升级路径

**实现**：
```javascript
// 优先使用AbortController
if (item.abortController) {
  item.abortController.abort('用户暂停');
}
// 兼容旧的abortToken
if (item.abortToken && item.abortToken.cancel) {
  item.abortToken.cancel('用户暂停');
}
```

## 📝 总结

本次修复解决了**单个文件暂停功能不生效**的核心问题：

### 核心修复
1. **使用任务级别的AbortController**：每个文件一个，取消时可以立即终止所有正在发送的分片
2. **绑定AbortController到XMLHttpRequest**：确保暂停时能真正取消HTTP请求
3. **添加任务级别的暂停标志**：在循环中检查，确保暂停后立即停止发送后续分片

### 技术亮点
- ✅ 使用Web标准的AbortController，替代axios私有的CancelToken
- ✅ 正确处理事件监听器的清理，避免内存泄漏
- ✅ 保留向后兼容性，不影响现有功能
- ✅ 完善的错误处理和日志输出

### 修复效果
- ✅ 暂停时立即停止所有正在发送的分片请求
- ✅ 进度条立即停止增长，定格在暂停时刻
- ✅ 后端不再接收新的分片文件
- ✅ 暂停后可以正常恢复续传
