## 一、问题描述

### 核心问题（严格基于用户日志）

#### 🔴 问题1：分片上传永远挂起，卡在某个分片后（P0）

**现象**：
- 新上传或续传大文件（>20MB）

- 分片请求永远挂起，无法完成

**实际日志**：
```
[传输] 上传分片 6/19: 19-【徒手】第4周，周一，全身肌肉强化.mp4
// 日志在此处中断，没有任何后续输出
// ❌ 没有 "上传分片 7/19"
// ❌ 没有 "所有分片上传完成"
// ❌ 没有任何错误日志
```

**预期日志**：
```
[传输] 上传分片 6/19: 19-【徒手】第4周，周一，全身肌肉强化.mp4
[传输] 上传分片 7/19: 19-【徒手】第4周，周一，全身肌肉强化.mp4  // ❌ 缺失
[传输] 上传分片 8/19: 19-【徒手】第4周，周一，全身肌肉强化.mp4  // ❌ 缺失

```

## 二、根因分析

### 根因1（P0）：xhr 缺少 load 事件监听器，导致 Promise 永远挂起 【概率 100%】

**位置**：`spug_web/src/pages/document/stores/UploadCoreStore.js:949-954`

**问题分析**:
```javascript
// 当前代码（949-954行）
xhr.open('POST', '/api/document/upload_chunk/');
xhr.setRequestHeader('X-Token', X_TOKEN);
xhr.withCredentials = true;
xhr.send(formData);
// ❌ 缺少 xhr.addEventListener('load', ...)
// ❌ 导致请求成功后无法 resolve，Promise 永远挂起
```

**时序分析**:
```
1. 上传分片 6/19
   -> xhr.send(formData) 发送请求
   -> 请求成功返回（HTTP 200）
   -> ❌ 没有监听 'load' 事件
   -> ❌ Promise 无法 resolve
   -> ❌ await xhrPromise 永远等待
   -> ❌ 循环卡住，无法继续下一个分片

2. 用户观察到的现象
   -> 日志输出：`[传输] 上传分片 6/19: XXX.mp4`
   -> 之后没有任何日志
   -> 分片永远挂起
```

**影响**:
- 分片请求成功后无法 resolve，Promise 永远等待
- 分片循环卡住，无法继续上传后续分片
- 用户体验极差，文件永远无法上传完成

**影响**:
- 新上传时，第一个分片可能成功，第二个分片立即失败

## 三、修复方案

### 修复0：xhr 添加 load 事件监听器（P0，核心修复）

**文件**: `spug_web/src/pages/document/stores/UploadCoreStore.js`

**行号**: 941-948

**修复内容**:
```javascript
// 修复前
xhr.addEventListener('error', () => {
  controller.signal.removeEventListener('abort', abortHandler);
  reject(new Error('网络错误'));
});
xhr.addEventListener('abort', () => {
  controller.signal.removeEventListener('abort', abortHandler);
  reject(new Error('上传取消'));
});

xhr.open('POST', '/api/document/upload_chunk/');
xhr.setRequestHeader('X-Token', X_TOKEN);
xhr.withCredentials = true;
xhr.send(formData);
// ❌ 缺少 'load' 事件监听器
```

**修复后**:
```javascript
xhr.addEventListener('load', () => {
  controller.signal.removeEventListener('abort', abortHandler);
  if (xhr.status === 200) {
    resolve();  // ✅ 请求成功，resolve Promise
  } else {
    reject(new Error(`HTTP ${xhr.status}: ${xhr.statusText}`));
  }
});

xhr.addEventListener('error', () => {
  controller.signal.removeEventListener('abort', abortHandler);
  reject(new Error('网络错误'));
});
xhr.addEventListener('abort', () => {
  controller.signal.removeEventListener('abort', abortHandler);
  reject(new Error('上传取消'));
});

xhr.open('POST', '/api/document/upload_chunk/');
xhr.setRequestHeader('X-Token', X_TOKEN);
xhr.withCredentials = true;
xhr.send(formData);
// ✅ 添加 'load' 事件监听器
```

**修复点**:
1. **添加 load 事件监听器**：请求成功后 resolve Promise
2. **检查 HTTP 状态码**：只有 200 才 resolve，其他状态码 reject
3. **清理事件监听器**：在 resolve/reject 前移除 abortHandler

**修复效果**:
- ✅ 分片请求成功后能正确 resolve Promise
- ✅ 分片循环能正常继续
- ✅ 所有分片都能正常上传

## 六、技术细节

### 为什么需要添加 load 事件监听器？

**问题**:
```javascript
// 创建 Promise
const xhrPromise = new Promise((resolve, reject) => {
  const abortHandler = () => {
    reject(new Error('用户暂停'));
  };

  controller.signal.addEventListener('abort', abortHandler);

  xhr.upload.addEventListener('progress', (e) => {
    // 进度更新
  });

  xhr.addEventListener('error', () => {
    reject(new Error('网络错误'));
  });
  xhr.addEventListener('abort', () => {
    reject(new Error('上传取消'));
  });

  // ❌ 缺少 'load' 事件监听器
  // 导致请求成功后无法 resolve，Promise 永远等待

  xhr.send(formData);
});

await xhrPromise;  // ❌ 永远等待，无法继续下一个分片
```

**解决方案**:
```javascript
// 添加 'load' 事件监听器
xhr.addEventListener('load', () => {
  controller.signal.removeEventListener('abort', abortHandler);
  if (xhr.status === 200) {
    resolve();  // ✅ 请求成功，resolve Promise
  } else {
    reject(new Error(`HTTP ${xhr.status}: ${xhr.statusText}`));
  }
});

await xhrPromise;  // ✅ 请求成功后继续下一个分片
```
