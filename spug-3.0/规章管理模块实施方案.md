## 1. 模块概述

| 项 | 值 |
|---|---|
| 模块名 | 规章管理（`regulation`） |
| 后端 app | `apps/regulation/`（新建，不复用 `apps/industry_rule/`） |
| 前端目录 | `spug_web/src/pages/regulation/`（新建） |
| 菜单位置 | 资料库 → 规章管理 |
| 物理文件 | 走资料库 `DocumentFilePublic`，受 `system_folder=industry_rules` 范围保护 |
| 权限体系 | `regulation.*` 权限码 + 超管强校验（写操作） |
| 风格 | 沿用 `TableCard` + `SearchForm` + `AuthButton` + `AttachmentCountBadge` |

## 2. 设计决策（确定版）

| 决策点 | 选择 | 理由 |
|---|---|---|
| 新建 `apps/regulation` vs 改造 `apps/industry_rule` | **新建 `apps/regulation`** | 避免与系统目录 `industry_rules` 命名混淆 |
| `category_id` 是否可空 | **可空（允许"未分类"）** | 兼容历史导入数据 |
| 分类树是否需要"叶子节点"控制 | **需要（`is_leaf` 字段）** | 简化 UI 提示，非叶子节点不显示"新建规章"按钮 |
| 列表是否按业务类型分组 | **不分组**（YAGNI） | 图中表格未分组，先不做 |
| 上传权限 | **权限码 + `is_supper` 强校验双保险** | 默认仅超管，保留扩展性 |

    STATUS_CHOICES = (

    biz_type = models.CharField(max_length=50, blank=True, default='', db_index=True, verbose_name='业务类型')
    keywords = models.CharField(max_length=500, blank=True, default='', verbose_name='索引关键字')
    applicable_scope = models.CharField(max_length=255, blank=True, default='', verbose_name='适用范围')
    publish_date = models.DateField(null=True, blank=True, verbose_name='发布日期')
    effective_date = models.DateField(null=True, blank=True, db_index=True, verbose_name='生效日期')
    repeal_date = models.DateField(null=True, blank=True, verbose_name='废止日期')
    status = models.CharField(max_length=20, choices=STATUS_CHOICES, default=STATUS_DRAFT, db_index=True, verbose_name='状态')
    version = models.CharField(max_length=50, blank=True, default='', verbose_name='版本')
    summary = models.TextField(blank=True, default='', verbose_name='摘要')

    created_by = models.ForeignKey(User, null=True, on_delete=models.SET_NULL, related_name='+', verbose_name='创建人')
    updated_by = models.ForeignKey(User, null=True, on_delete=models.SET_NULL, related_name='+', verbose_name='更新人')
    created_at = models.DateTimeField(auto_now_add=True, verbose_name='创建时间')
    updated_at = models.DateTimeField(auto_now=True, verbose_name='更新时间')

    class Meta:
        db_table = 'tdyw_regulation'
        verbose_name = '规章'
        verbose_name_plural = '规章'
        ordering = ['-effective_date', '-created_at']
        indexes = [
            models.Index(fields=['rule_no'], name='reg_rule_no_idx'),
            models.Index(fields=['issuing_authority'], name='reg_issue_auth_idx'),
            models.Index(fields=['biz_type'], name='reg_biz_type_idx'),
            models.Index(fields=['status'], name='reg_status_idx'),
            models.Index(fields=['category'], name='reg_category_idx'),
        ]

    def __str__(self):
        return f'{self.rule_no or ""} {self.title}'.strip()


class RegulationAttachment(models.Model):

### 3.4 decorators.py

```python
from functools import wraps
from libs import json_response


def require_supper(view_func):
    """写操作超管强校验装饰器

    与 @auth('regulation.xxx') 叠加使用：
        @auth('regulation.add')
        @require_supper
        def post(self, request): ...
    """
    @wraps(view_func)
    def _wrapped(request, *args, **kwargs):
        if not getattr(request.user, 'is_supper', False):
            return json_response(error='仅超级管理员可操作规章')
        return view_func(request, *args, **kwargs)
    return _wrapped
```

### 3.6 views.py 接口清单

| View 类 | 方法 | 路径 | 权限 | 超管校验 | 说明 |
|---|---|---|---|---|---|
| `CategoryTreeView` | GET | `/api/regulation/categories/tree/` | `regulation.view` | ❌ | 全量分类树 |
| `CategoryListCreateView` | GET/POST | `/api/regulation/categories/` | `regulation.category_manage` | POST 要 | 列表/新建分类 |
| `CategoryDetailView` | PUT/DELETE | `/api/regulation/categories/<id>/` | `regulation.category_manage` | ✅ | 编辑/删除分类 |
| `RegulationListView` | GET | `/api/regulation/` | `regulation.view` | ❌ | 列表（按 category_id/keyword/biz_type/issuing_authority 筛选） |
| `RegulationCreateView` | POST | `/api/regulation/create/` | `regulation.add` | ✅ | 新建规章 |
| `RegulationDetailView` | GET/PUT/DELETE | `/api/regulation/<id>/` | `regulation.view` / `regulation.edit` / `regulation.delete` | PUT/DELETE 要 | 详情/编辑/删除 |
| `RegulationRetireView` | POST | `/api/regulation/<id>/retire/` | `regulation.edit` | ✅ | 废止 |
| `RegulationAttachmentView` | GET/POST/DELETE | `/api/regulation/<id>/attach/` | `regulation.view` / `regulation.upload` | POST/DELETE 要 | 附件管理 |

> **附件文件校验**：关联文件时 `file_id` 必须在 `system_folder=industry_rules` 范围内（复用 `apps.document.services.system_folder_service.ensure_file_in_scope_or_error`）。

### 4.5 关键组件设计

**`index.js`** — 入口（参考 `contractAgreement/index.js` 风格）：
- `<AuthDiv auth="regulation.view">` 包裹
- `<Breadcrumb>` 面包屑
- 左侧 `<CategoryTree>` + 右侧 `<SearchForm>` + `<ComTable>`
- 弹窗：`{store.formVisible && <ComForm/>}` + `{store.categoryFormVisible && <CategoryForm/>}`

**`CategoryTree.js`** — 左侧分类树：
- antd `<Tree>` 组件
- `store.fetchCategories()` 加载全量树
- 点击节点：`store.fetchRecords({ category_id })`
- 右键菜单（超管可见）：新增子分类 / 编辑 / 删除
- "全部规章"虚拟节点：不传 `category_id`，显示全部

**`Table.js`** — 右侧表格（参考 `contractAgreement/Table.js`）：
- `<TableCard>` 组件
- 列：规章名称 / 法规编号 / 发文单位 / 业务类型 / 索引关键字 / 操作
- 操作列：查看 / 编辑 / 废止 / 删除（按权限 + 超管显隐）
- 双击行：打开详情（`store.showDetail(record)`）
- 新建按钮：`<AuthButton auth="regulation.add">` + 超管判断

**`Form.js`** — 规章新建/编辑弹窗：
- antd `<Modal>` + `<Form>`（`visible` 属性，antd 4.21.5）
- 字段：规章名称 / 法规编号 / 分类 / 发文单位 / 业务类型 / 索引关键字 / 版本 / 发布日期 / 生效日期 / 状态 / 摘要
- 附件区域：`<AttachmentManager>` 组件（复用公共组件）
- 详情模式（`viewMode`）：所有字段只读

**`store.js`** — MobX store（参考 `contractAgreement/store.js`）：
- `@observable records / categories / isFetching / total / pageNum / pageSize`
- `@observable formVisible / detailVisible / categoryFormVisible / record / categoryRecord`
- 筛选字段：`f_keyword / f_category_id / f_biz_type / f_issuing_authority / f_status`
- `fetchRecords()` / `fetchCategories()` / `showForm()` / `showDetail()` / `showCategoryForm()`

### 4.6 文件预览/下载

复用资料库现有接口：
- **预览**：`GET /api/document/file/<file_id>/preview-url/?system_folder=industry_rules` → 返回 kkFileView URL

## 6. 技术约束清单

| 约束 | 说明 |
|---|---|
| Django 版本 | 4.2（已升级），`models.Index` 需要命名 |
| MariaDB 10.8 | 不支持部分唯一索引 `UniqueConstraint(condition=...)`，但本模块不需要 |
| 租户隔离 | 本模块**暂不加租户字段**（规章是全租户共享的法规库），如果将来需要再加 `tenant_id` |
| antd 版本 | 4.21.5，Modal 用 `visible` 不是 `open` |
| 装饰器 | `@auth` + `@require_supper` 叠加，注意顺序（`@auth` 在外层） |
| 附件文件 | 必须校验 `file_id` 在 `system_folder=industry_rules` 范围内 |
| 审计日志 | 复用 `apps.logs.audit.record_audit_event`，目标类型 `regulation` |
| 审计映射 | `apps/logs/audit.py` 的 `URL_AUDIT_MAP` 需添加 `'/regulation/': {'type': 'regulation', 'name': '规章管理'}` |

## 7. 不做的事（YAGNI）

- ❌ 不加租户隔离（规章是公共法规库）
- ❌ 不加版本历史（一条规章一个版本，废止后新建另一条）
- ❌ 不加导入导出（先做手动 CRUD）
- ❌ 不加全文检索（用 `icontains` 模糊查询够用）
- ❌ 不加订阅/提醒（法规不涉及到期提醒，与合同/执照不同）
- ❌ 不处理 `apps/industry_rule/` 历史代码（保留不动，不挂载，不删除）
