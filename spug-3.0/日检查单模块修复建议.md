# 日检查单模块修复建议

> 模块范围：`checksheet` 部门值班日检查单  
> 覆盖代码：后端 `spug_api/apps/checksheet/`，前端 `spug_web/src/pages/checksheet/`，权限配置 `spug_web/src/pages/system/role/codes.js`  
> 说明：测试脚本未纳入本次检查。

## 一、总体结论

当前 `checksheet` 模块前端源码语法层面可解析通过，未发现会直接导致页面白屏的 JSX 语法错误。主要风险集中在前后端接口契约、权限展示、模板分页、项目唯一性和统计口径上。

建议优先修复以下 4 类问题：

1. 右键标记异常无效，且会误写日汇总数据。
2. 模板分页导致只加载前 50 个项目。
3. 项目名称未 URL 编码，特殊字符会导致查询失败。
4. 模板项目名允许重复，但后端按唯一项目名查询，存在 500 风险。

## 二、P0 高优先级问题

### P0-1 右键标记异常实际无效

**影响范围**

- 日检查表录入页
- 用户右键某检查项设置“异常”时

**涉及文件**

- `spug_web/src/pages/checksheet/CheckSheet.js`
- `spug_web/src/pages/checksheet/hooks/useCheckSheetUI.js`
- `spug_web/src/pages/checksheet/hooks/useCheckSheetData.js`

**问题说明**

`CheckSheet.js` 调用 `useCheckSheetUI` 时传入的是 `updateDailySummaryField`：

```js
useCheckSheetUI(allProjectsData, loaded, confirmedOperator, updateDailySummaryField)
```

但 `useCheckSheetUI.js` 中第四个参数按 `updateCellStatus` 使用：

```js
updateCellStatus(project, itemIndex, 'ABNORMAL');
```

因此右键标记异常时不会更新检查项状态，反而可能把日汇总对象写成错误结构。

**建议修复**

在 `CheckSheet.js` 中从 `useCheckSheetData()` 解构出 `updateCellStatus`，并传给 `useCheckSheetUI`：

```js
const {
  allProjectsData,
  loaded,
  confirmedOperator,
  todayDay,
  selectedYear,
  selectedMonth,
  getTotalRows,
  handleLoadAllData,
  handleCellClick,
  handleBatchFill,
  handleConfirmOk,
  updateDailySummaryField,
  updateCellStatus,
  calculateStats
} = useCheckSheetData();

const {
  confirmVisible,
  setConfirmVisible,
  handleRightClick,
  handleConfirmSignature
} = useCheckSheetUI(allProjectsData, loaded, confirmedOperator, updateCellStatus);
```

同时建议把 `useCheckSheetUI` 的参数名明确为 `updateCellStatus`，并移除未使用参数，降低再次传错的概率。

### P0-2 模板分页导致项目加载不完整

**影响范围**

- 日检查表录入
- 数据查看
- PDF 导出
- 项目筛选下拉框

**涉及文件**

- `spug_api/apps/checksheet/views.py`
- `spug_web/src/pages/checksheet/store.js`

**问题说明**

后端模板接口默认分页：

```python
page_size = int(request.GET.get('page_size', 50))
```

前端 `fetchTemplates` 只请求：

```js
http.get('/api/checksheet/template/')
```

随后用第一页模板生成 `store.projects`。如果模板超过 50 个，第 51 个之后不会进入项目列表，导致录入、查询和导出都漏数据。

**建议修复**

方案一：前端模板列表继续分页，但项目列表使用单独接口。

新增后端接口，例如：

```text
GET /api/checksheet/template/projects/
```

返回所有项目名称：

```json
{
  "projects": ["导航", "通信", "自动化"]
}
```

前端 `store.projects` 改为从该接口加载。

方案二：短期快速修复，在 `fetchTemplates` 中显式请求较大的 `page_size`：

```js
http.get('/api/checksheet/template/?page_size=200')
```

但该方案仍有上限，不建议作为长期方案。

### P0-3 模板项目名允许重复导致后端 500

**影响范围**

- 查询检查记录
- 保存检查记录
- 数据查看
- PDF 导出旧接口

**涉及文件**

- `spug_api/apps/checksheet/models.py`
- `spug_api/apps/checksheet/views.py`
- `spug_web/src/pages/checksheet/TemplateForm.js`

**问题说明**

`CheckSheetTemplate.project` 没有唯一约束，但后端多处按唯一项目名查询：

```python
CheckSheetTemplate.objects.get(project=project)
```

如果创建了同名模板，接口会抛出 `MultipleObjectsReturned`，最终返回 500。

**建议修复**

业务上如果一个项目只能有一个模板，建议：

1. 模型层增加唯一约束：

```python
project = models.CharField('项目名称', max_length=100, unique=True)
```

2. 新增迁移文件。
3. 模板新增/编辑前做重复校验，返回友好错误：

```python
if CheckSheetTemplate.objects.filter(project=form.project).exists():
    return json_response(error='项目模板已存在')
```

4. 前端保存模板失败时展示后端错误信息。

如果业务允许同名项目，应改为使用模板 ID 作为记录查询和保存主键，不应继续用 `project` 字符串定位模板。

## 三、P1 中优先级问题

### P1-1 项目名未 URL 编码

**影响范围**

- 检查记录查询
- 日检查表加载
- 数据查看

**涉及文件**

- `spug_web/src/pages/checksheet/store.js`

**问题说明**

当前请求直接拼接项目名：

```js
return http.get(`/api/checksheet/record/?year=${year}&month=${month}&project=${project}${dayParam}`)
```

如果项目名包含 `&`、`?`、`#`、`+`、空格等字符，后端收到的 `project` 会被截断或解析错误。

**建议修复**

使用 `encodeURIComponent`：

```js
@action fetchCheckRecords = (year, month, project, day) => {
  const dayParam = day ? `&day=${encodeURIComponent(day)}` : '';
  return http.get(
    `/api/checksheet/record/?year=${encodeURIComponent(year)}&month=${encodeURIComponent(month)}&project=${encodeURIComponent(project)}${dayParam}`
  ).then(res => res);
};
```

更推荐使用 axios `params`：

```js
return http.get('/api/checksheet/record/', {
  params: { year, month, project, day }
});
```

### P1-2 后端参数转换缺少校验

**影响范围**

- 检查记录查询
- 模板分页查询
- PDF 导出旧接口

**涉及文件**

- `spug_api/apps/checksheet/views.py`

**问题说明**

以下代码直接执行类型转换，非法输入会抛异常：

```python
day_filter['day'] = int(day)
page = int(request.GET.get('page', 1))
page_size = int(request.GET.get('page_size', 50))
```

例如 `day=abc` 或 `page=abc` 会导致服务端异常。

**建议修复**

增加通用解析函数：

```python
def _parse_int(value, name, min_value=None, max_value=None):
    try:
        result = int(value)
    except (TypeError, ValueError):
        return None, f'{name} 必须是整数'
    if min_value is not None and result < min_value:
        return None, f'{name} 不能小于 {min_value}'
    if max_value is not None and result > max_value:
        return None, f'{name} 不能大于 {max_value}'
    return result, None
```

用于校验：

```python
if day:
    day_value, error = _parse_int(day, 'day', 1, 31)
    if error:
        return json_response(error=error)
    day_filter['day'] = day_value
```

分页参数也应限制范围：

```python
page = max(page, 1)
page_size = min(max(page_size, 1), 200)
```

### P1-3 统计口径不准确

**影响范围**

- 录入页统计面板
- 数据查看页统计面板

**涉及文件**

- `spug_web/src/pages/checksheet/hooks/useCheckSheetData.js`
- `spug_web/src/pages/checksheet/hooks/useDataViewQuery.js`

**问题说明**

录入页统计只遍历 `checkData` 中已经存在的记录：

```js
Object.values(projectData.checkData).forEach(item => {
  stats.total++;
});
```

如果模板有 20 个检查项，但当天没有记录，表格会显示 20 个“未检查”，统计却可能显示总数 0。

数据查看页也只统计后端已有记录，没有按模板项和日期补齐未检查项。

**建议修复**

录入页按模板检查项数量统计：

```js
projectData.template.check_items.forEach((_, index) => {
  const item = projectData.checkData[String(index)] || { status: 'UNCHECKED' };
  stats.total++;
  if (item.status === 'NORMAL') stats.normal++;
  else if (item.status === 'ABNORMAL') stats.abnormal++;
  else stats.unchecked++;
});
```

数据查看页按 `项目检查项数量 × 31 天` 统计，并把缺失记录视为 `UNCHECKED`。

### P1-4 导出按钮权限展示与后端权限不一致

**影响范围**

- 数据查看与导出页

**涉及文件**

- `spug_api/apps/checksheet/views.py`
- `spug_web/src/pages/checksheet/components/QueryControls.js`
- `spug_web/src/pages/checksheet/DataView.js`

**问题说明**

后端 PDF 导出要求：

```python
@auth('checksheet.checksheet.edit')
```

但前端导出按钮是普通按钮，只有查看权限、没有编辑权限的用户也能看到。点击后会失败。

**建议修复**

把导出按钮改为 `AuthButton`：

```js
import { AuthButton } from 'components';

<AuthButton auth="checksheet.checksheet.edit" onClick={onExport}>
  导出PDF
</AuthButton>
```

如果业务认为导出应属于查看权限，则应统一调整后端权限为 `view`，并确认安全边界。

## 四、P2 低优先级问题

### P2-1 前端仍残留调试日志

**涉及文件**

- `spug_web/src/pages/checksheet/store.js`

**问题说明**

`filteredTemplates` 中仍有调试日志：

```js
console.log('[CheckSheet Store] filteredTemplates called, f_project:', this.f_project, 'templates:', this.templates);
```

与注释“移除调试日志”不一致，也会污染生产控制台。

**建议修复**

删除该 `console.log`。

### P2-2 保存空记录时仍允许写日汇总

**涉及文件**

- `spug_web/src/pages/checksheet/hooks/useCheckSheetSave.js`
- `spug_api/apps/checksheet/views.py`

**问题说明**

如果项目模板为空或前端状态异常，`records` 可能为空，但仍会保存 `daily_summary`。这可能出现“当天有签名/备注，但没有任何检查记录”的数据。

**建议修复**

前端保存前校验每个项目至少有检查项：

```js
if (records.length === 0) {
  message.warning(`${project} 暂无检查项，无法保存`);
  return;
}
```

后端也可根据业务规则拒绝空 `records`。

### P2-3 日汇总数据为全局共享，但前端按项目重复提交

**涉及文件**

- `spug_web/src/pages/checksheet/hooks/useCheckSheetSave.js`
- `spug_api/apps/checksheet/models.py`

**问题说明**

`CheckSheetDailySummary` 的唯一键是：

```python
unique_together = ['year', 'month', 'day']
```

说明日汇总是当天全局共享的。但前端保存时会对每个项目都提交一次同样的 `daily_summary`。当前因为数据一致，通常不会错，但会产生重复写入，未来如果项目级汇总出现差异，会互相覆盖。

**建议修复**

短期：前端只在第一个项目请求里提交 `daily_summary`，其他项目只提交 records。

长期：明确业务模型：

- 如果日汇总是全局的，保留当前唯一键，但接口拆成“保存检查记录”和“保存日汇总”。
- 如果日汇总应按项目独立，则模型增加 `template` 或 `project` 字段，并调整唯一键。

## 五、建议修复顺序

1. 修复右键异常传参错误。
2. 修复模板分页导致项目漏加载。
3. 增加模板项目名唯一约束或改用模板 ID。
4. 修复项目名 URL 编码。
5. 增加后端参数校验。
6. 修正统计口径。
7. 对齐导出按钮与后端权限。
8. 清理调试日志和重复提交日汇总问题。

## 六、建议验证用例

1. 新建 51 个以上模板，确认录入页、数据查看页、导出都能包含全部项目。
2. 创建项目名包含 `&`、空格、`+` 的模板，确认检查记录可正常加载。
3. 尝试创建同名模板，确认前端提示友好错误，不出现接口 500。
4. 右键某检查项标记异常，确认表格状态变为异常，保存后刷新仍为异常。
5. 新模板当天无记录时，统计应显示全部为未检查，而不是总数 0。
6. 只有查看权限的账号不应看到导出按钮，或点击导出不应出现权限错误。
7. 手工请求 `day=abc`、`page=abc`，接口应返回参数错误，不应返回 500。
