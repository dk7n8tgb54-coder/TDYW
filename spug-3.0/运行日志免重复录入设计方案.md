# 运行日志免重复录入设计方案

## 核心思路转变

**原方式（重复录入）**
```
故障模块 → 录入故障详情
干扰模块 → 录入干扰信息  
升级模块 → 录入升级记录
运行日志 → 再手写一遍今天发生了什么 ❌
```

**新方式（一处录入）**
```
故障模块 → 录入故障详情 ──┐
干扰模块 → 录入干扰信息 ──┼──► 运行日志自动汇总展示 ✅
升级模块 → 录入升级记录 ──┘
```

---

## 推荐方案：运行日志作为"汇总视图"

### 1. 核心机制

运行日志不再手动填写事件内容，而是：
1. **自动聚合**各模块当天的记录
2. **手动补充**纯文本的值班笔记
3. **双向关联**支持点击查看详情

### 2. 运行日志结构拆分

```
┌─────────────────────────────────────────────┐
│ 运行日志（2024-01-15 白班）                  │
├─────────────────────────────────────────────┤
│                                             │
│ 【自动聚合区】← 各模块记录自动汇总            │
│ ├─ 系统升级 (2条)                           │
│ │   • 14:15 支付服务v2.3.0升级完成 [查看]   │
│ │   • 16:00 数据库补丁更新 [查看]           │
│ ├─ 干扰记录 (1条)                           │
│ │   • 10:30 机房空调维护导致短暂波动 [查看] │
│ └─ 故障处置 (1条)                           │
│     • 14:30 支付超时故障已修复 [查看]       │
│                                             │
├─────────────────────────────────────────────┤
│ 【手动补充区】← 纯文本值班笔记               │
│ ┌─────────────────────────────────────────┐ │
│ │ 今日值班情况良好，除上述事件外无其他异常 │ │
│ │ 交班事项：关注支付服务监控指标           │ │
│ └─────────────────────────────────────────┘ │
│                                             │
├─────────────────────────────────────────────┤
│ [保存日志] [导出PDF] [发送交班邮件]          │
└─────────────────────────────────────────────┘
```

### 3. 使用流程

**值班人员操作：**
1. 有故障 → 去【设备履历-故障管理】正常录入
2. 有干扰 → 去【干扰管理】正常录入  
3. 有升级 → 去【系统升级】正常录入
4. 写日志 → 打开运行日志，自动看到上述记录，只写额外补充内容

**可选操作：**
- 点击"一键引入"把各模块记录生成摘要文本
- 手动调整显示顺序或隐藏某些记录
- 添加纯文本补充说明

## 技术实现要点

### 方案A：聚合视图（推荐）

**后端：**
- 运行日志表只存基本信息（日期、班次、补充内容）
- 查询时聚合各模块当天数据
- 关联关系通过时间范围+可选的手动关联

**前端：**
- 运行日志详情页分两个区域展示
- 自动聚合区：调各模块API获取当天记录
- 手动补充区：富文本编辑器

### 方案B：智能创建（备选）

**后端：**
- 运行日志保存时解析内容
- 提供"识别建议"API
- 确认后调用各模块接口创建记录

---

## 方案对比

| 维度 | 方案A：聚合视图 | 方案B：智能创建 |
|------|----------------|----------------|
| 录入习惯 | 保持各模块独立录入 | 集中在运行日志录入 |
| 字段完整性 | 各模块字段完整 | 需补充缺失字段 |
| 流程规范性 | 符合现有流程 | 简化但可能遗漏 |
| 实现难度 | 低（只读聚合） | 中（需AI识别） |
| 推荐使用 | ✅ 团队已有成熟模块 | 暂无专业模块时 |

---

## 最终建议

**采用方案A（聚合视图）**，原因：

1. **符合现状** - 你们已有设备履历、干扰管理、系统升级模块，流程是成熟的
2. **字段完整** - 各模块有自己的完整字段，聚合展示即可
3. **责任清晰** - 专业模块由专业负责人录入
4. **实现简单** - 只需开发聚合查询，不动现有模块

**实施步骤：**
1. 运行日志改为"日期+班次"维度
2. 详情页自动查询当天各模块记录
3. 只保留一个"补充内容"文本框
4. 支持点击跳转到各模块详情
