## 一、当前租户架构

### 1.1 Tenant 模型

- **模型**: `apps/account/models.py` -> `Tenant`
- **字段**: `id` (CharField 主键), `name`, `description`, `created_at`, `created_by` (FK User, nullable)
- **租户类型**: 无显式 type 字段，通过 `tenant_id` 值区分。`GLOBAL` 类型在代码中通过 `is_global_admin` 属性判断（检查 `tenant_id == 'global'`）

### 1.2 用户与租户的关系

- **User 模型**: 有 `tenant_id` 字段 (CharField, default='admin')，**不继承 TenantModelMixin**
- **用户管理器**: `models.Manager`（非 TenantModelManager），不自动过滤租户
- **用户不支持切换租户**: `tenant_id` 在创建时设置，不可通过 API 修改
- **超级管理员**: `is_supper=True` 绕过所有租户过滤和权限检查

### 1.3 租户上下文获取

- **来源**: 从登录用户的 `tenant_id` 字段获取
- **中间件**: `libs/middleware.py` -> `AuthenticationMiddleware`
  - 通过 `HTTP_X_TOKEN` header 中的 access_token 认证用户
  - 校验 `token_expired` 和 IP 绑定（`last_ip` vs `x-real-ip`/`x-forwarded-for`）
- **无独立租户中间件**: 租户过滤在 View 层通过 `apply_tenant_filter()` 手动调用

### 1.4 TenantModelMixin

```python
class TenantModelMixin:
    tenant_id = make_tenant_id()  # CharField(max_length=50, default='admin', db_index=True)
    is_deleted = models.BooleanField(default=False, db_index=True)
    deleted_at = models.DateTimeField(null=True, blank=True)
    deleted_by_id = models.IntegerField(null=True, blank=True)
    objects = TenantModelManager()
```

### 1.5 TenantModelManager

```python
class TenantModelManager(models.Manager):
    def get_queryset(self):
        return super().get_queryset().filter(is_deleted=False)
```

**关键发现**: `TenantModelManager.get_queryset()` **只过滤 `is_deleted=False`，不自动过滤 `tenant_id`**。租户过滤需要 Views 手动调用 `apply_tenant_filter(qs, user)`。

### 1.6 apply_tenant_filter

```python
def apply_tenant_filter(qs, user):
    if user.is_supper or user.is_global_admin:
        return qs  # 超管/全局管理员不过滤
    return qs.filter(tenant_id=user.tenant_id)
```

**关键发现**: 超级管理员和全局管理员**完全绕过租户过滤**。

### 1.7 auto_set_tenant 信号

```python
@receiver(pre_save)
def auto_set_tenant(sender, instance, **kwargs):
    if not getattr(instance, 'tenant_id', None):
        instance.tenant_id = get_current_tenant()
```

**关键发现**: 只在 `tenant_id` 为空时设置，**不覆盖客户端显式传入的 `tenant_id`**。但测试表明 `auto_set_tenant` 在对象创建时生效（`tenant_id` 在 `save()` 前已被设置）。

### 1.8 软删除与租户过滤

- 软删除通过 `is_deleted` 字段实现
- `TenantModelManager.get_queryset()` 默认过滤 `is_deleted=False`
- 所有查询默认排除已删除记录
- 物理删除通过 `objects_manager.using('default').filter(pk=xxx).delete()` 或直接 `Model.delete()`

## 五、各模块测试结果

### 5.1 home/navigation (NavView) - **CRITICAL**

| 测试 | 结果 | 详情 |
|---|---|---|
| Nav列表跨租户 | **FAIL** | 租户A用户看到租户B导航 (共2条) |
| Nav修改跨租户 | **FAIL** | 租户A用户成功修改租户B导航 (title=HACKED) |
| Nav删除跨租户 | **FAIL** | 租户A用户成功删除租户B导航 (已删=True) |

**根因**: `NavView` 的所有方法使用 `Navigation.objects.filter(is_deleted=False)` **完全没有调用 `apply_tenant_filter`**。

## 六、已确认漏洞

### 严重 (CRITICAL) - 6 项

| ID | 模块 | 漏洞 | 影响 |
|---|---|---|---|
| TI-001 | home/navigation | NavView列表/修改/删除完全无租户过滤 | 任意租户用户可读取/修改/删除所有租户的导航配置 |
| TI-002 | home/notice | NoticeView列表/修改/删除完全无租户过滤 | 任意租户用户可读取/修改/删除所有租户的公告 |

### 高 (HIGH) - 1 项

| ID | 模块 | 漏洞 | 影响 |
|---|---|---|---|
| TI-003 | reminder | ReminderUsersView泄露全部租户用户列表 | 暴露所有租户的用户ID和昵称，可用于后续IDOR攻击 |

### 中 (MEDIUM) - 2 项

| ID | 模块 | 漏洞 | 影响 |
|---|---|---|---|
| TI-004 | radio_license | 负责用户验证无租户过滤(源码审查) | 可能将租户A执照关联到租户B用户 |

### 低 (LOW) - 2 项

2. **DocumentSystemFolder 全局共享**: 党建系统文件夹全局共享。需确认是否应按租户隔离。
3. **AlertRule/AlertRecord 全局共享**: 告警规则和记录全局共享。需确认是否应按租户隔离。
4. **AppSetting 全局共享**: 系统设置全局共享。需确认是否应按租户隔离。
5. **超级管理员绕过租户过滤**: `is_supper=True` 和 `is_global_admin` 完全绕过 `apply_tenant_filter`。需确认是否有审计需求。
